# Aux public-client OpenAI sign-in

Original implementation for `docs/spec/daemon/agent.md` Model/provider contract. Provider ID `openai-codex` now means a user-authorized Aux registration using the public Responses API. It does not read another application's auth state, borrow an application client ID, or use a ChatGPT private backend endpoint.

First sign-in starts the local callback listener before returning a browser URL, using OpenAI's documented dynamic entry point and Aux's actual app name. Only an issued client ID paired with a verified ID-token subject is saved. Later sign-ins use that registration's issued identity; failed exchanges retain their issued ID for an in-memory retry with new state/nonce/PKCE values. Authorization URLs deliberately omit ID-token hints so browser JavaScript never receives retained identity tokens. [Official registration and sign-in protocol](https://developers.openai.com/siwc/token-sharing-open-source/sign-in).

The host identifier is installation-scoped; client/account registrations are separately persisted per Aux account. Access, refresh and identity tokens live in AES-256-GCM encrypted `u/<account>/oauth-credentials.json`, with account-bound authenticated data and a separate owner-only `oauth-private.key`. Credential replacement is atomic; files are bounded, reject symlinks/hardlinks/unsafe permissions, and use mode 0600. Buffer keys/plaintext are cleared after encryption/decryption; required token strings remain private process state. Model configuration and cached public catalog metadata never hold tokens. Ordinary file tools deny these paths. Redaction covers current and previously used tokens.

The listener accepts only IPv4 loopback, exact Host/path, GET, matching state and unique callback parameters. Each callback is consumed before exchange; timeout/cancel/account deletion/service close invalidate it. `jose` verifies issuer, issued-client audience, signature, expiry, nonce and returning subject against a bounded, origin-pinned discovery/JWKS cache. Discovery cannot redirect token or revocation requests to a different origin. No arbitrary callback URL, issuer, client ID or token can be supplied through RPC.

Refreshes coalesce within the daemon. A separate SQLite exclusive transaction serializes credential mutation across processes; its database contains no tokens and an OS process exit releases the lock. Successful rotation atomically replaces the credential set. Terminal refresh failures clear tokens and require reauthorization; transient failures retain credentials. Sign-out retries temporary revocation failures, clears local tokens and explicitly reports an unconfirmed remote outcome. Registrations remain for later sign-in. [Official session/refresh/revocation lifecycle](https://developers.openai.com/siwc/token-sharing-open-source/profiles-and-sessions), [official refresh error codes](https://developers.openai.com/siwc/token-sharing-open-source/errors-and-recovery).

Selecting another registration is blocked while persisted sessions are running/suspended. A new sign-in can verify and save a separate connection without changing an active run's registration. Catalog results remain scoped to the selected registration and retain server ordering; no entitlement, context window, reasoning levels or pricing is invented. The UI exposes separate verification, consent, catalog and error states. [Official account catalog and inference route](https://developers.openai.com/siwc/token-sharing-open-source/models-and-inference).

Every HTTP inference uses `POST https://api.openai.com/v1/responses`, `store:false`, `stream:true`. The SDK adapter also streams requests made by non-stream helpers such as compaction, then supplies the completed response to the normal SDK parser. Missing completion, failed/incomplete terminal events and interrupted streams fail explicitly. Structured errors retain HTTP status, redacted body shape, code/parameter and request ID. Usage-limit/invalid-body errors are not automatically retried or sent to another billing path.

## Public unknowns and acceptance limits

The public token reference names `earliest_refresh_at` without specifying its wire units. Aux preserves numeric/string metadata without interpreting it; when present, renewal waits for access-token expiry rather than guessing units or scheduling an early refresh. Otherwise renewal starts within the final minute. Provider refresh rejection remains authoritative. For a user explicitly enabling previously ungranted plan usage, Aux requests the complete scopes with the documented `prompt=consent`; it does not assume deployment of `force_reconsent`. [Token reference](https://developers.openai.com/siwc/token-sharing-open-source/token-reference).

No live registration, authorization, token, model-catalog or inference endpoint was called in this slice. Tests use an independently generated RSA issuer on disposable loopback servers/homes, including actual SDK parsing of fixture Responses events. Actual account eligibility, provider consent screens, deployed discovery, rotating-token behavior and completed live inference remain unverified. All real AI acceptance stays Muse-only under the workspace instruction.

## Root integration

- Add `jose ^6.2.12` from the agent manifest to the integrated lock/dependency bundle. No lane install was run.
- `createModelRouter` already mounts the new procedures; no extra namespace is required: `models.oauthAuthorize`, `oauthStatus`, `oauthCancel`, `oauthRegistrations`, `oauthSelect`, `oauthSignOut`, `oauthDiscoverModels`. Callback RPC deliberately rejects caller codes; only the one-use loopback listener exchanges them.
- Register `engine.registerCloseHandler(() => engine.credentials.oauth.close())` and `store.registerAccountDeletionHandler(accountId => engine.credentials.oauth.cancelAccount(accountId))`. Engine shutdown must still abort active inference before closing storage, as it already does.
- Mount `OpenAIOAuthSettings` from extension `oauth-settings.tsx` in the provider settings page with `accountId` and optional `onModelsChanged` refresh callback. No native Chromium edits, extension permission, host registration or client secret is needed. This module opens the authorization tab only after an explicit button click; it does not perform a background sign-in or persist provider credentials in browser storage.
