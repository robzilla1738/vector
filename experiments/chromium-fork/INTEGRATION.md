# Aux shell and host proof map

This maps the **current Aux checkout** to the isolated `//chrome` candidate. It is a source-inspection plan, not evidence that the candidate already contains Aux's shell. Keep the running identity-only build intact. First finish the live Store install/restart proof in that executable. Only then add the narrow host integration and rebuild the same checkout.

## Narrow implementation order after Store proof

The first likely upstream touch points are `chrome/browser/ui/views/frame/browser_view.{h,cc}` (the child view hierarchy and tab observation), `chrome/browser/ui/views/frame/layout/browser_view_layout.{h,cc}` and its layout implementation (shell/stage geometry), `chrome/browser/ui/webui/chrome_web_ui_controller_factory.cc` plus `chrome/common/webui_url_constants.h` (a trusted Aux shell origin), and the relevant `BUILD.gn` resources. `BrowserView::AddedToWidget` and `BrowserViewLayoutViews` already enumerate toolbar, horizontal/vertical strip regions, and `MultiContentsView`; this makes native placement and popup/fullscreen behavior a real integration patch, not a CSS-only port. These are candidate seams from source inspection; compile and runtime behavior still need proof. Record the resulting upstream diff, rather than estimating it from the two-file branding patch.

The renderer's startup `refresh()` immediately requests a catalog snapshot and then `workspace.get`, `settings.get`, bookmarks, downloads and programs through `api.invoke`. It can display a disconnected shell if the runtime is absent, but the prepared two-layout journey switches layouts through `settings.set` and requires runtime `pages.list` to agree with the native catalog. Therefore a static WebUI paint or a bridge containing only `tabCommand` cannot pass the shell proof. Wire the sidecar before calling the complete integration journey; record early visual/geometry checks separately if it is still disconnected.

1. **Shell surface:** bundle current production renderer assets into an Aux WebUI source in the existing checkout. Add a browser-process bridge for only `tabsSnapshot`, `tabsSince`, `tabCommand` and stage/layout methods first. Render both original Aux layouts in the actual candidate window with Chromium's own toolbar/tab-strip regions hidden only for Aux windows; preserve extension popup and other native browser UI. Record patch size and touched upstream areas after every step.
2. **One tab truth:** wire `TabStripModel` changes into the Aux catalog and route bridge commands back to the same model. Add/reuse page ID mapping keyed by tab identity, not URL. Keep extension-created tabs and normal shortcuts in this path. Run the prepared candidate shell journey against the binary; a stock Chrome window or a painted mock is a failure.
3. **Runtime:** attach the existing Aux runtime to candidate targets in the disposable profile for one controlled click and takeover, then replace proof-only raw CDP access with an authenticated target-scoped transport before any packaged claim. Preserve the runtime's current data/profile boundary.
4. **Broader host gates:** candidate extension APIs/update/disable/removal; two Profiles, private, passkeys/SSO, signed 1Password, native window details, performance, signed update and one upstream security rebase. Keep the Electron preview working until an evidence-backed host recommendation is presented.

If the Store journey fails, preserve the failed profile and candidate process logs before changing the source patch. Separate failures at Store page eligibility/button, native permission prompt, CRX download/verification, extension activation, and restart persistence. Record the candidate binary path and revision, URL/visible UI, `chrome://extensions` status, relevant extension ID in `Default/Secure Preferences`, version directory, update URL, disabled reasons, and the first concrete browser/Store error. A “Switch to Chrome” banner alone was present in the successful Chrome for Testing reference and is not a failure diagnosis. If installation works only after a small host configuration fix, record that patch and rerun the **same** candidate journey. Do not infer 1Password, extension updates or Aux-shell compatibility from a successful uBlock install.

Measure compilation time, peak process-tree RSS, free disk, patch file count and an upstream rebase conflict rate. The current first compile is the identity/Store feasibility build; its time is not an estimate for the shell port or recurring release cost.

### Native shell inspection after the scripted journey

Use the visible candidate, never the mock renderer or a separate stock Chromium window. Capture the candidate window and accessibility tree in light and dark appearance at a fixed 1440 × 960 starting size, then resize it. Record pass/fail and any screenshot alongside the candidate binary revision and patch SHA.

- **Horizontal:** one Aux tab row and toolbar, no exposed Chromium duplicate controls; traffic lights sit clear of interactive elements; Cmd+T opens in this window, tab selection and close match the native page and address, and content begins exactly under Aux's toolbar.
- **Vertical:** expanded, collapsed and peek sidebar retain Aux's CSS/materials; native page reaches the intended flush edge, the address bar/menus layer above it, and traffic lights hide and reappear with the toolbar. Clickable controls do not start a window drag; blank designated chrome does.
- **Split and overlays:** two distinct page targets occupy the reported stage at the selected ratio without covering the divider; palette, menus, tab preview and page-region capture take input above the native pages and restore focus afterward.
- **Window behavior:** native full-screen entry/exit, minimize/restore, resize, popup and new-window flows retain the owning Profile and Aux layout. A web popup must not acquire the privileged shell bridge. Cmd+T and extension `tabs.create` must not create a stray stock browser window.
- **Agent:** identify the visible tab by both Aux page ID and Chromium target ID, perform one bounded action, take over from the human shell, reject another Profile/private target, and reconnect after a runtime restart without a duplicate tab.
