# Private attachment upload and transcript imports

This is a new Aux cloud API, not a claim that the supplied local attachment restore flow is wired. Root mounts `attachmentRoutes` after `requireUser` and mounts `blobCallbackRoutes` outside session auth; only Vercel SDK signature validation can authorize the callback. The Blob store must be **private**. `BLOB_READ_WRITE_TOKEN` identifies that isolated store; no caller-controlled URL is downloaded. `AUX_API_ORIGIN` must be the deployment's reachable HTTPS API origin for signed callbacks, including Preview.

1. POST `/attachments/intents` with `{name,contentType,size,sha256,purpose?}`. SHA-256 is of exact upload bytes. Purpose is attachment or share; share requires JSON, at most50,000,000bytes. Other files cap at100MiB. Response includes id, pathname, access:private, clientPayload and uploadUrl.
2. Use `upload(pathname,file,{access:'private',handleUploadUrl:'/attachments/upload',clientPayload,headers:{Authorization:...}})` from `@vercel/blob/client`. For large files use multipart:true. The authenticated token endpoint consumes a matching owner/path intent once, restricts MIME/size, forbids overwrite and limits token validity to10minutes. The reservation expires at15minutes.
3. SDK-signed `/attachments/callback` independently fetches private content, bounds bytes and verifies actual size/MIME/SHA-256 before readiness. Untrusted declared hashes are never sufficient.
4. POST `/attachments/:id/commit` returns verified metadata. This also supports callback delay. Purpose share parses the verified JSON and calls the same strict publication schema as direct POST `/shared-sessions`; response adds share:{id,title,createdAt}. The desktop must still adopt this upload/commit extension for transcripts over the4MB direct API limit.
5. GET `/attachments/:id` metadata; GET `/attachments/:id/content` authenticated download, optionally a single Range. Responses use no-store, nosniff, forced attachment disposition and restrictive CSP. DELETE removes private Blob bytes before marking the row deleted. Never send the Blob read-write token to the browser.

Quota reservations are atomic per owner with committed bytes and unexpired intents counted together:100MiB free,5GiB Pro,20GiB Max,10000active objects maximum. Only active/trialing paid plans count. An upload is scoped to `aux/{internal-user-uuid}/{intent-uuid}/content`. Blob paths and IDs supplied to SDK get/del come from the owner-scoped database reservation.

`cleanExpiredAttachmentUploads` removes expired uncommitted uploads in bounded batches. Root must call it from a protected scheduled maintenance handler. A lost response after token issuance requires a new intent; canceled/expired unused blobs are later collected. Read/delete/commit require real authentication; callbacks use the SDK's verified signature and signed token payload, then recheck the reserved path and owner.

Private Blob and TLS do not imply client-side encryption. Local file restoration, attachment manifests, E2EE/key derivation and session ownership mapping still require a separate desktop adapter. Shared-transcript imports are explicitly public after commit; ordinary attachments remain private. Provider upload/callback/read/delete and concurrent quota integration tests must run against an approved disposable Aux store before runtime readiness is claimed.

References: [private storage](https://vercel.com/docs/vercel-blob/private-storage), [client uploads](https://vercel.com/docs/vercel-blob/client-upload), [SDK](https://vercel.com/docs/vercel-blob/using-blob-sdk). Implementation uses SDK callback verification and private pathname-based get; range output is sliced as a bounded stream because SDK range return shapes vary by version.

## Supplied daemon adapter (inactive pending staging review)

`vendor/provided/cloud-attachment-adapter.mjs` count-checks four source boundaries. Successful supplied upload RPCs back up their already-authorized local attachment; a failed backup preserves the local operation and records a generic warning without signed URLs. Missing stored attachment content can recover only when the local session already exists and sync is enabled, reusing the original exclusive-create attachment writer. Incognito/ephemeral sessions are excluded, hashes and sizes verified before writing, and redirected session/attachment directories refused. No cloud-provided filesystem destination is accepted. Cross-device session discovery/transcript restoration is a separate required integration.

The native transport POST `/attachments/:id/upload-url` consumes the exact owner intent once and returns a scoped private presigned PUT URL valid10minutes. Native fetch uses no Aux Authorization header for that external PUT and refuses redirects/unrecognized origins. Afterwards the normal commit performs private-download integrity validation. This path needs no added Blob SDK inside the supplied daemon. Oversized explicit sharing uses the same intent/presigned-PUT/commit path, while ordinary small publication remains unchanged.

Migration005 stores owner/session/local-path-to-verified-blob bindings. PUT/GET/DELETE `/attachment-sessions/:sessionId/files` use `{localPath,attachmentId,blobId}` for PUT and `?path=attachments%2Ffilename` for reads/deletes. Only immediate files under attachments/ are accepted; the referenced blob must be ready and belong to the authenticated owner. Session IDs are opaque cloud names; they do not authorize local session creation or filesystem writes.

A local attachment delete removes its cloud path binding before deleting the local file, preventing automatic resurrection. Rename reconciliation, old unreferenced ready-Blob retention and retryable background backup queues still require follow-up. Full chat/session history synchronization is not established by these file bindings.
