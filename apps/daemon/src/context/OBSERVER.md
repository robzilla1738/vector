# Opt-in context observer

Original implementation of `docs/spec/daemon/services.md` Context awareness. `createContextObserver(services,context,{isUnlocked})` samples the current account only, with one active cycle, bounded helper/bridge requests, cancellation on close/security change, and no automatic permission prompt. OS observations and browser metadata use separate trust boundaries.

OS capture prepares app/window identity, checks app exclusions, then consumes a one-use helper token. The helper skips HTTP/HTTPS handler/browser apps and web accessibility trees, omits entire editable subtrees and verifies the same foreground process launch and focused window after capture. Browser/private mode is never inferred from titles or URLs. Browser activity instead comes from `context.activity` on an authenticated ordinary-profile bridge. The extension resolves its actual native profile/account, rejects incognito context and incognito tabs, checks domain exclusions and opt-in, revalidates the same active tab and stable debugger target. Only URL/title/target/time metadata is collected; no historic page body or arbitrary caller JSON becomes observed evidence.

Every observer capture checks current account, unlocked state, opt-in, pause, permissions and exclusions before capture and before ledger/index commit. Settings/security generations invalidate pending work, including pause/resume races. Permission revocation blocks subsequent capture. Newly captured events and dependent vectors are removed on revocation while indexing. Unchanged observations are deduplicated in memory. Status separates enabled/permission from a live observing phase and actual capturing phase; no observer means capturing=false even with granted permission. The optional `status(url)` cannot establish a profile/mode proof, so URL observability is conservatively false.

No automatic summary thresholds are introduced: those measurements remain draft. Existing explicit comprehension remains separate. Actual OS runtime capture acceptance is outstanding; tests use fixture adapters/bridge responses, disposable homes, pure Swift policy fixtures, and no owner apps, profiles, or prompts.

## Exact root hooks

- Add HelperMethod values `semantic.prepare` and `semantic.capture` (root already applied).
- Give `createHelperCaptureAdapter` a **separate** `HelperClient` from Vault/interactive tools. It uses 3–6 second deadlines and cancellation retires its private helper child. Sharing with an interactive biometric prompt could cancel that operation. Both clients use the bundled independent executable, separate private artifact directories, and close at shutdown.
- After constructing ContextService, import `createContextObserver` from daemon `context/observer.js`; instantiate with `services`, `context`, `{isUnlocked: accountId => /* actual current Vault unlocked predicate */}`. Call `start()` after services initialize, `await close()` during shutdown **before closing helper and account storage**.
- Call `contextObserver.changed(accountId)` after a real `contextAwarenessEnabled` change and from the existing Vault security-change listener (lock/password/biometry reset), plus account deletion. Pause/resume/exclusion/clear APIs internally increment a generation and are rechecked by the observer. Account-current changes are also checked before/after async work.
- Agent extension background imports `readContextActivity` from `./context-bridge`; authenticated command map adds `'context.activity': readContextActivity`. Daemon bridge default command allowset adds `context.activity`. No new extension permission is needed beyond the existing tabs/debugger bridge permissions.
- Caller JSON `context.ingest` and `reportTabSignal` RPCs fail closed; the observed internal service methods remain available to trusted source adapters and fixture tests. Do not restore a caller assertion of profile/mode as proof.

The sampling interval is an observation cadence (default five seconds), not a summary/consolidation threshold. Observer phases/reasons contain no captured text. Event content is redacted before persistence by the existing ContextService normalization.
