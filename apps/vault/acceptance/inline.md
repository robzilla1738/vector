# Inline login suggestions

Implements approved `docs/spec/ui/vault.md` Generator and autofill, `vault-security.md` lock/reprompt boundaries, and `visual-measurements.md` M4/M6. Original Aux source only; no reference code, owner browser profile, credential, clipboard or Keychain was accessed.

A trusted click on the isolated content actor's control opens matching login suggestions. Cards/identities keep the existing popup field-review path. The panel is a closed shadow DOM: declared outer width308px,24px side/bottom inset with zero top inset, result scroll maximum240px, options8px side/6px vertical inset,10px gap and16.8px corners. Heights follow content. Account theme comes from the ordinary `theme` setting; muted labels use the M6 neutral55%-alpha roles. There is no invented native material or popup-placement parity claim. Keyboard users can operate fields and choices, move with arrows and dismiss with Escape; outside pointer actions, hidden documents, navigation and expiry dismiss.

The worker calls the root-owned `vault.getAutofillCandidates({accountId,documentUrl})` metadata API. Its client-kind gate allows only the Vault extension, and its authoritative unlocked snapshot filters active exact-origin login records, bounded100. Only `{id,title,username,revision,reprompt}` crosses to the isolated UI; future extra fields are stripped. Passwords, TOTP, notes, card data and custom fields are absent from suggestion lists. Generic DOM body text does not include the closed-shadow list. This does not claim that visible usernames cannot be seen in a screenshot or accessibility UI.

Only an explicit item choice plus the checked login fields acquires that selected Vault item. The worker checks item identity, revision, active/category/reprompt state, exact saved origin and allowed selected fields. Native profile proof must explicitly identify the current account, profile and default/incognito mode; missing flags fail closed. Scope and authoritative lock state are rechecked across async boundaries, before metadata is returned, before secret acquisition and before actuation. Normal/private split workers never infer mode from a URL. Neither metadata nor credentials are written to browser storage, page storage, logs, generic tools or model transcripts by this path.

The fill target retains Chrome tab/frame/document IDs, exact frame and top-level URLs, actor token, form identity and element fingerprints. It expires after two minutes; at most64 requests are held per worker. Frame sender mismatch, removed/replaced/hidden/readonly fields, changed form/attributes/document, navigation, profile/account change or Vault lock rejects. Clicked fields are selected explicitly; a form has no document-wide fallback. The actor verifies each selected element immediately around native input/change events and reports partial/changed-value errors truthfully. It never invokes submit, requestSubmit or an equivalent form submission.

Locked suggestions contain no saved-item metadata and offer the existing real Vault popup. After user authentication, a non-overlapping two-second status/scope check resumes only the same unexpired actor target, re-verifies it and reloads metadata. These checks do not fetch the Vault snapshot while already unlocked, so polling does not renew idle expiry. Changing focus/target or navigating requires a new request. Lock/account/profile errors clear the displayed list on the next check. Metadata is transient; worker restart loses grants and fails closed. Dismissal/supersession while an async item read completes prevents later actuation. Each chosen fill is one-use and never automatically retried after failure or uncertainty.

Existing trusted-submit capture and popup save/update review remain separate and unchanged: the isolated actor retains the submitted password transiently, sends only a token until explicit user acceptance, and the worker verifies current scope/document/origin/item revision before saving. New suggestions do not submit, save automatically, broaden source capture or introduce password values into generic snapshots. Reprompt-protected items are disabled in suggestions and rejected again during fill; no unsupported authorization/grace-period protocol is invented.
