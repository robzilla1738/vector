# Connected services Settings refinement

This UI-only slice addresses the current native unconfigured-state evidence at `/tmp/aux-34117-native/connections-unconfigured-dark.jpg`. That candidate showed uppercase section labels, a 235px minimum empty review browser and an always-expanded raw checkbox stack. No service authorization, account identity, scope, grant or dispatch implementation is changed.

The Google and X permission selectors now use explicit native disclosures, showing the actual selected count before expansion. Expanded choices retain shared Checkbox controls in joined Settings rows (52px minimum, 14px/500 labels and 20px leading), with bounded 320px scrolling for long lists. The existing permission explanations remain visible inside the disclosure. Disclosure arrows use the existing utility glyph. Draft choices make no authorization request; only the existing explicit Connect buttons start OAuth. X's three required identity/refresh scopes remain selected and disabled.

Service headings use the shared compact 14px/500/20px role without uppercase transformation. Supporting copy uses 12px/500/16px. Standard action buttons and native Select triggers are 32px. Account/task selectors use the existing SettingsField/SettingsGroup card roles, including the 636px visible wide card, rather than an extra nested card implementation. Google/X granted permissions and task operations remain separate and display real returned values. Account-revision/task-revision bindings and uncertain-write behavior are unchanged.

Connector review keeps actual Space/task selectors but renders a compact truthful empty/loading/error state instead of an empty two-pane browser. A populated catalog retains its selected connection and real effective access, with a 176px connection list beside its detail. Below 520px available Settings content width, the list becomes a bounded horizontal selector above the detail. The former glass blur/saturation layer, 235px minimum height and oversized chip/row variants are removed. Review/confirm/revoke still use the existing Calendar grant routes.

Calendar retains its separate read-only connection and original task-grant routes. Routing its Connect button through Google permission replacement would change which scopes are requested and could retire prior Calendar access. This slice therefore clarifies the distinction and shares visual roles while preserving both real setup paths. There is no duplicate simulated account or permission state. Upcoming events retain their exact account source and use compact separated rows.

Long account labels exposed a concrete Chromium customizable-select issue: the default selected text could wrap over its picker icon. `ConnectionSelect` delegates the existing shared Select and gives Chromium a native `selectedcontent` slot; React still owns value/options/change events. The slot is attached at the native control boundary so the current React DOM version does not emit invalid-nesting warnings for Chromium's new select children. Closed labels ellipsize within the compact slot, while the real option text remains available in the native picker. No JavaScript menu or action stack is introduced.

Verification:

- Fifteen renderer tests cover exact Google/X task-account revisions, truthful missing registration, draft selection without OAuth, explicit selected-scope sign-in, required X scopes, late OAuth retirement, retry after failure, real Calendar grant/revoke review, catalog empty versus failure, and stale account read isolation.
- Shell typechecking passes. Existing shared runtime dependencies were copied into the isolated worktree only to typecheck the current integration; they are not part of this patch. Contracts alone were rebuilt for the mock renderer's package exports; there are no runtime source edits.
- An isolated installed Chrome155 renderer fixture observed unconfigured, populated/expanded, failure and loading states in both themes at 1712/900/400×989 (24 states). Geometry is in `/tmp/aux-connections-renderer/geometry.json`; screenshots include each panel's scrolled start. No page errors or horizontal Settings-content overflow occurred, and cards stayed within the Settings canvas. The intentional 14px card outdent from the narrower text column is recorded separately. All populated Select triggers measured 32px; ordinary permission rows measured at least 52px, expanding for long labels.
- Native picker keyboard observation in the synthetic renderer changed to the exact second Google account, updated the selected label and returned focus to the Select after Escape (`/tmp/aux-connections-keyboard2.log`). No live OAuth, providers, messages or owner Profile were used.

These are source/test and synthetic renderer observations. Current Aux native comparison, integration checks, performance and full captured-state acceptance remain separate work. No phase-completion claim is made here.
