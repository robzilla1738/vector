# Shared native Select label boundary

The scoped Settings audit observed the actual “When context changes” Routine suggestion label wrapping inside its fixed 32px trigger at 400px width. The previous connected-services refinement had already isolated the same Chromium customizable-select behavior for long account labels. This follow-up moves that solution into the canonical `Select`, deletes `ConnectionSelect`, removes its duplicated connection-only CSS and imports `Select` directly in Google, X, Calendar and connector review. All four existing Routines selects now use that same boundary and keep their original values, options and handlers.

The shared control inserts only a native `button` / `selectedcontent` label slot. Chromium owns its selected-option clone and picker. React continues to own the original option nodes, controlled or uncontrolled selection and original change events. No listeners, JavaScript menu, cloned options, option-to-button actions, focus redirection or picker stack are introduced. The slot is installed at the existing native ref boundary to avoid the current React DOM version's invalid-child warnings for Chromium's new select markup. The exact owned slot is removed when the ref changes, the native control mode changes or the component unmounts. Multiple selects and explicit-size listboxes keep their original native option-only structure.

Single-selects inherit the existing startup-loaded 32px, 14px/500 native control role instead of the old shared text-field 36px minimum. Their label slots use single-line ellipsis, 20px leading and a separate unchanged 16px chevron. Full labels remain visible in the actual native picker. Native listboxes retain their distinct sizing; text fields retain their original role. No material, account, scope, task grant or run behavior changes.

Verification:

- Fifty-four distinct renderer tests in twelve files cover original native events/form values/reset/focus, keyed option replacement/reordering, optgroups and disabled options, controlled/uncontrolled selection, StrictMode ref replay, replacement-ref/unmount cleanup, native multiple/listbox transitions and exact Routine suggestion saves. Existing Google/X/Calendar/review authority tests and Memory/Channels/Desktop-context consumers pass. The final Routines-only rerun passes after adding an explicit missed-run label/control association and resetting its fixture's selected setting between tests.
- Shell typechecking passes. Scoped lint has no errors; existing unrelated advisory warnings remain. The React review checklist found no added render-time ref reads, effects, event listeners or data subscriptions in the boundary.
- Installed Chrome155 observed actual Routines and GoogleConnections components with explicitly synthetic account data at 1712×989 and 400×989 in both themes: eight closed-trigger and eight open-picker states. Trigger geometry is 160×32 normally and 140×32 narrowly, with 14px/500 text and 20px single-line label boxes. No horizontal Settings-canvas overflow, page errors or console errors occurred. Screenshots were inspected manually for the narrow light Routine label, narrow dark account label and both open-picker states; no pixel-diff program was used.
- In each of those eight states, native Space/Arrow/Enter selected the exact expected value, Chromium updated the selected label and Escape returned focus to the original select. Additional dynamic-option observation retained the original select/focus when closed; while open, the native picker stayed open across an option/value/ref update and Escape returned focus. The retired original select contained no owned label slot and its last callback was the normal null ref.
