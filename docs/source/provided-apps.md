# Supplied stack staging and preservation

`node scripts/stage-provided.mjs [--output <directory>] [--app-path <final-Aux.app>] [--replace]` stages the pinned supplied Agent/Vault UI, daemon, CLI, agent runtime and memory distributions atomically. It never launches those components, requests OS grants, reads adjacent profiles/settings/credentials or inserts independently reconstructed screens/runtime components. The default output is ignored `out/provided-reuse`. An existing destination is refused unless `--replace` verifies its supplied-stage marker; the old stage is then retained in a uniquely named sibling backup until manually retired. An invalid or incomplete new stage leaves the prior output intact. The final app path defaults to `~/Applications/Aux.app` and controls exact runtime relocation only; staging does not install or launch that app.

UI pinning and branding policy: `docs/source/provided-ui.md`. Actual native consumer mappings and remaining capability gaps: `docs/integration/provided-native-ui.md`. Daemon/CLI boundaries: `docs/reuse/daemon-runtime.md` and `docs/reuse/cli-runtime.md`.

`scripts/lib/provided-apps.mjs` verifies the entire static source app inventory in `provided-app-inputs.json`: daemon133 files/171,597,622 bytes, CLI6 files/155,541,595 bytes. It rejects symlinks, unknown resource bytes/modes and overlapping input/output roots. The daemon and CLI adapters independently require exact executable and SEA code hashes. The app stager preserves unchanged native libraries, original supplied importer code, runtime support files, licenses and static skills. It applies explicit Aux executable/app/bundle names, icons and visible plist descriptions; compiled principal-class/module identifiers remain intact. It removes original code signatures and provisioning profiles because those cannot authenticate changed Aux artifacts. Generated manifests record every source/output hash, rename, added icon and removal. Resources are not ad hoc signed in this staging slice.

The original native binding is copied byte-for-byte as `provided-native.node`. The modified SEA loaders cannot fall through to that file or the owner's installed binding. No `aux-native.cjs` wrapper is installed yet. Thus this stage **cannot provide working native crypto/storage/PDF** and does not claim to. The disposable test adapter is excluded. The supplied importer still needs a real Aux identity/entitlement contract; metadata rebranding alone does not establish import behavior. Bundled runtime startup/cache provisioning, Computer Use identity adaptation, native account/security/API integration and real packaged acceptance remain required. `manifest.json` records `productionReady:false` and these gaps.

The runtime stage preserves 9,346 supplied regular files and 19 catalog-verified memory files, with exact relocation/env-prefix edits and fresh minimal config/tmp. See `provided-runtime.md` for exclusions, symlink policy and installation-path requirements. The preservation checker verifies complete files/directories/link coverage, original modes, output hashes and count-checked text changes. It also requires current adapter hashes and canonical/derived Aux branding hashes, so changes to the supplied adaptation or updated logo require restaging.

`node scripts/provision-provided-home.mjs --stage <stage-directory> --home <new-directory>` seeds only the19 pinned static memory-distribution files into a new0700 Aux home. It refuses any existing destination, source symlinks or changed payload. It copies no account, profile, credential, runtime temporary file or Keychain state and executes no supplied code. This supports disposable launch preparation; native first-run cache provisioning still needs integration.

Baseline evidence before the updated logo: full preservation audit passed all UI/app/runtime/memory records. The supplied CLI `--help` ran successfully using a separate ad hoc signed disposable executable, isolated HOME/TMPDIR, disabled update checks and a nonexistent native binding path. It printed Aux commands/usage. This verifies the actual CLI host can start; it does not verify authentication, native crypto or a full app. CLI help evidence is ignored `out/provided-acceptance/cli-help.txt`.

`node scripts/check-provided.mjs [stage-directory]` verifies complete source/output coverage, pinned input and recorded output hashes, exact text-anchor replay, unchanged CSS declarations apart from font branding and matching `data-aside-`→`data-aux-` selector identities, and complete app resource accounting. Unchanged source equality is expected. This is a preservation audit of the recorded changes; integration anchors still require review, and it does not establish native capability behavior, helper isolation, cloud behavior or final UI acceptance. No readiness claim follows from this audit passing.
