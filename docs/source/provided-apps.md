# Supplied stack staging and preservation

`node scripts/stage-provided.mjs [--output <fresh-directory>]` stages the pinned supplied Agent/Vault UI, daemon and CLI atomically. It never launches those components, requests OS grants, reads adjacent profiles/settings/credentials or inserts independently reconstructed screens/runtime components. The default output is ignored `out/provided-reuse`; an existing output is refused. A complete candidate replaces its sibling temporary directory only after every input and adaptation succeeds.

UI pinning and branding policy: `docs/source/provided-ui.md`. Actual native consumer mappings and remaining capability gaps: `docs/integration/provided-native-ui.md`. Daemon/CLI boundaries: `docs/reuse/daemon-runtime.md` and `docs/reuse/cli-runtime.md`.

`scripts/lib/provided-apps.mjs` verifies the entire static source app inventory in `provided-app-inputs.json`: daemon133 files/171,597,622 bytes, CLI6 files/155,541,595 bytes. It rejects symlinks, unknown resource bytes/modes and overlapping input/output roots. The daemon and CLI adapters independently require exact executable and SEA code hashes. The app stager preserves unchanged native libraries, original supplied importer code, runtime support files, licenses and static skills. It applies explicit Aux executable/app/bundle names, icons and visible plist descriptions; compiled principal-class/module identifiers remain intact. It removes original code signatures and provisioning profiles because those cannot authenticate changed Aux artifacts. Generated manifests record every source/output hash, rename, added icon and removal. Resources are not ad hoc signed in this staging slice.

The original native binding is copied byte-for-byte as `provided-native.node`. The modified SEA loaders cannot fall through to that file or the owner's installed binding. No `aux-native.cjs` wrapper is installed yet. Thus this stage **cannot provide working native crypto/storage/PDF** and does not claim to. The disposable test adapter is excluded. The supplied importer still needs a real Aux identity/entitlement contract; metadata rebranding alone does not establish import behavior. Agent/memory runtime caches, Computer Use identity adaptation, native account/security/API integration and real packaged acceptance remain required. `manifest.json` records `productionReady:false` and these gaps.

`node scripts/check-provided.mjs [stage-directory]` verifies complete source/output coverage, pinned input and recorded output hashes, exact text-anchor replay, unchanged CSS declarations apart from font branding and matching `data-aside-`→`data-aux-` selector identities, and complete app resource accounting. Unchanged source equality is expected. This is a preservation audit of the recorded changes; integration anchors still require review, and it does not establish native capability behavior, helper isolation, cloud behavior or final UI acceptance. No readiness claim follows from this audit passing.
