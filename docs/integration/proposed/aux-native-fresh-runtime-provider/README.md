# Prepared native fresh runtime provider and explicit Environment caller

`AuxPreparedFreshRuntimeProvider.prepare(terminal:)` accepts only the genuine privately initialized terminal type. It performs actual typed runtime recapture/import and scoped retained-FD preparation, then publishes a native-only process-local registry entry retaining that terminal, capture and scoped owner material. Calling it requires real upstream native admission; this consistency validation does not establish whole-profile or foreign-process custody. No JS module initializer or registration invokes it.

Its read-only `nativeHandle` is a mechanical routing/lifetime identifier, not secret, unguessable, signed authority or serialized custody. C ABI cannot publish an entry or accept selectors, row data, roots, paths, review flags or arbitrary command cores. It can retain/release/close creation admission for an existing entry and create a per-Environment owner from one. Invalid IDs fail without effects. IDs never reuse during this process; forked calls fail. Each actual owner creation revalidates/reimports its own current four-row authority and constructs its own typed scoped dispatcher and immutable five-command OS utility capability. Constructors execute no OS utility. No generic installation API or globally selected token exists.

The two count-pinned WorkerHost successor files add an explicit native `AuxDevelopmentWorkerHost(uint64_t prepared_fresh_provider)` overload. It retains that immutable provider for its lifetime; invalid/closed IDs close the host rather than falling back. The original default constructor remains exact and continues its historical selected factory path. On the explicit path, the actual native Environment callback calls `AuxCreatePreparedFreshRuntimeOwner(provider,...)` instead of the old hardcoded selected factory. Environment matching, cleanup-before-factory reservation, late factory retirement, PDF/OS image capture, native owner retention and NAPI publication remain in the actual production path. A JS function argument never supplies the provider. Real embedding must deliberately construct and retain this overload from genuine native preparation.

`AuxClosePreparedFreshRuntimeCreation` permanently closes future creations and reports only whether owner creation is still pending (0 no creation pending, 1 pending, -1 invalid/wrong process). It is not an existing-owner drain. WorkerHost closes creation admission plus its actual workers and combines pending/untracked outcomes. The provider's mutex never crosses recapture, scoped preparation, OS construction, retirement or destruction. An in-flight factory finishing after closure retires its new owner before reporting completion; it never publishes it. Existing owners continue to require actual WorkerHost retirement. Registry/context references remain alive through pending creation.

Select the new provider Swift file together with this proposal's exact Swift graph (including the after-flock account successor), and the two WorkerHost logical replacements. Root owns shared host build integration; no shared manifest, active host source, package or browser checkout changes are made here. Current checks are source-pin/order only. The recipe exists for a final serialized graph check after source freeze; it has not run. This proposal does not invoke Security/factory/OS operations, signing or owner data.

Remaining integration is explicit: real early native cold/cohort admission, authoritative fresh/resumed terminal production in the daemon process, and actual native Node embedding/preload construction of the explicit provider-backed host. A kernel-authenticated Mach peer alone cannot produce the terminal. No token or JSON over that transport is a substitute. Protected startup refusal/quarantine remains unchanged. Existing selected policies and legacy migration remain separate and unchanged; UI is untouched.
