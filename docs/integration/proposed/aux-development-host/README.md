# Signed development policy and native owned-runtime producer

This implements an actual **source-level development route** for the minimal scoped owned runtime/Node graph. It does not activate it. Production `AuxCleanHostPolicy`/preflight files are untouched. No actual signed-policy loader, owner factory, attachment, Keychain call, private-key import, owner profile or provider service has run. No signing/provisioning or current loader replacement occurred.

## No self-hash cycle: authenticate the sealed resource

The narrower development identity uses the real fixed team/certificate/role instead of embedding expected hashes of itself. The current CDHash is observed and compared across one factory invocation, not predicted in signed bytes. The fixed **`Contents/Resources/AuxDevelopmentHostPolicy.json`** contains no expected-host/CDHash field. This avoids recursive self-hash inputs while tying policy bytes to the actual signed host bundle.

`AuxSignedDevelopmentPolicyLoader.load()` takes **no caller argument**. It:

1. Validates the actual current `SecCode` against Apple generic anchor + fixed team, extracts signing info only after validity, checks exact public certificate DER hash/role/application/group and hardened/exception flags.
2. Requires the **secured** `kSecCodeInfoPList` to declare `APPL`, exact Aux bundle identifier and expected executable. Canonical actual executable and `SecCodeCopyPath` must identify that `.app` bundle, not a standalone SEA/wrapper pretending to be a bundle.
3. Runs real `SecStaticCodeCheckValidity` with strict validation, all architectures, nested code, restricted symlinks and offline/no-network flags. Dynamic validity alone is never treated as resource authentication.
4. Opens bundle → Contents → Resources → fixed filename via FD-relative, non-symlink, nonblocking owned/root-owned nonshared-writable descriptors. It rejects extended ACLs, hard-linked/empty/over16KiB policy files and observed inode/time/size/path changes. The fixed `.app` Contents resource-base path passed to `SecCodeValidateFileResource` is **`Resources/AuxDevelopmentHostPolicy.json`**. The exact captured CFData must pass that API before parsing. There is no optional/unsealed-policy fallback or alternate path attempt.
5. Parses strict duplicate-aware JSON with exact fields, then validates loaded images and fixed approved home. The policy is read again byte-for-byte; whole bundle and dynamic signature are checked again. The authenticated policy type has a same-file constructor, no Codable/JS constructor or successful-validator callback.

The fixed scope and public disposable home match the existing approved `dp-scope-policy.h`; no owner home or arbitrary scope may be supplied. Nothing creates/deletes that home. Actual leaf/home checks remain unexecuted. Loaded non-system images must be exactly the host executable and fixed `Contents/Resources/native/aux-runtime-owned.node`; each gets real code-signature/team/certificate/identifier validation. A nested addon has no entitlements and exact `dev.aux.browser.runtime` identifier. System images use normalized protected-system paths; real Aux interposer symbols and imported Security function origins are checked. There is no old-group/default/login fallback.

The resource schema is exact: `format`, `role`, `home`, `scope`, `accessGroup`, canonical `generationId`, explicit `scheme`, canonical signing/KEM public-key Base64, all four `targetHashes`, and a finite `logicalKeys` array (1–128, total JSON ≤16KiB). Role is daemon or CLI; home/scope/group must equal the source-pinned existing disposable review. Public target values must come from an independently verified migration/cohort. Logical keys are exact reviewed user/application labels, never credential values. No arbitrary selector, image path or private representation is accepted. Unknown self-hash/admission fields are rejected. An unsigned copy of this JSON proves nothing; only the actual loader authenticates it.

## Actual producer/attachment source

`AuxCreateSignedDevelopmentOwner` has native output pointers only, with no JS/scope/core/path/observation parameter. It loads the authenticated fixed policy, performs the actual minimal exact four-row DP read, reloads/rechecks the signed policy before private authority import, constructs `AuxRuntimeCapturedCommandContext`, builds the real `ScopedAuxCommandContext.runtime` with the finite logical key policy and actual secure-store boundary, rechecks policy/bundle/CDHash again and constructs one real `AuxOwnedCommandDispatcher`. It returns exactly one retained owner and its immutable handle. Any failure returns a fixed status, without missing→fresh initialization, key reset or logging private contents. No fresh factory/legacy reader is linked.

`AuxAttachSignedDevelopmentDispatcher(env,target)` is the concrete native caller of that factory and the existing `AuxAttachOwnedDispatcher`; the real adapter consumes the retain on every return and owns retirement/release thereafter. The no-throw release callback releases that exact one owner. **There is no NAPI_MODULE initializer, JS factory, worker scope environment override, PID/receipt authority or new app entrypoint.** The future real native host still must choose the reviewed invocation point after its actual lifetime admission. The compiled `.node` is an inspectable source artifact and is never required/loaded by these checks; its missing registration is intentional, not a fake complete addon.

This makes a usable next native source boundary, not an admitted launch. The existing CLI wrapper is not reused: a clean CLI host must have the actual `aux-cli` SEA as the secured `CFBundleExecutable`, without the old wrapper/interposer path. Daemon/CLI source routing, actual native initializer call site and PDF/other retained implementations remain root integration work. Each worker requires its own genuine owned association and policy checks; inherited strings are not that association.
