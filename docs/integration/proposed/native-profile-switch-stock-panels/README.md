# Genuine window side-panel profile closures

Ten exact unchanged native source inputs: ReadingList, Bookmarks, History, HistoryClusters and TabsFromOtherDevices coordinators. These are required Chromium 155 adaptations for the supplied same-window algorithm, not a claim that the original UI exposed every stock Chrome panel. All actual stock views/CSS remain unchanged and are created only through their existing lazy callbacks.

Each stable coordinator retires its own exact window entry through real SidePanelRegistry::Deregister before profile identity changes. That closes/destroys its actual active/cached old-profile WebContents and releases its old view-creation callback. The same registry/userdata survives. ReadingList's existing callback captures Profile by pointer, so merely changing its member would be insufficient; registration is recreated with the real target. Bookmarks uses the genuine SidePanelEntryScope profile dynamically, but its old cached WebContents must still retire. No old renderer is reused as a different profile's content.

History/HistoryClusters detach their old pref registrar and clear old query/UI weak handles before registration. The target registrar uses its actual prefs. HistoryClusters follows the exact PopulateGlobalEntries predicate: target supported AND by-date History panel not supported. ReadingList/Bookmarks preserve actual registration state, rather than creating a phantom entry in an uninitialized graph. TabsFromOtherDevices retires its metrics observer BEFORE deregistering the source entry, because its scoped observation would otherwise reference a destroyed entry. Its old WebUI holds a weak recorder and cannot issue new events after recorder destruction; target registration uses the real unchanged metrics/view constructors and support predicate.

Rebind validates the same actual window owns each coordinator and derives its currently authoritative regular profile. It registers the unchanged lazy target callbacks; it never opens or navigates a target panel. Abort calls the same rebind against the actual restored source. The complete provider must pause side-panel pinning observations first, retire extension and stock entries while old toolbar actions still exist, and only recreate target entries after target toolbar/action model sources are installed. No whole SidePanelUI/Registry/Features reset or successful switch trigger is added.

Source scope: current actual coordinator, registry deregistration and global entry-population implementations. This patch does not establish the supplied gesture's complete popup/focus eligibility or require closing other windows' menus. Exact ten-file disposable replay passes all hashes. No shared source edits/build, browser/history/bookmark access, owner state, network or OS grants. Compile the five actual coordinator objects and expose public header buildflags dependencies as needed. Full provider/runtime acceptance remains pending.
