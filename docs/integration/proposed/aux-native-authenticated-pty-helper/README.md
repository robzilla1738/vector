# Fixed native PTY helper capability

This is a distinct successor of the actual embedded PTY policy loader, retaining its complete original prefix. It is not selected by the main source manifest and changes no accepted app, runtime, startup, helper bytes, UI or policy pin.

The native host captures a helper only after image preparation completed in this process. Full authenticated `load()` selects the actual sealed embedded daemon policy and its fixed PTY helper artifact. No API accepts a path, hash, scope or policy. Capture retains every descriptor and parent/child identity from `/` through that exact executable. Every namespace component remains root-owned, non-writable by group/others, and ACL checked; the caller must remain unprivileged. Each validation repeats policy/host identity, FD identity/entry checks, helper exact bytes and Mach-O execution role, independent role signature and the running bundle's resource seal. It does not load or execute the helper.

A process-local map owns these descriptors. Never-reused opaque numeric IDs avoid dereferencing a caller's pointer or admitting a stale allocation address. Each call takes its own strong reference before releasing the registry mutex; Security and filesystem operations occur outside that mutex. Release removes the map reference and closes descriptors only after the last in-flight operation ends. Wrong-process calls return before the registry/preparation mutex or protected API. The process stamp is the same stamp already established by actual image preparation, rather than a new lazily captured child PID.

The host must surround capture and revalidation with actual Owner authority validation outside Worker locks, retain the capability until spawn commit or proven no-child failure, and compare the producer's compatibility path to the returned fixed path. A JavaScript string, helper argument number, successful compile or receipt grants no authority. This does not prove descendant custody, install an immutable namespace, supply signed v3 helper bytes, enable cold startup or authorize signing/Security runtime calls.

`AuxAuthenticatedPtyHelperCopyPath` returns an authenticated canonical UTF-8 path only into a caller-owned buffer of at most 4096 bytes. Its returned count includes the trailing NUL. Native callers retain the capability and revalidate immediately before actual spawn; the fixed root-owned namespace remains essential because Darwin path-based spawn has no reviewed retained-FD execution API here.
