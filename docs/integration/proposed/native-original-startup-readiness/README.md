# Preserve supplied startup readiness ordering

The earlier Aux platform blocked before creating any profile until daemon health, authentication and public-key loading all succeeded. Supplied startup uses a different sequence: its StartupBrowserCreatorImpl launch first requests component readiness after assigning a real profile (041815c0→04183b1c→042a111c), then only at process startup requests startup readiness (042a155c). Original regular-profile and profile-shutdown checks remain relevant.

The actual readiness deadline is 10 seconds. Check042a5a28 and health completion042ac274 explicitly continue startup when both extensions are ready at timeout even if the daemon is unhealthy. Missing extensions fail. Original042abc18 checks both supplied IDs via ExtensionRegistry set offset0x80; the original named factory and real constructor confirm six24-byte sets at8/0x20/0x38/0x50/0x68/0x80, matching the upstream ready_extensions sixth field. Success042abe9c sets state2 and invokes true callbacks; failure042ac060 sets3 and invokes false. No installation authentication condition occurs on that success path.

The port validates bundled component manifests before profiles, starts the actual owned daemon asynchronously, and places the real 10-second/250-ms readiness wait in initial regular-profile launch. It uses actual ready_extensions for both Aux identities and genuine health observations. Authentication remains independent: daemon auth, public-key loading, CDP authority and the existing account/password gate retain their actual failures. No flag, unlock, health or token is fabricated. A healthy daemon alone cannot admit missing extensions. Callbacks and timers have a single owned lifetime, support nested startup waiters, and are retired on shutdown.

The supplied original updater can defer/rearm activation while new CRX components are downloading. Current Aux stages pin local immutable resources; no remote updater or service success is invented. Runtime acceptance, profile/password-gate fidelity, late CDP recovery and actual UI observation remain separate. This proposal is staged source only and has not been applied or compiled. Original binary ranges/strings and extracted source are recorded alongside it.
