# Stable omnibox provider lifecycle

Four exact applied v62 source inputs. This is a required Chromium 155 integration primitive for the supplied same-window owner transaction, not a claim that the original shipped class had identically named methods. The actual current LocationBarView creates a profile-bound ChromeOmniboxClient, whose AutocompleteController owns profile-bound providers. The existing classic popup observes OmniboxEditModel directly; replacing the entire controller/model would strand that observation and view pointers.

This private, LocationBarView-only reset retains the actual OmniboxController, OmniboxEditModel, popup state manager, view and edit observer list. It stops real old autocomplete work, clears provider-backed matches through the existing Revert lifecycle, destroys old contextual upload/session ownership and invalidates old weak bitmap/context callbacks before destroying providers. It then creates the genuine target client's provider graph with the unchanged constructor configuration and registers the real target emitter and same controller observer. No query, suggestion, navigation or network result is fabricated. The ordinary constructor shares exactly the same extracted provider creation body; its supplied stop timer override is retained on migration.

The owning LocationBarView must cold-refuse active user input, IME composition, open popup and unsupported direct/WebUI autocomplete observers before any profile effects. The private reset checks the active input/popup preconditions again. It must run only after genuine source tab state was saved/detached and actual Browser/model/location-bar profile identity points to the target while empty. Rebind the actual OmniboxViewViews TemplateURLService observation and SelectedKeywordView profile in that same owner phase; refresh actual target text through genuine target activation afterward. Those outer view hooks and the complete Features provider remain subsequent required integration; this patch alone installs no call site or successful UI trigger.

This avoids the unsafe shortcut of assigning only ChromeOmniboxClient::profile_: its scheme classifier, favicon cache and provider service graph also belong to the old profile. Actual old client destruction retains its ordinary cancellation behavior.

Verification is four exact source hashes and a disposable patch replay matching every output. No native source writes/build, browser execution, query/network or owner state access. Compile the actual OmniboxController and OmniboxEditModel objects. Public headers introduce the existing browser buildflags header and may require its corresponding GN public dependency in the composing graph. Native UI/behavior acceptance remains unperformed.
