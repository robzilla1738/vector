# Profile-local durable drafts, v607 proposal

Owner-requested restart persistence extends the supplied 1.26.1016.1852 draft writer's existing localStorage compatibility reader. Original draft records, attachment encoding, rich document, clearing rules and UI remain intact. This is a necessary adaptation, not a claim that supplied1852 already offered restart recovery: its writer explicitly deletes legacy durable copies and writes sessionStorage.

The existing `provided-draft-flush.mjs` now count-checks three supplied leaves. Conversation drafts use their original stable session ID. New sidepanel drafts use `sidepanel-page:<aux.page_id>`. A private optional tab ID on `auxAccount.getProfileContext` resolves only an exact same regular Profile WebContents and returns its already-existing PageIdentity. No DevTools target ID, attachment target, routing or public wire contract is changed. Incognito receives no stable page identity. Unknown and transient-target scopes remain session-only; no global new-draft durable fallback exists.

PageIdentity persists `aux.page_id` through SessionService tab extra data. `browser_tabrestore.cc` restores it before navigation entries and insertion, so active-tab queries see the restored ID rather than minting a successor. Moving a tab retains its identity; distinct tabs/windows use distinct identities. A live old target-scoped draft migrates only within the current document's sessionStorage, then deletes the old key so later clearing cannot resurrect it. Browser contexts partition both local and session storage by profile and extension origin.

Native proposal: two files, four exact anchors, pinned in files.json; sources and native.patch are reviewable. The optional argument preserves existing no-argument calls. Existing AuxFunction capability gating remains unchanged. No native build or running app was changed by this lane.

Full adapted modules parse; native patch applies cleanly to607 source. Actual app restart and sidepanel reopening remain integration checks.

Restoring a draft requires restoring its tab or reopening its conversation; this does not force a startup policy or auto-open sidepanel.
