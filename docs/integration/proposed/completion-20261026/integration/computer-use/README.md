## Filesystem and credential isolation

The fixed role creates only `computer-use/tmp` below the captured native Task account directory, with private mode, no-follow traversal and held-directory/name checks. It passes that fixed HOME/TMPDIR for compatibility. Those environment variables are **not** its confinement proof.

The inherited native sandbox allows file reads only from public system libraries/data, `/Applications` static application bundles, the exact outer sealed Aux app, `/dev/null`/random devices and the captured role directory. It allows writes only inside that role directory, denies all file links, denies Control and browser profile/cache roots, protects the app and captured root ancestors against mutation, denies network and child fork, and permits process exec only of the exact fixed helper. Private home databases, `~/Library/Keychains`, Aside/Aux owner homes, other account roots and global temporary directories receive no filesystem allowlist exception. The native policy denies the Securityd/SecurityServer/secd Mach service families as well. Chromium's mock-Keychain flag is not used as proof for this helper.

Static imported Security calls contain `SecRandomCopyBytes`, not observed `SecItem`/`SecKeychain` imports. The actual disassembly places observed dlopen/dlsym calls in SQLite's extension-loader functions. This is a bounded static callsite observation, not an exhaustive indirect-call proof. The retained exact-image review, protocol restriction, private-filesystem denial and credential-service denial are all required before any activation. No actual credential query was made.

The helper has no demonstrated documented Aux database/cache relocation argument. Its context observer communicates through NDJSON; the daemon persists observed events under its own captured account. Static Messages/Kakao defaults use Foundation `homeDirectoryForCurrentUser`, so overriding HOME alone would be unsafe. Those separate raw app-data exports and their permission requests are refused before helper activation on this ordinary observer route. Native normalization also rejects them. This is not a claim that all Computer Use needs those exports.
