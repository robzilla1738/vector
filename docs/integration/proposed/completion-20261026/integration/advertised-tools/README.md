# Supplied Bash background lifetime correction

The actual A51 `runSessionBash` races output collection against `moveToBackground`. Its `finally` removed the command from `runningCommands` and closed the JS runtime-use admission even when the background response arrived first. Therefore the existing daemon shutdown `killRunningCommands` no longer included that still-running command. Native exec reservations separately retain their own runtime lease; the JS early release was never proof that native custody had ended.

The three count-one source edits synchronously latch the original ChildProcess `close` event immediately after `spawnCommand` in `spawnSandboxed`, attach the existing Bash cleanup to that retained promise, and remove cleanup from the return-path `finally`. There is no await or callback between the original spawn return and listener registration. The latch survives close before either awaited child consumer resumes; the Bash consumer cannot miss a past close event. The supplied output, background behavior, timeout and signal paths are preserved. An `error` event alone does not release the live command. This is direct-child close bookkeeping, not descendant settlement, native ownership or an execution grant.

No app, native source, addon or runtime bytes were mutated.
