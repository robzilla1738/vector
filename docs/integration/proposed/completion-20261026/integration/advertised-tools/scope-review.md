Without an owner disposition, Bash, PTY, CLI REPL and other supervised REPL tools remain **required and incomplete**. They currently return disabled-capability failures rather than executing. Plain chat can use the separate lazy-construction correction; that does not complete tool parity. The concrete decision is whether to authorize the existing restricted-entitlement/provisioning path later, or explicitly alter release scope. This review makes neither choice.

## Computer Use: separate bounded helper route

Computer Use is not automatically excluded with arbitrary shell execution. The supplied `runComputerUseCommand` already distinguishes an account-owned long-lived NDJSON actor (`nativeContextAwarenessHelper.invoke`) from direct commands selected by a nonempty `dbPath`. Both currently pass through `auxRequireSupervisedTasks`; preparation and actor startup also independently refuse ordinary mode. Removing only one JS check cannot activate a safe implementation.

The smallest separate implementation uses the existing main native finite-process owner idiom, with a dedicated fixed Computer Use helper role. The native owner must choose the exact sealed helper, retain actual pipes and physical child closure, and bind requests to the original account incarnation; no caller supplies executable, argv prefix, native owner or a replacement DB path. Feed the existing actor's NDJSON requests through that role and retain its existing generation invalidation, pending-request rejection, pause/stop and account switch behavior. Use the already bundled copied helper directly through authenticated fixed-image admission rather than running generic `ditto`/`xattr` subprocesses and replacing its runtime app. Keep the direct `dbPath` path under supervised execution until its separate file authority is proven. UI, capture policy and original helper bytes can remain unchanged.

A **fork policy is required**, even for this fixed executable. The exact accepted helper imports `_posix_spawn` and `_OBJC_CLASS_$_NSTask` and contains `/usr/bin/osascript`. Imports do not identify which commands fork and do not prove every command does. Therefore direct child close alone cannot certify this helper's subtree. For an ordinary bounded role, enforce native child-fork denial inherited by the helper, and verify the required fixed command paths operate under it. A command requiring a child must fail honestly and remain unaccepted; do not emulate its result or infer success from the helper's fixed pathname. If complete supplied behavior needs its subprocess route, join the existing descendant owner after the entitlement decision instead. Launchd-delegated effects are not covered merely because a request originated in the helper.

The concrete existing producer is `/private/tmp/aux-browser-only-daemon-build-20261025-a72/source/AuxAccountMemoryHelper.mm`, pinned separately in the receipt. Its native seatbelt denies `process-fork` and restricts `process-exec` to the exact fixed image. Its launch uses `POSIX_SPAWN_CLOEXEC_DEFAULT|POSIX_SPAWN_START_SUSPENDED`, then the real account owner performs `PrepareLaunch`, `SpawnStoppedAfterPrepared`, `PublishSuspended` and `ResumeStoppedAfterPublished`. Reuse those physical ownership steps and the current app/runtime-seed write, link and ancestor protections. The owner must capture selected-account/session roots natively; the daemon's `Task/u/<numeric-id>/sessions/<id>` string is a locator, not a capability. The runtime lane owns that held-root integration.
