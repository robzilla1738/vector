# Remove disconnected product modules without renaming their protocols

The existing Vault exclusion removed the full TRPC/derived HTTP registration and builtin skill consumers, but its root initializer still built the unused product router and desktop/importer graph. `passwordManagerRouter` has only its declaration and assignment in both actual original A51 leaves; there is no remaining registration or export. `materializeEmbeddedBinding` likewise has only its function declaration and no caller. Its three asset reads and obsolete `aside-native.node` assignment belong solely to that unused Windows SEA branch; current macOS routing uses the fixed linked images.

`prepare-proof.mjs` parses the actual original pair and current root a5 pair with existing Acorn8.19.0. It establishes the same exact ranges in both: the unused product router initializer, its disconnected desktop router initializer, and the contiguous Apple credential-exchange sessionstore/helper module. That last block contains **73 top-level symbols and zero identifier consumers outside the removed ranges**. Property names are distinguished from identifier references conservatively; this is not a blanket token deletion or a reachability claim for unrelated modules. The resulting source pins record all names, empty external-reference lists, exact source ranges and complete before/after fragments.

`vendor/provided/aux-excluded-product-pruning.mjs` exports `transformAuxExcludedProducts({text,source})`. Root applies it to both accumulated daemon leaves with the separately supplied exact original A51 source. Seven count-one rules remove the unused Windows materializer and asset declaration/assignment, remove the unregistered Vault router variable/construction, replace its disconnected desktop initializer with a no-op, and remove the closed Apple helper/sessionstore module. The root's existing no-op-compatible initializer calls remain structurally valid. The obsolete helper argv, helper paths and old `.aside` helper context disappear instead of being renamed into a newly enabled Aux ABI.

The paired source check passed full syntax, exact offset-based reverse reconstruction, repeated-pruning refusal, absence of the removed helper/asset atoms and preservation of current preference, selected account, external-manager and linked-PDF consumers. Offsets are recorded at each application, including empty replacements, so reverse replay does not depend on replacing an empty string. The generated files are review artifacts in private temporary output; no app was assembled, compiled, signed or executed.

Shared `PwmAccountRegistry` and its authenticated legacy discriminators, active external password-manager preference routes and v2 marker compatibility reader remain unchanged. Shared installation authentication, provider credential handling, original native/addon/runtime bytes and legal/debug provenance remain untouched. Removing helper code does not inspect, delete, clean up or migrate any existing credential/profile/memory state. HTML/SQL semantics and external application exclusions remain unchanged.

This closes the concrete excluded Windows SEA/Apple importer branches. It does not claim complete whole-package identity or that every other historical billing/Vault module has been eliminated. Any further removal must establish its actual incoming consumers and shared authentication dependencies first.
