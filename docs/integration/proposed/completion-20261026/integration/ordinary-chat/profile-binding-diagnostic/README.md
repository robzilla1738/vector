# Payload-free native browser binding diagnosis

Actual selected-page prompt preparation failed before tool cards with the native browser profile binding rejection. The throw is owned by the installed extension, not direct daemon read scope. This single counted change preserves every rejection condition and appends nine binary checks, without identifiers, paths, epochs, account data, URLs or tokens.

Bit order (1 passes): profile equality; account equality; regular profile; not off-the-record; not auth-paused; restore not pending; nonempty string browser context; nonempty string cookie binding epoch; nonempty string cookie restore epoch. This is diagnosis only, not a permission or binding bypass.

Current native aux_account_api.cc emits these exact properties; profile_identity.cc initializes both epoch strings. Daemon auxRunOwnedBrowserAction takes explicit route options, requires one connected account/profile, and the original bridge send serializes the selected connection's account/profile/mode. The extension compares that route against its native profile. There is no demonstrated daemon correction from the compound error alone.
