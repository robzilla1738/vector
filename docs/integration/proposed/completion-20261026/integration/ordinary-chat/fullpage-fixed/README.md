# Full-page capture through the existing fixed document capability

The actual toolbar full-page route called daemon capture.fullPage, whose globalCdpClient.ensureConnected requires supervised execution. Viewport/area already use the existing native page-surface owner. This change replaces only the full-page callback in the installed extension; it preserves the toolbar, preview, native begin/validate/cancel sequence, and supplied vertical tile planning, sticky/fixed cleanup, scroll restoration and bounds.

The supplied daemon algorithm is copied from the pinned current derivative with three count-checked adaptations for browser byte arrays and asynchronous browser PNG composition. OffscreenCanvas replaces pngjs byte blitting with matching source/destination rectangles. This is browser-page capture, with no desktop screenshot grant or generic execution path.

Each command uses the original sender tab and native page-surface capability through chrome.debugger's existing __auxDocumentCapability marker. ChromeDevToolsManagerDelegate::GetAuxDocumentCommandGuard already falls back to GetAuxPageCaptureDocumentGuard; that guard binds actual DevTools target, native profile, original document, selected pane/window owner and admission generation. No agent session is fabricated. There is no arbitrary caller expression or debugger method API: only the closed-over supplied stitching expressions and five fixed methods are used.

The capture and each original attach/command/detach promise use existing auxWorkerPhysical tracking. Native lease validation brackets each command and image operation. Native profile-context change or lease revocation initiates detach; a 45-second bound also requests detach. Neither timeout nor cancellation is reported as successful completion. The owner awaits the original operation and detach. Native validity is polled during an awaited renderer frame to catch revoked captures; polling is stopped and its in-flight promise drained. Images are closed after composition. Failed detach marks unknown settlement through existing worker tracking.

Input is the payload-free binding diagnostic extension derivative, retaining that change exactly. No daemon or native modification is needed, and the same extension can accompany the future execution candidate. Current full-page acceptance remains pending; viewport acceptance was separately observed by the integrator.
