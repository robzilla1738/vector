## Actual adapter facts, not a vendor approval claim

Current source is vendor/aside/shims/aux-chatgpt.cjs, pinned in source-review.json. Existing eligibility/current-review.json has the same reviewed adapter identity. It is a native/local public-client implementation prepared around the documented [open-source registration/sign-in contract](https://developers.openai.com/siwc/token-sharing-open-source/sign-in); its availability is not permission for an unapproved private app to use that contract.

- App display name is **Aux**, sent as **agent_name_hint=Aux** only on first dynamic registration. There is no separate stable `agent_name` credential. The first client value is dynamic_agent_client; subsequent attempts retain the actual per-account issued client ID instead of storing that dynamic entrypoint as the issued ID. Whether that initial entrypoint is appropriate for approved private Aux is a question for OpenAI, not an assumption.
- The adapter uses Authorization Code + S256 PKCE, fresh state/nonce/verifier, a stable local host identifier, and **http://127.0.0.1:<selected-port>/auth/callback**. It requires the same selected loopback URI for its attempt; no production hosted callback or localhost substitution is proposed. A private/client registration may impose its own callback conditions, to be confirmed.
- Configured scopes are **openid profile email offline_access resource.invoke chatgpt.tokens.use.direct**, resource **https://api.openai.com/v1**. Identity and plan permission are separate; the implementation checks actual granted plan scopes, verified issuer/audience/subject/nonce and issued client binding. It does not treat an ID token alone as plan access. Source prepares the public Responses endpoint and catalog-based entitlement gating; no model/account entitlement has been observed here.
- Credentials/host identity are prepared under protected local Aux storage with account-incarnation binding, atomic private records and retained issued-client identity. Current-account changes cancel pending work. Refresh/local disconnect/provider revocation have source paths; real successful consent, refresh, sign-out/revocation and inference on the coherent successor remain acceptance work. No live correctness or security audit is claimed from these source facts.
