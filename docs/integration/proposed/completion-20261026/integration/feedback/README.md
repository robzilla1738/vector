# Feedback: authenticated private report custody

The actual dialog discloses session data and only shows its success toast when `sessions.reportFeedback` resolves. Its old daemon implementation attempted authenticated `/voc/session-feedback/upload`, then silently inlined the full dump into an unauthenticated `/voc/session-feedback` POST. Neither cloud receiver exists. A local source schema agreement did not provide delivery.

The bounded adapter uses the **existing** schema12 private attachment service; it adds no cloud route, migration, service, email recipient or paid API. `auxSubmitSessionFeedback` requires the initiating account's real cloud session, pins its account/incarnation/user/creation identity and original session ID/createdAt, and rechecks around dump construction and transfer. Private/ephemeral sessions refuse explicitly. It preserves `buildSessionFeedbackDump` byte-for-byte, including its original stored-message/row/turn/tab export behavior; no new transcript harvesting or redaction claim is added.

The report JSON has explicit `aux.session-feedback.v1`, component version, submitted timestamp, comment, original session ID and original dump. It is at most8MiB, named `session-feedback-<random UUID>.json`, MIME application/json, purpose attachment. The existing account-bound `auxCloudUploadBytes` performs authenticated intent, limited signed private Blob PUT, and server size/hash verification before commit. Success requires the original transfer identity plus exact ready/purpose/name/MIME/content-URL metadata, and the helper's ID/SHA/size checks. No anonymous inline fallback or automatic resubmission is introduced. No cloud connection, quota/size failure, account/session change, upload failure or unconfirmed commit returns success. The original native broker awaited owner remains pending through the original promise.

`transformAuxSessionFeedback({text,source})` applies the two count-one daemon joins and appends the adapter to both original-pinned accumulated leaves. It removes the now-unused incompatible upload helper. `transformAuxFeedbackCopy({path,text,source})` changes two strings in the existing dialog without geometry/style changes: **“Saved privately for review.”** and **“This saves your feedback and session data privately for Aux review.”** This promises private storage after verified commit, not team inbox delivery, email, a response or actual human review.

One focused fixture uses the real existing account-bound attachment helper and fake transports to verify authenticated intent/PUT/commit, ready receipt, rejection of nonready/upload errors, incarnation/session changes, no-cloud/8MiB bounds and broker original-promise lifetime. Both complete a6 daemon leaves and the UI parse, with exact paired reverse replay. No app/helper, email, external API, private report or cloud write was executed.

## Existing operator custody, not inaccessible ciphertext

The report is ordinary private Blob JSON through an existing attachment reservation, not a new client-encrypted object whose key is unavailable to Aux. Its row in `aux_attachments` binds authenticated `user_id`, exact pathname, name, expected byte length/hash, ready state and verified timestamp. The existing service's private-store credential can read that exact object through `@vercel/blob.get(pathname,{access:'private',useCache:false})`, as the current attachment verification/content and recovery paths already do. No owner support inbox is invented and no arbitrary provider URL is accepted.

For a legitimately submitted report, an authorized service operator can identify a bounded set of ready application/json rows with name prefix `session-feedback-`, and then verify exact ID/name, expected size/SHA and envelope format/session before reviewing content through the existing private-store custody. The prefix alone is untrusted; other uploaded files can use arbitrary names. Do not execute report contents or expose store credentials, raw private paths, report bodies or personal account information in shared diagnostics. This task performs no such query/read and grants no new account access.

Reports count against the existing authenticated attachment quota (100MiB free storage and10,000-object admission bound). Account access revocation and the existing account/attachment deletion/purge path apply, including outstanding upload-token expiry handling; an identity webhook alone is not claimed to instantly erase every Blob. Current recovery capture includes ready non-inference attachments, so these reports are recoverable through the same approved capture path. No new backup is needed for this source change. A separate feedback review/retention policy and operator contact remain owner/legal decisions; generic ready attachments do not expire merely because the upload reservation's15-minute token deadline passes.
