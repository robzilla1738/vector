# Preserve automatic pin titles across unloaded restoration

The integrator observed an A38 pin change from **Example Domain** to **example.com/?aux-review=one** after direct restart. The live URL was unchanged. This observation alone does not prove lost navigation history or prove whether the stored logical title changed.

The source has a concrete matching defect: `WebContentsImpl::GetTitle()` delegates to `NavigationEntry::GetTitleForDisplay()`, which returns a formatted URL when its raw title is empty. The organization automatic-title writer accepts that nonempty fallback as an observed page title and can persist it over the last real title. The pin-grid projection independently replaces its saved label with `TabUIHelper::GetTitle()`, which uses that same display fallback. Restored/discarded/loading placeholders therefore need not have an actual loaded document to replace retained metadata or its presentation.

This three-file counted successor uses one read-only current-owner title query in the existing controller. Real nonempty committed/session titles remain usable during restoration. A raw-empty title's formatted URL is deferred while the controller needs reload, the page is loading or its native frame is not live. A genuinely untitled completed live page may still use its URL; automatic titles are not frozen forever. The existing observer schedules one fresh title read when loading stops. Automatic publication, ordinary row presentation and the supplied pin grid consume the same boundary. Manual titles and the legacy non-organization pin path retain their existing behavior.

No pin/tab IDs, URLs, launch/history/discard semantics, profile bindings, CSS, typography, geometry or icons change. No current saved metadata is reset or repaired from guesses. The exact old label's durable state remains uninspected; final actual-app acceptance must distinguish display fallback from stored metadata.

`source-plan.json` chains controller input **20ee4db7…** and header **b4fdf93e…** from root's integrated repaired pin-unload overlay; it does not use the older live controller or overwrite that repair. The third input is the actual native pin-grid source. Exact hashes/counts and complete successor files are supplied. Root owns projection, combined build/package and actual observation. Only the two affected translation units receive focused read-only VFS compilation; this is not runtime title-persistence acceptance.

The lean final check is to pin one page with a real title, leave that pin unloaded, quit/reopen and observe its retained label before loading it. Select/reload and confirm the real title still appears. Navigate an automatic tab once to a genuinely untitled fixture and confirm its eventual URL fallback still updates. No broad restore/history campaign is needed.
