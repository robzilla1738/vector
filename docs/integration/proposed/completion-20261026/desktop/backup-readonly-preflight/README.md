# O1 dedicated backup capture role: catalog preflight

Preparation only; no network/database/credential access, SQL execution, role/ACL mutation, or production capture. `catalog-preflight.sql` is one read-only SQL script, not a proposed grant script. It leaves primary data untouched and ends with ROLLBACK. It targets PostgreSQL16+ catalog columns (`pg_auth_members.inherit_option/set_option`); confirm actual version before running. Source review is not an executed syntax/coverage result.

Actual source is `services/aux-cloud/scripts/cloud-recovery-online.mjs`; its import is **online-recovery-objects.mjs**, not online-snapshot.mjs (no such file in this tree). It starts REPEATABLE READ READ ONLY, reads aux_migrations, obtains ready non-inference attachment and referenced avatar metadata from aux_attachments/aux_users, exports that same snapshot and runs `pg_dump --format=custom --no-owner --no-privileges --snapshot=…` against the direct endpoint. It validates the archive index, copies private Blob objects, and commits before encrypted bundle completion. No owner credential should be placed on a runner just because that transaction requests READ ONLY.

**Important scope:** pg_dump has no --schema/--table restriction. It includes current-database objects, extension configuration data and large objects under its normal rules. Twelve migration files are schema version12, not twelve PostgreSQL namespaces. A role restricted to public SELECT cannot be declared compatible with this whole-database dump until the nonpublic/extension/large-object results are resolved. Do not silently filter the dump or omit objects to make a role succeed. Foreign table metadata does not imply remote foreign data is included by the current invocation. pg_dump omits global roles/tablespaces; --no-owner/--no-privileges intentionally omits restoration of ownership/ACLs, so capture-role catalog results belong to review evidence, not the current encrypted data archive.

## Query sets and interpretation

1. **Database identity/ownership:** current database owner, review/session roles, server version and transaction_read_only. The review login is not the proposed runner login and its effective privileges do not prove runner access.
2. **Database/public schema/relation/sequence ACLs:** expands stored/default ACLs, including explicit PUBLIC and grant options. Owner default ACLs are expanded where null. Owner powers are not limited by an explicit grant listing. Check database TEMP/CREATE, schema CREATE and all mutating relation/sequence rights; a revoke from one role does not remove PUBLIC or inherited rights. Sequence SELECT reads state for dumping; USAGE/UPDATE are not the proposed minimum. No sequence values are read here.
3. **Column grants:** expose public column-specific ACLs; SELECT on selected columns is insufficient for a full relation dump. Unexpected grants remain part of the privilege review.
4. **Relations and sequences:** records type/persistence, ownership, RLS/forced RLS, partition status and sequence dependencies. Includes names not starting aux_ because actual schema12 includes sync_heads/shared_sessions/etc. Foreign and materialized relations must be understood; do not count catalog presence as data capture.
5. **RLS policy metadata:** records policy command, permissive/restrictive and role targets plus presence of expressions. Bodies are deliberately withheld because they can contain literals. Any relevant RLS/forced-RLS table is a completion question: ordinary pg_dump defaults row_security off and refuses inadequate visibility rather than promising a full filtered dump. Do not add --enable-row-security or grant BYPASSRLS/superuser to suppress the failure. If fuller policy review is needed, prepare that precise separate metadata request, not blanket data access.
6. **Routine/default ACLs:** records public routine owners/security-definer flags and EXECUTE grants, plus current-database global/public default grants. PUBLIC functions may expose writes even when tables are read-only; no function bodies or defaults are printed or executed. A dedicated role proposal must account for dangerous reachable routines and future object grants from the actual migration owner. A global default ACL can apply to future public objects, so it is included without listing unrelated cluster roles.
7. **Outside-public/cross-schema aggregate boundaries:** only counts, not other schema data/names. Nonzero means a public-only privilege proposal cannot certify the current unfiltered dump. It also catches partitions crossing the chosen boundary. No silent namespace expansion.
8. **Extension metadata/config relations:** extension name/version/owner/schema and registered dump relation identity/access/RLS. Configuration filters are reported only as presence; predicate literals are omitted. Nonpublic configuration names are redacted. Required extensions/version availability must match the separately isolated restore environment; this packet does not install extensions or promise restore compatibility.
9. **Large-object metadata:** current-database count, current reviewer unreadability count and PUBLIC-read count. Reads pg_largeobject_metadata, not pg_largeobject pages. Nonzero objects require a precise complete-capture permission decision; lack of reviewer access is a failure boundary, not permission to elevate the runner.
10. **Relevant role/membership graph:** seeds only review/session roles, current database/public object/default/policy/large-object owners and ACL grantees, then traverses their upstream membership roles. Reports flags (superuser, create-role/db, login, replication, BYPASSRLS, INHERIT), grant-edge ADMIN/INHERIT/SET options and actual immediate/SET reachability. No pg_authid, password/hash, validity timestamps, role settings or unrelated cluster-role listing. Role-level INHERIT alone does not characterize modern membership-edge inheritance. Existing application/admin membership is not an acceptable capture-role shortcut.

## Result needed before a grant proposal

Reconcile the public inventory against the current twelve migration sources and actual objects without reading application rows; catalog shape alone does not prove recorded migration hashes. Identify each actual owner/migration creator and all relevant inherited/PUBLIC authority. Then propose a **new non-owner, non-admin-member login** with only required CONNECT, public USAGE, table SELECT and sequence SELECT, accounting for future migration-owner defaults and complete-dump exceptions. This document deliberately creates no role, chooses no password and emits no executable GRANT/REVOKE plan before actual metadata. PUBLIC TEMP/CREATE or callable mutating security-definer functions cannot be subtracted by revoking only the new role; any shared privilege change needs explicit impact review preserving the application. The restore credential remains separate and never belongs on the capture runner.

Catalog review does not prove pg_export_snapshot/pg_dump same-endpoint access, full RLS visibility, extension/large-object coverage or an actually complete restore. Those require the later bounded capture and isolated restore acceptance with the exact proposed role; no new broad test campaign is proposed here.
