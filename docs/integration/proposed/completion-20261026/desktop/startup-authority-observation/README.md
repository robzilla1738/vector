# Bounded startup authority observation — conditional source proposal

Do not apply on the current log alone. The integrator's numeric phase/status diagnostic must first demonstrate phase 6 `timedOut`/`pending` (or a transient ACK at phase 11). This proposal does not repair a digest mismatch, signature refusal, lost owner or root violation. It is not projected, compiled, signed or run.

Three source overlays, eight exact anchors, pinned to the actual native tree including the integrator's phase diagnostics. `prepare.py` replays only the frozen baselines and emits hashes plus `native.patch`; it never touches native source or app/state. The root integrator owns projection and affected-object compilation once the observed cause justifies this change.

The existing `StartupAttempt` retains the same deadline already created after the one allowed daemon launch. The typed accessor returns that process-bound deadline without extending it. The startup receipt and its ACK share the remainder. Before/after every exchange, the browser checks its original selected owner, roots, generation, fresh pulse/export count, live child and unclosed state. Only pending/timeouts continue. All other statuses refuse; elapsed time never proves admission or settlement. Four maximum transport waits fit within each requested remaining-budget slice; synchronous validation may finish later, but the subsequent deadline check then refuses admission.

`RequestAuthority` already retains sequence/nonce after the first attempted send. Calling the same startup operation again sends `kObserve` rather than issuing another root transition. The daemon's existing cached path freshly validates the same owner. A late reply sent to an expired receive right produces recoverable `MACH_SEND_INVALID_DEST` and leaves the original completion observable. No transport or daemon code changes are proposed.

Once ready, the loop keeps the exact `DaemonAuthorityReply` publication and calls `AcceptAuthorityReply` again after a pending/timed-out ACK. This repeats its original nonce-bound ACK; the backend's ACK is idempotent. Only a validated successful ACK sets the publication acknowledged and clears pending. An uncertain ACK is not converted into success, and no new request/owner/state is created on deadline expiry. Existing shutdown/retention owns unresolved work.

The previous A38 descriptor is `aux.fresh.bootstrap.policy.v9` without PDF/utility modules. The current signed descriptor is v10 with the 9,437,920-byte PDF and 409,728-byte utility derivatives. The current loader verifies loaded-image signatures and digests during full policy reloads; nested dispatcher/coordinator/cold-guard startup receipt validation repeats these checks. This is evidence of additional work, not a measured latency diagnosis. Preserve those checks and the approved addon bytes.
