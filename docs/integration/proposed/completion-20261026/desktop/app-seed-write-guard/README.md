# Browser app seed write guard

Concrete supplied-source gap: File System Access protects DIR_EXE, DIR_MODULE and DIR_ASSETS, which do not cover the entire enclosing app. Browser base writers have no app exclusion. A normal browser download/save path could therefore truncate a writable native preload/runtime seed in Aux.app.

Five counted source outputs (four existing files, one header), no new translation unit or GN registration. The existing POSIX File implementation retains one canonical native app path plus directory identity. Writable File opens and descriptor writes/truncation/times, direct FileUtil write/append/fopen/copy/temp/directory/link creation, macOS copyfile and rename/delete paths refuse mutations in the registered app; destructive rename/delete also refuse its ancestors. Existing Foundation webloc SaveToFile gets the same deny check before its atomic Foundation write. Permission changes are denied. Unregistered processes preserve existing behavior.

Root startup join (not included in this source patch): include base/apple/bundle_locations.h and base/files/aux_read_only_app.h; after PackagedIdentityAllowsStartup succeeds and before any ordinary selected roots or daemon startup, require base::RegisterAuxReadOnlyApp(base::apple::OuterBundlePath()). Registration validates canonical existing Aux.app directory, is immutable/idempotent, and grants no authority. Registration failure must refuse ordinary startup. Do not derive this from argv/environment or a selected profile.

This closes the traced browser base writer paths, including download Save As and file-system backend File handles. It is not syscall interposition or a general claim about every Foundation/libc writer. The bounded raw source audit found Aux snapshot raw writes constrained to a newly owned temporary directory, local runtime socket output constrained to captured browser roots, and remaining Aux raw opens read-only or /dev/null/PTY. Existing web-app shortcut Foundation writes use independently created shortcut bundles, while install-from-DMG is a separate installer path. Runtime lane owns daemon fixed-addon and native-host sandbox app protections.

Limits: this path guard does not authenticate unrelated same-UID processes, pre-existing hardlink aliases outside the app, or adversarial filesystem races performed outside the browser. No such protection is claimed. Native API descriptors that bypass File/FileUtil still require their own bounded owner review. The original accepted app is not changed by this overlay.

Regenerate with prepare.py against the read-only native source snapshot. source-plan.json pins every existing input and exact output; native.patch contains the replayable diff. No native compilation, app launch, signing or state mutation performed in this lane. Root will compile affected TUs once with its combined projection.
