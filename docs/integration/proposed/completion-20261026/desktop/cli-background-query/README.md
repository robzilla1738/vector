# Read-only CLI queries while Aux is in the background

The integrator observed packaged `list` return exit 78 with `query-owner-changed` while the reopened browser and daemon were stable. The receiver used `SelectActualWindow({})`, whose `GetActiveBrowser()` requires the window to be OS-active. `GlobalBrowserCollection` documents and implements this explicitly. An ordinary terminal invocation can therefore have no selected query window even with a visible, admitted Aux browser. The unconditional final current-owner check also replaced an initial admission failure with `query-owner-changed`, misreporting a change that never occurred.

One source file, three exact anchors: read-only queries retain the first usable visible normal window in existing activation order, without activating it or loading a profile. Exact native readiness, invocation identity, retained window/profile/epoch, cookie restoration and generation checks remain before/after metadata access. A genuinely changed admitted owner still refuses. Initial admission errors now retain their original reason. Explicit profile filtering, list/resolve routing and all mutable open-command selection/approval remain unchanged.

This uses only the running browser's existing profile index and loaded Space models. It adds no disk-profile reader, state location, capability, credential or OS authority. The source proposal is unprojected/uncompiled. Counted recipe replay passed; root owns affected-object compilation and one real foreground-terminal `list`/scoped-list/resolve sequence. No broad tests or app operations were performed by this lane.
