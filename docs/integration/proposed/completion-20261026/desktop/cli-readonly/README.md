# Native CLI list/resolve — finite authenticated response join

The one-way NSWorkspace open envelope could not return requested profile/Space listings or routing decisions. The supplied/native CLI infrastructure already has a stronger suitable boundary: `AuxCliIngress` authenticates a Hello using kernel audit tokens, executable birth identity, strict signed-image requirements and exact paired CDHashes; it then gives that same process a nonce-bound private invocation right and authenticates the browser's reply. This batch reuses that transport. No socket, AppleEvents grant, environment credential or new task-capability architecture is introduced.

## Delivered source

- `aux list [--profile <exact ID or unique name>]` prints JSON profile IDs/names and available Space IDs/names from the running browser's existing routing index. An explicit selector is checked against the full returned index, so an unopened duplicate name cannot silently select an open profile. `spacesAreLoadedOnly:true` makes the existing loaded-model boundary explicit. It does not load profiles or parse profile files from the terminal.
- `aux resolve URL [--profile … [--space …]]` prints the existing routing resolver's decision, including matched/unmatched, target identities, Space availability and errors. It does not navigate, load the target profile, mutate routing rules or start a task. The existing resolver remains authoritative; the terminal never guesses a path/destination.
- Distinct finite read-only request/result frames carry bounded argv and bounded JSON. Queries send **no cwd, stdin, stdout, stderr or other fileports**, no environment and no credentials. The terminal prints the result only after verifying the original nonce, exact frame shape, version, kernel audit token and the same signed browser process/birth. Invalid or oversized replies refuse. JSON comes from Chromium's serializer, so metadata/control characters cannot be printed as raw terminal escape sequences.
- The existing UI receiver verifies its actual admitted regular Profile, binding epoch and native generation before and after computing the result. It returns typed refusal on shutdown, queue/post failure, invalid arguments, owner loss or unavailable destinations. Queries require the matching app running with a visible normal admitted window; they do not auto-start a second browser or fall back to an unrelated app.
- In ordinary builds the receiver explicitly rejects every non-query invocation. Existing ordinary `aux open` continues through its OS URL path. This does **not** enable the unpaired retained Node/installation CLI, LocalAuthentication flow, exec or process descendants. The signed-image authority implementation is unchanged.
