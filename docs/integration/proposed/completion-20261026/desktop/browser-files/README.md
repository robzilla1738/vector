# Browser file owners

This successor composes **after** browser-automation `3ee52363d` (entry/background), current root a6 `debugger_api.cc`, and runtime selected-builtin-owner native scope. It changes supplied consumers without a UI/permission addition. It is source implementation, pending native compilation and actual successor journeys.

- Upload: supplied locator/filechooser still resolves each path through the original `browser.ensurePath` / `file.access` hook. A private single-use receipt binds the completed hook to this browser, original tool call, resolved path and access mode; a missing hook or active tool refuses. A private selected-session method snapshots only that resolved input through a canonical, nofollow parent and regular, single-link FD, compares device/inode/size/mtime/ctime and named identity, and closes before returning bytes. The existing supplied DataTransfer/File branch receives those bytes. Byte payloads and empty clear continue to work; arbitrary raw DOM paths remain unavailable.
- Download: existing component Agent debugger attachment acquires a native Profile-owned DownloadManager observation before page actions. Native DownloadItem creation records exact item pointer/GUID and actual source WebContents/frame document. Native opener-chain provenance can attribute a generated download popup to its original same-window task parent (including a transient popup with no published window). No referrer/URL search grants ownership. Created-source provenance survives source closure; borrowed selected-document guards still revoke on document change. Account binding/restore epochs and actual original window are revalidated.
- Native snapshot chunks share exact original DownloadItem pointer/GUID, total size, device/inode/mtime/ctime and a native snapshot nonce. Each chunk is at most 256 KiB, regular/single-link/nofollow, before/after/named checked, read on the existing ThreadPool, and response revalidated. Debugger detach leaves the original read promise pending until the actual read's descriptors close. The standard DownloadManager remains the physical download writer. Browser-wide `setDownloadBehavior` remains refused; the scoped FrameManager explicitly uses its already acquired native observer instead.
- Only complete bytes publish. The private selected scope duplicates the actual retained Task session directory and atomically publishes a native random filename under its artifacts directory. `download.path()` returns this actual completed path. `saveAs()` retains original destination resolution and `file.access` write approval, then uses native retained-parent EXCL staging, fsync/close, rename and parent fsync. It also handles explicit selected-session destinations. Read streams use a completed native snapshot in an in-memory Node Readable; no open file stream survives selected-owner closure.
- Native observers hold no account locks or writer lease. Explicit task retirement releases observations where its original debugger remains available; orphaned/revoked observations expire through the profile timer, and profile destruction owns teardown. A capture bound is 256 per profile and each observation holds at most 256 item receipts.

Bounds match finite native document work: file snapshots up to 64 MiB, download wait up to ten minutes. Larger inputs fail explicitly. Failed/partial publication does not return a completed path; unknown output close marks the selected scope unknown. General raw CDP, arbitrary filesystem/exec/PTY and global download mutation remain unavailable.
