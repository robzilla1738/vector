# Cold first-command input ownership

Source-only proposal; no shared projection, compile, package, signing, app or profile operations. 25 counted anchors in five files (existing palette owner/header, existing private command API/schema, one renderer leaf). Based on current source containing conditional palette-document recovery.

The first-load WebContents had no input DOM when native Show focused it. Retaining a mounted document fixed warm reopen only. This proposal temporarily places a Chromium Textfield at the existing palette input position/44px row with the supplied 16px text size. It receives native editing, clipboard and IME; it is hidden permanently for that invocation after handoff. There is no new persistent control or replacement settings/UI.

On first mount (or failed-document replacement), the native field owns the complete text and directional UTF-16 selection. getCommandContext returns a snapshot/revision only to its existing bound palette. Renderer commits the same controlled value and selection, then acknowledges revision plus existing generation through an optional argument to that same API. Native releases focus only if the current text/selection/composition snapshot still matches and composition has ended. Concurrent edits return a newer snapshot; no timer or raw-key replay. The typed private event carries an optional inputPending boolean so late update events cannot clear the handed-off query. Normal warm invocation behavior remains unchanged.

Enter stays pending in the native owner and is released only by a matching successful acknowledgment; a subsequent native edit cancels that pending submission. Renderer submits through the original action handler after its normal results exist. Escape/dismiss invalidates native invocation and renderer continuation; later acknowledgments cannot focus or submit it. Existing generation gates prevent old commands from owning a later invocation. Existing delayed-select behavior is suppressed during handoff so transferred selections are retained. No input text is logged or persisted.

The fixed original getCommandContext zero-argument contract remains valid for all existing callers; only the palette handoff adds optional generation/inputRevision. No new API name, event ID, identity, port or authority. Existing event gains optional inputPending, preserving old receivers.
