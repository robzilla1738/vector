# Explicit experimental-settings identity transition

The paired daemon/UI schema now emits `format: "aux.experimental.v2"` and `auxCode`. The known previous unversioned `asideCode` object is a supported legacy reader: its boolean and the existing sync, KakaoTalk, onboarding and compaction flags survive normalization. Normal UI writes serialize the explicit new format. This is a settings-field migration, not an installation-key/ciphertext migration.

New-format objects containing the legacy field, unversioned objects containing the new field, unknown format versions and invalid booleans refuse. Neither version can silently default a conflicting value. Empty settings retain the previous disabled defaults. Input objects are not mutated; no disk/profile operation runs in the transformer. Ordinary persistence continues through the supplied settings owner and its existing atomic write boundary.

Five UI consumers/producers are joined: the actual RPC settings schema, Experimental controls/defaults, skill controls and both sides of the transient code-agent context key. The transient context now uses `auxCodeAgents`. No stylesheet, component topology, setting availability or coder capability is changed. The actual native coder capability remains a separate open requirement.

`prepare-experimental-settings.mjs` composes the cloud-transfer and final-runtime identity predecessors before applying this transition to both complete daemon leaves, then transforms the five current pinned UI scripts. All seven complete scripts parse. The emitted daemon and UI schemas are evaluated with the installed Zod implementation against legacy/new true/false values, input preservation, other-flag preservation, JSON save/reload, empty defaults, malformed/mixed generations and unknown-version refusal. `experimental-settings-v2.json` pins inputs, anchors and outputs. The original supplied files, accepted app, installed settings, credentials and cryptographic material were not changed.

Root must use these paired outputs in the combined candidate and preserve the source parameter when composing subsequent event changes. Future UI staging includes the same transform/provenance. Actual successor settings read/write/restart remains unaccepted until packaged observation; source checks do not close that gate. The earlier identity remaining ledger's experimental-setting and transient `asideCodeAgents` entries are superseded by this implementation, not by runtime acceptance.
