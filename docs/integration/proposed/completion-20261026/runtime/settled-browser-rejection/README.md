# Settled browser rejection is not unknown physical work

Startup10 exposed a real shutdown defect: the browser rejected a request with the existing authenticated settled-response tag; the operation completed, but the generic broker latched its business error as unknown physical custody. Native `WithBrokerAwaited` independently marks every rejected callback unknown, so changing only the JavaScript failure flag would be incorrect.

This exact three-anchor patch registers errors in a private WeakSet only where a valid bridge response matches the pending request and its authenticated connection, after removing the pending request and clearing its timer. Existing bound-browser response handling establishes physical settlement, while operation/selected-scope cleanup still runs before its callback completes. The callback's recognized rejection is converted to successful native settlement; the original error is rethrown to the caller only after the native guard observer and broker tracking succeed. Any separate cleanup/authority error overrides that result and remains unknown. The public auxBrowserActionSettled tag alone grants nothing.

Current inputs are the two prepared analytics-no-spawn leaves; future inputs are the exact future analytics/direct-dispatch pair. Exact counted substitution and reverse replay preserve everything else, including FS/session lease/cancellation/disposal. Outputs: `/private/tmp/aux-settled-browser-rejection-20261026-a1/{current,future}`. No native source/ABI change or build is needed.

Four syntax checks and focused tests of each actual extracted broker passed: original rejection reaches caller, shutdown waits outstanding callback settlement, marked error permits native close, unmarked/forged/asynchronous errors still fail, stale native authority still fails, and failed producer cleanup still fails. The bridge registration remains inside the matched-response condition. Fixture native bindings model the existing observer success/rejection behavior; actual app shutdown acceptance remains required. No signature, app, account, credentials or OS state changed.
