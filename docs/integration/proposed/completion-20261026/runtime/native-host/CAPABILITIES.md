# Advertised native capabilities: exact remaining work

This inventory inspects static A38 resources and actual A72 sources. It does not load an addon, launch a helper or read a user profile. `capability-inventory.json` pins the entry bytes, guard locations and actual addon exports. Every row remains an implementation/acceptance item until integrated and observed; none is silently deferred.

| Capability | Current ordinary-mode behavior | Smallest existing-owner work / external requirement |
| --- | --- | --- |
| Third-party native messaging | A38 refuses before spawn through the absent ES bridge. This successor implements a separate finite, no-fork host lease on the existing native peer and TaskLayout. | Integrate all 30 paired files and the two daemon-object rebuilds; run one dummy host launch/cancel/quit/reopen plus real extension journey. Native Mach-O hosts only; interpreter/fork chains fail truthfully. Vendor support is separate. |
| Browser actions / CDP / extension commands | `ensureConnected`, `send` and both extension-command consumers call the disabled supervised-task guard. This is actual unavailable implementation, not a missing account test. | Bind the existing browser/extension consumer to the actual request Profile/account incarnation and existing browser action lifetime; admit the bounded browser paths independently of arbitrary exec. Reuse existing selected-profile URL/tab dispatch. Validate active-pane identity and cancellation. |
| Local files and chosen attachments | Existing chosen-file references and ordinary broker I/O exist, but `createDesktopRepl` and general tool execution are guarded. | Expose existing handle-scoped chosen-file/broker operations to the retained account owner; do not grant another account's TaskHome or caller-selected root. Runtime content/cancel/missing-file behavior still needs the packaged journey. |
| Local memory | Actual A38 indexing is accepted. Search is unverified. | Keep current memory producer/consumer unchanged; one actual search is outstanding. This native-host work does not requalify it. |
| PDF utilities | The packaged `aux-pdf.node` has real `AuxPdfCloseAdmissionAndDrain` and `AuxPdfPendingOperations` exports; its hash-checking CJS loader is present. The JS loader is guarded. | Resolve lazy load versus native ownership: `AuxLoadedPdfLifetime` captures after authenticated owner creation, before the lazy module loads; its later image-set change is untracked. Load the exact approved fixed image after authentication and before capture, or perform native fixed-image post-load capture tied to the existing owner. Then use existing operation close/drain ABI. No generalized task architecture is required for this fixed addon. |
| macOS utility/capture addon | The packaged addon has real native close/pending-environment exports and pinned CJS loader. The JS loader is guarded; the same late-image capture issue applies. | The same bounded authenticated fixed-image load/capture repair. Capture/input commands additionally require exact helper-specific OS permission outcomes. Do not treat a signed/loaded image as an Accessibility or Screen Recording grant. |
| General exec and PTY | `AuxNativeExecBeginCurrent` and `AuxNativePtyBeginCurrent` return null in ordinary mode; runtime use/mutation factory callbacks also refuse. The actual `node-pty/prebuilds/darwin-arm64/pty.node` is packaged. | Existing reservations retain actual Environment/owner/direct wait, but permitted arbitrary children can fork/detach and their descendants remain unknown. A no-fork direct-command adapter is bounded but would narrow the advertised shell/PTY behavior. Full multiprocess parity needs a concrete descendant or delegated-spawn mechanism within existing owners, or explicit launch-scope disposition. A process-group kill or a flag flip is insufficient. No same-UID protection requirement is being reintroduced. |
| Computer Use | `runComputerUseCommand` is guarded and task-runtime preparation is disabled. The actual helper is packaged under `apps/computer-use/Aux Computer Use.app`; `native/aux-computer-use` is not the package location. | Pair the existing fixed helper/runtime path, retained account incarnation, pipe/cancel/original-reap owner and terminal journal using the finite-helper pattern. Inspect actual helper fork/exec requirements before choosing no-fork. Obtain only the exact needed AX/capture/input OS permissions when execution is ready. This is not merely a permission test while the factory remains disabled. |
| Arbitrary native addons / agent session runtime | `prepareSessionSpawn`, `executePreparedToolCall` and REPL construction are guarded. Known PDF/utility ownership does not cover arbitrary loaded native code or detached work. | Keep the supplied runtime and its existing mutation/use owners. Review each advertised addon against actual fixed-image lifetime exports; unknown code cannot inherit the fixed-helper proof. Larger unsupported capabilities need an explicit concrete scope decision, not a broad claim that all automation is complete. |
