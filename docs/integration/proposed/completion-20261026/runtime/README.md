# Native host ownership and cancelled-launch cleanup

Source baseline `dd18033d4`; read-only Chromium input `/private/tmp/aux-chromium-recovery-snapshot-20261023/src`. This slice does not enable native messaging or change the accepted A38 app.

The actual regular calling Profile now supplies an opaque owner before the launcher leaves UI. Its existing `ScopedProfileKeepAlive` is released on UI; no background thread dereferences Profile. The owner follows the launch through IO/background work into the native lifetime reservation with the verified extension origin and host name. The optional reconnect-directory argument remains separate and cannot select the owner. Missing, off-the-record or non-regular owners refuse; off-the-record support requires its own explicit lifetime owner rather than substituting an ordinary profile.

Mac launch tasks and cancellation reaping now block ThreadPool shutdown. A successful child left in an unpublished `ProcessState` is terminated/reaped when its reply is dropped, cancelled or replaced. Its actual raw framing descriptors close on the cleanup worker before the existing original reaper. Successful delivery moves process, pipes and lifetime out, so destruction does not create a second reaper. Other platforms retain their existing task policy and cancellation implementation.

It reads source only and does not project into Chromium. `syntax.py`, run through `scripts/native-build.py`, uses a Clang VFS overlay and the actual messaging target's flags, Chromium plugins and system module. All four affected translation units pass `-fsyntax-only`; logs and exact commands are in `syntax.json`. Initial style-plugin failure required an explicit out-of-line lifetime destructor; final logs pass. No native object, live tree, app, owner profile, credential, grant or signature was changed.

This is source implementation plus focused compile evidence, not ordinary host acceptance.
