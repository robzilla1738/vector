# PDF methods ABI correction for the fixed builtin wrapper

`InitializeFixed` wraps the original PDF image by reading `extractText`, `merge`, … from the module's returned exports. The PDF image (`aux-pdf.node`, `AuxPdfFour.cc`) publishes those methods on `exports.pdf`; only the utility image exports `run` at the top level. Every PDF route through `aux_pdf_builtin` (scoped `read_file`, REPL `aux.pdf`, unscoped `nativePdf`) therefore cannot reach the engine. In the 2026-10-26 combined check the scoped facade returned `undefined` and `read_file` reported `Cannot read properties of undefined (reading 'pages')`, while HEIC conversion through the utility worked.

`source/AuxFixedBuiltins.inc` is the pinned `selected-builtin-owner` copy with two substitutions: PDF methods are read from `original.pdf` (refusing with "Fixed builtin ABI changed" if it is not an object). `daemon-recipe.json` is the `final-daemon` recipe with this directory first on the include path and a fresh output `/private/tmp/aux-completion-final-daemon-pdf-abi-20261026-a1`. The build passed (`Aux Daemon` 200f8c6d…).

Active since `integrator/final-polish-a1`. The 200f8c6d build above was refused at startup ("paired daemon receipt") because it used the final-daemon recipe rather than the packaged link base. The packaged daemon is the two-addon build-a2 link; `relink/relink.py` re-runs that exact command (`orig` reproduces 0153626b byte-for-byte, `new` swaps only `worker-host.o` for `/private/tmp/aux-completion-final-daemon-pdf-abi-20261026-a1/worker-host.o`, giving 080844f5). That image passes the embedded startup policy, and Muse `read_file` on `document.pdf` returned both markers. The REPL `aux.pdf` route shares the same wrapper but was not exercised separately. Hardening still worth adding there: `SelectedInvokeFixed` should throw instead of returning a bare `nullptr` when an N-API call fails without a pending exception.
