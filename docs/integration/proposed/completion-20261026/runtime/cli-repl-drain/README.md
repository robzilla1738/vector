# Inactive generic REPL bridge drain

This source-only successor uses the existing selected session owner and original QuickJS/REPL implementation. It preserves the ordinary full supervised globals and extensions. Current browser-only factory selection, the native supervised-task guard, ES requirements, and the signed candidate remain unchanged.

Both original factory callers now pass their actual stored SessionStore session and exact Task session directory. The actual generic supervised factory captures the native owner through the existing authenticated guard, wraps original host function results in native awaited custody, and joins the existing original bridge/eval custody hooks. Timer APIs retain the original scheduler, clear functions and run-state behavior; their real async callback Promises are retained separately even when the guest does not await them. Closing stops original timer admission/handles, awaits original host/eval promises independently of the user cancellation race, waits for actual bridge disposal, then closes the native owner. Account cancellation uses the original authenticated guard signal. Errors retain native untracked state; they do not declare drain complete.

The CLI close caller already awaits `repl.dispose()` in the browser-automation predecessor. It therefore removes SessionStore membership only after this factory's real disposal Promise settles. The earlier context-only anchor in `exec-session-runtime` is superseded by this batch; apply this batch after browser-automation's counted entry resource anchors. The selected guard AbortSignal anchor from `exec-session-runtime` is also required. The exact current browser-only branch is kept as-is; no global guard is enabled.

`entry.anchors.json` pins the actual predecessor composition and count-one joins. The complete supplied entry with browser-automation and these joins parsed successfully; `verification.json` records that exact projection hash. No native compilation, link, fixture, application execution, signing, policy or candidate mutation occurred.

This is actual bridge/host-promise lifetime custody, not a claim that every retained full REPL API has a complete cross-profile filesystem authority boundary. In particular, the supplied `createReplFs` resolver uses string-root checks and subsequent raw Node fs operations. A selected owner alone cannot make a caller path or symlink safe. Native selected file/PDF/upload/publication helpers already provide retained no-follow producers for their finite methods; generic fs mutation/read counterparts must use the same actual retained roots before future full capability acceptance. This batch deliberately does not add a broad Task exception or new capability registry to hide that remaining source requirement. Future packaging/link/activation remains gated and ES authorization remains required.
