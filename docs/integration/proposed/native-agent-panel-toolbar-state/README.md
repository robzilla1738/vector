# Agent panel toolbar presentation on Chromium155

This is an explicitly observed-platform adaptation, not a claim to have recovered the stripped original visibility predicate. Root compared actual supplied Aside and actual Aux547: Aside hides its Ask action while the supplied Agent panel is open; Aux keeps Ask Aux plus a second stock circular Close Side Panel button. Root authorized this Agent-only native-host correction. The supplied panel already owns its close affordance.

The actual155 producer is source-established. `SidePanelCoordinator` opens the real panel, installs its actual entry key, and invokes `SidePanelToolbarPinningController::UpdateActiveState`. That controller forwards extension-active state to `ExtensionsToolbarDesktop::UpdateSidePanelState`. Close forwards false through the same owner before notifying the supplied entry. The current desktop method unconditionally shows the stock close button and never changes the pinned action's visibility.

This proposal uses that existing event and `SidePanelUI::IsSidePanelEntryShowing` for the exact real Aux Agent key. Only when the event is active and that key is genuinely showing does it hide the Ask action and suppress the duplicate native close button. The state does not change the genuine pin preference, installation state, session, account, authorization or extension's panel content. Closing the panel, switching to another extension panel, or switching to a built-in panel restores normal action visibility from the real pin/force rules. The existing close-button behavior remains intact for other extensions.

The exact Agent state is applied in the initial action-view visibility, subsequent icon-visibility/animation updates, and the toolbar's visibility query; later pin or popup updates therefore cannot accidentally resurrect the hidden action. Existing fade/layout code performs the actual native transition. The auxiliary state belongs to the concrete toolbar view and dies with its existing owner. No new global observer, timer or service is created. The branch is `ENABLE_AUX_BROWSER && IS_MAC`; no other platform's behavior changes.

Two exact547 source baselines, complete outputs, hashes and counted anchors are retained in `manifest.json`; `native.patch` is replayable. `python3 verify.py` passes disposable patch/hash/count replay. No shared native edit, build, stage/package/signing, browser action, profile or credentials operation occurred in this lane. Root should compile the affected toolbar object and observe: Agent open hides both redundant controls, its own close restores Ask, CmdE reopen/close retains actual content, and another extension panel keeps its ordinary close button. Reference timing beyond the settled open/closed states is not asserted.
