# Supplied popup folder-picker lifetime

Three-file proposal after `native-popup-profile-ownership`: CC baseline `65cbf95010af412cbd81ed99198e8104226a774bd34ca2e0347080bfd9806327`, unchanged popup header `0cb820967652c34ae60d1bca240b34362b78f04efef142982241152f1825d13b`, schema `578dd5a5bb429ba672ed7734135ff2d474e83c5f14c599d17167beaf76e92828`. `manifest.json` and `native.patch` pin/replay all changes. This is isolated proposal material; shared native source and dialogs are untouched. Root owns applying/regenerating the API schema; no GN dependency changes.

Original API Run0427de54 obtains its sender WebContents and reserves the coordinator's picker through0459676c. That helper requires an existing visible main widget and accepts only the coordinator's current main or options contents. It returns0 for a new reservation,1 for unavailable and2 for an already pending request. Original Run maps2 to `Folder picker request already in progress` and1 to the native popup unavailable error. Current Aux accepts any calling contents and sets a singleton boolean without checking duplicates. The proposal restores actual caller identity/visibility and duplicate checks before creating a dialog. The existing user-gesture requirement and real `ChromeSelectFilePolicy` remain.

Original selected callback08134484 and cancel0427e2b0 release their dialog, resolve their actual sender again and invoke0459699c. The completion helper clears pending state **only if that sender still matches the current coordinator's main/options contents**. Visibility is not required at completion. A callback from destroyed old-profile contents therefore cannot clear a new profile's pending picker. The proposal uses the same contents comparison and resets the retired coordinator's picker bookkeeping during actual widget-tree destruction. It stores no selected paths in manager state and does not treat a changed profile identifier as the same native owner.

The supplied IDL's callback path is optional. Original cancellation responds with NoArguments, while selection returns the actual selected path. Aux previously returned an empty string on cancellation and its independent schema made the result required. The proposal makes only that current callback field optional and restores NoArguments cancellation, retaining actual selected `local_path` for success. Original Run initializes an empty native dialog title; the invented `Choose a working folder` title is replaced with that empty title, leaving AppKit to present the original default folder-picker text.

Listener lifetime is deliberately preserved. Original Run retains the API function before `SelectFile`; selected/cancel callbacks respond and release that retained reference. Original listener destruction notifies the dialog. Aux retains the same mechanism through `picker_hold_`, releases it after the completion callback, and retains `ListenerDestroyed` in its destructor. It does not introduce an unproved forced panel-close/cancel method. The current155 `SelectFileDialog::Listener` explicitly permits the one completion callback to run synchronously inside `SelectFile`. Current `ExtensionFunction` documents `AlreadyResponded` for exactly that case, so the proposal returns it when the callback already responded; asynchronous callbacks still use RespondLater. This is an explicit155 integration correction, not a fabricated asynchronous success.

`python3 docs/integration/proposed/native-popup-picker-lifecycle/verify.py` passes original input/function pins, exact three-file replay, source-scoped reservation/completion, duplicate and visibility checks, optional cancellation, retained-listener ordering and synchronous-response boundaries. It verifies that profile binding, Show/lock routing, reopen and focus are unchanged, and that the schema delta is only optional:true on that callback field. These are static checks. No native build, target execution, picker opening, owner profile, Keychain, signing or OS grant occurred.

Actual native panel behavior remains an explicit gap: destroying its owner window may or may not immediately trigger cancellation. The original API function retains itself until the real callback, and this proposal preserves that lifetime rather than reporting a fake cancellation. Disposable runtime observation must verify main/options callers, rejection from another page, duplicate requests, selection/cancel/policy-denied synchronous completion, profile switch/destruction with a pending panel, late old-source callbacks while a new picker is pending, and native focus after completion. Source/hash checks do not establish those outcomes.
