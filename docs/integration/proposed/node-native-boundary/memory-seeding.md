## Assembler seam

Stage `memory-bootstrap.cjs`, `memory-seed.cjs`, and `memory-pins.json` beside the daemon's guarded native CJS in `apps/daemon/Aux Daemon.app/Contents/Resources/native`. Copy only the pinned static memory distribution into root `memory-distribution`. Bootstrap derives this root from its exact canonical bundle placement, checks the manifest SHA, and reads absolute AUX_HOME. Existing canonical home must belong to the current user and have exactly0700 permissions; symlink traversal refuses. Source and destination must be disjoint (neither may contain the other). Existing pinned paths must have their expected regular-file/directory type at each visited component; non-directory traversal refuses. On macOS `/var` aliases must already be canonicalized to `/private/var` by launcher/caller. No external source/manifest environment override is accepted.

It uses built-in node:module createRequire(process.execPath), not a development Node subprocess or a minified helper guess. The adapter now applies this exact count-one hook in platformEdits. Integrator confirmed staging of these three files and coordinated supplied-wire preservation before enabling the hook. Original startup catch propagates seeding errors; no synthetic ready/health state is introduced. The --verify-local-memory branch bypasses daemon main and remains unchanged.

## Publication and existing cache behavior

All allowlisted source types and file bytes are verified before publication. Existing catalog and descriptor-hash directories are retained exactly, including newer/modified catalog bytes, missing files and CURRENT. Pinned descendant symlinks refuse. No cache repair, prune or overwrite occurs. Source or destination symlink roots refuse. Credentials/users/account paths cannot enter the allowlist.

A missing descriptor directory is reserved with exclusive mkdir, files use exclusive writes, CURRENT is written after generation content, and missing catalog uses exclusive file creation last. This avoids POSIX rename replacing an existing empty descriptor directory. A crash can leave an incomplete newly reserved cache; later seed retains it and the original loader performs its own genuine validation/download. This does not claim transactional directory publication. A simultaneous cooperating seed retains a directory won by another seed; original loader readiness remains authoritative. Provision before daemon use; no concurrent cache repair is performed. Failed source verification may create the empty private home but publishes no cache files.

Lean fixtures pass for new/partial existing homes, modified existing catalog, changed CURRENT, unrelated fixture credentials untouched, corrupt source pin before cache publication, and source/destination symlink refusal. Startup anchor occurs exactly once in the pinned code and CJS syntax passes. No real supplied daemon, memory model, native binding or owner state was executed by these tests.
