# Captured credential payload compatibility

This external source-only preparation is separate from the generic four-row authority migration and opaque copy journal. A logical/physical selector rename does **not** establish payload compatibility. `source/prepare.mjs` validates explicit captured bytes, returns a new exact byte copy plus nonsecret hash/count/family receipt, and refuses unsupported payloads. It has no discovery, state IO, Security executor, original addon, provider request or runtime registration.

| Family | Actual supplied consumer | Preparation |
| --- | --- | --- |
| Channel bot/app secret | `saveChannelSecret` stores its string directly; `readChannelSecret` returns `readSecureStorageItem` unchanged. No local HKDF/AAD/envelope. | Exact nonempty bounded UTF-8 byte copy, only reviewed account/channel/platform/kind grammar. Does not assert remote token validity. |
| MCP index | `mcp:index:<account>` is JSON string array, each entry 1–32 JS characters. | Duplicate-aware JSON parsing and that exact array constraint; retain serialization/order/content. |
| MCP OAuth | `mcp:<account>:<server>` is JSON with optional identity/clientInformation/tokens/codeVerifier/clientSecret. Identity is URL plus configured client ID; it is not product branding. | Conservative known-field validator for exact source schemas; unknown fields/types refuse rather than stripping/translating. Preserve tokens, OAuth identity, PKCE and whitespace exactly. Does not reconnect OAuth or assert settings/client/redirect compatibility. |
| CSK | `storeLocalChromeSyncKey` encrypts purpose `csk` using installation DK. Persisted blob may be bare `{purpose,nonce,ciphertext}` or owner-bound `{schemaVersion:1,accountId,boundUserId,encryptedBlob,syncGeneration?}`. | **Refuse opaque copy in this semantic preparer.** Requires authenticated legacy open, explicit versioned Aux-v2 reseal, unchanged owner/generation and same-DK continuity, then coordinated consumer rollout. |

The exact current composed state2 daemon source at base `29704df5f` has hash `d69b87e91e30edadaef456b63d7f4751a09ce4c997f31b6129d01b5801a3e6d4`. `AUX_KEYCHAIN_ID_PREFIX` selects Aux logical keys, but `DK_SUBKEY_INFO_PREFIX` remains the original domain and `DK_WRAP_INFO` remains the original wrapping domain. Its `readLocalChromeSyncKey` still parses the original blob and runs original `decrypt('csk',blob)`. This is a concrete incomplete integration, not a testing gap. Proposed `aux.dk.v2` records cannot safely be advertised to this consumer by copying or changing the `format` property.

In original JS, `getPurposeInfoBytes(purpose)` is UTF-8 `aside.dk.<purpose>.v1`, used as **both** HKDF-SHA256 info (empty salt, 32 bytes) and ChaCha20-Poly1305 AAD; nonce is 12 bytes. CSK purpose is `csk`, not a branded logical selector. New proposed Aux-v2 uses `aux.dk.csk.v2` and explicit format. Changing only service/account leaves an old-domain encrypted payload; changing labels without decrypt/reseal breaks authentication. Installation wrapper versioning alone does not migrate these subkey blobs. No owner ciphertext or authority was inspected.

`source-pins.json` pins complete frozen daemon hash plus exact function byte ranges/text/hash and involved current source dependencies. `source/extract.mjs` verifies those before returning only bounded pure consumer snippets. `tests/check.mjs` statically composes the current daemon and checks this concrete domain gap; executes the actual extracted channel writer/reader; checks conservative MCP accepted/refused bytes; executes actual extracted pure JS CSK encrypt/decrypt with a Node ChaCha20-Poly1305 implementation of the sodium call ABI on fixed synthetic data. It proves legacy roundtrip and rejection after domain substitution or superficial v2 format addition. It does not execute the app, original addon, sodium runtime, Keychain, provider or owner state. MCP schema validation is source-derived conservative validation, not execution of the entire bundled Zod application.

Run `node docs/integration/proposed/aux-credential-payload-compatibility/tests/check.mjs <explicit frozen daemon-original.mjs path>`. This module is **not wired into** the generic Swift credential-copy component or startup. That component alone remains only a byte-preserving mechanism and must not be treated as CSK semantic approval. Remaining work: genuine captured source provenance/custody, explicit Swift/native host integration of the semantic gate, versioned CSK rewrap and exact composed reader/writer/schema update, authenticated owner/generation validation, then bounded disposable integration. Vault authentication/session/PWM families remain excluded from the reviewed policy and are not reintroduced here.
