# Inactive macOS crypto-source finalization

This source adapter closes exact residual original-domain literals after the paired CSK and live-purpose proposals. It requires the precise coordinated successor hash, then performs count-pinned fail-closed exclusions. It is not in the active packaging/startup pipeline and does not run the app, original addon, Security or owner state.

The output explicitly refuses non-macOS execution. It does **not** claim Windows parity. It removes the two original domain constant declarations/assignments; generic purpose-byte/subkey/blob encrypt/decrypt functions and old Windows P256 wrap/unwrap functions keep their symbols only as immediate throwing stubs. Existing export references therefore cannot execute an unreviewed generic old-domain derivation. Unknown late callers fail before reading authority rather than deriving from a renamed constant. Current macOS native installation init/status/unwrap/sign/public-key delegation is byte-identical to input.

After paired consumers, remaining generic `encrypt/decrypt` calls are in excluded Vault auth storage, biometric-key serialization and persisted Vault sessions; token/evidence/cache/CSK live consumers have their explicit Aux-v2 paths. This map is exact direct-source evidence, not a formal proof of all dynamic reachability. Fail-closed generic boundaries do not require claiming those late calls are impossible. Excluded Vault PMK/CSK derivation, keyset recovery, settings-key derivation, account-password verifier and session selector builder are also explicit stubs; their original-domain literals and unused session-prefix assignment/declaration are removed. This is a crypto-source exclusion, not a claim every remaining Vault class, biometric helper, settings symbol or backend artifact is eliminated.

**Account browser-data Sync recovery is separate from Vault and remains unfinished.** The source `recoverAccountSyncKey` uses authenticated `/auth/onboarding/recovery-material`, an original-format recovery backup, old recovery KDF/AAD, then AUK→CSK derivation. That entire entry point and old backup schema now refuse in this inactive target. Renaming that encrypted backup or deriving a different CSK would lose access to existing Sync data. `recovery-contract.json` pins exact function, endpoint, schema, KDF/cipher/AAD, generation/identity checks and next required implementation. This refusal is an explicit unsupported legacy feature, not completed recovery parity. Ordinary new-Aux Sync status, key fetch and new CSK store functions remain byte-identical to the paired input.

`references.json` records original-domain occurrences and direct generic call boundaries before/after the exclusions. Five exact domain families have zero output occurrences: original DK, wrapping, recovery, PWM and account-password derivation names. This is not a full raw-product-brand inventory; other source branding/third-party attribution/HTML semantics and embedded artifacts are owned by their respective integration lanes. Original authorized snapshots and external importers remain truthful.

`tests/check.mjs` statically composes the actual supplied daemon with the two reviewed adapters, applies this successor, parses the **whole** generated application source with `node --check` without importing it, executes only the17 fail-closed stub functions, confirms non-macOS guard rejection, and compares exact preserved native/storage/auth/ordinary-Sync function bodies. It does not repeat unchanged migration/CSK/cipher fixtures or imply actual native installation acceptance. No parent pipeline, manifests, native checkout, UI or state is changed.

Before activation: authenticate same installation root and actual captures, complete admission/custody, materialize fixed Aux runtime module graphs, durably migrate captured CSK/cache/evidence records and retain originals, coordinate token reacquisition, and implement Aux-versioned account recovery writer/reader/server or a reviewed authenticated legacy importer. Removing old source literals cannot substitute for these operations. Newly disabled old recovery must remain visible as an actual feature gap in readiness reporting.
