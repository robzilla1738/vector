# Native development-host worker consumer — source only

This adds an actual native embedding callback and lifetime consumer to the signed development route. It does not activate a module or authorize state 2. The existing signature/resource loader, runtime capture, dispatcher, NAPI adapter and UI are unchanged.

`AuxDevelopmentWorkerHost::RegisterCurrentWorker(napi_env,target)` is called by the trusted native embedding during its actual Node environment bootstrap, on that environment's thread/current V8 context. It observes the current `node::Environment*`, `v8::Isolate*`, Node/NAPI `uv_loop_t*` and `pthread_t`; no PID, worker ID, scope, receipt or environment variable is accepted. A synchronous private NAPI function, never exported, compares the Node Environment observed **inside the actual NAPI callback** with the current bootstrap context. Merely sharing an event loop is insufficient. As with Node's API itself, the native embedding must pass a live `napi_env` belonging to its current thread; attempting to dereference a foreign/destroyed env is not a supported validation interface.

The native registry has explicit process lifetime so C++ module destructor ordering cannot destroy its mutex/maps before a host destructor; completed entries still release at actual cleanup, and pending custody is not auto-released at process-global destruction. One process-local reservation binds the actual Environment to exactly one owner. A second host cannot adopt it. The reservation remains terminal after initialization failure, attachment failure or host close, until actual environment cleanup. Cleanup then detaches that dead Environment identity; pending ownership moves to a distinct native monotonic generation in quarantine. Native generations are nonreusable and refuse overflow. Node may reuse an Environment address for a new independent worker without aliasing or adopting the old owner. Forked use is refused by the native process identity check. These identities are runtime pointers/thread handles, not persistent credentials or proof of exclusive writer custody.

The callback calls the existing `AuxCreateSignedDevelopmentOwner` only after registering cleanup ownership. That real Swift producer performs the signed-policy checks and exact target capture/import already reviewed. Its resulting handle and retained owner are paired in a refcounted native object; the existing NAPI adapter receives one separate retain for that same owner/handle. JS receives only the existing `run` function. No JS factory, handle selection, module initializer or `NAPI_MODULE` exists in production source.

Initialization is an explicit in-flight phase registered before releasing the host mutex. No host or worker mutex crosses cleanup-hook registration, the Swift producer, NAPI publication, native retirement or retained-owner release. A close during the factory returns `pending`; a factory returning afterward is adopted only into retained retirement/quarantine and never reaches attachment. A close during `defineProperty` retires the already-created handle, returns `pending` while attachment is in flight, then initialization completion refuses success. This handles actual Proxy traps reentering native close without deadlock. An arbitrary Proxy can retain the function object passed to its trap; it cannot be forcibly unpublished from hostile JS, but that function is permanently retired and unusable after the close. No successful live command capability is published after closure.

`CloseAndDrain()` permanently prevents new registrations, calls the **actual Swift registry retirement** for every registered handle and waits for acquired synchronous calls to finish. Its new Swift retained-owner bridge also calls the actual `closeOSAdmissionAndDrain(timeout:0)`: `.notPresent` is the real no-OS-capability case; `.drained` is verified tracked completion; `.pending` and `.untracked` are never accepted as drained. Both native host shutdown and environment cleanup use this path. The original retained owner is released only when its host record and adapter have released their exact shares. Native host shutdown does not replace the adapter's published function: subsequent calls preserve the existing JSON-string error contract while the registry refuses operations. Normal worker termination independently retires/releases that worker and leaves other workers usable. If async drain is pending or unknown, cleanup deliberately retains the exact owner in a generation-keyed quarantine after environment teardown; later explicit host close uses only the retained owner to re-observe completion; it never dereferences the dead Environment, Isolate or thread identity. Destroying the host while pending cannot silently release that quarantine, but also loses its practical retry coordinator, so it is caller misuse rather than certified shutdown.

Retirement's `-2` reentrant-lease refusal is not success: the method returns `reentrant`, retains the owner and keeps registrations closed. The embedding must call close again outside the active lease and retain its host object until close returns `drained`. A destructor attempts retirement but cannot certify shutdown; it is not a replacement for that explicit close protocol. Environment/adapter references keep uncertain ownership alive until their cleanup, rather than releasing an active owner. A failed NAPI cleanup-hook registration installs Node's native current-environment cleanup hook, preserves the failed reservation and never calls the protected factory.

## Concrete integration seam

The native embedding owns one `AuxDevelopmentWorkerHost` for its lifetime. Its actual main/worker bootstrap calls `RegisterCurrentWorker` with the real env and actual export target. Before destroying its runtime/worker cohort it calls `CloseAndDrain()` outside command callbacks and requires `drained`; actual environment cleanup then releases retained adapter ownership. The source does not discover or attach arbitrary workers, spawn a replacement host, patch a Node SEA, or inject an initializer. The current packaged host still needs this real bootstrap/shutdown call site and its separately reviewed signed bytes.

## Remaining admission gaps

This consumer is process-local command admission/lifetime, not all-writer authority. It does not prove browser/renderer/descendant custody, coherent four-row capture, provisioning/entitlement acceptance, owner provenance, migration completion, or worker association **outside** callbacks the real embedding registers. Trusted policy generation, approved exact-byte signing and actual embedding call sites remain outstanding. No state-2 launch gates, accepted app, signatures, grants or packaging inputs change. The two-image signed development inventory stays unchanged: the separate optional PDF module requires an explicit reviewed signed-image inventory before this route may load it. Root's current PDF artifact path alone is not a signed shipping layout, so no speculative allowlist entry is added.

The process registry permits a newly observed native environment under a new monotonic generation while an old generation remains in OS quarantine. That is pointer/lifetime isolation only: it does **not** prove same-profile or same-authority cohort exclusion. Whole-profile readmission remains refused at the actual startup gate; no generation/receipt here grants admission.
