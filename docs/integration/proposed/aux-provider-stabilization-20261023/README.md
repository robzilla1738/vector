## Crash recovery without taking a live lock

Authentication operations now use macOS's built-in `/usr/bin/lockf -s -t 0 3`, with the private, nofollow-opened account lock descriptor inherited as fd3. `lockf(1)` explicitly supports descriptor mode and BSD `flock` ownership of the inherited open-file description. The original Node descriptor retains the lock after the short utility exits. Closing that descriptor releases it; a crashed Node process has its descriptor closed by the kernel. No resident helper, PID age heuristic, file deletion, guessed stale owner or background service is involved. A fixed clean environment is passed to the utility, not the daemon's provider credentials.

The account-hashed permanent file has explicit `aux.chatgpt.auth-lock.v2` metadata and is never unlinked. Same-account live contenders fail; other accounts remain independent. File identity/owner/mode/link count and parent directories are checked before admission. An old empty v1 marker, or a marker left incomplete during first-ever creation, is preserved and refuses with an explicit recovery-review error. Such a marker cannot distinguish a live old binary from a crash and is deliberately not stolen. A v2 marker also prevents an older O_EXCL-only implementation from admitting a concurrent operation. This is authentication-store serialization, not native browser/profile writer custody.

A real disposable child Node process acquired this exact lock implementation, a second store was refused while it lived, the child was killed, and the second store acquired the same retained inode afterward. A separate probe confirmed the lock remains held after the utility exits and releases after the original descriptor closes. No OS grants or native authentication were invoked.

## Provider lifecycle and supported payloads

- Cancellation aborts pending code exchange and JWKS fetch, not only the final write. Disconnect also cancels/aborts selected-account refreshes. Queued attempts recheck cancellation before requesting tokens.
- A second initially unbound sign-in cannot overwrite a different registration established while it waited. Refresh still verifies the current session before replacing tokens.
- Known rejected refreshes persist `auth-expired`, which the supplied provider settings already render. A second request fails locally; raw provider error bodies are not exposed. Latest tokens are retained locally for explicit disconnect/revocation rather than silently deleted.
- All provider requests remain bounded by a 15-second timeout even when an external cancellation signal is supplied.
- The existing Responses implementation remains in use. The final payload now follows the current plan preview contract: full input history, developer messages instead of system messages, stateless streaming, omission of unsupported sampling/output/cache/history fields, and local function/custom tools carried as supported `additional_tools` developer input. Tool names/history are preserved. Unsupported hosted tools, tool-search history and audio/video inputs refuse rather than disappear silently. Public-plan image generation remains explicitly unavailable.
- Exact supplied model slugs retain their pinned metadata. Unknown catalog slugs get explicitly conservative local bounds/text-only input; arbitrary undocumented catalog capability fields are not trusted. Contract compatibility overrides disable tool_search/output-token controls and enable supported additional-tools encoding. These bounds do not assert actual provider model limits. Current account-visible names/order still come from the public account catalog.
