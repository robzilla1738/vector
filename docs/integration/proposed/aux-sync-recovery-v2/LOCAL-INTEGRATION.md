# Local recovery backend successor

This slice integrates the earlier source proposal into the actual service. It does not deploy, connect to a real database or wire the inactive desktop client. Owner UI is unchanged. Earlier `evidence/local-check.json` is historical crypto/client evidence; it is not re-run or promoted to native/hosted acceptance.

Implemented source:

- Actual `app.ts` mounts both authenticated recovery routes under `/api/v1`; existing JWT and live-session verification are unchanged. The router additionally requires a bound macOS installation signature and rejects portal sessions. Existing own 16 KiB body bound and no-store policy remain.
- All four reviewed ordinary Sync guards are applied exactly. Current recoverable generations refuse random resolve/ordinary enrollment if the key row is absent. Existing key resolution remains available, and new owners without a recovery backup retain ordinary provisioning.
- Migration `012-sync-recovery-v2.sql` is now in the active migration directory and schema hash manifest. It is additive and never rewrites existing keys. The original proposed SQL remains unchanged as historical review. The active successor removes the historical `created_by_session` foreign key (retains its UUID after pruning), and uses `ON DELETE CASCADE` for short-lived challenge/session references. Without this correction, ordinary expired-session pruning would fail once recovery was enrolled.
- Existing protected maintenance prunes at most 200 challenges older than one day per invocation, with row locks/skip-locked and deterministic expiry/ID ordering. Helper limits are integers 1..1000. No encrypted recovery revision is expired by maintenance.
- Existing deleted-account purge explicitly removes challenge and recovery records before marking data purged; ordinary session pruning retains encrypted history and its creator UUID.

Focused current check: `services/aux-cloud/src/sync-recovery-integration.test.ts` executes **all twelve actual migration DDL files** in private in-memory PGlite, verifies every manifest hash, then runs the actual mounted Hono app. Only `CREATE EXTENSION IF NOT EXISTS pgcrypto;` is omitted: that installer is unavailable in this PG/WASM build, which already implements `gen_random_uuid()`. Production extension installation remains untested; no reduced replacement table schema is used.

The test uses Neon's documented `neonConfig.fetchFunction` transport seam to route actual app SQL to that database. Global fetch is replaced with an unconditional denial, not a network fallback. The actual `requireUser` verifies a synthetic HS256 JWT, its token hash, live session/owner/generation, and the recovery service verifies an actual synthetic recorded P256 signature. Neither JWT validation nor application middleware is replaced. No credentials/env files are read. Synthetic environment values are restored afterward. This does not test Clerk/provider networking or production Neon transport.

The focused case proves missing/forged/cross-owner token rejection, actual challenge/material routing, 16 KiB refusal, existing encrypted material unchanged, missing-key guard refusal, unchanged fresh-key provisioning, bounded expiry cleanup retaining the live receipt and encrypted revisions, session deletion retaining creator/history, and actual deleted-account purge completion. Test-only wire serialization uses PostgreSQL text timestamp format, matching the Neon driver's real parsers; ISO timestamps were an initial fixture transport error and were corrected without changing auth.

Still required before browser recovery is usable: real desktop atomic absent-or-same CSK/owner/generation publication; saved/verified 12-word enrollment flow; native signing/account request wiring; post-cold-refusal dynamic client preload; one reviewed disposable native/UI recovery. No automatic enrollment, original backup reinterpretation, password manager or Vault is added. Real migration/deployment, production key operations and PQ-provider verification are not done. Production activation must keep migration 012 and the new source version coordinated.
