# Supplied native toolbar palette and focused address glyph

This proposal restores35 exact dark/light toolbar, location-bar and omnibox tokens exported by the supplied Aside color pipeline. The current Chromium155 pipeline contains no Aux-specific final color mixer, so upstream material colors replace the supplied palette. In particular, the supplied toolbar, location-bar background and resting icon background resolve to the same color (`#171717ff` dark, `#ffffffff` light); the differing upstream icon color produces the visible circular search-glyph backing in Aux.

The override is Aux-only, after native baseline mixers and before custom-theme/app-controller mixers. OS high-contrast/forced-color modes and subsequent custom themes keep precedence. This does not hardcode grey sampled from a screenshot or override native material/backdrop rendering. The reference's dynamic toolbar/page-color sampling and sidebar translucency require their own native owners; this palette alone does not establish full visual parity.

The focused plain-search icon is omitted from the location-bar decoration chain, matching both the owner's focused-address reference and the live Aside observation reported by the integrator. Active keyword bubbles, overriding permission chips and labelled security states retain their original handling. Focus/input state remains the actual omnibox edit-model state. This is a narrow integration correction in Chromium155, not a claim that the original custom C++ source exists.

`source-evidence.json` records every token and both original CSS hashes. `manifest.json` pins actual v510 native preimages and outputs for the two files. No native checkout modifications or build performed in this lane. Root must integrate, compile and observe both resting/focused address states. Toolbar Downloads is not removed: its absence in a populated reference profile does not establish an original default-pin policy, and pinned state must not be overwritten based on a screenshot.
