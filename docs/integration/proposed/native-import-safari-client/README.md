# Supplied Safari native client port

This five-file proposal replaces public Safari's independently authored per-category reader with the actual supplied owner: a staged binary archive and a lifetime-owning SafariDataImportClient using genuine Chromium155 SafariDataImporter, SavedPasswordsPresenter and MakeBookmarkParser. All card/history/password/bookmark parsing and destination policy remain in that real upstream component. No new archive schema, SQL, card CSV parser or fake installation/write result is added.

Apply after native-import-safari-owner (optional Safari profile/name admission) and native-import-safari-bookmarks-only (the supplied default-false PrepareImport bool and its exact parse/commit branches). The three overlapping files use the first slice's proposed outputs as baseline; new files are ordinary /dev/null diffs and null-baseline manifest rows. Integrator owns GN and native application.

That alias admits full Safari categories or bookmarks-only; another partial checkbox request is rejected instead of silently importing unselected data. The old ReadSafariArchive call and include are removed from this public dispatch path; its historical standalone helper/probe can remain recoverable.

## Integration and limits

The manifest lists sources and exact existing GN dependency targets for integrator review, including browser_process, affiliation/autofill/reading-list/sync factories, genuine component browser/UI owners, content BookmarkParser and safari_data_importer. No shared GN or native source was written and no build was launched by this lane.

Native source evidence is pinned in this directory and the prerequisite owner ledger. The supplied outer caller does not issue a separate SavedPasswordsPresenter::Init call; the adapter mirrors that construction/pipeline and adds no speculative password-store/account readiness gate. Real saved-password conflict/cache behavior must still be observed in a disposable authorized import before runtime acceptance. This caveat is explicit rather than a reason to invent different account behavior.
