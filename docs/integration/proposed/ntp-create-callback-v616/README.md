# Preserve recovery through the editor's initial notification

The first-Ask fix incorrectly treated every change callback as a user edit. The supplied create-editor explicitly runs `onCreate:()=>f()`, where `f` publishes its current snapshot through runtime.callbacks.onChange. That delayed initial callback can run after the New Tab initializer installs its callback, with an empty Search snapshot. It therefore cleared the pending restoration flag without any user edit. Actual616 retained its page identity and attachment but lost saved text, consistent with this path.

One replacement condition keeps restoration pending through that empty initial notification. Nonempty text or an embedded attachment consumes the flag; a genuine edit followed by clearing therefore still prevents saved text from reappearing. The earlier nonempty query/startup checks and one-shot mode transition remain intact. No styling or new UI is introduced.

The focused check executes the complete transformed New Tab initializer with its original initialization ordering and the supplied create-editor's exact delayed callback chain, then switches to Ask before the React subscriber runs. Recovery survives the initial callback and precedes subscriber notification; typing then clearing cancels recovery. DOM/editor rendering is represented by boundary doubles, so this remains a source lifecycle check, not actual browser acceptance. It corrects the previous standalone setMode check's omitted initial editor notification. The transformed module parses. Root only restages the existing newtab-editor leaf; no native build.
