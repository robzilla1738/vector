# Retain the real focus controller and resolve actual target services

The actual Views focus controller retains one profile reference. Its accessibility
bubble gesture resolves UserEducationService and FeatureEngagementTracker from that
reference on every invocation. It caches no profile service, observer or deferred
profile callback. The supplied same-window profile transaction therefore needs to
rebind that reference to the same owning window's actual current regular profile.

RebindForAuxProfileSwitch(BrowserWindowInterface&) checks the genuine unowned-data
owner and derives the profile from that owner. The physical base window, element
context, toolbar provider, pane focus logic and actual accessibility handlers are
unchanged. The full migration provider calls this after identity commits; it can
also restore the actual source reference if rollback ever follows a commit. No
focus gesture or engagement event is generated by rebinding. The existing public
focus target exposes its newly included browser build flags.

This is a necessary Chromium 155 service adaptation, not a recovered replacement
for the supplied UI or a full profile-switch acceptance claim. Exact source pins
and patch are recorded in manifest.json. Compilation is recorded separately.
