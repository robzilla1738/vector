# Aux-isolated native secure-store source adapter

This inactive source adapter implements the supplied `secure-save/read/clear` consumer contract for protected application credentials. It is not the excluded Vault/password-manager product. No installed app, UI, pipeline, native loader, Keychain record, owner state or provider setting changed.

## Recovered evidence

The pinned original daemon calls secure storage for MCP OAuth credentials/indexes, channel secrets, session material and encrypted cloud/bootstrap data, as well as Chrome sync. Limiting this API to Chrome sync alone would drop existing behavior. The Windows generic installation reader/writer and excluded Vault consumers also exist in the static original source; this does not authorize reactivating those on Mac or shipping Vault. Literal call counts and original source SHA are in `evidence/consumer-counts.json`; this is not a claim that all possible dynamic callers were found.

Bounded Apple SDK `nm`/`llvm-objdump` observations identify original `secureStorageBaseQuery` at0x2ec84, Add0x2ee14, ReadData0x2efe8, Save0x2f434, Read0x2f62c, and three command handlers0x2f6ec/0x2fd08/0x302cc. GOT bindings establish generic-password, service/account, explicit original access group and Data Protection; the base query uses the logical key for both service/account. The fixed original group string at0x519630 is retained only in this external evidence, not the new API. Add uses AfterFirstUnlockThisDeviceOnly; reads request data and match-one. Indirect stubs identify SecItemAdd0x514980, CopyMatching0x51498c and Delete0x514998. Original Save reads backup, deletes, adds, and tries to restore old bytes after failed Add. These are assembly observations, not recovered original Swift source or observed execution.

The REA session had no open target; native analysis providers were unavailable (installed Ghidra/Java mismatch and absent Hopper). No setup changes or duplicate analysis jobs were started. The bounded SDK observations above are ordinary shell evidence, not fabricated REA Evidence. Original addon bytes were never loaded or executed.

## Explicit Aux namespace and behavior

`ReviewedAuxSecureStoreScope` takes an explicit64-hex scope, explicit Aux-only group and finite set of exact UTF8-byte allowed logical keys (maximum1024; each nonempty512UTF8bytes, no NUL). The trusted host must construct this immutable set; renderer/JS scope selection is not supplied. Logical values can retain standard `mcp:` spelling and user content, including a user's word containing the reference name. Physical service/account are both `aux.<scope>.secure.v2.<SHA256(logicalKeyUTF8)>`. This keeps all physical selectors Aux-only, avoids logging account labels and prevents this API from selecting installation records. There is no legacy/group fallback, prefix wildcard or enumeration.

The actual Security adapter source uses explicit class/service/account/group/Data Protection queries with authentication UI fail, bounded exact CFData decoding, and match-one reads. It has no constructor side effects and is never the test backend. The existing SDK reports the known authentication-UI constant deprecation; migration to a reviewed LAContext policy is separate from this unchanged no-dialog intent. Apple documents [Data Protection without synchronization](https://developer.apple.com/documentation/security/ksecusedataprotectionkeychain) and [targeted updates without result-return keys](https://developer.apple.com/documentation/security/secitemupdate(_:_:)); the update query includes no return keys.

The command core consumes strict duplicate-member-aware JSON (whole input16KiB) and returns JSON **text**. `secure-read` returns string data or null only for actual missing state; inaccessible, invalid-type, oversized and non-UTF8 results return a fixed error without sensitive detail. Save and clear retain `{success:true}` on actual successful operations. Save uses exact-selector Update, Add only on not-found, and reports duplicate/race/error without retry. This deliberate platform adaptation avoids delete-before-add and stale backup restoration over another writer. It is not cross-process CAS; cooperating writers still require native admission. Explicit clear deletes only its one reviewed exact selector; not-found is idempotent success. It is source only, not permission to clear any real data.

## Focused verification and limits

`sh docs/integration/proposed/aux-native-secure-store/check.sh` compiled the actual adapter/core as separate Swift files through `scripts/native-build.py` and passed24 captured-backend/query assertions. Checks cover exact DP/group/selector attributes, distinct hashed keys, UTF8 response, update failure preserving existing data, Add race refusal with no retry, missing versus blocked/invalid read, canonically equivalent but unreviewed UTF8 key refusal, duplicate JSON/unknown key refusal with zero backend operations, and exact clear isolation. Actual Security calls:0. No real private material enters the fixture.

Remaining: trusted host/finite-key policy, scope/custody/entitlement approval, actual adapter execution, routing this separate module alongside installation/PDF/OS consumers, and explicit copy-only migration for existing credential selectors. Existing protected records are untouched; the new namespace cannot automatically read them and no reset is substituted for migration. This adapter alone neither replaces the original common addon nor eliminates its embedded names. No signing, hardware crypto, password-manager UI, cloud request or product-readiness claim.
