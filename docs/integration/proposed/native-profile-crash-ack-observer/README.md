# Rebind genuine crash acknowledgement observation across profile transfer

Pinned native v605, three files. BrowserManagerService::TransferForAuxProfileSwitch deliberately sends no collection create/close events. ExitTypeService's BrowserTabObserverImpl otherwise only observes newly created non-startup, non-omitted browsers. Thus the target profile cannot observe subsequent user tab creation in the persistent transferred window; an existing source observer can incorrectly treat target tab insertion as source crash acknowledgement.

After a successful transfer has inserted all actual target tabs, reconcile both services' observation of that same window. Source detaches; target attaches only if profile identity, relevant type and non-omitted window match. An explicit profile switch is outside startup even if the native window's original immutable creation source was StartupCreator. Transfer-generated tab insertions are ignored while the existing transaction mutation flag is active. Rollback retains the original observation and also ignores synthetic insertion.

The fix does not clear crash state, release crashed locks, enable saving directly, acknowledge hidden cache insertion, or treat profile switching alone as crash acknowledgement. A subsequent real user tab insertion calls the unchanged OnTabAddedToNonStartupBrowser / CheckUserAckedCrash logic, including pending-restore and shutdown guards. This preserves the user's chance to restore before overwriting data. Successful hidden restoration alone still does not invent user acknowledgement; separate explicit recovery UI may remain necessary if no user action acknowledges a prior crash.

Validation: count-checked source edits, exact preimage/output pins and isolated replay. No shared native edits, build, runtime or profile mutation. Compile exit_type_service.cc and aux_profile_switch_transaction.cc; actual verification should switch to the disposable target, create a new tab, then inspect the bounded saving/crash readiness diagnostic on the next switch.
