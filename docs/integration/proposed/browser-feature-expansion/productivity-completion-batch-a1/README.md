This batch fixes concrete gaps in the actual current feature implementation. It preserves existing default layout, typography, corners, materials, classes and artwork. It is not runtime or UI acceptance.

## Implemented

1. **Mixed-axis and nested split interaction.** Double-clicking/tapping a recursive divider now swaps that divider's two branches through the actual `MultiContentsViewDelegateImpl`, `SplitPaneTree::SwapBranch` and `TabStripModel::UpdateSplitPaneTree`. The actual native SessionService persists the resulting layout. It preserves genuine tabs, documents, active selection, unrelated branch geometry and the current pane-slot mapping. Legacy two-pane swapping keeps its existing path. No new command IDs or schema are required.
2. **Split handles after changing splits.** Different split trees can use the same branch-node IDs. Reused resize handles now refresh their axis in `ConfigureBranchHandles`, including the `PrepareSplitView` path when selecting a different split. Previously only a visuals update refreshed the axis, so a divider could show/resize in the old orientation after switching to another tree. The existing current-tree visuals path delegates to the same refresh instead of duplicating it.
3. **Unavailable recent files.** Known-unavailable entries remain visible in the existing sidebar row, with explicit unavailable text/accessibility/tooltip and disabled drag/reveal. Previously the sidebar silently dropped these entries even though the listing returned their unavailable status. The same32px/14pt row, icon,10px hover corners and section spacing remain. This does not claim proactive identity validation for every persisted chosen-file entry; drag/reveal still perform their existing actual identity checks.
4. **Filename suggestion review lifetime.** The active supplied files adapter now binds each asynchronous action to its current review epoch. Cancel/back, selecting another file or unmounting invalidates the earlier action and requests cancellation of its exact provider request through the existing daemon boundary. A late result cannot reopen the old rename screen, replace the new review's input, or focus its field. If account lookup finishes after a review changed, it refuses before creating the provider request. An obsolete `finally` callback cannot clear a newer request. The guard supports React effect cleanup/re-establishment without disabling later explicit actions.
5. **Screenshot area bounds.** The supplied capture path now validates the actual captured PNG's dimensions before cropping an area. Selections extending below the image refuse instead of producing blank/off-page output. Dimensions come from the native image's bounded PNG header, not a claimed viewport height; only one raster pixel of edge rounding is tolerated. Invalid PNG dimensions refuse and release the existing native capability. No new image upload, capture permission or automatic AI action is introduced.
