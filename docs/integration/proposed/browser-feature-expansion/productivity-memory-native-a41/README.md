# Fixed per-account memory helper

This slice connects the supplied memory client to one native fixed helper per actual registered Aux account. It changes no UI, style, assets, general task permission, PTY, shell, browser automation or native-messaging admission.

`projection.json` is the flattened native/Swift source handoff. Existing inputs are pinned to the actual ordinary-storage native owner and the already integrated A40 account resolver. `source-transforms.json` independently pins the actual paired supplied source/entry and eight exact one-count transformations per leaf. `replay.py` verifies all inputs, counts and output hashes in a fresh output directory without running a product. Source-entry native bootstrap and existing loader/refusal bytes are retained.

The real main Node Environment alone captures the existing retained Worker/dispatcher and actual account registry identity/incarnation/profile binding, plus private account/task memory FDs. Requests may only use fixed status/search/sync/close/shutdown methods; native code substitutes the held memory directory. The supplied MemoryProcess protocol, request IDs, JSON response handling and Node stream backpressure remain. Each account now owns its process instead of sharing the supplied global directory-selectable process.

Launch uses the fixed system sandbox-exec idiom, a fixed native SBPL, fixed executable/model, private stdio and no caller argv/environment. General fork/exec, network and other Aux account/profile/control reads/writes remain denied. The native producer durably records a prepared lease, creates the direct child suspended, independently verifies its kernel parent/birth/stopped state, fsyncs the spawned record and only then resumes it. Native original waitpid, all three parent pipes and joined original thread precede terminal recording and exact own-file retirement. No timeout, JS ACK, object GC or callback disappearance proves cleanup. Failed/lost record mutations and unknown wait ownership retain the native account owner and block ordinary retirement/restart. Completed helpers do not consume a permanent 256-success quota.

The startup consumer is organization A31 (`319a4fc0d`, source-plan `53d3968b7878e0782793ac5dde4e29c99cd68a443bd8fceca2d77671dbb9c0d2`). It reads the same `.aux-memory-helper-lifetimes.v1/<native UUID>.json` under the actual TaskLayout home, before startup and again after installer flock. Unknown prepared/no-PID outcomes remain an explicit recovery limitation; this slice does not delete or reinterpret them.

Account ownership changes use the existing accounts.json writer and actual native account registry lock. A proposed change that differs from a live helper's selected record/binding installs a native pending-target fence, requests physical closure and returns a BUSY refusal before writing. New helper captures remain blocked until the exact same target is physically published and native same-lock readback confirms the actual bytes. The caller must retry the account action after closure; no mutation callback is automatically replayed. Display/session/unrelated account changes that preserve the held ownership projection remain allowed. Unexpected publication failures retain the fence. This behavior needs an actual profile/account-switch check; it is not claimed seamless from source.
