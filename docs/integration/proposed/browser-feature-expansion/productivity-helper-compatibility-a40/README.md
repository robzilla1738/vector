# Finite memory helper: actual registered account owner

The current ordinary build deliberately refuses general child execution. The supplied MemoryProcess therefore fails with EPERM; it currently shares one process across accounts and passes raw directory selectors. Native messaging likewise requires the absent ES custody bridge. Removing either refusal would not create the missing owner/lifetime service.

This first implementation slice adds the native account producer needed by a finite memory helper, without enabling general exec. Three existing A16-linked Swift leaves are changed; one new Swift owner and one private C header are added. The resolver reads the actual admitted accounts registry under its existing OS lock, requires one account with an incarnation and one profileAccountBinding, and returns a typed identity. It does not use currentAccountId/account0 fallback, caller paths, session credentials or a cached readiness flag. Actual control/task roots come from the retained native capture. No-follow directory FDs pin fixed `u/<account>/memory` under that task root. Every use rechecks the selected account/binding fingerprint, incarnation, real directories and native ordinary authority. The profile-path hash is correlation data, not an independently minted native Profile grant.

Each helper owner remains in the actual dispatcher Entry. Capture is bounded to one owner per account/64 per Entry. Retirement refuses outstanding owners; unknown or changed identity never deletes one. Only the actual native launcher/reaper may release after definite pre-child failure or original child reap plus stdio closure. The NAPI consumer must prove the actual embedding main Environment and obtain its own retained dispatcher; these C adapters must never be exposed as generic Worker/page commands.

`publication-callers.json` pins a required source/entry change at the existing atomic accounts writer. Under the existing account registry callback, a private native preflight rejects ownership/incarnation/binding changes for any retained helper; display metadata and unrelated current selection remain independent. Launcher admission must remain disabled until this caller and the native NAPI consumer are paired. There is no replacement write stack and no caller readiness grant.

`fixture/compile-plan.json` uses the actual linked strict JSON parser plus the new producer's parser. Its synthetic cases cover ambiguity, missing ownership, account reuse, binding epoch change, independent current selection and duplicate keys. The fixture is prepared, not executed by this source lane. No real state, signing, provider or product operation occurred.

Remaining integration before operational indexing: actual-main NAPI producer; fixed manifest/artifact validation; native pre-spawn reservation; existing seatbelt/launch integration restricted to the held memory directory and fixed read-only model/runtime; native-owned pipes/original wait and physical settlement; per-account supplied MemoryProcess caller; revocation/close and the publication consumer above. General exec/automation/PTY remain refused. Root owns registration, source composition, compile/link, package and any later exact signing review.
