# Read-only control/task proof before browser lease mutation

Two actual A59 source successors, three counted anchors. `AuxFreshColdInstallerGuard.acquire` previously acquired browser lease markers before it inspected control/task records. Even a completely unknown Control file could therefore cause browser-marker creation before the later refusal.

The guard now opens the actual authenticated task parent and native control descriptor, verifies their metadata/path/disjoint identities, then performs the existing control inventory plus the new **read-only existing-pair preflight**. Only after those succeed does it execute the unchanged ordinary/full-mode browser lease acquisition and existing installer-lock sequence.

The task preflight takes real native retained descriptors, not a supplied root or validity Boolean. Missing control/task reservation markers must be a pair and Tasks must be empty. Existing markers must both exist. The actual existing-only `AuxResumedFreshNativeHome` factory derives the native scope/transaction/reservation hash, and the actual private `AuxNativeTaskLayout.acquire(create:false)` validates exact reservation bytes, policy hash, home metadata and topology. No target write, key, caller-selected map or journal reinterpretation is added. Native policy/peer/generation/crypto validation, create/reopen codecs and receipt formats remain unchanged. It does not adopt old state or repair partial installations.

`check.py` uses the existing `/usr/bin/swift` interpreter. It executes the actual retained-home/task codecs, private owner constructors, binding logic, inventory and filesystem methods on synthetic private directories. Only the policy/identity context is an explicit immutable fixture adapter; real signatures and peer authority are not claimed. The old order is reproduced with the actual browser marker preparation region: it creates two markers before unknown-Control refusal. In the successor, six unknown/malformed/partial control/task cases preserve every relative name and raw byte; an actual matching synthetic pair and an empty fresh pair both pass the read-only preflight without mutation. No hash was shimmed; actual CryptoKit scope/reservation hashing runs. Independent patch application reproduces both output hashes.

The runner writes source/evidence only and creates no host executable; no compiler-default signature is produced by it. No real home, owner profile, credential, native app/daemon, signing/provisioning or OS grant was used. Root still owns complete paired-graph compilation and actual approved installation/reopen testing. This fixes the known record-ordering defect; it is not a general migration grant or a claim that unrelated same-user processes cannot race filesystem names.
