# Defer child retirement from the native closing callback

One counted-line successor to A32, before A32 projection. `AuxProfileMenu::OnOrdinaryWindowClosing()` may run inside actual native Widget/activation observer iteration. It must not synchronously destroy the child Widget/delegate under that stack. The callback now invokes `RetireAuxProfilePopup` (disable/hide, remove the exact registry owner and DeleteSoon); the parent destructor alone retains `DestroyAuxProfilePopup`. No other source byte changes.

The actual pinned Chromium implementation supports the deferred child lifetime: `CloseOnDeactivatePin` retains a `WeakPtr<Pins>` and its destructor calls `RemovePin` only when that weak owner still exists (`bubble_dialog_delegate_view.cc`452–462). Therefore a deferred child close callback may release its pin after the parent delegate has died without dereferencing the parent. `AnchorWidgetObserver::OnWidgetDestroying` resets the actual widget observation, then calls `OnAnchorWidgetDestroying`, which clears its anchor via `SetAnchorView(nullptr)` (319–327,702–704); `AnchorViewObserver::OnViewIsDeleting` also clears the actual anchor before its view disappears (243–248). No observer is inferred closed from a timer. A32's actual child command WeakPtrs are invalidated at the beginning of the parent destructor.

The closing callback copies its pending action into the existing weak browser/Profile plus cookie-epoch continuation before clearing the child handle and before retirement. After the child is retired it uses only its local runner/action; the eventual `RunProfileMenuAction` rechecks actual sender/Profile/epoch, browser-close state and profile restore state. This successor does not weaken or change those exact bytes, does not dispatch from an old raw parent pointer and does not introduce an extra action.

Focused checks independently apply the one anchor and reproduce the output SHA, verify the callback contains only deferred child retirement and retains post-retirement task ordering, and check the same pinned native pin/anchor implementation. No native build or app/helper execution occurred. Root still owns compilation and the actual parent-with-open-child close journey. No fixture executable, signing, owner-state read, OS grant or UI/style change.
