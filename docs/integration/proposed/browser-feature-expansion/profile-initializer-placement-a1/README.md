# Fresh identity initializer native ownership

The profile identity core target is a low-level source set used by profile/account code. Its declared dependencies do not include the full browser UI target. Completion A2 put the genuinely admitted fresh initializer there and introduced an upward include/call to the UI lifecycle owner. A successful full link would not make that source dependency appropriate.

This exact two-file overlay moves the complete initializer body, byte for byte, into the existing `profile_gate.cc` implementation. That file is already implemented by the full UI target behind an interface-only `profile_gate` target. The read-only ID lookup remains in `profile_identity.cc`; its UI include is removed. Public declaration, return values, admission checks, original PrefService writer, callers and UI behavior are unchanged. No GN edge, authority event, retry or readiness claim is added.

`source-plan.json` records four count-one anchors and exact before/after hashes. The combined overlay retains all87 changed/367 selected A3 source inputs except the two reviewed outputs. No native checkout mutation occurred during preparation. Focused two-owner compilation is serialized behind the current full build. Later projection/build/package must use this successor before calling the source dependency complete. The earlier linked browser remains historical rather than silently acquiring this source correction.

No product lifecycle, native command, signing/release, owner profile or provider operation is performed.
