# Retain the remaining sidebar popup delegates

One native source successor, pinned to the actual selected `aux_sidebar_view.cc` SHA7e47702c3a4df0aa6fa4e981fe79c50f2f58632e1da7fc6f65a514fb12a88dcc. It changes only ordinary-build popup lifetime handling; no component, layout, icon, typography, theme, profile binding or action model is replaced.

The actual Chromium ownership implementation confirms a concrete defect: `BubbleDialogDelegate::CreateBubbleDeprecated(unique_ptr, ownership)` calls `.release()` and its non-View `WidgetDelegate` defaults `owned_by_widget_` to false. The supplied primary menu already has an explicit client owner, but the bookmark child, profile-actions child, indicator menu and icon popup still use the releasing overload. Their delegates are not destroyed at native close. Apart from retained rows and parent-deactivation pins, the indicator stores its actual icon/settings/sign-out dispatch in a destructor continuation, so leaking the delegate prevents that continuation from running.

The successor reuses the primary menu's actual client-owned Widget-before-Delegate container for the indicator root. A separate exact-Widget registry holds the child delegates and widgets. Native close retires that exact owner, disables/hides its rows, and defers destruction out of activation/close callbacks. Parent teardown destroys its current child Widget and then delegate before the parent row/delegate disappears. Retired child command callbacks hold the actual parent WeakPtr instead of an unretained parent pointer, and the primary invalidates those weak callbacks at destruction. The icon grid already uses its parent WeakPtr. All profile/source-cookie-epoch and posted-action checks stay intact.

There is also a confirmed retirement mismatch in the existing primary pattern: `Widget::CloseNow()` bypasses `MakeCloseSynchronous`. Ordinary top-level menu retirement now calls `Close()`, allowing the actual retained owner's exact native close callback to run. Nonordinary builds retain their original native-owned creation/retirement paths.

`check.py` verifies12 counted anchors reproduce the exact output hash and pins the actual Chromium bubble/widget ownership implementation. It compares existing style-call/value lines byte for byte, checks all four ordinary owner sites, verifies Widget destruction precedes delegate destruction, and preserves the actual profile/dispatch-fence counts. This is source evidence, not a runtime or compiler claim. No fixture executable was created. Root owns the affected native object/full app compilation and a focused real-app journey: open/close bookmark/profile-action children, indicator icon popup and selection; retire the parent while a child is open; then verify profile/settings actions and stale profile menu refusal. No broad suite is needed.

No shared native file was mutated, app/helper was launched, owner state was read, new signature was created or release/OS grant occurred.
