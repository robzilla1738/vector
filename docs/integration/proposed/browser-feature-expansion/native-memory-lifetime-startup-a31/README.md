# Prior memory-helper lifetime checks before ordinary startup

This is a two-file successor to the A30 actual native TaskLayout/ColdGuard sources. It does not enable a helper, alter the accepted UI, migrate records, or grant task/readiness authority.

`AuxNativeTaskLayout.requireNoUnresolvedMemoryHelperLifetimes()` is called only from startup's existing-pair preflight. It reads the fixed `.aux-memory-helper-lifetimes.v1` directory under the actual retained TaskLayout task home. Every record must match the actual private task reservation's control scope, transaction, reservation SHA and policy SHA. The reader verifies private directory/file metadata, no ACLs/symlinks/hardlinks, canonical UUID filenames and exact schema, at most256 records and16384 bytes each. It checks named identities, stable file metadata and repeated directory inventory. It never creates, repairs, expires, removes or replays a record.

The schema is frozen with the native helper producer lane: `aux.memory.helper-lifetime.v1`; native lease UUID; actual scope/transaction/reservation/policy hashes; captured nonzero transport generation; canonical account ID including0; account incarnation/profile UUID; profile-path and account-record hashes; actual daemon/browser PID+birth tuples; and phase. `spawned` adds the helper tuple. `reaped` additionally carries actual signed32-bit raw wait status. `not-spawned` carries a positive signed32-bit spawn errno without a helper. Unexpected fields, noncanonical numbers, missing data or unknown names refuse. Process tuples and other record fields are data, never grants.

A `prepared` intent without a PID is unresolved even if its old parents have exited: a successful suspended spawn could have happened before publication. It always refuses. Other valid records yield native process queries. Startup requires the existing actual `AuxOrdinaryPriorBrowserHasExited` primitive to return1 for the old daemon and browser, and for the exact recorded helper when present. A live or uncertain result refuses, including for a `reaped` record. This relies on the paired finite helper's actual sandbox forbidding fork/other execution; it is not generic descendant custody. Kernel process absence is never mocked in the fixture.

The first observation occurs before browser lease marker acquisition. A second full existing-pair preflight runs after the actual installer flock is held, before the native guard can return, so a prior legitimate daemon cannot publish another helper between the preliminary inventory and new ownership. Current-owner normal revalidation is intentionally unchanged: a running helper must not invalidate its own daemon. Missing lifetime directory means no producer journal exists; it is not independently a startup admission proof. All existing signature/peer/root/install/auth/crypto checks remain mandatory.

The paired producer must durably create the intent before `posix_spawn`, use `POSIX_SPAWN_START_SUSPENDED`, publish actual native PID/birth durably before `SIGCONT`, and mark terminal only after its original waitpid, three parent stdio closures and thread join. Any interrupted atomic temporary file refuses. The readonly consumer has no GC; reaching256 retained records safely refuses additional inventory. A separate exact terminal cleanup policy would be needed for indefinite use and must not delete unresolved intents.

`check.py` executes the unchanged actual decoder and filesystem reader with the existing Swift interpreter on18 synthetic cases: missing/empty journals, account0 spawned/reaped/not-spawned, unresolved prepared, duplicate/malformed/unknown fields, wrong root binding, invalid process birth/canonical numbers, unknown atomic temporary names, symlink and unsafe modes. Every synthetic name, mode and byte remains unchanged. It typechecks the same generated single source without producing a host executable. It does not include or replace the native process observer and does not claim actual kernel/helper behavior. Counted patch application must reproduce both output hashes.

Root still owns paired full-native compilation, producer registration/callback custody verification and any separately approved disposable helper/reopen checks. No helper/app launch, real-home/owner-state read, credential access, signing, provisioning, OS grant or release occurred in this slice.
