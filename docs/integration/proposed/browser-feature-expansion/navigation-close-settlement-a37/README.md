# Preserve accepted native close through actual storage settlement

This fixes an independently demonstrated drop in the existing close continuation. `HandleClose` posts archive work, but `ArchiveEntry` refuses immediately when the organization store is pending; its callback only notifies the UI. The close intent is lost. Native dialog dismissal can reactivate the browser, whose existing activation observer starts a `RecordActivity` write before the accepted ClosePage acknowledgement returns. A normal live row can then remain indefinitely without being archived. The actual next app check must confirm the new bounded status trace; the source audit does not claim that this race is the only possible runtime refusal.

The same controller now retains that exact continuation while genuine storage is pending and resumes it through the existing `ObserveSettled`/`QueueReconcile` path, before starting more maintenance writes. It retains the actual TabHandle, WeakDocumentPtr, view document identity, committed URL, weak Profile, logical identity and organization generation. Every fact and current protection is checked again. Changed/retired documents are refused; there is no timer, storage-success flag or invented readiness.

The initial native unload delegation from A36 now also works while storage is pending. It continues the ORIGINAL native beforeunload before any durable archive, so Cancel leaves the live logical record unchanged even in that state. A posted continuation that discovers a new unload obligation refuses instead of archiving or replaying an acknowledgement. Only unchanged no-unload/accepted native work can wait for storage and continue. Lifecycle retirement and actual tab removal drop the retained intent without closing a page.

`CloseViewNow`, `ArchiveEntry`, automatic cleanup and creator-protocol owners remain unchanged. Pins/retention and other protections are reread as before. Status-only logs distinguish deferred storage, settled continuation, identity/organization/unload refusal and membership-save result. They contain no URLs, profile IDs, content or credentials. UI and all native admission guards remain unchanged.

`source-plan.json` pins the two actual A74 controller preimages and exact successors; `native.patch` and full output sources are supplied. `python3 check.py` passes counted replay, original-body preservation and focused continuation ordering checks. No native tree, build, app, state, signing or provider execution was performed here. Root owns projection/A75 compilation and actual Cancel/Leave/close checks. Historical Recovery data is not deleted or automatically settled.
