# Match the actual Node Environment layout during peer-loss shutdown

The scoped daemon report `aux-daemon-2026-10-25-211547.ips` identifies PID54743, parent54721, with `EXC_CRASH/SIGABRT`. Its faulting thread calls `ReadyPulse` → `RequestPeerLossShutdown` → inline `Environment::SetImmediateThreadsafe` → `uv_mutex_lock` → abort. The main thread is still inside `SpinEventLoop`; the report does not support a claim that CommonEnvironmentSetup had already been destroyed. Browser exit0 and stopped process group therefore did not prove a clean daemon exit. Only the exact matching report was inspected; `scoped-crash-evidence.json` preserves its hash and minimal PID/frame facts, not register contents or unrelated reports.

The actual failed main object addresses the private native-immediate mutex at `Environment+0x968`, as its arm64 disassembly shows. The actual `env.o` extracted from the linked `libnode_base.a` declares that field at `+0xa18` in its DWARF. The old compile additions were taken from `libnode.target.mk`, a snapshot target, rather than `node_base.target.mk`, which actually owns `src/env.o`. The latter defines `HAVE_INSPECTOR=1`; inspector-dependent Environment fields account for the layout difference. The pointer belongs to the existing live Environment, but the inline accesses the wrong part of that owner.

This repair changes no runtime shutdown behavior. The one-counted-anchor source successor adds a compile-time guard requiring the actual linked inspector layout before including private `env-inl.h`. It preserves the original actual listener lookup/dispatch, failure recording, Stop fallback, retained Environment/setup and native thread joins. It neither replaces the shutdown architecture nor enables an inspector endpoint. The actual linked Node library already has that configuration.

The main compilation now uses the pinned actual `node_base` Release defines and required include directories. DWARF is emitted for independent verification. Before linking, the build compares ten relevant Environment member offsets from the newly compiled main object against the actual linked env object: isolate data, async handle, stopping/call-into-JS flags, native queues, their mutex, async initialized flag and principal realm. Every offset must match; the verified mutex is `0xa18`. The actual field output and `actual-layout-match.json` are retained. No host executable fixture or product execution is used for this check; it reads existing/new compiler object metadata.

Only `main.o` is recompiled. The exact successful A66 link changes only that object and the fresh A67 output. All50 Swift sources, A65 diagnostics/policy,14 other native objects and the proven A66 ordinary storage includes/worker object remain unchanged and pinned. Root's native-build lock covers compilation and linking, with `-no_adhoc_codesign` retained. The output is inspected as unsigned arm64 Mach-O. Failed old source/object/binary bytes are not modified.

No app/helper launch, signing, root/Keychain access, owner-state change, UI change, OS grant or release occurs. Actual normal Quit and peer-loss behavior still require root's separately approved corrected candidate observation. Compilation/layout agreement alone is not runtime acceptance.
