# Ordinary local CLI URL/profile routing — A29

The packaged narrow native CLI currently always calls the privileged Mach receiver, which is intentionally disabled in ordinary mode. The app already registers aux:// and its real LaunchServices handler already stamps one-use native external receipts. The native routing owner already resolves exact profile UUIDs/unambiguous names and gives explicit selection precedence over rules.

The ordinary terminal-only CLI now uses LaunchServices to send one bounded aux://open envelope to the exact Aux.app containing its own canonical executable. It does not spawn Node or a shell, execute an Aux task, read Local State/profile files, alter keys/installation state, invoke a generic helper or enable the privileged receiver. The existing retained native-parent endpoint role still refuses. Root must add AUX_BROWSER_ONLY_NATIVE_STARTUP=1 and AppKit.framework to the existing native_cli_open target; no app metadata change is needed.

A shared bounded pure-data codec preserves URL/profile bytes and rejects unsupported outer/inner schemes, duplicate/unknown/encoded keys, credentials, malformed percent escapes, raw plus ambiguity, embedded NUL, control characters, profile paths, fragments on the outer envelope and oversized fields. The actual browser receiver additionally checks GURL validity, HTTP(S), UTF8 profile text and no credentials. Only a genuine native OS receipt can enter this path. Explicit missing/ambiguous destinations are consumed with the existing native warning; they never fall through into another profile. Without explicit selection or a matching rule, only the decoded HTTP URL falls back to the original native opener/Profile, with its receipt cleared.

CLI exit0 means LaunchServices queued the request for browser validation. It is deliberately not a navigation-success receipt. OS dispatch failure and unknown bounded wait have separate exit codes; an unknown result may still arrive later. Missing/ambiguous destination errors appear in the native browser. Cold startup still requires the existing authorized app launcher/native admission, and arbitrary installation/task commands remain unavailable.

Four source owners/fourteen counted anchors, no UI/style/permissions change. Exact replay passes. The actual C++ codec fixture and finite receiver cases are supplied unrun; root owns their focused execution, compilation/pairing and one queued/destination real-app check. This lane performed no app/helper launch, native build, signing, provider or owner-state operation.
