# Official ChatGPT plan source integration — 2026-10-23

This slice replaces the supplied daemon's legacy ChatGPT connection path while retaining its connection dialog, OAuthFlowManager public status contract, provider ID and model-picker renderer. No CSS, geometry, logo, accepted app or owner state changed. It is source integration, not real account or inference acceptance.

`vendor/aside/shims/aux-chatgpt.cjs` implements Aux dynamic registration and a stable host ID; exact IPv4 loopback callback, state, nonce and S256 PKCE; issued-client persistence before exchange in a separate unconnected registration; RS256 signature/JWKS and issuer/audience/azp/time/nonce/subject validation; returned plan-scope validation; per-local-account registration/session records; serialized rotating refresh; cancellation and local-session checks before persistence; and remote revocation support. Generic provider credentials cannot install a ChatGPT token set. A returned status contains no tokens.

Credentials live under `$AUX_HOME/local-only/chatgpt`, outside account roots and their file-sync watchers. Files are atomic owner-only JSON; parents reject symlinks, unrelated owners and nonsticky group/world writes; reads use nofollow/nonblocking descriptors and fstat; lock contention across processes refuses. Tokens are not encrypted at rest beyond filesystem protection. This follows the official local-file storage contract and makes no Keychain/encryption claim. Legacy synced credentials are ignored for this provider and left intact; they are not migrated, deleted or silently reinterpreted. The existing sync format is unchanged. Credential enumeration exposes only ChatGPT type metadata, not its tokens. Low-level local deletion cancels attempts and clears tokens; it is not evidence of remote revocation. The actual settings disconnect RPC now awaits ModelsManager removal, which awaits async logout/revocation. It removes local provider configuration and reports a truthful error if remote revocation was not confirmed, directing the user to ChatGPT Settings. Real dialog/RPC acceptance remains pending.

The provider uses the supplied public OpenAI Responses implementation, forces `store:false`, `stream:true`, zero retries and the exact public endpoint. A streamed response must contain `response.completed`; incomplete and interrupted streams fail. The account catalog uses public `/v1/models`, preserving visible slug/name order and refreshing against the selected token. Unknown catalog models use conservative text-only 8192 context/4096 output limits until documented capability metadata is integrated. The old private usage request is disabled, not fabricated; a future usage UI can link to ChatGPT Settings. The unintegrated legacy ChatGPT image capability is suppressed from its provider model list, and both the provider API and underlying legacy driver refuse before any private transport. Other supported BYOK image providers remain available. No public-plan image support is claimed.
