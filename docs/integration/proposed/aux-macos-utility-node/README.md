# Five-command macOS module and paired daemon routing

This inactive source integration separates the actual five nonprotected Mac utilities from the original installation/credential addon. It reuses the existing `AuxMacOSUtilityCommandCore`, `AuxAppKitUtilityBoundary`, `AuxOSJobCustody` and callback mechanism without rewriting their method bodies. It changes no UI, state2 refusal, protected owner, credential policy, shared pipeline, package, native checkout or permissions.

## Actual native module

The production Node-API8 initializer constructs a **specific utility-only host for the actual Node Environment** and registers only `run(command,input)`. Construction performs no OS operation or grant. No installation core, generic command owner, protected factory, Security adapter, arbitrary core/scope callback, JS enable switch or environment flag is linked. These five utilities do not need installation/cohort authority. The normal require→run interface is preserved; real clipboard/open/QuickLook/file access still has the original caller-context and OS-access requirements.

The immutable Swift producer owns only the existing five-command core and actual AppKit boundary. Recognized calls return JSON **text**, not a Promise/object. Missing command throws the original TypeError; omitted input is an empty string. Invalid types/NUL inputs refuse without coercion. Unknown commands return an error and never reach a protected route. No password-manager, key, secure-store or PDF operation is exported by this module.

The actual C++ host independently observes the current V8 isolate, Node Environment, NAPI event loop and actual callback Environment before attachment. It reserves each real Environment generation once, installs cleanup before constructing the utility owner, and owns the exact callback data through cleanup. Host closure refuses new calls and retains admitted calls. No host/registry mutex crosses a Swift owner/effect callback or publication. A failed or closed late attachment stays retired rather than becoming a live capability.

Cleanup closes utility admission and consumes the actual OS custody result. Pending/dropped/timed-out callbacks are not treated as completion: the exact owner is retained in a process-native quarantine after worker teardown until explicit native closure can observe drain. No timeout, cancellation, destructor or worker exit invents a drained receipt. The host retains its exact already-loaded code image using native `dladdr`/`RTLD_NOLOAD`; it never loads a caller-selected image or unloads code behind outstanding callbacks. This is image lifetime custody, **not** signer authentication or whole-profile exclusion. The initializer's own host cleanup and per-Environment worker cleanup are paired. Native host methods remain native-only; production JS exports no close/enable/handle operation.

## Paired actual source transformation

`source/adapt.mjs` authenticates the exact current staged **SEA code and Node-development source separately**. Each layout applies eight count-one changes: insert the fixed five-command selector/loader; route synchronous run; route async run; pass the selected binding path to actual child workers; and update four OS-specific availability guards. The inserted paths use each layout's actual Resources convention. Only darwin + one of the five exact names uses `native/aux-macos-utilities.cjs`; all other commands/platforms retain the original common loader. Utility load failure has no protected-addon fallback.

Actual daemon async workers still perform their supplied require→run→JSON post behavior. They now receive the selected fixed utility loader path and instantiate their own utility Environment host. Main-thread-only attachment is insufficient and is not the implementation here. PDF's nine call sites and independent loader are untouched. Four first kilobytes, including the unconditional first state2 refusal/preloads, remain byte-identical; the complete reviewed source hashes and all count guards fail closed on drift. The adapter is not imported by root staging yet.

`createMacUtilityLoader` emits a fixed sibling loader with the reviewed concrete image hash/size, regular/non-shared-writable/single-link checks and before/after metadata/hash checks. It takes no runtime environment path. Root must build/register the actual output and pin its bytes when integrating; the generated loader does not itself prove bundle-signature or all-writer custody. This lane has not changed root's packaging/artifact manifest.
