# Native fixed-image utility closure successor

This successor adds exactly two **native C exports**, with no JS lifecycle export:

- `int32_t AuxMacUtilityCloseAdmissionAndDrain()`: permanently closes this loaded image's utility Environment admission, then consumes actual closure for every retained native owner, including post-cleanup quarantine. Returns0 drained,1 pending,2 untracked,-1 wrong process. It never reopens or unloads the image.
- `uint64_t AuxMacUtilityPendingEnvironments()`: observation of retained owner/active-call/initializing/draining Environment records, including owners quarantined after cleanup. Returns UINT64_MAX for wrong process. It does not close, poll/wait, release or invent callback completion. Before closure, an open owner is also counted; zero alone is not an admission-closed receipt.

The image captures `getpid()` at native image initialization (`kImageProcess`), before any first command or pending observation. An inherited already-loaded image therefore refuses exports/attachment/run before accessing inherited mutexes or native owners. This is a load-time PID boundary; it does not claim an image loaded for the first time in a child was previously bound to its parent. No actual multithreaded Node fork was attempted.

Permanent admission closure and new Environment reservation share the same registry mutex. Already-reserved/initializing owners remain pending, cannot publish successful late attachment after closure and retain ownership until cleanup/actual drain. Ordinary Environment cleanup remains local and does not close unrelated future Environments; only the explicit image-wide native export closes global admission. Closure copies retained owners before entering them and holds no registry lock across Swift/OS custody callbacks. A concurrent drain reservation/release remains counted until it unwinds. Unknown/untracked outcomes never become drained by timeout or destructor.

The focused changed-boundary fixture uses real frozen Node main/worker Environments and captured Swift OS effects. It terminates a worker with a genuinely pending custody token; the image native export observes that post-cleanup owner, closes the live main owner, retains pending work, refuses future workers before factory creation, then observes explicit late completion and releases the quarantined owner. Repeated closure remains closed/drained and future worker attachment still refuses. This fixture does not repeat the previous18 native route cases or14 wrapper cases. Its additional fixture-only JS methods are not in `source/utility-module.cc`.
