# Canonical fresh-parent parser successor

The previous pure policy decoder used Foundation `standardizedFileURL.path` as a lexical-canonical test. A real disposable existing directory demonstrated that macOS changes a genuine `realpath` `/private/var/...` name to `/var/...`, rejecting the exact parent required by the authenticated FD reader. This is a real admission failure before protected effects, not evidence that a signed policy was loaded.

Select this proposal's `source/AuxFreshBootstrapPolicy.swift` instead of the historical same-named source. Do not compile both. The only production change adds bounded absolute lexical component validation (no root, empty component, dot, dot-dot, NUL or trailing slash) and uses it for the parent decoder. The actual signed-resource authentication, access group/role/image restrictions, historical-scope exclusions and live reader remain unchanged. Pure syntax deliberately cannot establish symlink/canonical/private ownership; the unchanged live reader still requires realpath equality, private FD metadata and retained identity before creating the fresh home. No authority is granted by decoding JSON.

The final 23-input graph in the cohort-lease proposal remains a truthful historical check of its original policy source. This successor was compiled only with the actual envelope parser and changed policy, then executed against one disposable directory and malformed labels: 14 checks passed. No signed reader, Security query, generation, startup, owner state or UI was executed. Current selected-policy paths and existing formats are unchanged. Future combined graph must explicitly select this successor; it has not been claimed as production startup acceptance.
