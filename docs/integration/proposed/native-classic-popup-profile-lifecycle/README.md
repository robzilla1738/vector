# Idle classic WebUI popup profile lifecycle

Actual586 passes AIM admission and rejects readiness.location.16. Source proves this is the next ordinary155 owner: `omnibox_next_features.cc:48` enables kWebUIOmniboxPopup by default, and LocationBarView::Init constructs OmniboxPopupViewWebUI under the dropdown-only branch. Previous admission categorically rejected the enabled feature. This proposal handles the real owner; it does not disable the feature, bypass profile guards or substitute legacy popup UI.

## Ownership and transaction

LocationBar tracks a raw pointer set exclusively by the exact classic-dropdown constructor. Full-WebUI, BrowserView, debug and legacy variants are not downcast or assumed equivalent; full/browserview flags retain their previous rejection. Clear that pointer before popup destruction.

The classic view remains alive throughout the transaction, preserving OmniboxEditModel's popup_view pointer and the controller/edit-model identity. Admission requires no edit in progress, settled autocomplete, popup-state none, an observing model, a hidden/nondeferred presenter without pending widget deletion, permission work or blockers, and no content context menu/file chooser. A separate file-picker pending latch covers the case where deactivation-blocker feature is disabled. Any media-requested content remains conservatively rejected because this owner lacks a media session completion signal. Fixed diagnostic stages identify each model/state rejection. A closed ordinary URL dropdown can therefore switch after navigation; prior use or selection is not itself a permanent blocker.

Prepare occurs only after global preflight and LocationBar's pause begins, before controller/provider replacement. It pauses the classic view, resets its edit-model observation, then destroys its presenter synchronously. The original base presenter destructor ReleaseWidget drains the widget deletion queue. Its content owns the original WebUI wrapper, Mojo handlers, tab listener, location observation, weak callbacks and source-profile WebContents. WebuiOmniboxHandler's ScopedObservations therefore retire before OmniboxController::RebindClient destroys the source AutocompleteController.

While paused, IsOpen returns false and UpdatePopupAppearance/selection entrypoints return without accessing the absent presenter. Model identity stays live so normal native draft/selection/IME SaveStateToTab on source tab deactivation is preserved. Full-popup SaveState is not admitted. `presenter()` returns null, consistent with the existing interface's legacy default; source callers check it.

End reconstructs the exact original OmniboxPopupPresenter against the now coherent LocationBar profile and controller, then reconnects the original edit-model observation. Abort already restores the source client/prefs and calls the same End, so it recreates source ownership rather than target ownership. Layout and renderer-load callbacks can be canceled by owner destruction; active context menus/files/permissions cannot. The content's is_shown flag is intentionally not treated as proof of user use: it is the WebUI host readiness signal, whereas presenter's Show and actual visibility track user presentation.

### Ordinary navigation completion proof

OmniboxPopupPresenterBase::Hide resets permission observation/prompt handling, clears deferred state and invalidates visual-state callbacks, hides the widget and detaches/clears its content. The existing deletion queue must drain before idle admission. Classic WebUI owns display/results handlers, while native OmniboxEditModel/OmniboxViewViews retain draft and selection. OmniboxViewViews::SaveStateToTab confirms/cancels IME, gets the real model state and saves model+selection under OmniboxTabHelper's per-tab key. Existing LocationBar transaction verifies that save occurred before replacing the client; this proposal neither resets the model nor invents the save. RebindClientForAuxProfileSwitch keeps the edit model alive and recreates only client/autocomplete services. Pausing the popup observer and destroying source WebUI before this operation prevents dangling autocomplete observations. Commit and rollback both resume against their coherent actual profile.
