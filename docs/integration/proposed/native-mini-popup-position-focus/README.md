# Supplied main popup placement and explicit-close focus

Proposal only, no native build/launch/signing or OS focus operation executed. Incremental **after native-mini-popup-options**: C++ baseline is exactly`940de3c895cc0e987c0c9e6540e826f3fa4df0c8a69bb085f75fca441453efdf`, mac baseline is the unchangedv32`cf32406e6f70ec75ab60bb1d2853e764e0b339055b5eedd5fc86439aa6bd77b0`. Two output sources, exact pins and replay patch are included. There are no new GN dependencies or shared source edits, and the `switchProfile` branch is unchanged.

Original04598240 selects the display nearest the **cursor**, places the new popup at horizontal center with its top one third down that work area, then fits it to that area. Aux currently picks the display nearest an unplaced widget and recalculates quarter-height placement on every composer resize. The proposal restores initial cursor-display placement. Its main size updates use original04596d1c's current-window center expression and fit the nearest-center display; adding an attachment no longer moves the entire popup back to a guessed screen anchor.

Original045983e0 remembers the application's prior key window once before popup activation, only if the app was already active, using a weak reference. Original045965a0's explicit `RequestHide` clears that capture, verifies the old window is still visible and can become key, and makes it key before hiding the popup. Blur dismissal is a different path. This proposal mirrors that separation: explicit close/Escape/main `window.close` invokes restoration; automatic blur/profile teardown/settings-disable hides clear the capture without stealing focus back. Destroying the widgets also drops the weak capture. It never activates another app or retains an owner document/window beyond the weak native reference. Chromium's inspected macOS defaults already enable ARC; no build configuration change is needed.
