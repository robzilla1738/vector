# Actual remaining common-addon surface — source-only map

This audit reads the current `out/provided-reuse-aux-crypto-stage` daemon, daemon/CLI `native/aux-native.cjs`, independent PDF loader and current native proposal sources. It executes no supplied code, addon, protected operation, OS action or heavy reverse-engineering job. UI is unchanged. `source-map.json` pins all14 inputs, exact wrapper anchors and literal call sites with character/UTF-8 byte offsets and bounded context. The standalone `native.mjs` leaf is **not present** in this actual stage: its common-binding wrapper is bundled in daemon `init_src$6`.

## What the actual staged loader still does

`candidateBindingPaths()` returns only fixed `native/aux-native.cjs`. `loadBinding()` caches that require. The shim loads the existing native guard and role-pinned **provided-native.node**, then exposes the original exports; this is still the original common addon, not the own command core. Its load-only branch registers exports but refuses commands. Existing explicit execution refusal and state2's first unconditional refusal remain. No own protected host is activated.

`runNativeHelperCommand(command,input)` calls `JSON.parse(binding.run(command,input))` synchronously. `runNativeHelperCommandAsync` creates a **new actual Node Worker**, passes that same loaded shim path, requires it again inside that Environment, calls `binding.run` and posts the output JSON string. It then terminates the worker after response/error. Replacing only the main-thread module or attaching only one Environment would break thumbnail/secure-store callers. Worker factory/cleanup/pending native ownership must be paired; `loadedBindingPath` is not a process-global capability. The current WorkerHost has that actual lifetime model, but its trusted producer/whole-cohort admission is not active. The old direct attachment export now refuses and must not be reused as a shortcut.

## Best next substantial local source lane

The useful Mac lane is **paired OS route/Environment integration**, not another method-body port and not a new generic owner constructor. Preserve the actual `run(command,input)`→JSON-string interface and Windows/platform guards. Route only the five inventoried Mac commands, pair main-thread and actual child-worker module initialization, and preserve genuine native cleanup/OS pending ownership. The existing exact typed utility capability and WorkerHost ownership rules should remain the basis; do not inject arbitrary cores or let JS select scope/authority. Any implementation that still invokes the protected signed owner before real cohort admission must remain inactive. A bare module initializer or reuse of the retired direct attachment cannot complete that boundary.

Without protected execution or OS effects, the next pass can finish/review the paired source transforms and captured real-Environment fixtures against existing typed native utility/lifetime code. It can compile the actual AppKit boundary and verify JSON/error/async-worker behavior with captured OS callbacks. It cannot truthfully finish authentic startup, real OS acceptance, remove the common addon from the whole product or declare app readiness until the shared trusted bootstrap/custody dependencies are solved. If an independent utility-only module is considered later, it must be a specific five-command capability with explicit Environment/async lifetime, not a generic alternate owner or silent bypass of current WorkerHost restrictions; that architecture is not introduced by this audit.

The original common addon/interposer therefore remains **unretired** for both daemon and CLI. PDF separation and compiled own implementations are concrete progress; none is proof that the staged run wrappers have switched.
