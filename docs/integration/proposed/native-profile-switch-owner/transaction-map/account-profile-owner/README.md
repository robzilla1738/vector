## Original selection and effects

`4160ce0` and its actual helpers select an existing binding by canonical profile UUID then exact path, otherwise saved user, otherwise a real saved account row's user. Automatic binding requires the exact last-used **already-loaded** profile, real persisted-session or paused auth, actual nonempty email/user, and no existing registry or other loaded-profile claim of that user/account. A missing bound account is not replaced with the current account. A disconnected unclaimed account clears the binding; a disconnected registry-bound account retains its identity while clearing session presentation. No tokens enter the projection result.

The owner preserves the distinct original global-completion and legacy per-profile-bootstrap predicates. The existing bootstrap evaluator is factored without changing its public policy; a separate legacy export supplies the updater's original predicate. Global completion is only written true from actual parsed completion, not inferred from local/anonymous mode. Auto-binding preference/setup effects precede the common bootstrap branch as in the supplied callback.

Actual attributes use `SetLocalProfileName(GetLocalProfileName(), true)`, real GAIA display/given-name fields, and empty-GaiaId `SetAuthInfo` with the actual email; no Google identity/consent is fabricated. Avatars use the real `ImageFetcherServiceFactory`/network-only fetcher, valid original URL admission, source URL completion guard, actual storage cache/picture tests and exact owned-picture cleanup. A picture belonging to another account/provider is not cleared. The tiny `ProfileKey::HasPrefs()` accessor ports the original reduced-profile readiness check without peeking into private fields or calling a DCHECK-ing getter as a probe. Real initialization completion retries persisted account presentation.

The real SyncPrefs/SyncService effects are preserved: source-account bootstrap token removal (or original legacy-global token clear without a user), conditional per-account dictionary clear after setup completion, cached-passphrase-type clear, and real initial setup completion only in the authenticated/paused-account presentation branch. The original full clear branch resets sync independently of the bootstrap true-to-false reset. These are actual profile service effects, not gate authorization or fabricated remote sync results.

Actual binding POSTs use the original `/accounts/profile-binding` and `/accounts/profile-binding/delete` bodies and current installation authorization from the real native supervisor. The requester has fixed loopback routing, exact Aux port selection, omitted cookies and forbidden redirects; it never manufactures authorization or treats an unavailable request as success. Its completion does not mutate a deleted Profile. Actual profile removal may legitimately cause the supplied daemon's real binding-removal effects; this proposal does not simulate them.

## Real startup authorization boundary

The existing supervisor writes the actual nonempty `AsideDaemonSessionToken` header and expiry before `SetState(kReady)`. It also reports `kReady` on health polls, so readiness alone cannot trigger an authorization claim. The narrow `BrowserPlatform::ObserveDaemonAuthorization` callback list notifies only a transition to **both** real ready state and a genuine nonempty exact-prefix snapshot. It does not perform a new handshake, sign anything, expose a token to observers or call listeners inline while subscribing. Each updater stores a weak subscription; its initial real registry read covers subscription after authorization. A real later authorization transition rereads current account state and retries only genuinely needed binding writes.
