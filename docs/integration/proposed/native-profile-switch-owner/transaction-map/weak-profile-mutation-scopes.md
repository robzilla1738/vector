# Destruction-safe newly introduced profile mutation scopes

This is a pinned followup to the precise previously delivered proposal outputs; it does not silently rewrite those artifacts. The manifest lists 14 exact baseline/output SHAs. Apply after Skills/Toast, TabStrip client guard, Download source rollback, Cookie coordinator, ContextHighlight and Avatar state manager proposals.

The new member AutoReset counters were unsafe if a real nested menu/action/observer callback destroyed its window. AutoReset would write its referenced member while unwinding after owner destruction. This patch replaces those new depth scopes in TabStripUIControllerImpl, ToastController, SkillsUiWindowController, DownloadToolbarUIController, CookieControlsBubbleCoordinator and ContextHighlightWindowFeature with actual increment plus ScopedClosureRunner bound through a private destruction-only WeakPtrFactory. The leave helper decrements only while that same actual owner remains alive. Every added factory is the final member and is never invalidated for profile task cancellation, so canceling a transient task does not leave a living owner's depth stuck. Existing actual callback/observer/service lists are untouched.

Download's newly introduced rebinding bool uses a weak restore of its real previous value. Avatar's newly introduced prepare initializing bool does too. Its existing InitializeStates scope is now reused by the new profile rebind, so that exact initializing scope also uses weak restoration, with actual owner-liveness checks after CreateStatesAndListeners and each state Init before continuing the loop. The new Rebind checks liveness before its follow-on UpdateAvatarButton. Unrelated upstream updating flags and static test-time AutoReset controls are deliberately unchanged.

This patch removes newly introduced scope-destructor writes through dead members. It does not claim that all existing upstream callback bodies are deletion-safe or authorize broad mutation of their behavior. Actual cold checks and synchronous transaction invariants remain required, and callback-driven deletion still must be reviewed at complete provider level. No permanent callbacks are invalidated by these lifetime factories, no user callback result is fabricated, and no UI/client is closed to obtain a cold state.

Fourteen-file isolated replay and exact output equality passed, with actual shared inputs rechecked unchanged. This is source-only and uncompiled: no native source writes/builds, runtime/owner data, OS grants or credential access occurred.
