# SkillsUiWindowController profile-source audit

This is a concrete remaining binding, not unchanged-safe. Current `chrome/browser/skills/skills_ui_window_controller.{h,cc}` retains the same BWI and resolves SkillsServiceFactory dynamically, but constructor binds PrefChangeRegistrar to source prefs and ScopedObservation to source IdentityManager. It also retains last-saved/deleted skill IDs, pending deletion IDs and v2 deletion callbacks. `OnToastClosed()` and the destructor resolve the **current** Browser profile when deleting those stored IDs. Changing identity with these pending source operations could delete/undo a same-ID skill in the target profile.

Safe narrow stable-controller seam for a subsequent adaptation:

1. Cold Can must reject pending_deletions_, skills_v2_delete_callbacks_, any live skill toast/queued close operation, actual showing SkillsUiTabControllerInterface dialogs in this window, and a scoped mutation callback on the current stack. It must not complete deletions, invoke callbacks with fabricated false/true, close dialogs, reload skills pages, or discard an active user transaction to make the window eligible.
2. Prepare captures the exact source Profile, resets actual IdentityManager observation and PrefChangeRegistrar via `Reset()` (which removes observers and clears its PrefService), then invalidates only those private weak tasks after the actual cold checks. Keep the stable controller and its UnownedUserData registration. Public entrypoints need a generation/prepared guard so stale external source invocations cannot create target actions during transfer.
3. Commit reconstructs the exact existing preference callback and IdentityManager observation using the real committed target Profile, clears source-only last-saved/deleted metadata (not an actual skill deletion), and does not reload/navigate or issue an authentication event.
4. Abort validates the captured source and actual restored source tabs, rebinds the real source services, and retains source metadata. It must work against restored populated source collections.

The current ToastController's IsShowingToast is a real toast-ID check, cleared in OnWidgetDestroyed **after** actual close callbacks and subscriber notification. That is useful but insufficient by itself for a complete reusable Skills cold API because queued next_toast_params_ is private. A concrete source hook on ToastController can expose actual pending/closing ownership state without using test getters. Do not treat `GetToastWidgetForTesting()` or a cleared high-level boolean as a production lifetime proof. The existing pending skill maps protect deletion callbacks; saved-toast action callbacks and the actual shared toast owner still need full cold-lifecycle checking.

Actual source anchors: SkillsUiWindowController constructor, destructor, OnSkillDeleted, ShowToast, OnToastClosed, UndoLastSkillRemoval, InvokeLastSavedSkill and StoreLastSavedSkillMetadata; PrefChangeRegistrar::Reset; ToastController::OnWidgetDestroyed (callbacks before cleared ID, then real queued toast handling). These were read statically; no owner skill/profile data, dialogs, browser execution, or native builds were accessed. No Skills source patch or complete migration claim is made by this audit.
