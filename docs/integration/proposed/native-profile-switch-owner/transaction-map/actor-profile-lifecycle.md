# Actual Actor window/container profile lifecycle

The normal window may create ActorUiWindowController whenever kGlicActorUi is enabled by default. Merely rejecting its presence blocks ordinary idle windows. This eight-file platform adaptation preserves the actual window/contents controllers, same content/overlay views, handoff owner and tab controllers while exposing a genuine cold migration boundary.

## Exact window API/order

1. `CanRebindForAuxProfileSwitch()` checks the registered normal regular window/model and every real tab, not only the visible contents. It rejects an associated ActorTask (including paused tasks), non-default tab UI state, actual pending UiResult completion, scrim debounce/hover, open omnibox popup, posted window/container notifications, current callback stack, actual handoff Widget/delegate/view/hover/focus, and any initialized overlay WebContents.
2. Run this on **all genuine cohort windows after actual caches exist**, before effects. A target cache can contain real Actor work even if the visible source is idle. This follows the same surrounding no-yield/window/profile-lifetime contract as the rest of the proposed synchronous transfer.
3. `PrepareForAuxProfileSwitch()` captures source Profile, resets the actual fullscreen pref registrar and immersive observation, and prepares each stable contents controller. Contents preparation clears only real tab-controller unregister runners and old WebContents/view observations. It does not call SetActorTaskPaused/Resume, CloseUI, finish an animation, or manufacture a UI result to become eligible. Permanent WebView attached/detached subscriptions remain alive with their original weak factory; no permanent callback is invalidated.
4. `RebindForAuxProfileSwitch(target)` requires actual committed regular target Browser/model identity and the real empty model. Each still-empty ActorOverlayWebView calls the existing SetBrowserContext with that genuine target. The same window initializes its real existing immersive observer and Mac prefs::kShowFullscreenToolbar callback against target prefs.
5. `FinishForAuxProfileSwitch()` runs after real target insertion. It restores the stable contents owners through their original OnWebContentsAttached path, using actual present content/tab and normal Actor registrations/notifications. It retains weak lifetime checks between controllers. No synthetic actuation completion is delivered.
6. `AbortForAuxProfileSwitch(source)` works against actual populated restored source tabs: captured source/Browser/model and every WebContents context must match, then real source overlay-context/pref bindings restore and Finish performs original source attachment. No empty-model fiction or post-commit source rollback is claimed.

## WebContents and active-work limits

ActorOverlayWebView constructor stores browser->GetProfile through WebView::SetBrowserContext, then lazy ShowUI creates chrome://actor-overlay WebContents. CloseUI merely hides it; WebContents, WebUI handler, input-ignore and initialization/animation callbacks can remain. An old hidden WebContents is therefore **not** cold migrated or destroyed by this patch. Its presence causes an honest refusal. The real empty overlay context is rebound, so the first later ShowUI cannot create target overlay UI in an old profile. Full initialized-overlay retirement would need an additional real WebUI/handler completion and Mojo lifetime seam; this proposal does not fake it.

Handoff cold checking uses actual owned Widget/delegate/view/observation state, not visibility alone. The existing unregister runner sets its tab interface null then invokes stock default UpdateState. Because cold checking already proved no actual handoff UI/work, this does not close a genuine handoff to gain eligibility or pause a task. Normal Handoff actions and tab callbacks are untouched.

ActorUiTabController's production cold query includes actual UiResult callback work. Existing same-state posted results and ConcurrentClosures completion are wrapped only to track their real lifetime; every original result/callback is forwarded unchanged, even if the tab owner has been destroyed. No callback is canceled or invoked with an invented success/failure. Actual pending work remains ineligible until it completes. The real debounce timer, default UiTabState and profile ActorKeyedService task association are also checked.

Window/container private posts are counted until their original notification runs. Preparation refuses pending notifications rather than invalidating their weak factories, which would silently break permanent attachment subscriptions. During the explicit prepared interval, actual attach/detach and window UI notifications defer observation changes to Finish; no operation-result callback is dropped by those void notification guards. All new callback depth scopes use destruction-only final-member WeakPtr leaves, so nested real UI callbacks cannot unwind into dead members.
