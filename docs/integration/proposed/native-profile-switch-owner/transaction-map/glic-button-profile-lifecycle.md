# Stable GlicButtonController profile sources

Two-file source-only platform adaptation. Compose with the separate stable Split controller/nudge/task-bubble owner port. The same GlicButtonController, userdata, external WeakPtrs, split owner and actual horizontal/vertical view delegates survive; no startup constructor or view replacement is invoked during migration.

`CanPrepareForAuxProfileSwitch()` validates the actual normal/regular window, real model and original Profile/Glic service, actual split/userdata owners, real source pref registrar and its two subscriptions, no callback stack and no actual panel for this window. Split separately checks nudge/task/promo/widget pending work. Preparation captures weak source profile/service identity, resets only the actual old pref registrar and subscriptions, and suppresses ordinary UpdateButton while the graph is prepared. Delegate attachment changes can still update the real outer aliases during toolbar migration; they cannot dispatch a mixed-profile button update.

`RebindForAuxProfileSwitch(GlicKeyedService&)` requires actual target Profile/model identity and an empty model, selects only the real target service, and binds the original pin-pref, allowed-change and global panel callbacks. These registrations are direct CallbackList::Add in the inspected source; they do not issue a synthetic initial update. Finish resumes the unchanged UpdateButton last, after actual target tabs/services/delegates settle. Source Abort verifies the captured real source and every restored WebContents, then reattaches its original service/prefs and runs the real source update. No empty target rebind is used for source rollback.

All introduced callback-depth leaves use the existing lifetime WeakPtrFactory, which is never invalidated during preparation; no AutoReset writes into a destroyed controller. Actual delegate callbacks may close the real window, so UpdateButton/CallOnBoth make no member accesses after the outgoing delegate path and check real lifetime after startup metric handling. The outer Split CallOnBoth must likewise stop between delegates on actual owner loss. Existing startup metric/icon/pin/panel semantics remain; no fake state, permission, task pause, promo result or user action is introduced.

Exact two-file patch replay and all baseline/output SHA comparisons passed; shared source hashes remain unchanged. Compilation, current runtime eligibility and functional fidelity are not proved. No native build/target launch, owner data, network/AI, credentials or OS grants were accessed. Original feature scope proof is `973bdb2a0`; it establishes compiled defaults, not runtime override absence. No UI trigger is enabled.
