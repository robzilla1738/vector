# Recovered real delayed session rebuild

This refines the remaining integration row in README. The accompanying source-only scheduler implements this recovered delayed effect; it does not implement the owner transaction. Bounded disassembly plus matching current source establishes the delayed operation concretely.

Original `04559f80` tail (decompile lines1848–1889) obtains the old and new **original** Profile paths and inserts both into the path set at Browser+0xd8. It increments the sequence at+0x100 and posts a weak-owner callback carrying that sequence with delay500000 microseconds. The literal is `ScheduleSessionRebuildAfterAsideProfileSwitch`, original browser.cc line0x66b.

Callback `0455d6bc` first rejects a stale sequence and absent BrowserProcess/ProfileManager. It moves the accumulated set into a local set and clears the owner's pending set. For every touched path, `027a56a4` performs an existing loaded-profile map lookup; no path-based profile load/create occurs. A found profile is reduced to its original profile. The callback obtains `SessionService` from factory `0108d1d0` through existing-only service lookup (argument create=false), skips an absent service and tests its saving-enabled byte. Only then it invokes `021836b8`.

`0108d1d0` initializes its keyed-service factory with native literal at0xdac2f02, bytes `SessionService\0`. The effect sequence of `021836b8` matches `SessionService::ScheduleResetCommands` in155: pending_reset=true, clear pending commands, clear tab-range/window-tracking/last-selected maps, rebuild_on_next_save=false, build commands from real registered browsers, set has-open/move-on-new-browser flags when tracking is nonempty, then start the storage save timer. The public safe current entry point is `SessionServiceBase::ResetFromCurrentBrowsers()`, which performs the saving-enabled check before that protected virtual method.

Therefore an eventual faithful owner can implement a generation-checked500ms path-set scheduler using loaded-only `ProfileManager::GetProfileByPath`, `GetOriginalProfile`, `SessionServiceFactory::GetForProfileIfExisting` and `ResetFromCurrentBrowsers`. It must retain all touched paths across rapid switches until the latest callback drains them, and weak-cancel on owner destruction. It should not create a service or load a profile merely to rebuild it.

The original operation rebuilds **both affected registered workspaces**, not merely the new active profile. Thus cached real Browser workspaces and correct profile ownership/role must already exist when the delayed callback runs. A map of unregistered detached source tabs is insufficient for the upstream BuildCommandsFromBrowsers traversal. That is why this must be wired together with the actual original cache and hidden-role lifecycle, not fired prematurely as an isolated success path.

Original+0x105 migration-suppression and+0x108 suppression-generation are separately visible in the switch path and final zero-delay callback0455d804. In155 the model-to-session/history persistence was moved into SessionServiceBrowserHelper. A narrow migration pause/rebind there is still required; toggling saving for an entire Profile would change unrelated windows and is not justified by the supplied guard. The exact helper migration implementation remains a separate port seam.

## Concrete scheduler integration

`session-rebuild.patch` creates `chrome/browser/ui/aux_profile_switch_session_rebuild.{h,cc}`; manifest baseline null pins these as new paths. The exact sources are also retained under port/. Add those two sources to the same ENABLE_AUX_BROWSER UI target as the parent owner primitive; no shared BUILD file is changed by this proposal. Own one `aux::ProfileSwitchSessionRebuild` in the real same-window transaction owner, and call `Schedule(previous_profile, target_profile)` only after completed cache/model/controller/manager migration. Its weak factory cancels delayed work on owner destruction; generation guards suppress older tasks while the touched-path set accumulates. No profile pointer is retained across the delay. Profiles/services are never loaded or created by the task.

The public source API checks a present, saving-enabled existing SessionService before ResetFromCurrentBrowsers. Callback disappearance and absent loaded profiles are truthful skips; there is no successful profile-switch RPC or fabricated session result.
