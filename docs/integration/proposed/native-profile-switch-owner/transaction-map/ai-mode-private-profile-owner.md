# AI Mode private profile owner

AiModePageActionController retains a const Profile raw_ref, old PrefChangeRegistrar, old AiModeButtonService callback subscription and an OmniboxEditModel observation. Its favicon callbacks use dedicated original weak factories and may consult the old profile's favicon DB/network service. It is a private BWF controller; the same actual LocationBar/Omnibox edit model/per-tab PageActionController are separate owners and must survive.

PageActionObserver has no unregistration API. Its destructor does reset the actual model observation. Reconstructing this private controller at the actual cold boundary is therefore narrower and safer than changing its Profile ref while leaving an old per-tab observation attached. The proposal does not replace views, edit model, page actions, icon/config values or navigation behavior.

## Exact owner lifecycle

1. `CanRetireForAuxProfileSwitch()` requires same genuine registered normal regular window/profile, actual current edit-model observation, no prepared phase and no actual callback on stack. All profile-sensitive callback scopes use a final-member destruction-only WeakPtr leave, so a real callback/window close cannot cause a counter destructor write into a dead owner.
2. Before source model transfer, call `PrepareForAuxProfileSwitch()`, then reset the private BWF pointer. Prepare detaches the actual edit observation, resets source prefs/subscription and invalidates only the original old-profile favicon/config callback boundaries. It does not call Hide, emit an icon-source metric, fabricate a fetch result, navigate, or cancel through a different profile service. Actual destructor unregisters the base page-action model observer and userdata.
3. At committed target eligibility, use `CreatePreparedForAuxProfileSwitch(actualBwi,actualTargetProfile,sameLocationBar)` and assign it into its real private owner. Eligibility remains the actual BWF condition: existing BrowserView/LocationBar and non-null AiModeButtonServiceFactory result. Target can gain or lose this optional private owner. No replacement is created for an ineligible target.
4. After real target tabs and same edit-model profile services settle, call `FinishForAuxProfileSwitch()` as the final effect on that pointer. It validates real window/model/profile/edit observation and invokes the unchanged actual config/icon/favicon update pipeline. Parent must perform its usual weak window/owner check before further operations; actual UI observers may close a window.
5. For pre-identity source rollback, restore real source tabs/profile/edit sources, then construct the source private owner via the same prepared factory using the genuine source Profile and LocationBar, assign it, and Finish. This is a concrete source abort path, not an empty-model target Rebind or fabricated source config. Source eligibility is captured from the genuine original factory condition; no post-commit rollback is claimed.

The prepared factory is necessary: AiModeButtonService::RegisterOnConfigChanged invokes its callback **immediately** before adding its subscription (components/search_engines/ai_mode_button_service.cc:67-70). The stock constructor can therefore UpdatePageAction and fetch icons immediately; it is not a deferred-only constructor. Prepared construction preserves the actual subscriptions but postpones that update until the new private owner is assigned and real tabs are ready. The original public constructor delegates with prepared=false, retaining ordinary startup behavior.

Moved tabs may already have the AI action visible. RegisterAsPageActionObserver copies its actual current state but does not emit OnPageActionIconShown. Update now initializes is_visible_ from that genuine copied state, avoiding a false visibility result after private reconstruction without synthesizing UI events.

## Source and scope evidence

* Actual class constructor and destructor own the sources listed above; original favicon fetch weak factory already exists specifically to retire stale config work. Static OpenAiMode and triggered-feature navigation behavior are unchanged.
* PageActionObserver destructor and PageActionObserverImpl reset the actual scoped model observation. There is no public Reset method, so a stable in-place Profile rewrite would require another base-class adaptation.
* LocationBarView::RefreshAiModePageAction and WebUILocationBar::RefreshAiModePageAction resolve From(window) and null-check. Existing WebUIReadOnlyOmnibox::AimButtonVisible dereferences From without a null check. A temporary private-owner absence is therefore only valid inside the current provider's existing synchronous native/classic-only boundary; the provider already excludes WebUI toolbar/omnibox renderer modes. Do not broaden that support based on this patch.
* A favicon network request may continue in its original service while its UI callback is invalidated, exactly as the original weak boundary permits. This proposal does not issue a test request, supply a replacement image, misattribute old work to target services, or claim to cancel a network transport it does not own.
