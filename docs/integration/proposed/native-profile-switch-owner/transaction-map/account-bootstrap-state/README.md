# Supplied account bootstrap evaluator

Source-only new-file proposal; no changes to the live gate/security client. It implements the actual supplied account-reader semantics rather than reusing independent `ProfileSecurityState::allows_browsing()`. API is `aux::ReadAccountBootstrapState(home, actual_profile_pref_id, actual_profile_path, optional_actual_user_pref)`; result is `optional<bool>`. `EvaluateAccountBootstrapState` accepts an in-memory JSON value for focused fixtures without opening a real home.

## Source mapping

The supplied reader `0x4100b88` accepts an accounts JSON dictionary; unreadable/invalid/nonobject input is absent state. A readable object with incomplete/no matching account is a **known false**, not an absent result. Its original JSON depth is200. The Aux-only state path is `<StateHome>/accounts.json`; no owner default or alternate home fallback is introduced.

`0x4100468` selects actual local `profileAccountBindings` by exact profile ID then exact path, followed by actual cloud `profileBindings` by ID then path, then explicit user ID. Current-account fallback is permitted only with no actual bindings and no user ID. A matched binding is sticky even if the account is missing: it goes to the original legacy evaluator rather than silently choosing another account's explicit onboarding field. An actual present `onboardingCompletedAt` property is engaged boolean: only a nonempty string is true; null/empty/wrong-type is false. Only an absent property permits the legacy fallback.

`0x41007c4` first tests that exact resolution, then searches actual binding rows with equal `FilePath::StripTrailingSeparators()` paths and retries their real IDs/paths. The original helper `0x10cc104` returns an equality boolean (zero means different), pinned separately to avoid reversing this condition.

Legacy `0x40fff68` and state classifier `0x40ffa68` retain the actual global/per-account localBootstrap records, `hasEverBoundCloudUser`, `vaultSyncMode==pending_choice`, bound-user comparison, current real session presence and paused auth. Tokens are inspected only for original nonempty access/refresh presence, never returned or logged. The actual explicit onboarding field takes precedence over this legacy state; **anonymous/local is never synthesized as complete**. The original parser's valid account0 bootstrap replaces its legacy default; the historical default participates in the vector count guard when appended without account0. Malformed binding rows are omitted before no-bindings/count decisions, matching the original parsed representation.

The bounded REA evidence retains provider caveats. The first multi-entry fragment resolved state/fallback helpers but did not discover `0x4100468`; a second fragment resolved its entry. That second decompile truncates the external tail branch to `0x40fff68`; the exact bounded raw disassembly pins the real tail branch and complete fallback. No bad-instruction decompile output is treated as a successful bypass.

## Required next integration / correction

This is the policy dependency for replacing native gate admission, not a completed gate mount. The full owner must use actual profile `aside.profile_id`/`aside.account_user_id`, actual profile `aside.bootstrap_complete` fallback on **absent** results only, global `aside.onboarding_completed`, original suppression and omitted-profile criteria, and1s unknown-state retry. Native original `0x410347c` creates/persists a real profile UUID only when missing. The existing independent hash ID/automatic ensure-binding and Vault-unlock predicate are not faithful substitutes. The current native account API producer must align its actual returned/set profile context to these preferences before final integration; no fabricated state is written by this module.

Correction to the preceding popup checkpoint: original helper `0x417b7a0` retrieves a real `ProfileAttributesEntry` and reads `+0x60`, the original in-memory **is_omitted_** field. It is not a proven `IsGuestSession` call. The original entry has a virtual table pointer, two service pointers and three24-byte strings before that byte; current155 retains that exact field/semantic. Suppression-clearing constructor helper `0x417a8d8` is additionally contingent on new-profile status and another nonomitted profile path. Full policy integration must preserve these conditions, not invent a guest/anonymous exemption.
