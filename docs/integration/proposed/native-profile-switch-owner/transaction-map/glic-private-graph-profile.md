Source-only six-file Chromium155 platform adaptation, pinned to actual135. Independent patch replay and shared-input hashes verified; no compile/runtime acceptance claimed. Requires the outer Split and dormant-bubble view proposals; does not enable a trigger.

Its real nudge TabHandle, optional prompt, activity callback, call-to-action lock, executing call depth and posted outcome callbacks must all be absent before Prepare. Already-posted actual outcomes are counted and forwarded unchanged even if their original controller dies; no fake rejection/cancellation or callback dropping. Its same tab observer remains: with no nudge handle the existing active-tab callbacks have no UI effect. No state is cleared to manufacture coldness.

GlicActorNudgeController keeps its stable userdata, view aliases and permanent bubble-visibility callback lists. Prepare removes only the actual profile icon-manager subscription. Source Abort binds genuine restored source. Coldness includes actual manager task rows empty and active callback depth; this deliberately refuses retained Actor task state rather than pretending a live task/nudge was migrated.

ActorTaskListBubbleController keeps its actual shown/destroyed callback lists and view owner. Its delayed real Show requests now have an outstanding count through their original weak callback execution; no request is cancelled or success fabricated. Prepare refuses queued work/active callbacks/showing bubble, then detaches the actual old-profile manager subscription. Rebind/Finish attaches the genuine target manager; it does not force Show/Close/OnStateUpdate. Source Abort restores actual source subscription. The outer delegate guard additionally requires complete widget destruction, not visibility.

All introduced call-depth scopes leave through a dedicated weak factory; destruction during real view/callback work cannot make a new scope write a dead owner. The existing public WeakPtr generations are retained. CHECK(!prepared) on actuator callbacks states the actual synchronous/no-task-pumping transaction boundary; there is no synthetic pending-outcome handling.
