# Same-window profile transaction: owned registration and command sources

Two independently replayable proposals against the applied v32 source. No shared native files were changed, no build or target was run, and no owner state was read. Neither patch installs a profile-switch trigger or claims a completed transaction. Apply alongside the parent owner primitives only after integrating the remaining real migration seams below.

## Implemented source-backed hooks

`ownership.patch` / `ownership-manifest.json` change only `browser_manager_service.{h,cc}`. `BrowserManagerService::TransferForAuxProfileSwitch(browser, target, commit_identity)` transfers the SAME owned browser from its actual source manager to the target manager, replacing its three activation/deactivation/close subscriptions. The synchronous identity closure must be prepared, non-yielding, incapable of failure and free of external callbacks. All unsupported/testing/unowned/duplicate state is rejected before the closure. The hook keeps both profiles alive during transfer; it does not supply the longer-lived cache keepalives required by the complete transaction.

Bounded disassembly of original `04568238` and `0456847c` establishes the ownership operation, not just a name analogy: the old manager extracts its unique browser pointer and three callback subscriptions from 32-byte entries, removes the profile activation pointer, then the destination registers the same three callbacks and appends the same browser. There are NO collection create/close/activate/deactivate notifications. The proposal therefore preserves global identity/order and does not synthesize window closure, creation or native activation. The raw proof windows are included.

`commands.patch` / `commands-manifest.json` change only `browser_command_controller.{h,cc}`. `BrowserCommandController::RebindForAuxProfileSwitch(previous_profile)` detaches the actual old profile's TabRestore/extension/pref/Glic sources, initializes target sources, recomputes command state and schedules the real bookmark-model-ready update. The existing command updater and its UI observers survive. Constructor factoring preserves the original current155 constructor call order; local-state prefs and the same tab-model observation are not re-created. `PrefChangeRegistrar::Reset()` permits an actual different service before `Init()`.

The original post-identity sequence is `04560b20 -> 0455ebf0 -> 0455f5d0 -> 04560a50`. Direct instructions and matching current constructor effects identify teardown, profile source initialization, `InitCommandState`, then bookmark-load scheduling respectively. They do not justify destroying the command updater.

## Actual identity commit and migration phases

The original `04559f80` retains the SAME Browser, native window, TabStripModel and session identifier. Its old layout writes Browser profile `+0x68`, features profile `+8` and model profile `+0x58`. These offsets must NOT be copied into Chromium155. The following table is the concrete source migration plan; rows without a supplied patch remain integration work, not implemented behavior.

| Phase | Current155 operation and invariant | State of port |
| --- | --- | --- |
| Prepare | Resolve actual source/target profiles and original eligible window role; acquire active AND per-profile-path cached keepalives, freeze re-entrant switch/close work, finish all fallible preparation before ownership extraction. Original `0455c674` maintains the path-keyed cached keepalive map at old Browser `+0xc8`; it is not BrowserList registration. | Ownership duration guards supplied; persistent cached keepalives and whole-transaction guard still required. |
| Hidden workspace role | Original preview/cache Browser role byte `+0xf0` separates the hidden workspace from ordinary Browser windows. A cached real Browser must remain excluded from ordinary ProfileGate Show/Hide/activation until commit. Current gate showing every permitted matching-profile window would expose the hidden workspace. | Parent recovered role predicate; explicit current role/lifecycle seam required before creating a cached real Browser. No hidden-window workaround added here. |
| Detach source | Use actual model-owned tabs/collections, preserving real WebContents, groups, splits, ordering, pinned/selection state and BrowserContexts. Public155 `DetachTabsAndCollectionsForInsertion`, `DetachTabGroupForInsertion` / `InsertDetachedTabGroupAt`, `DetachSplitTabForInsertion` / `InsertDetachedSplitTabAt`, and `DetachTabAtForInsertion` / `InsertDetachedTabAt` provide real ownership operations. Cached source WebContents must stay with their own profile. | Exact original cache/collection algorithm remains caller work; no flattening into URL reopen or screenshot substitution. |
| Suspend session effects | `SessionServiceBrowserHelper` observes the same model and writes session/history for insert/remove/move/group/split/pin changes. It stores a **const** profile reference; Browser identity alone cannot rebind it. Real source extraction must not be persisted as user tab closure or target tabs written to the old service. | Add an internal guarded migration pause/rebind on the same helper before target insertion; recover original delayed rebuild semantics before scheduling it. Merely calling ResetFromCurrentBrowsers could erase cached source workspace state. |
| Commit identity | Change only the existing Browser's authoritative `profile_` and active `profile_keep_alive_`; current `profile_` is const and requires a guarded internal mutability seam. Keep `window_`, `session_id_`, model and delegate objects stable. Change model profile only at the empty migration boundary. Move ownership and its three callbacks with `TransferForAuxProfileSwitch`. | Concrete manager hook supplied. Browser/model identity setters are deliberately not exposed before the complete safe transaction. |
| Rebind source-bound controllers | Rebind target prefs/services on stable controllers whose views hold callback/delegate references. BrowserWindowFeatures155 has **no profile_ member**; its original `+8` write has no direct155 equivalent. Do NOT wholesale call Init or replace every feature. | Command hook supplied; precise other seams below. |
| Insert target | Insert the target's actual detached collections into the stable, now-target model only after helpers/controllers use target sources. Preserve genuine collection IDs, BrowserContext, selection and session semantics. Retain the previous workspace with its keepalive. | Caller/cache owner still required. |
| Refresh and settle | Recompute actual commands and theme/bookmark/vertical state; preserve normal model observer cleanup for UI queues/zoom; release transition/preview only at the real activation boundary. Original delayed500ms session rebuild and zero-delay post-switch callback are generation guarded. | Command refresh supplied. Delayed rebuild/callback and final activation semantics require recovered owner integration. |

`BrowserInitState::browser_window_create_params_` is const historical creation state in155. It must not be cast away or treated as the old feature profile field without tracing each consumer. `SessionServiceBrowserHelper` already receives the actual profile explicitly; its Ozone creation-parameter use concerns restore identity. `TabStripModel` and its delegate are const unique_ptr members in Browser, but the model's own profile raw pointer is mutable: preserving the instance is compatible with a narrowly guarded setter at an empty boundary, not replacement.

## Stable-controller migration map

| Controller | Exact current profile binding | Necessary stable-owner operation |
| --- | --- | --- |
| BrowserWindowThemeObserver | Observes `ThemeServiceFactory::GetForProfile` in its constructor. BrowserView subscribes to its callback list. | Reset old observation and observe target service on SAME observer, then notify real theme change. Recreating it discards the view subscription. |
| BookmarkBarController | Holds the same model and delegate; PrefChangeRegistrar binds bookmark visibility and show-groups prefs. | Reset/init target prefs, preserve delegate/model/callbacks, recompute state. Constructor replacement is not an equivalent rebind. |
| VerticalTabStripStateController | Stores target-sensitive PrefService and SessionService plus model/browser/session/root-action identity. | Rebind real pref/session sources and read target state while preserving view subscriptions and action ownership. |
| BrowserWindowZoomObserver | Observes individual tab ZoomControllers through the same model; no cached Profile field. | Preserve instance; real detach/reinsert callbacks already remove/add per-tab observations. |
| BrowserUiController | References same browser/model/window/bookmark controller; scheduled updates can retain old contents. | Preserve references and use real detach cleanup (`RemoveScheduledUpdatesFor`) rather than rebuilding controller. |
| BrowserWebContentsDelegate | Primarily obtains profile dynamically from browser or each actual WebContents. | Preserve object, retain existing detach/delegate cleanup, audit queued callbacks against source tabs. |
| BrowserCommandController | Old profile pref, TabRestore, ExtensionState and Glic subscriptions; stable command updater. | Implemented source rebind in `commands.patch`. |
| SessionServiceBrowserHelper | Const profile reference, stable model/session ID; persists model mutations. | Internal pause/rebind/resume required, as above. |

Other current BrowserWindowFeatures constructors bind profile services directly: cookie controls (CookieSettings/HostContentSettingsMap/incognito), extension browser helper, data sharing bubble, profile customization, reading list/signin, tab group deletion/menu delegates, other-device tabs, BrowserInstantController, merged bookmarks and Glic. Each needs an actual source audit and narrow rebind or correctly reattached replacement; constructors taking a Browser may also cache its profile. `UserDataFactory` returns unique_ptrs rather than owning all controllers behind a generic reset, so it supplies no safe bulk-rebuild shortcut.

## Verification and evidence

The manifests pin every modified input and output SHA256. Both patches were applied to freshly copied pinned source files in temporary directories, and every resulting output hash matched. The four source files are disjoint from parent owner-primitives and staged v33 view overlays. C++ compilation and real same-window runtime acceptance remain unperformed. Full hot-profile-switch fidelity remains blocked by the explicit migration seams above.

`source-evidence.json` records authorized original/current source hashes and routine meanings. `original-extract-owned-browser.txt` and `original-adopt-owned-browser.txt` are bounded static arm64 disassembly, not target execution. No native build, shared write, profile read, OS grant or Keychain operation was performed.
