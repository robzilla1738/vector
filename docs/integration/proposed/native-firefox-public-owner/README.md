## Concrete prerequisites and callback interface

The class is usable source but must not be product-wired until these coherent prerequisites land:

1. L2's actual `chrome/browser/extensions/api/aux_browser_import/firefox_cookie_import.h` exports namespace `aux` function `PrepareFirefoxCookies(WeakPtr<Profile>, const FilePath&, RepeatingCallback<bool()> is_running, OnceCallback<void(bool)> prepared, OnceCallback<void(bool)> settled)`. This class passes its exact captured Profile/source path and a weak live-owner predicate. `prepared` is the real host's once weak prelaunch acknowledgment; `settled` sets only cookie complete/success. Original worker failure settles(false) before ack(false); empty successful worker settles(true) before ack(true); nonempty enqueued actual destination writes ack(true) immediately and settle later, true iff at least one native Include result. Prelaunch acknowledgment is never treated as cookie success.
2. L4's real host/client/utility result path must declare `AuxPasswordImportResult{bool succeeded; uint32_t count;}` and accessor `const optional<AuxPasswordImportResult>& aux_password_import_result() const`. Its real result must be published **before** NotifyImportItemEnded(PASSWORDS). The owner uses only the actual succeeded bit, preserving original host engagement/result semantics rather than inventing a neutral count or successful empty result.
3. Original Mac discovery produces0x4b, including actual PASSWORDS utility capability. Root must restore that actual source registry/version admission and real Mac password utility/result before mounting this class. The owner itself preserves original mask semantics: if PASSWORDS is unrequested, its completion/success flags begin true; it does not add a narrower rejection policy for another genuine services_supported mask. Missing actual results for a requested PASSWORDS item fail settlement. A narrowed descriptor or default-true callback is not a prerequisite implementation.

The public service wiring prepared separately by root can retain the legacy recovery alias while routing the actual public Firefox request here. This proposal does not change shared registration/GN, mask declarations, cookie/password reader, utility, source-profile discovery, JS UI, runtime/test gate, credentials or OS state.
