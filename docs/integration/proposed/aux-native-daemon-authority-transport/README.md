# Finite native daemon authority transport

Inactive source successor to the retained selected-home transport. No queued transport source, native checkout, shared GN, UI or startup refusal changes. No compilation, live Mach exchange, signing, protected call or owner data access was performed here.

The actual child connection creates a dedicated backend only from its genuine ready provider. It registers its owned receive-right send endpoint over the already audited parent channel using a distinct complex registration kind. Parent registration requires the same actual live direct child/code/PID-version and an accepted selected-home transfer; a different endpoint cannot replace it. A lost registration ACK can retry the same endpoint. Delivery is not a public authority factory.

Only three operations exist: exact51-byte Aux daemon-auth message (19-byte domain includingNUL+32-byte challenge), actual installation public-key JSON, and fixed-purpose inbox-v2 key (raw32 bytes). There is no command string, derivation purpose, arbitrary input, path or scope in this RPC. Inbox payloads are RAM-only. The typed actual selected transfer exposes `SignDaemonChallenge`, `GetInstallationPublicKeys` and `GetAgentInboxV2MasterKey`; raw signatures/keys never appear in logs, documents or receipts.

Each request/reply binds native monotonic sequence, immutable random16 nonce and transport generation. Every child request checks kernel audit PID/version, actual parent birth and exact live code; every parent reply checks actual owned child birth/waitability/code and revalidates the selected home before publication. The server's genuine backend/guard callbacks execute with registry/connection/server mutexes released because they reenter this same parent connection's real Revalidate. Parent must continuously service its actual peer channel while waiting for authority RPC; a native sign result is not a health/heartbeat receipt.

Parent serializes one current operation. Timeout/lost response retains sequence, nonce, kind/body and completion disposition. Same-body retry observes the same request and never begins a new sign. A ready/error result is explicitly ACKed before parent admission can begin a different request. Lost ACK leaves the same latest response observable; the backend's retired high watermark prevents old sequences from signing again, with exhaustion refusing instead of resetting. The parent keeps its latest completed response even after ACK so publication-fence retries cannot re-sign. A next accepted different operation alone advances the sequence and retires the previous response. There is no32-request process-lifetime limit.

The parent wipes its owned latest payload on replacement, closed/proven-loss handling and destruction. Actual fixed Mach reply payload buffers are wiped on all source returns, after their independent Mach header/right cleanup; header rights are never erased before destruction. The backend separately owns/wipes its own cache. Caller copies, Swift/Foundation/String implementation temporaries and kernel buffers are not claimed universally zeroized.

The Node-only server declaration composition flag selects real backend implementation; the Chromium parent graph contains only finite client/registration source and no Swift signer references. This build flag is not runtime custody. Native C bridge methods route actual registered connection objects, never a JSON observation or JS handle. In-flight receives/operations and backend close results remain pending/untracked. Factory admission closes permanently; a late actual factory result remains retained/queryable after closure. Parent raw active exchanges include actual authority calls. Wrong-process calls avoid inherited registry locks and Mach namespace operations.

The typed ready-home export producer's genuine busy status1 maps only to retryable timedOut, with no FD/fileport/pulse. Invalid descriptor returns remain refusal. This does not transform missing authority or arbitrary failures into a heartbeat.

It privately mints a native publication object bound to the exact selected object, client, generation, sequence, nonce, operation/body and cached payload. A caller-constructed status/vector has no publication object and cannot ACK. `AcceptAuthorityReply(const DaemonAuthorityReply&, timeout)` matches the private observation, revalidates the genuine selected home, performs only its exact ACK exchange, validates actual peer/owner/generation again and clears pending only after matched success. Transient failure/lost ACK leaves the same completion observable; other kinds cannot evict it. Completed errors without a successful payload may still be internally retired; they do not publish a result.
