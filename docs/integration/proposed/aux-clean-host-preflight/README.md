# Aux-only clean host preflight — inactive source

This is a concrete preflight implementation, not runtime activation. The actual signature/image/home inspector and optional selected-journal binder are **compile-only**. No Keychain, Secure Enclave, PQ, original addon, owner home/profile, signing, provisioning or provider operation occurred. The current loaders and state2 refusals are unchanged.

## Actual loader conflict

`loader-contract.json` pins exact source/anchors:

- `aux-native.cjs` uses environment execution/load-only settings, canonical AUX_HOME and scope, loads `aux-native-guard.node`, calls `guard.prepare`, verifies original binding role/hash and then requires `provided-native.node`. Neither that original binding nor this loader is the new host producer.
- `node-boundary-guard.mm` and `native-carrier.mm` require actual five-function pointer interposition before supplied-module loading; their current path cannot be made clean by setting a new acceptance variable.
- `keychain-query-map.mm` accepts only the original explicit group, rejects another explicit group and removes the accepted group; it prefixes service/account with `aux.<scope>.` while retaining original logical suffixes. The scoped historical default-group result is not equivalent to querying the original explicit group, nor to the proposed new Aux group.
- `keychain-interpose.mm` actually interposes Add/Copy/Delete/Update/KeyCreate; `cli-launcher.mm` clears inherited DYLD settings and injects that library. A new explicit Aux query sent through this host is therefore not the new clean query contract.
- `AuxAttachOwnedDispatcher` has no production initializer or JS authority factory: a trusted native producer still must supply a retained immutable owned instance. The secure-store adapter also needs the same actual installation scope/group and exact native key policy.

The clean host must be a separate reviewed loading route. Do not remove the original guard, weaken the mapper or fall back to an original/default/login group. Legacy capture/migration remains a separately reviewed tool boundary.

## Concrete source checks

`AuxCleanHostPolicy` is an immutable native Swift value with fixed role, team, signing/application identifiers, explicit Aux group, exact executable/CDHash, canonical private disposable parent/home, SHA256 home scope and exhaustive additional non-system image SHA256 allowlist. No JSON decoder, N-API factory, environment policy/path override or JS selector is provided. Role-to-identifier values are proposed Aux host identities, not evidence that a currently signed host with those IDs exists. ASCII canonical paths are deliberately required; Unicode path policy is unsupported rather than silently normalizing scope bytes. This initial policy supports explicit reviewed disposable homes only, not owner-profile adoption.

`AuxCleanHostPreflight.inspect(policy:)` performs actual source-level operations:

1. Strict policy checks, fixed Aux role identifiers, exact application/team/group shape, no wildcard group, exact scope derivation and image hash validation.
2. Negative-only environment checks: every DYLD variable, NODE_OPTIONS and historical provided-execution/load-only acceptance settings refuse. No environment value grants acceptance.
3. Actual dyld loaded-image inventory. System image paths are limited to normalized `/System/Library/` or `/usr/lib/` paths under the platform's protected-system assumptions; every other loaded image must exactly match the reviewed path/hash allowlist. The main executable must be in it. Known Aux interposer/guard images and exported Aux boundary symbols refuse. Original images are excluded by the exhaustive reviewed allowlist; no reference-product string is embedded as a runtime rejection filter.
4. Actual imported Add/Copy/Delete/Update/KeyCreate pointer origins via a small C++ address-only bridge and `dladdr`, requiring the exact Apple Security framework image. The bridge takes addresses and never invokes these functions. Library-resolution differences refuse; there is no alternate Security path.
5. Exact canonical parent/home paths; owned 0700 directories, no extended ACLs, FD-relative no-symlink opening, and path/inode rechecks. No directory is created and no HOME/AUX_HOME is used to select a target. These checks are not process custody or lifetime locks.
6. Actual executable path from `_NSGetExecutablePath`, dynamic current code from `SecCodeCopySelf`, Apple generic anchor + exact identifier/team requirement, offline strict `SecCodeCheckValidity`, and current signing information after validation. The exact CDHash, application identifier and single explicit keychain group must match; ad-hoc/non-hardened or insecure entitlement flags refuse. DYLD permission, disabled library validation, unsigned executable memory, disabled executable-page protection and debugger get-task access are denied. JIT permission alone is not treated as a provenance/custody grant.
7. Recheck signature, loaded images and home identity before returning non-Codable `AuxObservedCleanHost`. Its fileprivate constructor cannot be called by fixture/other logical source files. A pure captured-fact validator returns only Void and never manufactures this observation.

The Swift raw no-network/runtime/ad-hoc constants are pinned to public SDK `CSCommon.h`; no unknown flags are guessed. `SecCode` calls inspect public signature metadata; they are not SecItem/SecKey/Keychain operations. Actual preflight execution was not performed in these checks. Code-signature entitlement declaration is not proof that a protected operation will succeed or that provisioning/revocation/custody has been accepted.
