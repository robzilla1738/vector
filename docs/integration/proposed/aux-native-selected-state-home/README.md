# Native selected StateHome and ready-provider pulse

Inactive native source only. Six source files: four same-logical fileport successors plus new `AuxSelectedStateHome.{h,cc}`. No native checkout, shared startup, GN, app, UI or first-refusal gate is changed. No compiler/IPC/Security execution is claimed.

Only the actual private-constructor `SelectedNativeHome` from the owned child/fileport path can install this one-shot route. The holder consumes and retains that actual child/FD owner. It derives the canonical physical path through a real revalidated FD with no-follow inode checks. No path/env/status/JSON setter exists. Never-selected is distinct from selected-but-unavailable/closed: the proposed StateHome consumer can preserve the current legacy baseline only before any selected route is attempted; it never falls back to an old/default home after selected authority disappears.

The paired daemon main re-exports the actual ready-service FD every1s with the existing2000ms per-call timeout. Only an actual successful bound selected-home ACK updates the native monotonic timestamp/export count; v1 heartbeat, nonce, snapshots and caller flags cannot do so. Initial export and idempotent repeats keep the original physical selection. The holder refuses to return a path once its exact pulse is older than10s. A transient receive timeout leaves the same owner installed but grants no path while stale; it never resets identity or creates a new owner.

The holder starts and retains one actual `base::Thread` servicing the selected real child's250ms bounded receive loop after the prior parent bootstrap pump is transferred/stopped. Hard refusal/closed/wrong-process closes the route irreversibly. A native close synchronously closes actual peer admission; it does not wait for a running Security/resource callback. Creator-thread close joins only after the monitor is out of callbacks; pending monitor/initialization/active-read outcomes remain explicit. Failed initialization retains the real started thread/owner rather than reporting it gone. A closed route remains closed; no restart/reinstallation or process kill is supplied.

`integration-contract.json` pins the exact actual StateHome/BrowserPlatform/Supervisor seams and proposed ordering. BrowserPlatform currently has no owned-child adoption API: calling its existing Start would spawn another daemon; merely skipping Start would omit authorization/readiness. Root must pair the genuine existing child/endpoint authorization consumer and close actual browser writer admission on unavailable/closed before applying shared startup changes. The holder is a real selected-path/lifetime consumer, not all-writer custody or permission to cross current startup refusal. Historical installation migration remains separately unfinished.

Static source/seam checks passed. The combined C++ recipe in `aux-selected-home-fileport-compile` selects these four overrides and new Chromium TU; nativeaudit's single final Swift59690 selects rootv2 policy/loader. Neither a new compiler nor runtime fixture is queued here.
