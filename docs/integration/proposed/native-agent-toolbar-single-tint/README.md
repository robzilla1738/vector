# Supplied Agent page and toolbar tint

The pinned supplied extension root assigns normal Agent routes `data-theme=translucent`. Its exact stylesheet defines `--web-content-background` as an 80% color mix of `--background` with transparent; dark background is neutral900 (#171717), light white. The restored native palette supplies those same RGB values, but Chromium155 paints an opaque top-container matte, another opaque toolbar matte, and an additional main-region matte when a panel opens. Those stacked opaque owners prevent the supplied translucency from blending continuously across the URL toolbar and page.

This integration uses one toolbar-row tint at the supplied 80% opacity: the top container paints it; the nested ToolbarView and main-region backing omit their duplicate paint for an actual committed Aux Agent extension tab. Native material remains owned by the geometry lane. It keeps the existing palette and supplied renderer intact. It preserves external-page behavior, custom theme images, high-contrast paint, focused omnibox and popup backgrounds. The existing NTP resting omnibox already paints transparent; no extra address-bar redraw is introduced.

This is explicitly a Chromium155 paint-owner adaptation inferred from the supplied CSS and observed seamless reference, not a claim to have recovered the original C++ paint implementation. The supplied transparent sidepanel renderer is not classified as an active page, so opening a panel beside an external site does not change that site's toolbar. Switching tabs naturally changes the active-page check during paint.

One native file, exact preimage/output hashes; temporary patch application passed. No native checkout mutation, build or runtime action. Integrator must combine with restored native material/frame backing and inspect light/dark NTP, external-page switching, sidepanel visibility, focused address bar and extension-theme behavior. The opacity source is the stylesheet, not a screenshot pixel sample.
