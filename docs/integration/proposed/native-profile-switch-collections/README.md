# Actual tab/collection ownership transfer

Two new source outputs port the actual ownership operation using155's real model APIs. Temporary filesystem replay passed; no native compilation/runtime, shared write, owner data or profile inspection occurred. Add `views/frame/aux_profile_switch_tabs.{cc,h}` to the enabled Aux/Mac UI source list. Requires Browser's private friend/empty-transfer guards from121841c85; there is no externally callable UI trigger.

`ProfileSwitchTabCollection::Take` is PassKey-restricted to the owner transaction. It validates every genuine WebContents BrowserContext, preserves the actual selection objects and takes all model indices through `DetachTabsAndCollectionsForInsertion`. That API transfers whole real group/split collections and standalone TabModels, retaining group/split IDs, metadata, existing WebContents, pinned state and ordering. No URLs are extracted to reopen replacement tabs. Original04559f80's actual owned variant sequence distinguishes individual tabs, grouped collections and split collections before calling their corresponding reinsertion operations; current155's public API is the necessary platform adaptation of that operation.

`InsertInto` validates the entire detached payload against the exact live target Profile and empty destination model **before** the first insertion. It inserts real group/split/standalone variants with preserved pin state and sequential order, and checks the final actual count. Current155 selection is rebuilt for the destination model using the genuine surviving TabInterface pointers, rather than retaining an internal index cache bound to the old model. This also preserves current155 split/focused-group selection metadata; these details are a155 platform integration, not a claim that old raw selection offsets are identical.

An unconsumed snapshot rolls back to its original same-profile, still-guarded source Browser. Silent destruction of detached user tabs is an invariant failure, not an accepted abort. The whole owner transaction must remain synchronous/non-yielding while it holds snapshots and keep both source Browser and mutation guards alive. A snapshot must be consumed into its old-profile cache before that source Browser's identity is committed to another profile; otherwise rollback would cross BrowserContexts and is explicitly refused. Group IDs are accepted only from genuine owned collection objects.

Required owner order: acquire/prepare genuine source+target caches and all services; guard automatic empty-close/persistence on all affected Browsers; take source and target collections; insert source collection into its exact old-profile cache; transfer visible Browser manager ownership and commit the now-empty stable model's target identity; rebind target helpers/controllers/views; insert target collection into the visible Browser. Manager-transfer failure before identity requires taking old-profile cache tabs back into the unchanged visible Browser while target snapshot rolls back. No successful switch is exposed until all service/view rebindings are coherent.

Remaining owner work is explicit: actual coherent orchestration, metadata/session-window migration, view service rebindings, cache cleanup and the supplied sidebar preview/activation settlement. This source proposal supplies the real ownership mechanism, not an alternative window focus action or a reported-complete simulated switch.
