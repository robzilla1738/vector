# Propagate the actual persistence result through the draft writer

Actual615 quota diagnostics showed a completed attachment held by the writer, empty storage, and no toast. The supplied debounce implementation discards callback return values in both its invoke function and `flush`; returning `r.flush()` from the adapted draft writer therefore returned undefined even when persistence returned false. The earlier writer test mocked the callback boundary and missed this supplied implementation detail.

The draft writer now captures the actual persistence result inside its own debounce callback, calls the unchanged supplied flush, and returns that captured result. The shared debounce implementation and all its other consumers are untouched. The existing NTP custom callback can now forward false to the composer's existing failure toast. Successful retry/clear returns true and resets the existing once-per-failure toast suppression. Storage-failure protection was already registered independently; this corrects failure reporting, not a new storage policy or UI surface.

A focused check executes the actual supplied debounce, transformed writer/storage, transformed NTP callback and exact existing composer toast snippet together. Quota failure returns false, emits one toast per failure episode, retains unload protection, recovers to true, and re-arms the toast after a subsequent failure. The complete transformed storage module parses. Root restages only the already allowed draft-storage leaf; no new leaf or native rebuild. Source is frozen after this correction for616 acceptance.
