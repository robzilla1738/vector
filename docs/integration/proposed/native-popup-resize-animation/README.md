# Supplied popup bounds animation

This two-file proposal restores the supplied main/options resize interpolation after `native-popup-material`. Exact baseline/output pins are in `manifest.json`; `native.patch` replays against popup CC `9d9ce8a4631143756047bb4a01b866e542019c024e342a0ebe79a8b9234bfc7d` and local BUILD `4b3a5cfea55967a323a6bc02a9b306875b220d1f34e4483886f8655978ac9da1`. Nothing is applied to shared Chromium here. The only dependency addition is `//ui/gfx/animation` in the popup's own target.

Original main resize04596d1c and options resize045971d4 cancel their previous animation before checking current/target equality. Unequal bounds either apply immediately when the actual reduced-motion preference is true, or construct a `gfx::LinearAnimation` with180000 microseconds,60fps and a null delegate. The supplied command-line override precedence is reduced-motion, then no-reduced-motion, then cached platform preference. Current155 `gfx::Animation::PrefersReducedMotion()` retains that exact precedence, so this adaptation uses it directly and adds no independent AppKit preference reader.

The subclass vtable at original RVA0xe504700 has `AnimateToState` in slot9 targeting0459a0f0. That method evaluates Tween case8, interpolates its captured start/target rectangles, then sends the result through the actual native window bounds path. This is not an inferred easing name: the original jump-table entry at0xd2263c0+8*4 resolves relative to021cffac to021d0428. Its initialization at021d0acc loads the ten control coordinates `0.05,0,0.133333,0.06,0.166666,0.4,0.208333,0.82,0.25,1`, exactly matching current `EASE_IN_OUT_EMPHASIZED`. Original0265d304 interpolates rounded left/top/right/bottom edges, matching current `Tween::RectValueBetween`. No new motion curve or duration is selected.

Original FinishHide04598574 clears the main animation at coordinator+0x60, then closes options. Original CloseOptionsWindow04597c38 clears its animation at+0x80 before releasing the child. The proposal cancels both animations before hiding/destroying widgets, and the child animation before child replacement/close. Retargeting destroys the old animation and captures the currently displayed rectangle; it does not jump to the old destination. Each frame uses `Widget::SetBounds`, the current native bounds entry, after the existing target work-area fit. It does not repeatedly clamp interpolated rectangles or introduce another fit policy. A closed native widget receives no frame update; manager-owned widget objects outlive their animations, and explicit destruction clears the animations first.

The existing main centered-resize and options bottom-anchored geometry remain byte-identical except their final bounds application calls. Initial options placement remains unchanged. The current host also calls `Resize(size_)` before showing the main widget. This is an explicit integration adaptation: original Show0459577c applies initial/offscreen placement directly before showing, while original SetState04596b80 / SetSize04597014 enter04596d1c only for a visible actual widget. This proposal retains the host's pre-show immediate `SetBoundsConstrained` placement and animates only visible content-driven resizes. It does not claim that the remaining original reopen/offscreen route logic has been restored.

`source-evidence.json` pins the supplied framework/arm64 image, bounded original functions, vtable/curve data, relevant decompiles and current animation source. `evidence/resize.json` and `step.json` retain REA dossiers; bounded original disassembly records support the duration, frame rate, class, interpolation and control points. These are static observations, not original source line identities. `python3 docs/integration/proposed/native-popup-resize-animation/verify.py` verifies those hashes and data, exact two-file replay, unchanged existing geometry and cancellation order. It passed without executing target code, preferences, Keychain or OS grants.

This proposal has not been compiled, signed, launched or visually accepted. Focused popup-object compilation and actual disposable observation must verify180ms timing, both reduced-motion override modes/platform preference, mid-animation retargeting, hide/close/profile destruction, main/options rendering and real window placement. Lock-route and offscreen-reopen fidelity remain separate gaps. Supplied extension components/CSS/routes, the recovered material path, focus capture and three-color background behavior are unchanged.
