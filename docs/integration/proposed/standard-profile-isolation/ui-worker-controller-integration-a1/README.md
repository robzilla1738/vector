## Actual flow

1. Retain and compare every actual extension frame/document and the one real
   canonical worker as inventory, without granting it writer closure.
2. Prepare/flush every actual renderer editor. The existing finite own-extension
   ScriptExecutor path, real document identity and owner/data validation remain.
3. Begin the actual native worker helper. It retains its checked physical lifetime
   and source producer lease; callback data alone cannot supply native ownership.
4. Only then begin the actual LOCAL `StorageFrontend` lease on the actual enabled
   Extension object. Its opaque token is owned by this controller; no UI supplies
   a token, profile, path, epoch or ready flag.
5. Drain the actual loaded DOM areas, validate actual renderer leases and native
   worker hold, then validate/read back the same frontend token. Compare exact
   six raw source records and refuse queued ordinary work or changed ownership.
6. Persist the same preliminary capture through existing bounded operation7
   transfer. Repeat frame/worker/frontend validation and actual raw readback
   between transfer frames and after native readback.
7. Before productive restore, reopen the exact frontend gate. Restore original
   frame leases, then read/release only the same worker attempt. Keep any unknown
   physical callback/token outcome retained and wake settled observers only when
   actual owned work and cleanup are no longer pending.

The journal and result remain **captured-unqualified**, `qualified:false`,

## Recovery and cleanup

An unfinished transfer preserves its original upload UUID, frames, native worker
attempt and frontend lease. Explicit retry observes the same worker through the
native helper before revalidating all source holds; it cannot start a new capture
or release producers across unknown transfer work. A confirmed new readback on
the same opaque frontend token can resolve a lost read observation if the actual
native gate itself is no longer pending. No timer or callback destruction is
called completion.

Before-target cleanup can safely abort the actual frontend token, even if a
readback callback was lost, only when that exact native release succeeds. A
missing Begin result with no token remains unknown; there is no invented token
lookup or owner reset. The A6 callback path normally returns its exact token or
explicitly aborts before target work. A genuine lost Begin callback remains a
fail-closed integration/recovery gap until an actual native observation exists.

Native worker reads can supersede older *transport callbacks*. Those callbacks
are explicitly marked superseded and ignored as stale control flow; they never
resolve physical work as complete. Wrong attempt IDs, missing delivery, native
worker replacement and failed release remain pending. Correlated known pre-lease
refusal may retire only the helper's owned external request, while reporting
failure/unqualified state.

The paired renderer correction in19e98746f is required: release acknowledgment
now includes the exact lease ID the controller already expected. Successful
restoration has correlated readback, and failed restoration retains the original
cleanup lease and failed restorer closures for retry. The controller now requires
that actual restored correlation; anonymous absence is insufficient.
