# Actual preliminary controller consumes exact UTF16 wire data

This successor consumes the paired `utf16-v1` producer in the real native frame
Prepare/Read calls. It depends on the A11 actual document-token join output, with
exact input/output hashes and seven sequential counted anchors. The native tree
is unchanged by this lane; root owns projection and compilation.

The native parser accepts bounded integer code units, exact entry presence/empty
values and set/remove intents without converting values through UTF8. It checks
finite native draft key families, scope, duplicate keys/intents, aggregate entry
and unit bounds, real origin, request/lease/revision and the original native frame
ownership. Unknown Unicode draft identities refuse explicitly; arbitrary valid
UTF16 values, including lone surrogates, are preserved as data.

The original captureJson string is retained opaque inside the exact result bytes.
It is never reparsed as a raw-string substitute for the numeric arrays, avoiding
RFC parser rejection/replacement of lone surrogates. The producer constructs both
from its retained source; the later actual cache/native map join must still verify
the numeric data against real owners. Neither a reported origin nor numeric array
grants native Profile, root, document, path or target authority.

The current preliminary capture remains captured-unqualified with backend writer
closure false. No final Seal, DOM stage/target write or activation call is added.
A9 physical cohort joins must precede those later operations. Existing default UI,
classes, typography and styles are unchanged; only finite capture transport data
is adapted. Cached legacy modules lacking wire mode refuse rather than being
reloaded or treated as ready.

Counted source replay is verified by project.py. The paired producer has18 focused
actual-code synthetic cases including the single Unicode boundary journey. This
lane did not compile or run native code or an app; root still owns actual object
and paired-app acceptance. No signing, release, owner-state, provider or permission
operation was used.
