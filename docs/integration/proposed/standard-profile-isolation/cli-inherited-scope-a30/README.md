# Supplied CLI inherited scope: remaining native producer

The supplied installation/account CLI remains quarantined. Native `aux open URL --profile` is a separate, narrow browser command and is preserved. The remaining gap is an actual task-to-account/Profile grant, not a signing option or a missing flag.

The real current Worker host retains its exact native Owner and RuntimeScope, reserves a physical child before launch, and accounts for descendants through native custody. Those facts prove lifetime membership; they do not grant access to unrelated accounts, Profiles, installation auth or global secure-store namespaces. The current native signed command context uses installation-wide source-known logical keys. Passing it to an inherited task CLI would broaden that task's authority.

An inherited producer must originate at the genuine browser task dispatch, bind the actual immutable Profile/account and task capability subset to that native Owner/Environment, preserve it across the pre-exec reservation and actual audited child join, and retire it only after physical child/descendant settlement. The receiver must reject every requested command outside that exact inherited subset. Neither argv, `--account`, `--profile`, a JSON body ID, a runtime-scope string, code identity, a missing observer nor the narrow open-command LocalAuthentication approval is such a grant.

A human terminal's installation/account command admission is a separate native review boundary. It must name the finite command's real required scope and cannot reuse the one-shot Profile approval as installation-wide permission. No new runtime/account action is authorized here. These missing producers must be implemented before broad commands can run; no command is silently removed from the supplied implementation.
