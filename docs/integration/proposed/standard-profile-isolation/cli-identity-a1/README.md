# Supplied CLI native boundary: actual remaining work

The current runtime successor preserves the complete supplied CLI and its command/RPC implementation. State-v2 CLI execution remains refused by the native wrapper before home setup and by the first executable SEA statement. No CLI product process, key operation, provider request or owner state was accessed during this audit.

Static inspection selected the exact frozen CLI addon, SHA256 `66368b6846d2842a5ee0ba3d5c6d5d094fd40098d7819dbb63ef17600c85c3fc`. Its indexed native definitions include both original C entry points and their original Swift implementations. It is a different addon from the daemon's retired common module. The daemon's unchanged PTY module and 50-import proof do not establish CLI compatibility.

REA evidence `ev_9257ab78578efdff820f8651e2ad424d69dbfb0457c0212a5da1fecd23bf4cad` and the exported bundle record the actual dependency/symbol observation. REA explicitly reports imports/exports as nonexhaustive. The separate `nm-0.txt` and `nm-1.txt` preserve the actual tool output; `actual-static-a1.json` binds command results and exact input bytes. Static native inspection did not establish runtime loading or behavior.

The current supplied CLI loader uses the original guarded addon. Its native command wrappers return a JSON string and execute async commands in a Worker; the original wrapper terminates the Worker after receiving its result. The CLI's configuration/auth/session-host paths also contain filesystem and network writes. Its device-registration schema correction and browser-routing commands are already source-integrated, but that does not admit the CLI into the native-owned profile/recovery boundary.

The shared native carrier resolves the original C entry points by name. A symbol-only rename would therefore require a paired carrier change, while still leaving the actual original installation/storage semantics unresolved. It would not solve startup, custody, writer settlement or migration and must not be advertised as CLI completion. No addon or carrier was patched in this audit.

The complete successor must preserve supplied commands and JSON/Worker behavior while routing native installation/secure-store/PDF/OS calls through the retained Aux owner, capturing the actual CLI home/target before any mutable read or write, and accounting for CLI tasks/children/background writes through physical completion. It must pair the native wrapper/host, ordinary and owned entry, fixed module/PDF paths, carrier call sites and exact packaging records together. Removing the current refusal requires those prerequisites and actual disposable runtime acceptance; a marker, environment flag, renamed symbol or successful link is insufficient.

The accepted app and completed runtime package remain unchanged. Signing, OS capability, real credentials and app lifecycle remain separate and ungranted.
