# Read-only verified journal prefix inventory

This one-file/seven-anchor successor composes over root's actual journal A3 dispatcher source (input SHA-256 `123155615f78c51b034c137522a1a4be59646d69237655691ee236cef6b0c1b3`). It adds two finite frame13 subforms inside the existing authority-v6 operation7 native UI channel. There is no C export, NAPI entry, new Profile/root/path selection or startup grant. The same actual Entry execution lock, native admission, owner/root/directory and generation validation enclose every request.

The new inventory performs one content-validation scan under the actual authenticated journal owner. It returns only the verified contiguous complete prefix and explicit first-uncertain/tail status. A partial file trio, gap followed by later files or complete trio with rejected content/binding/chain ends the prefix. Later fixed slots are inspected only for presence; invalid/partial files are never skipped into a trusted chain, overwritten, removed or promoted. Unsafe file metadata, IO failures or failed actual root/context revalidation refuse the request rather than producing a usable inventory.

**A zero tail status or empty prefix is never proof that no target-attempt or write occurred.** It only describes observed fixed journal files during this read. A retained in-memory unknown upload, a partial physical attempt and later work remain independent uncertainty. The native controller must carry tail uncertainty into recovery and requalify actual stores/owners; the inventory is unqualified data and does not authorize absence-based cleanup or activation.

Legacy frame10 and frame12 request/reply bodies are byte-identical. The private parser has a strict default: frame12 still refuses any partial or gapped tail; frame10 still validates only its requested complete predecessor prefix and retains its existing physical sync/readback and exact matching-upload settlement behavior. Only frame13 uses the separate read-only uncertain-tail mode. Its scan calls no Write/Sync/repair/create/delete operation and never clears upload `physicalOutcomeUnknown`, a pending mutable operation or a prior persistence holder.

The parser now computes the actual loaded capture and capture-receipt SHA strings once per scan and supplies them only to a private binding-codec overload. Existing binding and receipt bytes remain unchanged. Record payloads are read and verified once, with at most64 records and64MiB aggregate retained prefix payload. This avoids repeatedly hashing a64MiB capture for every predecessor.

Frame13 inventory retains the actual journal owner/root/directory with its verified prefix and a native-random read-cache UUID. Its second bounded subform selects only a captured prefix ordinal into the existing frame11 payload download path. Selection and every inventory-backed frame11 chunk revalidate that actual retained owner/root; the UUID and generation fields are correlation/data, never ownership authority. Replacing these read caches does not touch either upload, unknown outcomes or mutable work. The selected record shares Swift Data storage with the single retained inventory; an old inventory-backed download is discarded when a new inventory is installed, keeping the retained prefix bounded. This selector avoids frame10's repeated predecessor reread/sync when loading the complete prefix; frame10 itself is unchanged.
