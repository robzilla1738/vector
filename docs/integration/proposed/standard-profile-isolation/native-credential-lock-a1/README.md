# Fixed-role native ChatGPT credential lease

Source-only implementation of the `native-credential-lock-review` decision. This successor replaces the unsupported `lockf`/FD3 subprocess with a native BSD flock on a native-owned descriptor. It preserves the existing profile location, account SHA-256, permanent `.lock` inode, `aux.chatgpt.auth-lock.v2` marker, credential records, public-client provider flow and UI. Generic child descriptor policy is unchanged. There is no caller FD, caller path, profile selector or completion flag.

## Exact changes

- New `source/AuxChatGPTCredentialLock.inc` supplies three private linked-binding methods: `beginChatGPTCredentialLock(logicalKey)`, `withChatGPTCredentialLockSync(nativeToken, finiteCallback)`, and `closeChatGPTCredentialLock(nativeToken)`.
- Five literal changes to the selected `AuxDevelopmentWorkerHost.cc`: explicit limits header, forward declaration, actual Worker-close hook, include, three read-only binding registrations. `source/host-anchors.json` and `host.patch` pin the actual a4 selected host predecessor.
- One literal daemon change replaces only the private ChatGPT module preparation function. It captures exact non-writable/non-configurable native methods in a private frozen capability object. No renderer/API or generic file-operation surface is added.
- Five literal shim changes remove the inherited-descriptor subprocess and guard the existing store's eight complete synchronous methods. The transaction's async callback is **never** passed to the native synchronous guard. The closure captures each original finite method before installing non-writable wrappers. Constructor directory creation now starts from the native authenticated root, never environment-selected or arbitrary caller storage.

`source/transform.mjs` exports `transformAuxChatGPTNativeCredentialLock`, `transformAuxChatGPTCredentialLockShim`, and `transformAuxChatGPTCredentialLockHost`; each returns `{text,changes}`. `overlay.json` pins inputs, transforms, helper bytes, full source outputs and actual source-check evidence. Current base is the actual final a4 ordinary/dormant projection (182 anchors), actual shim `43f8ce1e…`, and successful native a3 link. Appending this daemon stage yields 183 total anchors / 151 added over the original protected source; the shim's five edits and host's five edits are separate derivations.

## Authority and physical lifetime

Native `CaptureBrokerOwner` selects the actual environment/Worker/Owner. `AuxNativeContextCopyStorageRoots` supplies retained authenticated control/task descriptors and generation. The task duplicate is closed; only fixed `local-only/chatgpt/<native SHA256>.lock` is opened under control. Directory components use `openat` with no-follow/private ownership checks. Marker parsing uses native V8 JSON parsing, checks own string properties, and preserves existing JSON semantics. There is no global JS parser invocation or caller-selected digest. Existing malformed/foreign/empty locks refuse; no inode is replaced, unlinked, truncated or silently repaired.

The lease reserves existing `broker_pending` before filesystem work, remains in the native registry independently of JS receiver GC, and binds its exact originating environment and Owner. Initialization itself counts as active work. Acquisition is nonblocking `flock(LOCK_EX | LOCK_NB)`; contention is a definite refusal. The old `lockf -s -t 0 3` operation uses this same BSD flock family. No process, observer cohort or new entitlement is needed for this operation.

Each actual synchronous store method enters the lease's finite guard before filesystem work. Nested `read → hostId`, `write → path`, registration and token-clear operations reuse the same account context. Wrong-account reuse, changed roots, changed native generations, closed leases, detached/replaced owners and Promise returns refuse. Promise/unknown outcomes retain `broker_untracked`; returning from a JS async transaction is not treated as native work completion.

The whole logical read/provider-response/check/write transaction keeps the lease. Abort closes admission; late provider work cannot write through the closed token. Its separate existing network lifetime still waits actual request/socket cleanup. Worker close and GC also request close. Actual descriptor close occurs only when admitted synchronous stack depth reaches zero. No raw descriptor is duplicated or exported. Successful close releases the exclusive open-file description; uncertain close is never retried by numeric FD and keeps pending/unknown accounting and the native Owner retained. Closing the lease says nothing about other HTTP, process, browser or Worker work.

This is the selected standard cooperative profile boundary. It does not claim hostile same-UID namespace custody. Existing native authority and drain gates remain in force.
