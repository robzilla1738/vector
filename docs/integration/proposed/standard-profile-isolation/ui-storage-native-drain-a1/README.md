# Native DOM-storage queue completion proposal

The current Chromium wrapper's `Flush()` calls Local/Session Storage control `Flush()` without a reply. Both service implementations schedule immediate area commits; returning from the wrapper does not report the result. Extension Chrome-local storage separately uses `LeveldbValueStore`, whose ordinary write path uses default LevelDB write options. A JavaScript storage acknowledgment, a one-way flush call or a prepared JSON snapshot must not be labelled a durable multi-store migration.

The two-file proposal adds `AsyncDomStorageDatabase::DrainCommitsForAuxMigration`. It collects current commits and places a sentinel after previously queued DB tasks. The mutation-task wrapper retains the first failed status on the DB sequence, without changing existing callbacks or results. The sentinel returns that status; an empty current batch cannot bypass older queued tasks. Status ownership survives already-posted work outliving the frontend. Reply loss/default invocation and frontend destruction produce failure rather than a successful completion.

This is a private **queue barrier only**. The caller still needs retained native profile/epoch authority, closed writer admission, loaded target areas and complete capture. It does not cover future writes or work that has not posted to the DB queue, grant migration/startup authority, acknowledge disk fsync, provide extension ValueStore completion or implement a multi-store journal. Failure is not a CLEAN receipt. The service successor below supplies internal callers; no Mojo or renderer migration endpoint is exposed.

## Loaded-area service successor

`project-services.py` and `service-source-plan.json` add four count-checked header/source changes in a separate overlay. Both LocalStorageImpl and SessionStorageImpl now call the paired DB barrier through `DrainLoadedAreasForAuxMigration`. They require an already connected disk backend and refuse unloaded areas, pending load callbacks, mismatched area databases, missing backends and in-memory fallback. Existing immediate commits precede the DB sentinel; lost replies or destroyed/changed services fail. Ordinary Flush behavior is unchanged. The native source checkout is unchanged.

Both actual service objects compiled with the real per-target Ninja commands, generated headers and the paired DB overlay. `actual-service-compile-a1.json` records inputs and objects: Local Storage `8c82b77c3f8a35b092858829f3ee22647ac6cb6df7b9b23248a1f1546adf8ca7`; Session Storage `1f834db6f881617bcc4b77affeffdc3307e2003e98c82ec2824035cff96f856a`. No full browser link or product execution occurred, and this code is not in the inactive packaged app.

This acknowledges only currently loaded areas. It does not establish that every required origin/page namespace was loaded or captured, settle unsaved editor memory, close native writer admission, sync the DOM database to disk or transact with extension storage. The authenticated browser importer and interruption recovery are still required. Do not interpret an empty current area map or successful queue reply as complete target coverage or a CLEAN profile.
