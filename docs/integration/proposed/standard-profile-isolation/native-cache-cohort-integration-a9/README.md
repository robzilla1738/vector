## Real remaining limits

- Creating a newly persisted map from an originally absent/empty native registration, including exact metadata-absence rollback, is not implemented. Such target changes explicitly refuse; an empty unchanged registered map may be captured truthfully.
- A mounted historical Session cache whose current interpretation cannot pair exactly with its old raw key format refuses. Unmounted historical maps can be normalized; no loaded view is guessed or reset.
- Unknown/tainted cache identities after a target attempt stay held when strict original-owner recovery cannot be proved. No silent cache reset or owner substitution is supplied.
- Backend custody and opaque cache tokens exist only in the actual current service/renderer processes. A durable cross-process restart recovery consumer is still required; map digests alone do not create it.
- The complete controller/journal transaction, directory durability, new recovery admission, whole-browser/daemon writer inventory and activation remain independent gates. `source_ready`, private staging, source/target sync, compiler success and observer payloads grant none of those authorities.
