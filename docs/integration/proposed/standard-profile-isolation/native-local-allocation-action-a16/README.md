# Native SQLite allocation action and real physical observation

This source successor supports a reviewed current-key target on an actual captured, empty, originally unpersisted Local map when the actual database-open result established SQLite. It uses the existing real `UpdateMaps()` allocator and actual unique metadata/raw-data readback. No backend type, storage key, map locator or generated ID comes from a renderer or UI request. Unsupported LevelDB absent-map creation still refuses before writing. Original source map IDs/digests remain immutable.

New append-only fields distinguish two facts. `allocation_requested` plus `allocation_action_sha256` describe the exact captured native key/ordinal, original complete empty source and planned full raw target. Aggregate `allocation_action_sha256` also binds complete original source topology. These action digests are not physical target digests. Until the real allocator ID is observed, `target_map_sha256` for that map and `target_topology_sha256` are empty. The existing target digest field is never silently reinterpreted or populated with an invented future ID.

The first commit attempt is already recorded and cannot run twice. After the actual batch and explicit backend sync, actual metadata readback must contain exactly one real row for the retained key and its allocated ID. Its complete raw data and all metadata fields must equal the original plan; other captured maps must match one retained exact source/target alternative, and the digest of unrelated metadata must remain identical. Only then can `allocated_map_id`, `allocation_observed` and complete physical target digests be reported. A failed or unknown write stays held: a fresh read under the same original lease can resolve verified source absence or the exact known target; it cannot retry the allocator or bind a changed identity.

Original-absence recovery first performs that same exact retained-alternative CAS, then removes the actual observed map through the existing native Local deletion owner. Commit `3087484af` is required: it fixes the real SQLite metadata-before-ID-lookup bug and removes actual raw rows before metadata in the same transaction. If no allocation was observed and source absence is verified, rollback does not create or delete a map. A partial recovery can finish only the original exact alternatives. No blanket overwrite, caller-supplied recovery map, reset or schema change is introduced.
