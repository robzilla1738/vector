# Refresh transport settlement and skill extraction successor

This is a separate source successor to actual standard daemon projection a1. It does not modify the frozen 86-edit composer, old projection, stage, native build inputs or accepted app. It must be paired with the fresh-entry native descendant observer; it is not compatible with the old native host.

## Concrete changes

Fifteen exact count-one edits apply independently to the ordinary source and dormant entry. `source/transform.mjs` exports `transformAuxRefreshAndSkill(text) -> {text,changes}`. It pins its source/helper/anchor inputs and rejects anchor conflicts. It accepts another independently reviewed disjoint adapter's output for integration; the manifest records the exact a1 inputs and isolated outputs checked here. Root must freeze the combined chain and independently project the resulting ordinary source again.

**Skill extraction:** remove only the unconditional `noteUntracked()` at the start of `extractSkillArchive`. Its original retained wrapper, awaited pipeline, reader/FD closure, all three `tar`/`unzip` calls, final renames and three cleanup removals stay intact. `auxRunSkillArchiveTool` still waits both execFile's completion callback and child close. Failures still reach retained failure/unknown handling.

The actual spawn chain is `node:child_process.execFile` → Node `spawn` → native `ProcessWrap::Spawn` → `AuxNativeExecBeginCurrent`/`AuxNativeExecEnterUvSpawn` → original libuv child creation and reaper. The selected isolated archives contain the reviewed patched process_wrap/spawn_sync/libuv objects (continuation/build/archive-plan.json and evidence/archives.json). The fresh observer now owns the separate descendant cohort. Its admission, stream-loss refusal, cohort fence and original direct-child reap remain necessary. Merely relinking this JavaScript with a historical host would reintroduce missing descendant custody.

**Refresh transport:** the exact seven registered refresh graphs were inspected: Meta, Anthropic, GitHub Copilot, Codex, Claude-code, xAI and Kimi. These refresh bodies use HTTP; callback servers and interactive subprocesses occur in their distinct login workflows, which this adapter does not invoke or modify. Existing Codex account/broker routing remains unchanged; reviewing its legacy registered refresh implementation is not an assertion that it is the active subscription credential path.

The eight HTTP functions are `postJson$1`, `fetchJson`, `fetchWithRateLimitRetry`, `refreshToken`, `mintApiKey`, `refreshAccessToken`, `postForm` and `postJson`. Only their fetch calls use the scoped helper. Outside an actual reviewed refresh invocation the helper calls the original fetch unchanged; global fetch and dispatcher are not replaced. Membership uses the real registered OAuth object and exact bundled loader objects. Unknown provider/loader paths retain the original one-way unknown marker.

Within a reviewed invocation, the actual bundled Undici Agent/Client and connector use the original daemon's HTTP/1 configuration. Each client is retained even if its Agent evicts it. Connection callbacks, socket close events and DNS callbacks have independent lifetimes: Client.destroy may return before an in-flight connector completes, so it is not treated as the final physical proof. Abort requests destroy only this refresh's transports; the retained native broker operation waits for all callbacks and physical socket closure. No timeout resolves those lifetimes. Lost callbacks remain pending; cleanup failures mark unknown.

Responses are consumed through the actual reader before the supplied parser receives a buffered Response, preserving status/headers/URL fields. A response above 8 MiB refuses and awaits reader cancellation. The buffer is in memory only and is never logged or persisted by the helper. Claude-code refresh now propagates the supplied abort signal through its original request helper; its existing request timeout remains cancellation, not settlement.

**Credential transaction:** the actual FileJsonStoreBackend.withLockAsync now retains the entire existing lock/read/callback/write/unlock lifetime under the native background broker. The original callback-based graceful filesystem implementation is wrapped for the lock's five actual asynchronous operations; its callbacks and any nested operation remain retained through unlock. A pending proper-lockfile heartbeat stat callback now returns immediately if the lock was released, preventing a late utimes/reschedule. Unlock failures are no longer swallowed and mark unknown. Existing atomic write and credential-directory fsync refusal behavior remain unchanged. This is a resource-lifetime change, not a claim that every persisted write is durable; the original atomic writer's actual contract still applies.

## Integration requirements

- Apply this adapter after the actual a1 composition (or a frozen disjoint managed-producer successor). Do not edit/reuse the historical a1 output receipt.
- Pin the adapter, manifest, changes and helper. Compose ordinary and dormant independently and rerun the original entry projector for exact equality and unchanged loader.
- Pair with the compiled fresh-observer main/WorkerHost/observer and the selected patched Node/libuv archives. The manifest records source/native-plan reference hashes; root must establish the final exact native/source pairing. No old-host fallback is permitted.
- Preserve all native/JS unknown flags on actual failure. No flag-clear API or synthetic shutdown receipt is added.
- Source-only now: no provider request, runtime activation, native build, OS grant, product launch or signing.
