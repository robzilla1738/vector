# Shared native frame13 codec

This creates one header-only helper at `chrome/browser/aux/ui_storage_migration_journal_protocol.h`. It parses the exact A26 frame13 inventory/selected-record protocol and builds bounded frame13 requests plus existing frame11 payload reads. It contains owned factual data only: no Profile, root/path, RPC executor, approval callback, lifecycle capability or readiness/activation operation. Navigation owns the actual authenticated controller consumer and root owns projection/GN/compilation.

`aux::ui_journal::Inventory` exposes `inventoryID`, `sourceGeneration`, `currentGeneration`, `records`, `firstUncertain`, `tailStatus` and `tailPresent`. Record summaries have `ordinal`, `kind`, `receiptSHA`, `payloadSHA`. `SelectedRecord` exposes `ordinal`, `payloadBytes`, `kind`, `receiptSHA`, `receiptJSON`. All buffers are owned arrays, vectors or strings; no borrowed span or raw buffer pointer is retained.

The parser requires exact header/row sizes, at most64 contiguous records, kind1 only at ordinal0, kind1–8 bounds, nonzero digest fields, positive native generation data, a native-random UUIDv4/RFC4122 inventory ID and consistent tail geometry. A partial/invalid candidate must begin at the prefix count with actual tail presence; a gap requires a later fixed slot and cannot begin at ordinal63. A zero tail status is named `kNoneObserved`, never complete/ready/no-write. These checks do not authenticate the native producer or prove that no later write occurred.

`ParseSelectedReply(bytes, inventory, ordinal)` requires an actually captured ordinal in the supplied inventory, exact same inventory ID, expected ordinal/kind/receipt SHA, payload1–64MiB and exact bounded receipt length. It verifies SHA256 over the received receipt bytes against the captured digest. The controller still validates canonical receipt JSON, previous receipt chain, immutable intent and actual native owner/generation, and verifies the complete payload SHA after frame11 chunks. Parsed JSON claims and random IDs are data, never authority.

The three request builders return optional owned byte vectors. `MakeInventoryRequest(journal)` emits17 bytes; `MakeSelectRequest(journal, inventory, ordinal)` emits37 bytes and only a captured ordinal; `MakePayloadReadRequest(journal, ordinal, offset, count, payloadBytes)` emits29 bytes. They enforce non-nil journal IDs, ordinal0–63, payload1–64MiB, chunk1–8191 and subtraction-safe offsets. Integers remain little endian. No builder sends a request, modifies an unknown-write holder or chooses an actor.

The exact producer source/protocol and base span/crypto interfaces are pinned in dependency-pins.json. The implementation uses bounds-checked base spans, fixed arrays, safe copies and the real existing SHA function; no unsafe cast, raw-buffer arithmetic, warning suppression or span member is added. Source-plan.json records the actual native absent-file precondition and output hash. The root-owned GN request adds this public header and its actual `//crypto` public dependency to the existing interface target; no new architecture or executable target is introduced.

Three focused optional boundary case sources cover malformed prefix/tail geometry and sizes, selected receipt hash mismatch, and little-endian builders/offset overflow. They are not production projection inputs and were not compiled or run in this lane. No native build/API/product execution or broad test suite ran; static source checks do not establish runtime acceptance. Root should include the helper in the real controller, compile under the original relative-source Chromium checks and run only the focused cases if useful.
