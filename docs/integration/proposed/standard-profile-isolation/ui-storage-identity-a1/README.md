# Versioned Aux UI preference names and offline preparation

Eight nonsecret UI preference keys now use explicit Aux v2 names. All 18 literal reader/writer/event changes are count-pinned against the original source and integrated in the real state-v2 UI pipeline. They cover local Search/Ask mode, native tab-style mirror, confirmation choice, permission-mode mirror and onboarding-helper folding, plus Chrome-local color scheme, capture enablement and Tidy Tabs prompt. Existing supplied parsing, defaults, component structure, styles and behavior remain intact. Compatibility state-v1 is unchanged.

The offline helper is `vendor/provided/aux-ui-storage-migration.mjs`. It performs no filesystem, browser, native or network operation and is not a product runtime fallback. The caller supplies explicitly captured snapshots for the fixed Aux extension origin and one profile. Typed values retain their exact representations, including false, raw strings and prompt whitespace. Existing equal targets deduplicate; conflicting or invalid values and wrong storage/profile/origin boundaries refuse. Unknown keys and draft/auth data remain unchanged and counted as remaining legacy entries rather than being blindly renamed. The input snapshots are never mutated and no defaults, IDs, permissions or accounts are fabricated.

`migrateAuxUiPreferenceBatch` prepares both distinct storage scopes for one profile before returning any commit candidate. Its versioned receipts contain hashes, static moved/equal key names and counts, not stored values or profile IDs. Returned copies omit the recognized legacy aliases; original captures remain available for caller-owned backup/rollback. Neither a prepared snapshot nor a receipt authorizes a real write or startup.

The legacy map stays in the source-side importer, outside delivered product code. Product readers use only the new Aux names for these keys. Existing profiles require a separately authorized, stopped-writer export/import transaction with raw-byte/ownership validation, backups, durable writes and complete recovery before activation. This helper is the in-memory preparation step; actual Chromium Local Storage/extension-storage export, transactional import and native admission association are **not yet implemented or accepted by this slice**. Do not open an existing profile against the new key set without that migration. The accepted app/profile is unchanged.
