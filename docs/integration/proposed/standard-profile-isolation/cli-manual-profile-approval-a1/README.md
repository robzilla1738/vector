# Native manual CLI profile approval

This successor prepares an actual manual-target producer while keeping the CLI launch/runtime gates intact. It adds no ordinary browser UI/style changes and is not registered, invoked, compiled, signed or packaged by this lane.

`ManualProfileApprovalRequest::BeginForActualWindow` accepts the genuine native `BrowserWindowInterface` and the exact authenticated `Invocation` retained from the private Mach request. It cannot accept a profile path, parent PID, marker, environment value, JSON proof or approval Boolean. The selected Profile comes from that real loaded window. Its registered profile name appears in a native LocalAuthentication reason; argv/environment/token/URL text never appears in the prompt.

The actual `LAContext` uses `LAPolicyDeviceOwnerAuthentication` and zero Touch ID reuse duration. Only its internal OS reply can create the private `ApprovedCliInvocation`. That lease retains the same Invocation and actual weak Profile/window identity, profile ID, native cookie-binding and restore epochs, and protected-startup admitted generation. It expires after 15 seconds. A successful callback is revalidated on the UI sequence, after returning from the OS queue. The actual native NSWindow must still be visible/key and the app active; no Chromium `IsActive()` Boolean alone is treated as OS focus. A restore/rebind/profile destruction/browser shutdown/client birth change rejects it.

Known managed Aux clients refuse before and after the OS callback. Unknown custody does not silently become manual: it requires this explicit OS user-presence approval for the displayed concrete Profile and same private invocation. This implements the root-approved manual-target option; it does not create inherited task grants. Native task CLI support remains separate.

The owner retains the pending request. At most one exists on the UI sequence, with a 60-second deadline. A 100-ms native timer detects actual client death, target revocation and authenticated SIGINT/TERM/HUP, invalidates the LAContext and sends definite no-start to the retained terminal reply right. Destroying/abandoning a pending request or unused approval also reports no-start, so the terminal does not hang. Late OS callbacks use a weak receiver and cannot resurrect a canceled request. No OS authentication prompt was invoked during source preparation.

`source-plan.json` contains the exact one-anchor successor of the A1 Ingress header (adds only two native friend classes) and hashes/destinations for the three sources. `dependency-pins.json` records the actual native Profile/cookie/window APIs, macOS LA SDK header and Chromium callback-ownership example used here. `static-check.json` is limited source replay/inspection evidence, not a compiler or runtime result.

Remaining integration: root must choose the real native browser UI entry point, retain pending approval through shutdown and hand the private approved Profile lease into a genuine retained-daemon target gateway. A copied Profile pointer or an approval success Boolean is not a daemon target grant. The actual proxy owner/root-fileport/Worker/PDF/OS/child role image graph remains missing. BrowserInvocation still refuses all raw ingress, the A1 retained factory remains private/uncalled, and the native frontend's private-child/ordinary SEA quarantines remain. These sources must not be selected as a working CLI until those pieces are paired and actually verified. Root owns the focused Objective-C++/native compile, LocalAuthentication framework dependency, registration, packaging and later bounded authorized runtime checks.
