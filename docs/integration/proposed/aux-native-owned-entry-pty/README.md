# Owned-entry PTY projection and actual session lifetime map

Inactive successor resource only: this composes the exact existing owned-entry projection with the embedded-arm64 fixed PTY loader. The original full source and e3ca quarantined input are independently pinned. The actual generated Node resource had already replaced `path.dirname(process.execPath)` with `__auxDaemonMacOS` in the original loader; the new adapter recognizes exactly that one existing adaptation and no broader normalization. It returns a new proposed string; it does not edit the input, default SEA/CLI/fallback refusal, accepted app, UI or current native startup. No package/admission is selected by JS. The real native executable must still register its genuine private linked binding and authenticate the exact sealed resource before use.

This projection chooses the fixed PTY package under the running native daemon bundle, so packaging must put the exact sealed node-pty package there. Merely retaining an older source package elsewhere does not satisfy the new path. Gate owns the separate `aux-native-embedded-pty-policy` v3: fixed arm64 MH_BUNDLE plus separately validated executable helper, exact Aux signatures/resource seal/bytes and root-owned before-load namespace custody. The ordinary module require still initializes its Node-API exports after native preload. Neither this projection nor image validation establishes child/process-group drain or permission to run a terminal.

The actual supplied lifetime paths below are recorded as exact count-checked source snippets and offsets in source-map.json. Source names describe real JavaScript object callbacks; they are not native `base::Process`/kernel child-handle provenance.

| Actual source boundary | What is actually owned/observed | What it does not establish |
| --- | --- | --- |
| prepareSessionSpawn / acquireAgentRuntimeUse | An idempotent JS release closes a runtimeUseCount installation-replacement lease; permission/cwd/env and detached request are prepared | Does not mint native descendant ownership or close spawn admission |

`waitForRuntimeUses()` waits only its cooperative JS count to reach zero before runtime replacement. It is neither an independent-process exclusion mechanism nor migration custody. PTY yield commands attach lease release to actual exited promise; background blocking bash releases when the caller returns its background result. These distinct semantics must not be merged into a false lifetime receipt.

The actual current native prepared owner/WorkerHost owns guarded command handles and explicit PDF/macOS-utility admission/drain. It has no PTY pending-owner/token registration or actual pty.fork callback consumption. The direct-daemon supervisor owns the launched daemon, not every shell descendant; no scanned JSON/JS PID list can upgrade that to native ownership. Image admission for pty.node only measures code, not child lifetime. Environment teardown/Node loop exit likewise does not prove shell process groups stopped.

Smallest real next lifecycle integration needs the actual spawn boundary to retain native creation identity and exit observations before returning to JS, a permanent native spawn-admission generation, in-flight spawn registration before callback-capable work, and pending children retained through Environment cleanup until actual observation. Process-group children may escape/daemonize: a real supported descendant containment/ownership policy is required before any all-writer claim. Existing JS cancellation can remain a user behavior path, but cannot supply that authority. This proposal deliberately implements only the exact resource projection and identifies the missing native fork/exit bridge instead of treating logical store cleanup as custody.
