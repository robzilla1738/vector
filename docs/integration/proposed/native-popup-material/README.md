# Supplied native popup material

This proposal restores the supplied native permission/popup material path instead of the independent popup HUD backdrop. It contains eight pinned baseline/output files and an exact replayable `native.patch`. Shared Chromium has not been edited, compiled, signed or launched by this proposal.

Apply after the third-background-slot proposal: popup CC `03b6bc180c17ab9a34b6711eba83265ebe93921312b826493bfb7001c74e09d3`, focus MM `732b6ec397cff11aaf94e50f16229fc6b7f0195ca7f959bd6c1bce9c4000da03` and local BUILD `c8d5eef1a5161f425fde0c2544c17f80e83c9d053989bb991a6d9944478ef9b7`. The remote-Cocoa bridge baseline is the existing browser-vibrancy output `3096ae5b3d6d94269aea5768fdf5f3ac35ebfc303b81579ed0ada0e5a466a660`; all other exact pins are in `manifest.json`. Root v67 contains those inputs. Composition must reject any mismatch rather than overwrite newer source.

The supplied `NativeWidgetMac::PopulateCreateWindowParams` at original arm64 RVA02132740 sets one native flag for exactly `DesktopMediaPickerDialogView`, `DesktopMediaPickerVisualEffect` and `PermissionPromptNotificationBubble`. The original creation path at02132a58 passes this flag to `NativeWidgetMacNSWindow.usePermissionPromptVisualEffect`. The property is present in the supplied Objective-C metadata, with getter04383104 and setter04383114. This proposal restores the same names, flag, property and assignment through the current Mojo creation contract; ordinary unnamed widgets retain false.

Both actual popup constructors use `DesktopMediaPickerVisualEffect`: supplied decompiles0459577c.c lines320–332 and04598780.c lines278–316. Their native rounded corners differ: main16 and options12. The proposal retains main16 and restores options12, with no new minimum dimensions or independently selected layout.

The recovered `CreateContentView` at04383880 gates browser windows separately, then consults the flag for nonbrowser windows. Its effect is:

- Below macOS27: `NSVisualEffectMaterialPopover` (6), BehindWindow (0), Active (1), width/height autoresizing, layer backing and positive-radius clipping.
- macOS27 and later: `NSGlassEffectView`, Regular style (0), the optional corner radius, an explicitly allocated `NSView` content host and the original guarded `_setVibrantBlendingStyleForSubtree:0` selector. The original threshold is27 even though this SDK makes the Glass class available from26; the proposal preserves27.
- The existing supplied compositor hosting helper attaches the compositor inside Glass `contentView` when available, otherwise to the bridged root. The bridged root keeps positive popup clipping with continuous corners.

The independent `ApplyAuxPopupMaterial` selected HUD material, applied a different Reduce Transparency fallback and only styled the main popup. It is removed rather than layered over the recovered effect. Its QuartzCore dependency is removed from the popup's local BUILD file; AppKit and every other dependency remain. The common bridge already owns QuartzCore usage and its dependency. No new shared GN target or registration is needed. The Mojom addition does require regeneration and compilation of both creation/hosting sides.

The existing browser-window material factory, preference observer/timer, update/fullscreen lifecycle and compositor hosting helper remain byte-identical. The popup activation capture/clear/restore functions and current three-background-color implementation remain unchanged. This does not change supplied extension CSS, routes, components or wire contracts.

`source-evidence.json` pins the original universal framework, exact arm64 slice, relevant decompiles, Objective-C metadata and SDK enum definitions. Three fresh REA dossiers under `evidence/` retain assembly, pseudocode, evidence IDs and coverage limits for the name gate, window flag handoff and content host. Raw function hashes match the original Mach-O sections. Headerless extraction does not establish external call identity by itself: `decode-selectors.py <pinned-arm64-Mach-O>` resolves the original call veneers/Objective-C selectors and imports; its replay output is retained in `evidence/decoded-selectors.txt`. In particular043839c4 resolves the flag getter,02132b0c the setter,04383a70 `setContentView:`, and04383dd0/04383ddc/04383de8 the material/blending/state calls. The selector is guarded in the original and remains guarded here.
