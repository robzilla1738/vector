# Actual data-protection view migration

Chromium155 constructs DataProtectionUIController for normal BrowserView windows. Its real contents-view controllers cache profile PrefService and subscribe to real per-tab DataProtectionNavigationController watermark and screenshot callbacks. Keeping those cached prefs across a profile identity change is incorrect. This platform adaptation preserves the window controller, per-view controllers, tab navigation controllers, scoped user-data registration and WebView attachment subscriptions.

CanPrepareForAuxProfileSwitch(target) is cold: actual normal regular source/target, stable view roster, exact actual source prefs, attached WebContents identity/profile/model containment, no pending transfer or active callback mutation. PrepareForAuxProfileSwitch(target) captures weak real source/target profiles, suppresses attachment/callback updates, retires genuine source navigation subscriptions, and retains each per-tab policy. Where screenshot protection is compiled, the actual window becomes restrictive during transfer; this changes no OS permission or per-tab policy.

RebindForAuxProfileSwitch runs only after real target Browser identity commit with an empty model and empty contents views. It updates only each real cached prefs pointer. FinishForAuxProfileSwitch runs after genuine target insertion. AbortAuxProfileSwitch requires the original source identity, no target rebind and actual source tab restoration. Both resume the real per-tab navigation controllers and apply actual current profile watermark settings and screenshot policy. Empty views clear stale watermark text using genuine current prefs. The old source's renderer callbacks cannot update target views. Mutation scopes use weak lifetime callbacks and prevent reentrant migration; no UI redesign or replacement policy controller is introduced.

Public browser build flags are exposed by the existing enterprise header target. Metadata pins exact three inputs and outputs; independent patch replay passes. Native compilation and actual behavior acceptance are still pending. This proposal does not activate profile switching.
