# Native sidebar and search: actual supplied routes

Proposal only; shared checkout unchanged, no build or browser execution. Apply after the combined supplied profile-security/bootstrap/classification work. `manifest.json` pins three frozen native baselines and proposed outputs. No GN/schema/registration or layout changes.

Actual mounting is through `vertical_tab_strip_region_view.cc` (AuxSidebarView child, shown while expanded) and `vertical_tab_strip_top_container.cc` (AuxAgentPill child), rather than a direct BrowserView child. These are reachable native actions under the vertical-tab preference. The footer/profile menu and task buttons still navigated to independent `index.html#/tasks`, `/chat`, `/chat/<id>` and `/settings/general` routes. The supplied Agent has no index.html; those routes therefore do not recover the actual view.

The proposal routes the profile-menu Preferences action to `main.html#/u/<actual account>/settings/general`; task/activity buttons to `/u/<actual account>/tasks`; new task to `/tasks/new`; task rows to `/tasks/<actual session>`. It resolves the actual profile account through authenticated `FetchProfileSecurity`, checks current installation authorization and actual unlocked/onboarding state, then uses the returned numeric ID including zero. It never falls back to daemon currentAccountId, hardcodes zero or borrows another profile. Incomplete/unavailable state goes through the existing profile gate and explicit native error; it does not silently open another account. Browser-window weak pointers prevent navigation after the target window closes. Existing view geometry, menus and labels remain untouched.

The native search host previously opened absent `index.html#/tab-search`. It now opens actual standalone `tabsearch.html`. Its former metadata-only `ReadProfileSecurity(...).allows_browsing()` check can never establish a configured/unlocked supplied Vault: the new metadata reader intentionally leaves those fields locked until authenticated PWM verification. The proposal replaces that check with `FetchProfileSecurity` and rejects authorization changes during the fetch. Invalid explicit daemon-port configuration stays unavailable. The source search UI uses `window.close()` and Shift+Command/Control+A; its existing WebView CloseContents/Escape behavior is retained. No speculative resize filter or shim is injected.

`docs/source/provided-native-surfaces-inputs.json` pins the original task/settings route definitions, actual search HTML and search close/shortcut anchors. Patch-check and replay in an isolated temporary tree pass; all output hashes match. Native C++ compilation, real extension host behavior and packaged observation remain pending. These corrections restore existing native entrypoints; they do not establish native visual fidelity or repair the task feed's separate transport/projection/action contracts.
