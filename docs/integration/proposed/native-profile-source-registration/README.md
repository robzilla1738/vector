# Profile and sidebar native source registration

Register the staged original profile gate, account reader, saved identity, profile header controller and retained preview admission in their actual native targets. Keep the blocking state reader/probe separate from the browser identity and asynchronous security client. The gate header is an interface target; its Browser-dependent implementation compiles in full UI. Preference registration has its own low-level target so browser prefs do not depend on the gate implementation. Direct consumers declare the newly separated dependencies.

This proposal applies after v224 and changes no runtime policy. GN generation, affected compilation and actual popup/sidebar observation remain required.
