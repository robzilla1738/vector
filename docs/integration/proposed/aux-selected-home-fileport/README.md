# Authenticated selected-home fileport transfer

Inactive source composition, not compiled or executed. This adds a distinct complex v2 Mach transaction alongside the unchanged v1 heartbeat protocol. It changes no app, startup gate, native checkout, GN, UI or packaging.

The child has no FD/path payload API: `AuxSendAuthenticatedFreshColdHome(nativeParent, readyService, timeout)` calls the actual `AuxCopyAuthenticatedFreshColdHomeDescriptor` producer. The required c89c613f2 producer admits only the real provider phase, recaptures current terminal/scoped authority and four target rows, and revalidates around its retained-home FD duplication. A reserved or merely staged home cannot use this route.

The parent receives a kernel fileport from its actual direct waitable child. It repeats PID/birth/PIDversion and exact live code verification, derives the child's real `SecStaticCodeRef`, authenticates its fixed sealed fresh-bootstrap policy, and retains that policy's actual private parent FD. The directory must be private0700/no ACL, readonly, an exact `aux-home-<lowercase UUID>` immediate physical child, and match a no-follow `openat` dev/inode check. The received fileport right is destroyed only through the actual received message buffer; the independent directory FD is retained.

Only successful actual exchange constructs the private transfer. `OwnedNativePeerChild::TakeSelectedHome()` promotes it once into private-constructor `SelectedNativeHome`, retaining the actual launch/reap owner and directory. Each directory duplication repeats real peer/code/resource/physical-FD checks. Final release closes transport admission and retains unresolved actual child exit ownership through the existing quarantine; it never kills or reconstructs a child from a PID. Unknown Mach send cleanup is recorded and closes admission rather than guessing right ownership. A lost ACK may leave a pending authenticated parent transfer; retry does not replace/adopt a second transfer.

## Remaining actual integration

The actual native parent must launch/service its owned child, call the child transfer only after that service's real provider readiness, take and retain the typed selected home, and retain/monitor both child/provider lifetime through browser startup. A transferred FD authenticates the selected physical home at transfer time; it does not by itself prove ongoing provider readiness, all-profile writer custody, installation admission or safe restart after child death. No profile launch or existing first-refusal gate is changed here. Fresh-only ownership does not implement migration of historical installations.
