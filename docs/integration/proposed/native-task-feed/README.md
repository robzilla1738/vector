# Native sidebar feed: supplied transport and popover contract

Proposal only; shared native checkout untouched by this lane. Apply after the combined supplied profile-security/binding work. These three file baselines are disjoint from `native-surface-routes`; each input/output is SHA-256 pinned in `manifest.json`. No GN/API schema or view geometry edits.

The supplied daemon already implements `/session/for-chrome/chats` and its account-scoped pin/unpin/mark-read/archive/delete/rename/move-to-project actions. Those actual routes are preserved. The existing native feed nevertheless had three concrete incompatibilities:

1. It used metadata-only `ReadProfileSecurity(...).allows_browsing()` for listing, task actions and agent-tab requests. Supplied metadata intentionally cannot claim an unlocked Vault. All three paths now use the authenticated PWM `FetchProfileSecurity` client, reject changed installation authorization and revalidate the profile/account. A response is checked again before publishing the task snapshot. Invalid configured ports remain unavailable rather than falling back to a different port.
2. It implemented a second challenge/token client with a hardcoded independent token type. The browser supervisor already owns the original supplied token/signing flow. The proposal removes the duplicate challenge/session/expiry state machine and takes only its live `BrowserPlatform::authorization()` value. No wire protocol is renamed and no key/unauthenticated fallback is introduced. Requests retain credential omission/cache prevention and now explicitly reject redirects.
3. It expected `popover.request.title/message/operation`; the supplied projection actually sends `{id,kind,title,body,actions}`. The parser now accepts bounded flat metadata and validates actual action sets: `permission-approval` has approve/deny; `ask-user-question` has answer; `draft-approval` has review. A pending task no longer invalidates the entire chat list because it lacks a nonexistent request object.

The existing native review bubble uses the actual Approve/Deny labels for permission approval. Answer/Review opens the supplied conversation rather than inventing binary resolutions for those kinds. The request adapter translates its existing native callback body to the original **global** `/session/for-chrome/resolve-popover-action` endpoint with `sessionId`, `popoverId` and `actionId`. The daemon validates the current popover/action and resolves only permission approvals. Successful decisions open the actual conversation through the existing callback, matching the supplied endpoint's `clientAction:"open-url"` response behavior. No arbitrary returned URL is navigated. Normal task action endpoints remain unchanged; failures still surface errors rather than empty success.

`docs/source/provided-native-task-feed-inputs.json` pins the actual projection, popover kinds/action metadata, HTTP routes and approval body schema, using seven exact-count/offset anchors from the previously extracted static daemon. That JavaScript was never imported or executed. Changed C++ regions were formatted with Chromium style; patch-check and isolated replay pass, with every replay output equal to the manifest hash. Native compilation and actual disposable task/approval observation remain pending; no network, owner state, Keychain or OS grant was accessed.

Remaining distinct gap: the old native agent-tabs bubble calls `/session/for-chrome/agent-tabs[/close|/cleanup|/policy]`. That literal route is absent from the pinned supplied daemon. This proposal fixes that path's security preflight but does not invent a successful ledger API. The existing native bubble will continue to report unavailable on its actual failed request. Adapting it to the supplied session-tab/ownership mechanisms needs a separately source-backed contract; it is not covered by this feed checkpoint. Native sidebar/frame visual acceptance also remains outstanding.
