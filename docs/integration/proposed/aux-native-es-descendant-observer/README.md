# Native macOS27 descendant event observer — inactive source

This component constructs the real `es_new_descendants_client`, subscribes only to kernel NOTIFY_FORK/EXEC/EXIT and decodes the real SDK message callback synchronously. It has no production synthetic-event source, JS constructor, PID registration, policy Boolean, fallback systemwide client or authorization receipt. macOS27 availability is checked before the API. The actual SDK requires the Endpoint Security client entitlement; it states that this descendant-only API requires neither root nor TCC. This source grants none of those capabilities and has not invoked the factory.

Actual native embedding must call CreateBeforeFirstNativeSpawn before its first real child creation and before Node/userland. The method's name is an integration contract, not proof that an arbitrary caller previously had no children. No initial census is fabricated. Existing process/native entry integration remains external and inactive. Current browser/daemon startup, policies, accepted UI and ordinary PTY routes are unchanged.

The observer copies only process PID, real kernel birth time, pidversion, observed parent relation and event counters into bounded native state. It does not read command arguments, environments, files or credential material. Exec is handled as a new execution of the same PID/birth identity, because the SDK explicitly says exec changes pidversion. EXIT removes only that actually observed process instance; it is not a second waitpid/reaper. Completed instances are not held in a permanent finite request cache, so sustained sequential spawns do not exhaust active capacity. Active-capacity overflow, malformed identities, unsupported message versions, handler failure and sequence discontinuities stay sticky unknown.

Per-type and global sequence values are checked only after their first actual observed values. Only global gaps add to the missing-event count, avoiding double-counting the same loss. Initial sequence, potentially missing final events, existing descendants, default muting and a delivery barrier remain unproven; contiguous observed counters do not prove complete coverage. The observed process vector is an event cache, never a complete census. There deliberately is no drained/empty-success API.

StopObservation serializes actual ES API access, does not hold the event-state mutex across unsubscribe/delete, and refuses reentrant handler deletion. Successful delete proves observer resource cleanup only, not that any process or writer stopped. A deletion error is terminal cleanup unknown: the potentially deleted client pointer is never retried. Native state remains in process-owned retention and is counted by RetainedCleanupUnknownCount. Wrong-process calls are distinct before locks; inherited retained state is not released through foreign-process API calls. No process is signaled, suspended or resumed by this observer.
