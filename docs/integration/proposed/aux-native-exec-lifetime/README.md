# Source-only actual exec/session lifetime successor

This is a count-checked successor of the exact owned-entry PTY projection, not a default staging or accepted-app change. It reuses the supplied functions/classes, preserving shell options, output/tool responses, UI, normal yielded/background return timing, terminal APIs and source-known termination signals. No native module is executed and no native authority is created by these JavaScript observations.

Changes at actual producers:

- spawnSessionProcess attaches release to the real ChildProcess close callback immediately after obtaining the child; caller release after a background result cannot release early. It now forwards the existing caller signal through the actual sandbox wrap/spawn path.
- A source-known onStart callback runs after actual sandbox preparation/abort checking, immediately before Node spawnCommand or the actual PTY spawn call. A throw before that phase can release. A throw after invocation retains the actual runtime lease/release closure and unknown reservation, without deciding from exception text, PID, timeout or caller Boolean. There is no automatic retry or unknown-clear API.
- Successful yielded PTY retains its real onExit-based promise; non-PTY adds a separate actual close promise so an error/early UX promise cannot release installation use prematurely. User-facing exited behavior remains unchanged. The lease is not awaited before returning a background response.
- executeYieldedCommand reserves in its real store before awaiting spawn, attaches the actual returned handle and session, and binds lease release to actual close/onExit. A delayed handle from a canceled generation is retained and signaled; the fact of signaling cannot remove it.

Store integration:

ExecSessionStore retains actual pending reservation and process/session objects independently of its logical visible ID map. terminateAll captures/removes old logical sessions and rotates generation/controller before invoking abort callbacks, so reentrant new-generation work is not accidentally cleared or terminated. It signals/disposes the old generation promptly while retaining its actual handles until their close/onExit promise succeeds. A rejected close observation stays unknown. dispose permanently closes this one store's spawn/register admission; ordinary terminateAll still permits the next generation for current permissions, matching existing use. A process-global set retains closing/unknown stores through agent/session disposal; no timer or store-map clear asserts drain. Unknown pre-handle attempts retain their release closure and remain unresolved.

observeTermination returns raw generation/admission and pending/unknown/live/retiring counts. GlobalAgentSessionServer.terminateExecSessions returns those actual loaded-store observations plus the existing pending session-creation map size; existing shutdown callers can continue ignoring the return. It does not assert that asynchronously creating sessions, other spawn families, MCP/helpers, native process groups or foreign writers are closed. Existing daemon4s/5s shutdown bounds still are not exit evidence. This change adds no native/quiesce endpoint, authorization receipt, generic PID registration or process kill beyond the original cancellation requests.

Actual native descendant ownership remains missing. A pty.node image preload is code admission, not process lifetime custody. A genuine native spawn/process-group bridge must consume actual creation/exit provenance and close admission before any migration/all-writer claim. JS counts, retained records and numeric process IDs cannot grant that authority. Unknown runtime leases intentionally retain rather than invent successful cleanup; production recovery of those rare ambiguous attempts needs real native observations, not a reset flag.

Focused evidence: the complete projected module passed syntax checking without evaluation. Captured-effect fixtures execute the actual modified producer/store/yielded functions only: background prompt return with lease held until real captured close; cancellation during pending spawn; retiring-handle retention; rejected observation retention; before/after actual-launch-phase failure; disposed admission; reentrant abort callback starting a new generation. No original addon/helper, shell, signed producer, Security/Keychain, owner data, app or OS operation ran. There is no new compiler/build queue. source-check.json records the exact projected hash; inputs.json pins source/dependencies. Existing frozen native/Swift checks and receipts remain unchanged.
