# Non-pruning session read for hidden-workspace admission

Pinned actual native v604. Independent review found that the original GetLastSession path initializes CommandStorageBackend before Aux validates the saved workspace. InitIfNecessary creates the sessions directory and DeleteLastSessionFiles removes all older/invalid candidates. The preferred-encrypted read path can also delete the old cleartext last-session file. A refusal after that path cannot accurately claim the original session files were untouched.

The explicit Aux workspace restore now calls a dedicated preserving-files read through SessionServiceBase and CommandStorageManager. Backend admission uses the current last-session descriptor if already initialized, otherwise the existing const FindLastSessionFile scan; it reads the selected file with the original parser/encryptor. It does not call InitIfNecessary, create directories, change initialized state, create/write files, migrate or prune. No caller-supplied filesystem paths are introduced.

CommandStorageManager retains its exact configured clear/encrypted preference, comparison and fallback policy. The preserving flag reaches every backend read, deferred encryptor-ready retry and cleartext fallback; it suppresses the encrypted-success cleartext migration deletion for this read. The ordinary public GetLastSessionCommands path passes false, retaining all original initialization/cleanup behavior. After an accepted restore, normal real session writes may initialize/prune normally. This boundary promises that the admission read itself does not mutate existing candidates; it cannot undo unrelated prior normal activity.

SessionRestore selects the new read only for its explicitly validated hidden-cache mode. General startup/session restore and app restoration remain on the original API. Saved workspace validation, ambiguity refusal and existing async callback/weak-lifetime protections remain unchanged. v604's empty-cache WindowOpened guard is required as the preceding companion fix.

Added two focused parameterized backend tests (existing clear/encrypted and session types): successful admission retains newer-invalid and older-valid candidates without initializing; failed admission retains invalid-only candidates. The successful test then invokes the normal read and checks its original pruning still occurs. These tests were added but NOT compiled/run by this lane.

Validation performed: every transformation count-checked, including all six manager backend bindings and both queued retry branches; isolated git apply check/replay matches all eight output hashes. No shared native edits/build, runtime, owner files, profiles, credentials or signing. Parent should compile changed backend/manager/session_service_base/session_restore objects; the targeted tests can run if the test binary is already available, without a broad test build.
