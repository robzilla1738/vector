# Same native sidebar, real target profile sources

The supplied in-place profile switch keeps the Browser, model and window stable. The existing155 Aux sidebar constructor instead bound its bookmark observation, PrefChangeRegistrar and actual authenticated task feed only once. This necessary platform adaptation changes those real sources on the same view; it supplies no replacement sidebar layout or successful data.

Cold `CanRebindForAuxProfileSwitch(target)` checks actual regular target preferences, current source identity and absence of an active pinned-tab drag, with no source mutation. `BeginAuxProfileSwitch(target)` returns a generation, pauses view updates, invalidates stale weak callbacks, stops only the old feed transport, detaches old bookmark/preferences, cancels tracked favicons and closes native menus/review UI. It does not stop agent tasks or write target preferences.

After Browser/model/InitState identity and real tab transfer settle, call `RebindAuxProfileSwitch()` to bind actual current-profile bookmark/pref/feed sources and clear transient old task/sidebar state only when the actual profile changes. Abort preserves the same source profile's real cached task/running/view state while reconnecting its transport; closed menus remain closed. Both commit and abort need this rebind to the authoritative current Browser profile. `EndAuxProfileSwitch(generation)` ignores stale completions, checks actual bound identity, derives the real active chat, rebuilds through the existing renderer and starts the actual feed when attached. The abort-state follow-up preserves the existing source snapshot and running indicator on rollback; it never treats cached source data as target data. Existing view, model observation, running-change callback, typography, section layout and preference contracts persist. Refresh the existing footer through `AuxSidebarFooter::RebindForAuxProfileSwitch()` so current-profile avatar/dots and running state no longer reflect the old source.

The new API is internal C++ plumbing. No renderer/gesture switch trigger is installed. Parent BrowserWindowFeatures/vertical-region integration must cold-check before effects, call begin before tab transfer, rebind after coherent profile identity, and end after target tabs settle; rollback restores source tabs/identity first. No compile or runtime claim is made by these source files.

Exact current155 inputs and outputs are count-checked by the patch manifest. `PrefChangeRegistrar::Reset/Init` and existing actual feed Start/Stop/weak callback lifecycles were inspected directly. Shared native source is untouched until root applies the composed batch. Actual focused compilation and disposable profile switching remain required.
