# Popup ownership follows the actual profile

Separate one-file follow-up after `native-popup-reopen`, exact CC baseline `661a8ccfeb339715efbb37d6e9a441cc070d2980364eafb81cac8fedc206ca44`. The minimal delta destroys the old popup/options native tree before installing a different actual Profile in the global Aux popup host. No API, profile/account classification, binding, security summary, route, capability or GN contract changes.

The supplied factory04594b00 allocates a profile-bound coordinator, stores its resolved weak target at coordinator+0x38 and holder at+0x40, then keeps that coordinator in manager+0x48. Supplied Show0459577c reads that same target and reuses the coordinator's actual WebContents/widget. Supplied destructor04595260 invalidates its weak callbacks/removes observers, releases options animation/widget/delegate at+0x80/+0x78/+0x70 and main animation/widget/delegate at+0x60/+0x58/+0x50, then releases the profile holder/raw target at+0x40/+0x38. It does not relabel a retained WebContents with another profile. These field meanings derive from the supplied factory/Show/lifecycle call sites; the stripped image does not provide original C++ declarations.

The current Aux host is a singleton. Its previous `BindProfile` only hid the old windows and changed `profile_`. `WebView::GetWebContents` actually creates its owned `wc_owner_` using its original `browser_context_`, and `LoadInitialURL` performs navigation on that same WebContents. A later reload therefore cannot migrate it to the new target profile. Keeping the old tree while changing the bookkeeping risks acting in the previous BrowserContext.

The adaptation keeps same-Profile early return and normal Hide/reopen preservation. On a different Profile it hides, detaches the old profile observer, destroys both old owned widget/delegate/WebContents trees (with their animations and remembered entry URL), cancels any activation-dismissal task queued by that old hide, and only then assigns/observes the new target. Removing the old observer before releasing its tree avoids observing old-profile teardown during native destruction. The existing Hide increments the generation, so already-pending security fetches remain invalidated. The observer on the target is installed after retirement, not while old content is still alive. Both actual Profile pointer and BrowserContext remain real native identities; no state file or copied account identifier is used to pretend migration succeeded.

Normal Hide and explicit-close focus handling remain untouched. Profile retirement uses the existing Clear-capture path, so it does not restore an unrelated previous key window or activate another app. Global shortcut registration, live `FetchAuxProfileSecurity`, generation checks and the current locked/unlocked routes are unchanged. Pending native folder-picker cancellation and profile teardown still need real disposable observation; this patch does not claim that changing ownership proves every outstanding native dialog callback is canceled.
