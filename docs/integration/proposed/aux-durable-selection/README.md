# Durable external selection, restart and rollback

This implements the missing **descriptor publication mechanism** after an existing-installation migration reaches authenticated terminal captures. It does not integrate a browser startup selector, assert that a state cohort is complete, or authorize state2. The actual plan and cold storage ordering/readmission documents are pinned as design inputs; their native admission/ownership prerequisites remain in force.

## Concrete source and API

`InstallationSelectionPreparation.existing(previous:candidate:checkpoint:terminal:)` accepts typed previous/candidate public generation descriptors and the actual `CapturedTerminalCommandContext` constructed from exact ready migration checkpoint, candidate, reviewed selectors, original rows and target rows. That context imports the recovered authority and opens its Aux-v2 envelope. Preparation binds transaction, candidate, selector-review and terminal-journal hashes. It cannot be constructed from a success Boolean or serialized receipt. The supplied content-manifest hashes are **caller content anchors**, not proof of a verified filesystem/SQLite/renderer cohort or provenance. Previous descriptor capture is also a caller responsibility; this code does not read the owner's actual selection.

`PrivateInstallationJournalStore` has one reviewable same-file continuation. Its existing private FD implementation stays byte-identical. Compile the successor instead of the baseline; merge its continuation with the candidate-archive continuation when both are composed into the same logical file, never compile two store definitions. The new files are fixed names below the existing private per-transaction directory, never an active product home/global selector:

- `SELECTION.json`: canonical public generation descriptor. No key representations, metadata bytes, wrapped root or plaintext DK.
- `selection-revision-<revision>-<sha>.json`: immutable-by-API selection history, including both previous and candidate descriptors and terminal binding anchors.
- `SELECTION-HEAD.json`: atomically renamed, fsynced head referencing an exact retained revision.

`prepareSelection` requires the current authority journal to be ready and exactly bound. It creates the previous descriptor pointer with O_EXCL and an initial `.prepared` checkpoint. Existing pointer/head adoption is rejected. A crash before initial HEAD publication can leave a retained pointer/orphan and deliberately requires manual review; no guessed adoption or reset is provided.

`beginSelection(expectedHead:terminal:)` records `.selectIntent` before any pointer publication. It requires a current authenticated terminal context, exact authority journal and old pointer. `publishSelectionIntent(expectedHead:terminal:)` writes/fsyncs a uniquely named pointer temporary, rechecks observed bytes, atomically renames it and syncs its directory. `finishSelectionIntent` independently rechecks the pointer and context before recording `.selected`. The split is intentional: restart can observe a pointer rename with the old intent still durable. Explicit replay of pointer publication is idempotent only for the exact known intent and descriptor. No persisted hash reconstructs a terminal crypto context; on real restart the caller must recapture rows and reconstruct it (using exact candidate recovery, where needed).

For rollback, `beginSelectionRollback` records `.rollbackIntent` from prepared, select-intent or selected states. Explicit publish/finish restores exactly the retained previous descriptor and records `.rolledBack`. This **only rolls back the descriptor**. It neither changes old data nor authenticates old installation availability; the old generation's writer admission/authority must be independently verified before it could run. New rows, original rows, filesystem backups, all authority checkpoints and all selection records remain untouched. Rolled-back transactions cannot be automatically selected again.

`loadSelection()` validates strict bounded/duplicate-aware JSON and exact file hashes, then checks pointer bytes against the phase. Prepared/rolled-back require the previous pointer, selected requires the candidate pointer, and either intent can observe only those two exact descriptors. Unknown but readable bytes persist a `.blocked` history checkpoint and are never adopted or overwritten. Missing, corrupt, unsafe or inaccessible files refuse; they are retained. Blocked is terminal for select, rollback and pointer publication, including after a later favorable capture. All public results explicitly retain `state2LaunchAuthorized:false`, `writerAdmissionVerified:false`, `authorityProvenanceVerified:false`.

## Durability and limits

The copied FD boundary provides owned 0700 directories/0600 regular one-link files, no symlinks/extended ACLs, nonblocking FIFO/type refusal, maximum 16KiB records, cooperating flock, O_EXCL revision/temporary writes, file and directory fsync, expected-head stale rejection and retained orphan evidence. There is no delete/update/overwrite of authority rows, Security call, key factory, native activation or UI change. Pointer replacement is intentional within a recorded selection intent, never a Keychain overwrite.

HEAD and pointer renames are individually atomic; the pair and the authority/storage journals are **not** a single atomic transaction. Intent phases remain uncertain even when pointer bytes happen to look favorable. A valid selection history is not independent provenance: filesystem hashes are not authenticated against an attacker controlling all files. Cooperative locks and byte rechecks cannot prevent uncooperating external writes between check and rename. Actual exclusive target custody is required, and is not supplied by this API. It must never be run against a live browser profile/home.

The accepted state1 app and unconditional native/SEA/CLI state2 refusals are unchanged. Before activation, native-owned descendant lifetime custody, profile/renderer/extension storage exclusion, coordinated complete state-cohort terminal verification, effective selector/entitlement review, production authority execution, and pre-state readmission must be implemented in the actual native host. No new receipt/hash/flag here bypasses those gates. Hosting/provider acceptance remains external. A native consumer for this new external descriptor format does not exist in this slice.

## Focused verification

`node docs/integration/proposed/aux-durable-selection/verify.mjs` verifies exact baseline+continuation and imported source/design pins.

`node docs/integration/proposed/aux-durable-selection/check.mjs` compiles actual separate Swift files, then executes 39 terminal-context and selection assertions against a new private disposable directory. Synthetic software authority stays in memory. It uses actual reducer-generated, durable ready authority history and real authenticated captured terminal context; no Security executor function, enclave or PQ operation runs. Cases cover select, stale head, wrong terminal context, restart before pointer publication, actual pointer rename followed by restart before terminal checkpoint, exact idempotent completion, descriptor rollback, retained prior/original records, corrupted pointer refusal/preservation and blocked-terminal behavior after later favorable bytes. No readiness/admission claim follows from these fixtures.
