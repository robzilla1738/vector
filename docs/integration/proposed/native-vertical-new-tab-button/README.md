##155 adaptation and assembly contract

Include `chrome/browser/ui/views/frame/aux_vertical_new_tab_button.h`, construct `aux::AuxVerticalNewTabButton(actualBrowserWindowInterface)` and add it to the actual Tabs section contents at the source position6e8. Root owns that mount, original flex property on the outer child, visibility/corner/compact policy, GN and registration. No region/shared-file delta is bundled here. Dependencies are the same main browser UI target's existing browser actions, Views, gfx, l10n and generated resources; register `.h`,`.cc`,`.inc` explicitly.

The component owns its ActionViewController and its weak callbacks. On genuine completed same-window profile/window rebinding, call `RebindBrowser(actualNewBrowser)`; it retires the old action subscription and invalidates in-flight invocation weak state before installing the genuine new root. This is a narrow155 ownership adaptation: no old-profile browser pointer or synthetic action is retained. An already-started pre-invoke callback which destroys/rebinds the view or removes the action cannot then invoke a stale action. Normal same-profile notifications retain original notify-before-action ordering.

155's `Button::OnPaint` is final. The original custom foreground background paint is therefore in its actual supported `PaintButtonContents` hook, after View background and before child/focus painting, rather than overriding final OnPaint. Optional shortcut child removal uses the existing View ownership API. The original private colors are resolved with the current widget theme; pre-widget image geometry is explicitly16x16 and real theme callbacks install the matching image/text color.

Do not automatically use this leaf as a replacement for every New Chat caller: their supplied constructor supplies its own text/shortcut/callback policy. This proposal does not change those consumers.
