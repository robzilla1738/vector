Read-only audit of `out/provided-reuse-aux-identity-continuation`, paired with the frozen supplied daemon. Exact SEA code hashes and offsets are in [source-evidence.json](source-evidence.json). Offsets identify code positions, not executable file offsets. No pipeline, app, provider, profile, native checkout or UI was changed. This is static classification, not runtime acceptance.

The composed SEA code SHA-256 is `5e3c37a99cf9558d38b5869f13b2ea67fce2cabdd2a71d0d4a50f1083403f668`. Counting matters: this code has 158 `\baside\b` occurrences and 48 exact quoted `aside` values. A count of 65 uses a different predicate; it must not be interpreted as 65 equivalent product identifiers.

## Correctness changes to prioritize

1. **Coding-agent skill selection.** Daemon code still has `Cn.agents.includes(`aside-code`)` in the coding-agent skill loader (offset 11,471,729). The already prepared `migrateAuxSkillMetadata()` emits `aux-code`, and daemon `SKILL_AGENTS` now declares `aux` and `aux-code`. Change this exact filter and the nearby instruction `aside-code skill or CLI` together. The ordinary Aux filter was already migrated. No external service or native receiver is involved. Preserve existing selected skill metadata with the explicit migration rather than deleting it.
2. **Wedged daemon recovery.** `isAuxDaemonCommand()` still tests `/aside[- ]?daemon/i` (offset 12,146,556). Its caller `reclaimPortFromWedgedAuxDaemon()` consults the owner of the isolated daemon port before sending termination signals. It rejects the actual `aux-daemon` name and recognizes the old name. Change only the exact matcher to the Aux name; keep port, PID, health and namespace guards. Do not test by stopping any running process.
3. **History search for Aux.** `isBrowserApp` still recognizes `aside` and omits `aux` (offset 11,007,086). `createHistorySearchTool.execute` computes `gi=app!==undefined&&!isBrowserApp(app)` and gates browser-history fallback with `!gi`. Asking for app Aux can therefore suppress browser history. Update the product entry to Aux; keep the explicit other-browser names and HTML parsers untouched.

## Internal names and external request metadata

- `asideProvider` (3) and `asideModelIdsSave` (3) are private fields of daemon `ModelsManager`. `getAuxProvider()` already constructs `createAuxProvider` against `AUX_API_BASE_URL`; the old private property does not select the old cloud provider. Rename declaration and all property reads/writes together. No persisted model or cloud field by those names was found.
- `asideRouter` (7) is the daemon's bundled JS variable plus `router_exports` property, local destructuring and HTTP/TRPC mount references. Its spelling is not the `/trpc/*` route. Rename all seven together, including export key and dynamic import destructure. No cloud receiver is involved.
- OpenRouter `HTTP-Referer:https://aside.com`, Codex usage `User-Agent:aside`, OAuth `originator:aside`, OpenCode `x-opencode-client:aside` and default chat bot userName are active external request metadata. They are remaining identity leaks. Change each producer in a source-pinned slice while preserving authorization headers. OAuth originator is provider-facing, so authenticate with its documented Aux-supported value rather than assuming it is unconstrained.
- `aside:worker:<parent>:<profile>` is a derived external provider session identifier. Changing it changes continuity/cache/session identity, even though it is not a model provider ID. Give existing sessions an explicit transition policy; do not reset persisted sessions silently.
- `aside-probe.test` is the callback broker's synthetic probe state. It is not the public callback path or the user's OAuth state; update the producer and any validating receiver after inventory.
- `aside-gmail-compose-*`, `aside-gdocs-driver`, `aside-sheets-paste` are injected Trusted Types policy names. `aside-fullpage-stitch` and associated capture attributes are injected DOM identifiers. Pair creation and lookup; preserve third-party HTML selectors.
- `aside host profiles`, `aside skills list`, `@aside/native-helper`, CLI lookup/install paths and executable names are still instructional/runtime installation identities. Command text must match the actual packaged `aux-cli`/Aux command and installation layout. Do not change only strings while leaving lookup or installers targeting the old binary.
- `aside-world.ts` source-region comment and historical legacy session title strings are provenance/compatibility remnants, not active endpoints. Source inventory stays truthful; final artifact provenance policy may remove bundled source-region comments separately without claiming independent authorship.

## Explicit versioned or excluded boundaries

Original `aside.dk.*`, recovery AUK envelope identifiers, wrapping domains and account-password verifier domains remain cryptographic compatibility boundaries. They must use an explicit versioned migration with preserved ciphertext, keys and rollback; no blanket replacement or owner-state reads. The native addon SEA asset `aside-native.node` requires a matching loader/embedded-asset/package transition. The blocked Vault owner's `kind:aside`, PWM session namespaces and all remaining Vault cryptographic labels are unreachable/excluded product code, not evidence that a password manager should be restored.

HTML tokenizer/sanitizer tag lists, document role maps, `querySelectorAll("aside...")`, HTML element enums and third-party `.aside` CSS selection semantics must remain intact. They describe the standard HTML element or page markup, not the source product. No UI geometry or CSS declaration changes are proposed here.

## Evidence limits

This audit searched actual composed and original SEA code, the actual staged Agent modules listed above, and `services/aux-cloud` source. It did not inspect credentials, profiles, runtime state, provider accounts, signed catalog contents or every platform binary. No proof of an external receiver's acceptance follows from a caller rename. The three correctness findings above are actionable locally; the paired contract and immutable-boundary items need their complete caller/receiver inventories before staging.
