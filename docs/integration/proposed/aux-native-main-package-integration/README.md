It grants no runtime authority and activates no startup path. The current accepted app, UI stage, CSS, asset bytes, Agent revision, native checkout and default supplied-SEA packaging mode stay unchanged.

The optional `--native-main-receipt ABSOLUTE_FILE` selects one exact reviewed build, not arbitrary code. No compiler, executable, module or protected factory is run by verification.

The existing package producer independently requires the successful matching full native receipt, checks actual source/artwork/GN args and all native leaves, and requires state2 pre-home refusal evidence. This helper adds no acceptance flag, no qualified-entry projection, no new runtime marker enum and no signature or privileged-install receipt. ## Exact integration

`integration.patch` and its count-one `metadata.json` describe:

1. `scripts/package-provided.mjs`: one optional receipt argument.
2. `scripts/lib/provided-package.mjs`: fail-closed preflight before copying, then the fixed replacement immediately after checked supplied resource assembly inside its private transaction, plus the external package replacement record.

The new reusable helper is `source/native-main-package.mjs`; the proposed import points to this exact location. Complete successor copies of both edited modules are under `source/scripts/`. Root must review/apply the patch; these copies are not active pipeline code.

Staging/check-provided still replay the original supplied SEA and generated Node implementation exactly. After assembly the proposal verifies that copied `apps/daemon/Aux Daemon.app/Contents/MacOS/aux-daemon` matches its manifest, overwrites only that copied leaf with the pinned native executable, truncates it, sets0700, and verifies the new hash. It updates the matching `bundle.json.files` entry and adds `nativeMainReplacement` with original/output hashes and exact build-receipt reference. Original source audits stay external and truthful; they describe the stage before this separately recorded package replacement. `package.json.nativeMainReplacement` records the same evidence. No unreported file or source-path evidence is injected into the delivered app.

`daemonRuntime` intentionally stays `provided-node-development`: the ordinary supervised fallback continues using the original generated Node entry, while the native cold-entry startup branch stays default-off. Thus this is executable inclusion, **not** native bootstrap activation or common-addon retirement. It refuses `--development-dp-layout` to avoid mixing the older signing topology with this new executable. The absent option preserves the current package control flow/output.
