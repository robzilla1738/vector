# New Tab draft persistence and failure reporting

Actual614 New Tab Ask retained its oversized attachment after profile return but did not display the save-failure toast. This is distinct from the sidepanel: profile switching caches the entire ordinary tab document, so a successful transfer does not prove draft destruction or persistence. Its original editor writer uses the literal `new-tab` scope (sessionStorage only), and its custom composer callback discarded the writer result. The latter prevented the shared quota-error toast from seeing `false`.

The callback now forwards the writer result. The editor initializer resolves only its own `chrome.tabs.getCurrent().id`, then asks the existing native `auxAccount.getProfileContext(tabId)` for the persisted page identity. A validated identity selects `newtab-page:<id>` using the existing draft format and profile-local storage. It never queries whichever tab happens to be active. Private contexts skip durable resolution and retain original session-only behavior. Missing/invalid identity or API failure also retains the original fallback.

The initializer awaits resolution before constructing the existing editor/writer. The supplied New Tab React entry already waits for `aside-omnibox-input-ready` and checks the editor global, so the original readiness boundary remains intact. A legacy record is migrated only if this document's sessionStorage contains the original key. Successful migration clears the old key; existing stable data wins and clears stale legacy data to prevent resurrection after clearing. Separate tabs use separate native page identities. No styles, account wires, native APIs or renderer migration mechanism changed.

Root integration: cherry-pick the transform and evidence; add exact changed leaves `agent/assets/newtab-editor-u_GbForB.js` and `agent/assets/ask-omnibox-panel-DkxXbN8c.js` to the reviewed UI allowlist. `agent/assets/draft-storage-ixLojjZ5.js` is already allowed. Existing transform registration/provenance suffice. No native rebuild is required.

One focused actual-source check verifies current-tab argument, distinct page scopes, legacy migration, private/invalid fallback, callback false propagation, durable local write and quota listener retention. Three complete transformed modules parse. Actual acceptance remains: New Tab tiny draft plus attachment across normal Quit/restart, independent second New Tab draft, and immediate quota toast followed by attachment removal/recovery. Cached-tab profile switching need not be refused merely because an NTP draft is oversized: retained document ownership differs from destructive sidepanel retirement. The beforeunload guard protects actual unload; this patch does not invent a broader profile-switch refusal policy.
