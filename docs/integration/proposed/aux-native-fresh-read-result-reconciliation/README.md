# Native read-result observation and reconciliation

New successor to frozen readiness42; UI/startup/policy and all prior source/evidence stay unchanged. This proposal is not yet compiled or executed. Root reviews before any new compiler job.

Actual `AuxNativeContextRun` now routes each exact command through its genuine pre/post current-authority checks. It can preserve a completed, source-known read-only response when the post-check becomes unknown. The bounded request descriptor is command name plus SHA256(input); the actual response stays only in the retained process owner. Credential/root responses are never written to files, logs, journals or receipts. There is no arbitrary caller-provided result, selector, clear flag or authority initializer.

A later explicit native request first revalidates that same genuine current authority. An identical request receives the exact retained response once, without another read/sign/unwrap. A different explicit request acknowledges the reconciled side-effect-free prior reply, then runs only its new requested command. Reconciliation failure leaves the exact reply/observation intact. Proven identity/binding loss closes permanently. Thus a temporary heartbeat/locked-Mac failure on a completed read does not make the normal owner permanently unusable.

The exact read-only set is pinned to the actual imported installation core and secure store: status/public aliases, existing-captured init aliases (the core refuses absent-state generation), signing, unwrapping and secure-read. All write/CAS/OS utility commands and arbitrary account/generic callbacks lack this read-only classification. Unknown results on those paths remain retained/unresolved; there is no automatic replay, regenerated authority, inferred success or generic reset. Exact write/CAS readback descriptors are remaining work.

Physical operation completion and result disposition are distinct. `AuxNativeContextObserveOperationState` reports active native calls/reconciliation separately from idle unknown-read, unknown-write/generic and proven binding loss. It does not observe OS/PDF custody. Retirement may reconcile/discard a completed read only after real current validation outside the registry mutex. Inaccessible reads keep owner/result intact for later explicit close observation. New retirement statuses distinguish unresolved result(-3), wrong process(-4) and unknown failures(-5) from absent/already-retired(-1). The paired actual WorkerHost recognizes -3 as untracked and independently observes its real OS/PDF image custody, retaining the owner until both dispositions permit release. It no longer treats a guard failure as an invalid handle/drained operation.

`check.sh` compiles the actual dispatcher/C ABI against explicit fake authority/guard/secure effects, with cases for sleep/locked observation, same-result recovery without rerun, new-request handling, explicit close reconciliation, unknown write non-replay and actual binding loss. `compile-worker.py` is a changed production TU compile recipe with frozen Node headers. The full42 typecheck recipe is prepared only; do not queue another full graph until necessary/reviewed. No runtime/Keychain/Security/generation/signing, OS effects, owner data or application startup is used by the proposed checks.
