# Captured terminal readback to usable command context

This inactive source integration turns a **consistent captured terminal cohort** into the actual `AuxInstallationCommandCore`, rather than treating a public readback descriptor as a live installation context. No app, C/NAPI export, pipeline, UI, startup, signed helper or accepted-state gate is activated. No Security call, Keychain, owner state, enclave or PQ operation was executed.

## Implemented source boundary

`CapturedTerminalCommandContext.existing(...)` requires a typed prepared candidate, exact reviewed selector binding, ready migration checkpoint acknowledgement and captured originals/targets. It invokes the actual reducer’s candidate hash validation and terminal receipt validation. Every captured row must match the journal; the original rows must remain unchanged. Public keys come from the checked candidate. It then imports the **captured target** key representations through the recovered signer/KEM ports and authenticates the Aux-v2 root via the actual command authority constructor.

`CapturedTerminalCommandContext.fresh(...)` requires a typed fresh cohort, ready fresh checkpoint acknowledgement and exact four captured target rows. It checks the actual reducer’s candidate/public/payload binding, every captured row hash, public descriptor equality, and the explicit Aux-v2 authority constructor. It does not perform fresh generation, assert unknown state is absent, invoke a storage Add or turn a legacy namespace into a never-used scope.

The two reducers now expose narrow `validateCandidateBinding(...)` methods calling their existing private hash functions. No hash algorithm is duplicated in the binder, and neither method changes reducer phases or authorizes persistence. The binder has no global state and emits no private bytes. Its evidence explicitly leaves `authorityProvenanceVerified`, `writerAdmissionVerified` and `activeSelectionPerformed` false. Its usable `core` remains an **in-process captured-data object**, not an authorization token.

A caller-supplied `Stored*Checkpoint` is not proof of fsync, a current physical Keychain read, writer custody or trustworthy provenance. The constructor’s validation proves internal consistency of supplied evidence and crypto. The real journal store/executor must supply those data under a separately reviewed admission lifecycle. Possessing all these values cannot itself promote the current state2 app to accepted.

Existing init returns existing public material; fresh and destruction still refuse without their coordinators.

Its readback classifier preserves inaccessible/invalid/missing distinctions. That avoids relying on platform FIFO open behavior before regular-file validation. Twenty-four actual disposable-filesystem assertions and static pins passed. The journal lock is still not all-writer authority.

## Real C/NAPI wiring architecture still required

The original Node-API8 `run(command,input)` must continue to return a JSON **string**. Missing command should retain the original TypeError; absent second input means empty string. The original synchronous C ABI has no context argument: `Run(const char*,const char*) -> owned strdup string`, then `Free`. A random global optional core, JS-supplied scope selector or always-refuse export is not a functioning or safe integration.

The concrete route is an instance-bound host adapter:

1. **Trusted native admission before writers:** retain the current state2 refusal until a separately reviewed host validates exact executable/group/provisioning authority, fixed selectors, scope history and terminal receipt. Close all participating writer admissions before capture/migration; an NSLock or callback returning true is insufficient. Source-only selectors and SHA pins do not establish that permission.
2. **Coherent storage capture:** under that held admission, use the exact reviewed explicit source/target selectors and real executor to classify missing/inaccessible/invalid/partial states. Load the durable journal and recover the right existing/fresh transaction. Never fall back to omitted-group search, reinitialize inaccessible state or rerun uncertain Add. Revalidate terminal current rows before handing off; retain authority until command-context retirement.
3. **Opaque owned instance:** create a native owner containing the validated captured command core, scope/selector/terminal bindings and an operation/retirement lock. Do not permit a `run` argument or renderer message to replace that owner’s scope. NAPI module initialization receives this owner from the trusted host adapter; its `run` callback uses `napi_callback_info.data` (or module-instance data) and a finalizer, rather than a mutable module-global current installation. Worker-loaded modules each need their own authenticated host association; a worker path alone conveys none.
4. **Context-bearing internal C API:** a carrier can call an explicitly paired internal `AuxNativeContextRun(handle,command,input)` with a trusted retained opaque handle, plus owned-result free and explicit handle-retirement APIs. This deliberately adds a context parameter internally; it must update caller/receiver together. Exporting the original no-handle C signature honestly would require an authenticated immutable per-module host binding not currently present. No fake original-signature shim is implemented here.
5. **Lifetime and refusal:** acquiring a call retains the owner and checks it is not retiring; retirement closes new calls, drains active calls, removes host association and releases private handles. Capture/admission invalidation must retire contexts before writers reopen. Error paths return fixed JSON errors, never stale context from another scope or an unbounded interpolated private exception. Result buffers are copied and freed exactly once after producing the JS string; a released or unowned handle must never reach Swift `Unmanaged.fromOpaque`.
6. **Separate legacy migration:** legacy readers remain external tooling. The delivered command module compiles only the Aux-v2 core/dependencies; historical-label support in the synthetic migration test is not a production fallback. Existing PDF/OS binding consumers need their separate preserved route while the installation bridge is introduced.

These are exact remaining ownership/integration responsibilities, not implemented acceptance or signing claims. Static/source-only work can implement more host/IPC plumbing after its trusted context producer is specified, but cannot manufacture proof of actual Keychain authority, historical custody or OS grants.

## Lean checks and limits

`sh docs/integration/proposed/aux-terminal-command-context/check.sh` compiled all real interfaces and passed **15 captured-terminal checks**. Synthetic fixed software P256 authority/root goes through the real migration/fresh reducers and context constructors. The resulting core signs a challenge verified against the same public key and unwraps the exact root. Draft, wrong acknowledgement, changed/unavailable row, wrong candidate, changed originals and mismatched reviewed selectors are rejected. Evidence flags remain false. No test callback fakes signing/decryption.

The fixture does not instantiate either physical journal store or Security executor; those interfaces compile but do not run. External legacy migration readers occur only in the migration fixture. PQ/SE branches are compile-only. This adds no NAPI/C shim, live command context, dispatcher activation, signing or new permission.
