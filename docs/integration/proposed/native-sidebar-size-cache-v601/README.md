# Sidebar nested layout cache retirement — native601

Source-only proposal. Two files, six exact single-match edits; `files.json` pins input/output SHA-256. Generator refuses a changed baseline. No shared native mutation, build, runtime, UI, data or signing operation.

Actual601 preserves the active native model tab, collection node and visible row; all ordinary-tab exclusions are zero. Immediate/post-task diagnostics report zero new-body height and row height, with the retained strip still 43px high. Those phases precede guaranteed frame layout and do not independently prove a settled zero height. Root additionally observed persistent missing row after profile switch and restoration after switching the sidebar reconstruction setting. Roundtrip profile switching itself passes.

The actual custom `SidebarContentsView` memoizes preferred sizes by width. Its invalidators cover only direct-child callbacks. Tabs contents, native collection rows and animations live deeper under ordinary Views/BoxLayouts, whose layout invalidation propagates to the body (`View::InvalidateLayout`) without recursively invoking its `ChildPreferredSizeChanged`. Its custom map can therefore survive invalidation of its own FlexLayout and serve an early/incomplete height at the same width. Recreating the sidebar incidentally discards that map.

The fix observes the body's own `OnViewLayoutInvalidated` signal and clears only that map. It does not call `PreferredSizeChanged`, `InvalidateLayout`, measure, mutate bounds or post a task from the notification, so it cannot introduce recursive layout notification. Existing direct-child handlers and supplied width cache stay intact; ordinary toolkit invalidation still controls scheduling and geometry. Observer is installed once during construction and removed in the derived destructor, before member/base destruction. No borrowed profile/tab pointers or async lifetime are added.

Validation: six anchors and pinned baselines verified; `git apply --check` passes against current601. API is the existing `views::ViewObserver::OnViewLayoutInvalidated(View*)`, called synchronously by View before its layout manager invalidation. Native compile and actual profile forward/back row visibility remain integrator checks. No style/spacing/glass/predicate changes. This repairs a source-demonstrable invalidation defect; runtime confirmation is still required before declaring the row issue resolved.
