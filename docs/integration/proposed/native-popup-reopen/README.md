# Supplied popup reopen preservation

One-file proposal after `native-popup-resize-animation`, popup CC baseline `516843883096e0d86387f33f784d271f6f586dc4a9211b5d5dccbd9a6ede1db8`. `manifest.json` pins both inputs/outputs and `native.patch` is an exact replay delta. No new GN dependency: the popup already depends on Skia. Shared source is untouched here.

Supplied original Show0459577c loads `minipopup.html` only while creating a widget. The existing-widget branch at04595854 jumps directly to0459618c, after navigation, and examines the current window bounds. Current Aux calls `WebView::LoadInitialURL` every time; its actual155 implementation always calls `NavigationController::LoadURLWithParams`, so this is a real page reload, not an idempotent initializer. Reopening can discard the active in-page popup session and local draft state. The proposal retains the loaded entry URL and leaves that page alone on same-profile, same-entry reopen. The existing live locked/unlocked route transition still triggers navigation; actual WebContents BrowserContext must also match before a reload can be skipped. Destruction clears the remembered entry URL. This bookkeeping is not a cached security decision.

The same original common show block intersects the popup bounds with **all display work areas**, unions the intersections using SkRegion operation2 (`kUnion_Op`), then iterates its disjoint rectangles and sums signed64-bit areas. This prevents mirrored/overlapping displays from counting visible pixels twice. It invokes the original initial-bounds helper04598240 only when visible area is **less than or equal to half** of the current window area. A mostly visible straddling window is preserved. Disconnected-monitor/totally offscreen placement is recovered to the cursor's display, horizontally centered and one third down the work area, using the already recovered initial-bounds arithmetic and fit.

The proposal uses the actual SkRegion union/iterator operations, the original inclusive half threshold and64-bit area multiplication. Initial placement and recovery share the same existing arithmetic. It removes the unrelated unconditional `Resize(size_)` during Show, which previously fit even unchanged mostly visible windows to one display. Content-driven main/options resize interpolation stays unchanged, including its180ms animation and real reduced-motion handling.

The original native function loads only the popup entry; this evidence does **not** prove a replacement for Aux's current locked `main.html#/` entry. `ShowFor`, actual `FetchAuxProfileSecurity`, generation/profile checks and both existing route strings remain byte-identical. No unlocked/onboarded/account success is synthesized. Existing native capture/show/request-focus order and all explicit-close/blur semantics remain unchanged. The separate authorized profile-ownership follow-up will retire old WebContents on actual profile changes; this patch deliberately leaves BindProfile untouched.
