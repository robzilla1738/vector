# Fresh-only create-once installation journal

This inactive slice supplies a pure fresh transaction reducer and a distinct versioned private filesystem journal. It uses `PreparedFreshAuxCohort`; it never constructs a migration candidate, invents original payload hashes, creates authority or calls Security. It does not select an installation, reset, delete or overwrite records. Existing reviewed source is unchanged.

## Admission is an external obligation

`FreshInstallationTransaction.prepare` requires BOTH a `CallerAssertedNeverUsedScopeReview` and four target captures. The review explicitly asserts never-used scope history, exclusive stopped-startup custody and absence of all four legacy artifacts; target captures must separately report four absent rows. Known-existing/unknown scope, unavailable custody, any legacy artifact, inaccessible/invalid/partial captures refuse. An empty new v2 namespace within the existing historical disposable scope is **not fresh admission**; the historical selector review is migration-only. Caller assertions can be fabricated by a caller and do not prove actual scope ownership, provenance, process exclusion or absence. Only an independently reviewed native admission/capture boundary can supply those facts. No Boolean or receipt claims all writers are stopped.

Target selectors must have explicit nonempty access groups, distinct row identities, Aux-only names, and service/account prefixes matching the exact reviewed `aux.<64hexScope>.` namespace. The journal binds review ID, scope, selectors, public descriptor, candidate digest and four target payload hashes. It records captured absent-role assertions without inventing original row contents/hashes. Journal bytes contain hashes/public descriptor, never root plaintext or private-key representations. Sensitive payloads appear only in an in-memory add request.

## Ordered state machine

Fresh journal format is `aux.install.fresh.journal.v1`; roles are metadata, signing, KEM, wrapped root. For each role, draft → durable intent → add-only request → captured Add result → durable awaiting-readback → exact four-row capture → verified draft (or ready after fourth row). Earlier verified rows must remain byte-identical, pending row must match its target hash, and future rows must remain absent. Availability errors, collisions, duplicates, failed Adds and mismatched readback block terminally. Partial rows are retained; no cleanup/reset action is emitted. A durable intent interrupted before a known Add result can be reconciled only by explicit observation, never by replaying Add. `reconcileIntent` validates every verified/pending/future target: exact pending payload advances verified without claiming who wrote it; absent pending returns unresolved with no revision advance; changed, inaccessible or invalid captures block terminally. `interruptIntent` remains explicit terminal abandonment of uncertain outcome. A durable awaiting-readback can receive an exact capture again; neither path guesses absence from an error.

`AssertedFreshDurableCheckpoint` is a pure API assertion, not filesystem proof. The filesystem store supplies its acknowledgement only after immutable revision and atomic head publication with sync. The external caller must publish each state before requesting the next action, submit each Add at most once, and use an actual create-only Security executor that rechecks exact absence. The reducer alone cannot prevent a caller replaying an in-memory request or an uncoordinated process writing the same scope. This is not an executable Keychain coordinator. Hash-only journal recovery cannot recreate the fresh candidate private representations/root/wrapper: exact private-material restoration remains unimplemented, so observing a pending row does not imply later missing rows can be regenerated or safely completed.

## Private fresh filesystem store

`PrivateFreshInstallationJournalStore` is a clearly renamed, versioned adaptation of the pinned reviewed journal store; no migration structures or original hashes remain. It creates only `.aux-fresh-installation-journal-<uuid>` beneath an explicit canonical private disposable directory. Root/directory/file ownership, exact modes, no extended ACL, regular files, size bounds, one file link, no symlinks, descriptor/path identity and read metadata stability are checked. LOCK and reads use `O_NONBLOCK` as well as `O_NOFOLLOW|O_CLOEXEC`; FIFO entries fail promptly. Reads also require EOF after the captured size.

Immutable revision files use exclusive creation and sync. Stage leaves an orphan revision without changing HEAD; publish validates expected-head CAS, immutable transaction fields and the exact successor phase before atomic HEAD rename/directory sync. An actual fsync/metadata/rename failure throws; it never returns an acknowledgement or advances the reducer. An error after rename may leave a new head on disk, so callers must reopen/reconcile rather than assume rollback. Stale head/busy lock, ACL, metadata, corrupt or malformed checkpoints fail closed. The advisory journal lock protects journal CAS only; it confers no installation-writer custody. No orphan or partial evidence is deleted by the implementation.

## Focused evidence

`sh docs/integration/proposed/aux-fresh-installation-journal/check.sh` compiles and exits0. The fixture performs one software-only generated cohort and four-row synthetic Add/readback flow through a private disposable journal. It checks staging without publication, stale-CAS refusal, reopen/ready equivalence, unavailable/legacy/existing-scope refusal despite empty targets, duplicate/interrupted Add terminal failure, changed readback refusal, retained verified first row after second Add failure, FIFO HEAD/LOCK prompt refusal, and actual journal reload after synthetic Add but before status with observation-only matching-row advancement plus absent/unresolved and changed/blocked cases. Only synthetic in-memory rows are changed; filesystem test directories are disposable and removed by the fixture. Hardware is compile-only through dependencies; no Security API, Keychain, owner state, signing, activation or actual persistent installation writes execute.

Remaining work: enforce source-backed native never-used scope admission and all-writer exclusion; supply exact authorized captures; integrate a fresh-only create-only Security executor; provide postcommit command-core acceptance and explicit activation. This model intentionally cannot turn the existing historical disposable installation into a fresh scope.
