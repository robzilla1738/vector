# Prepared daemon authority: fixed sign/public-key backend

Native-only backend for the authenticated peer transport. `AuxCreatePreparedDaemonAuthority` retains an actual open prepared provider and obtains one actual independently scoped command owner from that exact producer; no caller core, home, selector, key bytes or admission Boolean is accepted. Only `cdp-sign` of the exact existing51-byte daemon Auth message and `get-public-keys` can run. The original installation_auth.cc HttpMessage prefix is19 bytes including its NUL, followed by exactly32 decoded challenge bytes. The existing core signs those exact bytes; no cryptographic protocol is redesigned.

Each caller-owned16-byte nonce binds its exact finite kind/body before any command attempt. Begin never reexecutes an existing record. Observe can call the fixed command again only if the dedicated actual owner reports a retained completed read result; the paired runtime dispatcher returns that original result after current-authority validation without another sign/read. Generic errors, lost replies with no retained native result and completed failures never select retry. A pending record blocks new requests, so a different request cannot silently consume the original reply. Completed/public replies remain cached within a32-record bound; no eviction resets unknown attempts. Signature and actual public-key JSON payloads are bounded8192 bytes. No private root or credential command is exposed.

Closing permanently stops new requests; active calls and unresolved/proven-loss owners remain retained. Close independently invokes actual typed command retirement outside the backend mutex. Release consumes native ownership, but never drops pending/untracked owner/provider references. Wrong-parent identity is enforced by the retained runtime guard and peer transport, never by a caller status. The transport must additionally authenticate every incoming kernel audit against the exact retained parent and suppress replies after its generation closes.

This source is not an activated server, signed helper or all-writer authority. Packagegate owns the paired audited Mach listener/nonce protocol and main lifecycle; crypto owns selected parent caller/challenge/session pairing. No Security/Keychain, authority generation, original addon, OS effects, owner state, signing or startup execution is performed here. Captured tests use explicit fake provider/authority effects with the actual current dispatcher/backend. Source-only until those checks finish and the final main graph compiles.
