# Prepared daemon authority: finite native backend

Native-only backend for the authenticated peer transport. Creation retains an actual open prepared provider and obtains one actual independently scoped command owner from that producer; no caller core, home, selector, key bytes or admission Boolean is accepted. Only cdp-sign of the existing51-byte Auth message, get-public-keys and purpose-bound inbox-key-v2 can run. The pinned installation_auth.cc HttpMessage prefix is19 bytes including NUL followed by32 decoded challenge bytes. The existing actual core signs those bytes. Inbox uses only root's explicit Aux-v2 purpose; no root/generic purpose export, old cipher rows or key migration is introduced.

Every request binds native monotonically increasing sequence plus16-byte nonce to its exact kind/body before an attempt. Begin never reexecutes an existing request. Observe can call the fixed command again only when the dedicated actual owner reports its original retained read result; the paired dispatcher resolves it without re-signing/re-reading. Generic errors or lost replies without a retained result never select retry. One latest response is retained; a new exact next sequence is accepted only after explicit ACK of a completed/error result. Lost ACK keeps that latest reply observable. Advancing retires the old sequence behind a permanent high-watermark, never a cacheclear allowing replay. Counter overflow refuses. There is no32-request lifetime exhaustion.

Cached material publication invokes the new exact-owner validateCurrentAuthority boundary: actual current authority validation, no command/callback/factory and no caller-granted success. Transient failure keeps the reply; proven loss closes. The final-main dispatcher successor adds only this real boundary and exact inbox-key-v2 read classification. Frozen queued42 files are unchanged.

Signature bytes and actual public-key JSON are bounded8192; InboxKeyV2 is exactly32 secret bytes. Backend cache uses its own private allocation, wiped with SDK memset_s on acknowledged replacement, successful close and proven loss. This claims wiping that owned buffer only, not all Foundation/Swift JSON/base64 temporary strings or separately copied transport buffers. No payload enters disk, logs or receipts.

Close permanently stops new requests; active/unresolved/proven-loss owners remain retained. Actual command retirement/revalidation runs outside the backend mutex. Release consumes native ownership but never drops pending/untracked provider/owner references. Gate owns transport authentication of every request against the exact retained parent and suppression of replies after generation closure. This backend does not turn a transport status/nonce into authority or whole-writer custody.

Packagegate owns the paired audited Mach listener/sequence/ACK protocol and main lifecycle; crypto owns selected-parent auth/session, public-key and inbox callers. No compiler, runtime Security/Keychain, authority generation, OS effects, owner data, signing or startup execution is claimed here. A focused fixture uses explicit fake provider/authority effects with this actual dispatcher/backend; the final main graph must select this dispatcher, native-inbox-v2 core+key source and busy-bridge successor coherently.
