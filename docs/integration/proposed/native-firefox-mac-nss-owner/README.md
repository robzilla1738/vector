# Original Mac Firefox NSS owner

Source-only proposal against native454's unchanged NSS files. Adds the missing Mac dynamic-loader owner, selects it on Mac and leaves the existing common JSON/form parser in place. The existing non-Mac decrypt implementation remains unchanged behind its platform guard. No public Firefox success path is enabled by this proposal alone.

Original arm64 source SHA256: `64c6c8a366d36d4c86b429de2f7fb0b7103099317f0a84f1cfded1bc87f4b31c`. `46bff58` is the original Mac initializer, `46beb2c` its decrypt implementation, and `46be6c8` the real Firefox utility consumer. These are actual implementation bytes, not a stock NSS substitute. `eae5310` is the six-pointer copy table. All seven resolved function names and all six filenames are pinned.

The owner requires `libmozglue.dylib` and `libnss3.dylib`, attempts optional `libsoftokn3.dylib`, then creates a private temporary directory. It copies existing `key4.db`, `cert9.db`, `pkcs11.txt`, `key3.db`, `cert8.db`, `secmod.db` in exactly that order; missing files are tolerated, failed copies fail initialization. `pkcs11.txt` is read without an invented byte cap and every source-profile path occurrence is replaced by the actual temporary path before writing. NSS is initialized with `sql:<temporary path>`, then the raw temporary path if the first call fails. Reset/destruction calls NSS shutdown only after successful initialization, unloads softokn/nss/mozglue in that order, clears pointers, then deletes the temporary directory. Optional module-load diagnostics are not replicated; load success/failure semantics are preserved.

Decrypt preserves the original legacy `~` base64 branch, initialized/empty/null-slot checks, authenticate-before-decrypt, SECItem release and slot release. The seven ABI declarations retain the existing Chromium/Mozilla license block and types from the actual155 Windows NSS loader; no system-NSS linker dependency is introduced.

Root integration prerequisites (not edited here): on Aux Mac, add `importer/nss_decryptor_mac.{h,cc}` and existing `importer/nss_decryptor.{h,cc}` to `//chrome/utility`, with `//crypto:buildflags`; enable the real Firefox utility password call only together with the original typed result transport and browser buffered-batch settlement. The common parser/form converter is retained from155; its current source is not represented as a newly recovered parser rewrite. No library search fallback, Firefox install discovery, sandbox grant or synthetic successful completion is added.

`python3 verify.py` passed original code/literal/table pins, three counted anchors, four output hashes and clean temporary patch replay. This is not a native compile or functional password-import acceptance. No Firefox/NSS library was loaded, no profile/key database read, and no runtime, Keychain, build, signing or OS operation occurred. The new module remains unmounted until the integrator adds its real producer/consumer prerequisites.
