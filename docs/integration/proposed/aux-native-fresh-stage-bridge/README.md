# Native fresh factory → durable secure-stage bridge

Inactive native source, distinct from the old caller-asserted fresh/migration flows. This path accepts only `AuxFreshNativeSecureCapture`, whose constructor is private and whose actual producer authenticates the sealed bootstrap policy, retains the exclusive fresh home and reads five fixed target/stage selectors. No Boolean review, caller-provided absence, hardware capability, scope, selector, root or cohort parameter admits this producer.

`AuxNativeFreshBootstrapFactory.prepare(capture:)` consumes the actual home's shared one-shot initial-generation attempt and repeats actual identity/absence checks immediately before generation. It derives Secure Enclave availability and OS availability natively, selects the recovered software/P256/PQ path, and reuses the exact original generation/access-control bodies. Failures have no fallback/downgrade/retry. Existing four-row preparation then wraps and verifies the generated material through the real command core; there is no new cryptographic format.

`AuxNativeFreshStageCoordinator.prepare(capture:)` privately constructs the material and prepares a new `aux.install.native-fresh.initial-journal.v2`. That **nonsecret** record explicitly binds reservation transaction/hash, authenticated policy hash, exact group/role/scope/selectors, candidate/public/target hashes and the exact sensitive stage-payload hash. It has no historical `newScopeReviewId` or fabricated legacy-absence roles. Only the actual five observed target/stage absence roles are recorded. No old v1 journal is reinterpreted as native admission.

The actual private-FD store retains reviewed O_NOFOLLOW/nonblocking/private-owner/no-ACL, bounded-read, metadata/path revalidation, flock, exclusive-create, fsync and exact readback mechanics. Its only publish API takes the typed expected nonsecret record; no arbitrary Data/secret output is accepted. A single immutable initial record combines draft and stage-hash binding durably before the coordinator can issue stage Add. Corrupt/partial/mismatching existing records are retained and refused.

`submitStageOnce()` consumes a locked process-local attempt before validation/calls, reauthenticates policy/home/reservation and actual durable journal, probes exact targets/stage again, and performs one add-only Data Protection query for that fixed stage selector. Actual status and exact readback are checked. No update/delete/reset/overwrite or replay API exists. Lost/unavailable readback can be observed again without another Add; explicit failures remain blocked on the same coordinator. The stage contains only the exact four prepared payloads (including the wrapped DK, never plaintext DK) plus typed lineage; sensitive representations never enter the filesystem journal or receipts.

`NativeFreshStagedContext` has a private initializer and is emitted only after this actual path reads the exact matching stage. Decoding or publishing a synthetic journal cannot create it. It is not a generic command-core owner, activation token, full-process custody grant or ready four-row installation.

Validation at initial source commit: pinned-source verification passes, including exact equality of recovered generation bodies and private-FD helper mechanics. The focused native-v2 record/disposable-filesystem fixture and 18-input actual producer graph typecheck are queued behind the integrator's native build lock. No compiler/execution success is claimed until a separate evidence commit. The pure fixture does not link/call the factory, live loader, probe or stage coordinator. The production graph is typechecked only, never linked/loaded/called.

```sh
python3 docs/integration/proposed/aux-native-fresh-stage-bridge/verify.py
python3 scripts/native-build.py sh docs/integration/proposed/aux-native-fresh-stage-bridge/check.sh
python3 scripts/native-build.py sh docs/integration/proposed/aux-native-fresh-stage-bridge/typecheck.sh
```

Choose the **successor** home in `aux-fresh-native-secure-capture/source/`, not the historical same-named home. Depends on authenticated-policy native revalidation `0b25472ad` and crypto capture `370561a8b`; neither supplies whole-profile/process custody.

Remaining seams are explicit: this is the initial secure-stage producer only. A distinct native-v2 four-target reducer/coordinator, durable terminal-failure observations, new-process retained-home/reservation adoption and exact restored-stage → ready-terminal handoff are still required. Existing v1 review-driven coordinator/records are not a substitute. This implementation intentionally cannot recreate a coordinator from a loaded journal, regenerate missing authority, or replay a stage Add on restart. A crash before any durable binding still leaves the exclusive reservation and cannot silently restart generation. Partial material/stage is retained; no cleanup/reset is introduced.

Actual early-host/independent-process exclusion, authenticated signed resource/image deployment, approved fifth selector, cold child-host handoff and real Node Environment registration remain unmet. Historical-scope migration remains separate; this new-home path makes no statement about old groups/rows. No signing/provisioning, factory/hardware generation, signature-reader execution, Security/Keychain operations, owner data, OS grants, original addon, startup/first-refusal, active host graph, shared pins, native checkout, package or UI changes were performed.
