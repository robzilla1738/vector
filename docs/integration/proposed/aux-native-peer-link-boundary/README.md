# Native parent/child link boundary — source successor

The frozen transport has two real undefined Swift C references in one C++ translation unit. Neither function is weak or dynamically resolved. The ordinary parent graph does not define the child/server macro. Object dead-stripping is not evidence that its final link can resolve these references.

* `AuxCopyAuthenticatedFreshChildParentDescriptor` is **parent-required**. `NativeOperations::AuthenticatedGuestParent` calls it after actual audit-token guest validation. Both selected-home receipt in `ParentTransport::ServicePeerOnce` and later `AuthenticatedSelectedHomeTransfer::DuplicateRevalidatedDirectory` call that real helper. Removing/guarding it would remove independent sealed child-policy and private-parent-FD validation.
* `AuxCopyAuthenticatedFreshColdHomeDescriptor` is **child-only**: the only call is `AuthenticatedNativeParentConnection::SendSelectedHome`. The successor guards that entire definition, its declaration and the cold-bootstrap header with the existing `AUX_NATIVE_DAEMON_AUTHORITY_SERVER` composition define. No denial stub or replacement caller is introduced.

`source/AuxNativePeerTransport.{cc,h}` is a pinned successor of commit34027c6fc's frozen transport; the currently queued checks remain historical inputs. `change.patch` contains only those three child-only guards. Existing parent validation, registration, finite RPC and ticket behavior are unchanged.

The new two-file parent dependency is deliberately read-only. `AuxAuthenticatedChildParentPolicyReader.swift` contains six exact helper bodies, the exact guest-validation body, and the actual C wrapper extracted from the current embedded-daemon sealed loader. Its type is renamed to avoid accidentally depending on the complete loader. `AuxFreshBootstrapPolicy.swift` is byte-identical to the current v1/v2 pure policy/schema implementation. Together they depend only on Foundation, Security, CryptoKit and Darwin. They do not reference `AuxFreshNativeHome`, imported-security helper symbols, installation/provider/dispatcher creation, native image preparation or credential/key APIs. The policy retains exact v1/v2 role, identity, resource and module declarations; it does not establish provider readiness or whole-writer custody.

`BUILD.gn.proposed` uses Chromium's actual `//build/config/apple/swift_source_set.gni` template. It is a review snippet, not applied GN. The browser target containing the transport must link this target, and the child graph must **not** link it because that graph already defines the same C symbol in its complete sealed loader. The child graph instead keeps its real ready-home producer/backend and existing server define. No C++/STL objects cross the Swift C ABI.

Run `python3 docs/integration/proposed/aux-native-peer-link-boundary/verify.py` for source/hash/extraction checks. A subsequent actual parent link must demonstrate that the transport's single parent-policy reference resolves to this target and that no cold-home producer reference remains in its object. The current queued six-TU compile cannot establish final-link resolution. This successor has not been compiled, linked, loaded or executed; no native checkout or active manifest was changed.
