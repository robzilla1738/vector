# Seven actual native-path unsafe-buffer diagnostics

Root's actual native Ninja51295 diagnostics identify exactly seven sites across transport, owned child and cold launch. The previous proposal-path checks were exempt from Chromium's native-path unsafe-buffer rollout; those successes did not prove this boundary. This successor targets the actual current native files and changes only those seven sites plus required standard headers. No path-handling changes, warning flags, GN, annotations, UNSAFE_TODO or unchecked caller-authority changes are introduced.

* Transport/owned-child wipes iterate actual owned span/vector elements and assign through a volatile reference. This preserves non-elidable stores without raw pointer indexing. It is the same pattern already compiled successfully at the native selected-home path.
* Transport CDHash comparison first requires actual CFData length to equal the immutable policy's validated20/32-byte size. It allocates exactly that size, calls the documented `CFDataGetBytes` for `[0,length)` into that owned capacity, and compares the vectors. The CF object is the owned Security signing-information value, not caller bytes. The original exact-length authentication predicate remains.
* Cold launch's actual signing hash is accepted only by its existing20/32-byte guard. It allocates that exact destination and copies precisely the same CFData range using `CFDataGetBytes`, replacing raw-pointer end construction. No unbounded range is fabricated and no hash check is removed.
* The two packet copies use `std::bit_cast` on trivially copyable records. The large incoming object has the existing exact-size assertion against SelectedHomeReceived, so that cast copies the same entire object representation. The smaller heartbeat uses a byte-array bit-cast, a compile-time-bounded prefix copy (`sizeof(Received)<=sizeof(Incoming)`) and a final bit-cast. It copies exactly the same prefix as the previous memcpy. Native byte order, message size gates, trailer offset/shape checks, kernel audit/code/birth authentication and actual original-header right cleanup are unchanged. Parsed copies remain plain numeric wire records; they do not create owned Mach rights.
* Signature-prefix comparison uses bounded iterators over the same literal array, including its terminating NUL, only after the exact51-byte input check. All19 prefix bytes are compared, as before.

`metadata.json` and `native.patch` contain three exact baseline/output pins against the actual applied native files. The independently fixed SelectedStateHome source is outside this lane and untouched. Root can compose/apply these records and compile exactly the three real Ninja objects at their true native paths; this proposal does not use another rollout-exempt docs-path compile as acceptance.

`verify.py` checks exact native/source hashes, the seven replacement boundaries, size/type/range constraints and unchanged nondiagnostic path code. It passed without compilation. No native checkout mutation, compiler queue, old receipt rewrite, signing, protected call, module/app execution, UI or state change occurred. Current daemon binary3e753 is historical and is not silently relabeled as compiled from this new source.
