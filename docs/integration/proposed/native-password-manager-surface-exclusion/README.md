# Exclude the remaining native password-manager surfaces

Owner scope excludes both supplied Vault and built-in Aux password management. Current native save/fill is already disabled by ChromePasswordManagerClient::IsFillingEnabled (ENABLE_AUX_BROWSER). CredentialManager store/get and the password context-menu gate consult that client. This proposal preserves those guards and all address/payment autofill, extension content scripts/native messaging, passkey/device authentication and installation/provider authentication.

Concrete remaining path: IDC_VIEW_PASSWORDS already redirects to Extensions, but distinct IDC_SHOW_PASSWORD_MANAGER remains enabled and invokes ShowPasswordManager; the stock submenu exposes it. Independently, chrome://password-manager remains registered and its privileged AddPassword endpoint delegates to SavedPasswordsPresenter::AddCredential. Thus disabling automatic save/fill alone does not remove the built-in management/manual-add product.

This Chromium155 scope adaptation removes PasswordManagerUI registration only for ENABLE_AUX_BROWSER, omits its menu item, labels the remaining address/payment submenu with the existing localized Autofill text, and rejects manager/checkup commands at the actual command eligibility boundary (including action-backed dispatch). It does not remove or mutate stores or credentials. No original Aside-source provenance is claimed for this owner-requested exclusion.
