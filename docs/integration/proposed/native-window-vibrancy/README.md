# Supplied native window vibrancy consumer

This is a staged two-file platform adaptation of the supplied `NativeWidgetNSWindowBridge` behavior, with exact current native baseline/output hashes and an independently replayed patch. It changes no shared native file while the full build runs. No target, preferences setter, Keychain operation or OS grant was executed.

The supplied effect is not a newly selected material. Static arm64 evidence shows the browser-class gate, disabled preference, Darwin notification, 250ms weak-bound repeating refresh, native Glass/VisualEffect branches, compositor reparenting and opacity/background behavior. The proposal retains those contracts and changes only the fixed preference domain from `at.studio.AsideBrowser` to `dev.aux.browser`.

The generic remote-Cocoa layer reads preferences and starts effects only when `base::apple::BaseBundleID()` is exactly `dev.aux.browser` and the actual window is a `BrowserNativeWidgetWindow`. `chrome/app/chrome_main_mac.mm:SetUpBundleOverrides` configures that base ID from the real outer browser app, including the helper layout. The preference domain remains fixed across widget hosts; it must not derive from an individual app-shim bundle. Existing base dependencies suffice; no Chrome browser API dependency or GN registration is added.

On macOS26+, nonfullscreen browser windows use dynamically available `NSGlassEffectView`; older macOS, fullscreen or missing class use the supplied `NSVisualEffectMaterialUnderWindowBackground` / BehindWindow / FollowsWindowActiveState combination. The optional supplied `liquidGlassVariant` accepts only CFNumber integer1..20. The optional original `_setVibrantBlendingStyleForSubtree:` selector remains guarded by `respondsToSelector:`. The compositor attaches to Glass `contentView` when available, otherwise the bridged root. Fullscreen transitions replace the effect only when the required Glass class differs, preserving the compositor across replacement.

`windowBackgroundVibrancyDisabled` only disables for a true CFBoolean. Enabled/disabled updates hide the effect and update opacity on actually translucent nonsheet windows. The enabled macOS26 background retains alpha0.001; other branches retain the supplied full system background color. The Darwin callback and 250ms repeating refresh compare cached state, so unchanged preferences do not repeatedly rebuild the hierarchy. Destruction stops the timer and removes its exact observer.

`source-evidence.json` pins the supplied universal framework and arm64 slice, bounded disassembly outputs, decoded imports/selectors/strings and the native host-guard inputs. `decode-selectors.py <pinned-arm64-image>` reproduces the static thunk/selector decoding without a disassembler database or target execution. Disassembly addresses are original image virtual addresses; they are not addresses in the new Aux binary.

`manifest.json` and `native.patch` are intended for the integrator's staged-composition extension. They use the unchanged livev16 remote-Cocoa baseline and can chain onto the disjoint preference APIv18 proposal. Exact patch replay and baseline/output hashes pass. The patch is **not applied, compiled or visually accepted**. The actual changed bridge object, full browser, preference refresh, fullscreen transitions, native compositing/transparency and both-theme visuals must still be checked after the frozen build finishes. The separate permission-prompt effect path remains current155 behavior and is outside this browser-window preference patch.

## Review follow-up

Helpers are placed after the actual `ViewsCompositorSuperview` interface/implementation, in a reopened anonymous namespace. They do not rely on an undeclared Objective-C class or warning suppression. Source patch replay still uses the same frozenv16 baseline.

The original Darwin callback04385768 directly uses its raw observer and tailcalls the updater; no main-queue dispatch or weak capture occurs. The local CoreFoundation header states that Darwin delivery requires the main thread's run loop in a common mode. The proposal retains this original callback, registers/removes on the window UI thread, and adds UI-thread assertions; only the original250ms timer is weak-bound. It does not invent an extra asynchronous callback with a different lifetime.

An important visual acceptance condition remains explicit: the original hosting helper uses Glass `contentView` only when it is nonnil, and the original creator never assigns that property. The original disabled refresh hides the effect without reparenting its compositor. The SDK declares `contentView` nullable but does not guarantee its default is nil. If actual AppKit returns a nonnil content view hosting the compositor, hiding the parent could hide the browser. This static adaptation preserves the supplied branch rather than inventing a workaround; actual Glass initialization and enabled→disabled rendering must be observed before accepting the consumer. Neither a patch hash nor compilation can clear that check.
