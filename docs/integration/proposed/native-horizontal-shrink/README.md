# Restore horizontal shrink on the default legacy strip

This proposal follows the final vertical/fixed-domain vibrancy proposal (root's proposedv18). Its overlapping API/header/GN input hashes are those proposed outputs, not the shared native v16 files still in the full build. New animation files use `/dev/null` creation diffs with null baseline hashes. Ten files are pinned.

The real supplied setter writes the browser-global shrink preference and the current/loaded profiles. Its native consumers observe the profile preference, read the global override and change the actual width policy. The previous Aux getter/setter only changed an unused profile boolean. This proposal restores the supplied global setter semantics and binds the default legacy horizontal strip to the setting.

Chromium155's unification flag remains unchanged. The legacy factory now owns the existing native TabStrip inside a ScrollView. Shrink enabled constrains the content to the viewport, respecting minimum tab widths; disabled preserves full preferred widths and permits horizontal scrolling. The wrapper observes preference and preferred-size changes, reuses155's overflow indicators and scroll buttons, and updates real layout. Native controller, tabs, drag ownership, focus and tab model remain the existing implementation. Region margins, paint ordering, caption hit-tests and the new-tab button follow the actual container rather than treating the nested scrolled TabStrip as a direct child.

The removed upstream selection-scroll animation is restored with its original shared animation clock/duration and active-tab reveal algorithm. The two small animation files are reused from pinned official Chromium source, retaining its license headers; the header adds an explicit raw_ptr include. Platform adaptations use the actual155 viewport/content hierarchy. Scrolling dismisses stale tab hover cards.

The native checkout is shallow and no longer contains the historical scroll-container files. The public153 source tag was unavailable, so the former upstream mechanism was obtained from official Chromium130, pinned alongside supplied native decompilation evidence. This is explicitly a necessary155 adaptation guided by the supplied behavior, not a claim that public130 files are the owner's supplied153 implementation. Existing155 scroll-arrow components are reused without new visual design; their exact appearance/timing still require comparison with the supplied app.

`validation.json` proves the final first slice and this follow-up apply sequentially in a disposable tree, every source/output hash matches, and the shared native files are unchanged. It does not prove compilation or UI behavior. No global preferences, owner profiles, target process or OS grants were touched.

Root must compile the changed API, frame, TabStrip/TabContainer and restored animation objects through the serialized build. Then observe real horizontal resizing in both modes, wheel/pagination/keyboard activation, pinned/grouped/split tabs, closing and dragging while scrolled, and multiple disposable Aux windows/profiles. Verify the active tab remains visible and the new-tab button/caption regions behave correctly before claiming acceptance.
