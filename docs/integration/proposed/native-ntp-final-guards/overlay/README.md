# Separate screenshot overlay: recovered lifecycle

This is static recovery of the original ContentsWebView+0x5c0 guard in Prepare045ccab0. It is **not** the +0x4f8 NTP compositor transition or WebContentsCloseHandler clone. No C++ screenshot API is wired to an invented NTP event. The exact primary-page paint fixes are independently actionable in the parent proposal.

## Recovered effects

- Capture045ceef4 first cancels the NTP transition, clears its weak destination and refreshes the background if attached. Clear045cf0c4 increments a capture generation, clears crossfade-active, restores requested native opacity to1, and removes/deletes the old child View if present.
- Capture then requires visible/nonempty owner bounds, current WebContents, its renderer view, and an available surface. It records owner size, increments generation, and requests a full-surface copy at that size with literal50000 microseconds timeout. The callback owns weak owner/contents references and the capture generation.
- Callback045cfea8 validates a successful nonempty bitmap and exact requested size, then the live owner generation, absence of an already-started crossfade, exact current WebContents identity, and exact current owner/image size. Invalid/stale captures are discarded. It creates an image-bearing child View sized/clipped to owner bounds, paints it to a nonopaque layer initially opacity0, inserts it as the last child, and stores that actual child pointer at+0x5c0. The stripped view constructor's exact class name remains unasserted; the child/layer effects are explicit instructions.
- Begin045cf184 requires that child, its layer, and matching owner dimensions. It marks crossfade-active and sets overlay opacity1; otherwise it clears and returnsfalse.
- Opacity045cf240 clamps the requested native opacity to[0,1], applies it to the renderer native layer through045cedc0, and, only during the screenshot crossfade, sets the overlay layer opacity to1 minus that value. Bounds changes resize/clip the image child separately from clearing an invalid NTP clone.
- The sole direct capture caller is464ca60, reached from464c780's ScrollEvent helper after horizontal movement wins against max(1,1.5*abs(vertical)). It enumerates visible hosted contents, capturing each. The sole direct Begin caller4656514 is in4655e40's settlement path, requiring every collected host to begin successfully before marking the owner crossfade active. Several settlement/cancel paths clear all overlays; per-frame animation paths update native opacity. These are browser-level horizontal scroll/surface-switch effects, not normal NTP navigation callbacks. The precise destination-selection owner (tab/group/workspace semantics) still needs its separate original controller recovery; the screenshots alone do not prove a tab-selection API.

## Integration consequence

Original Prepare's screenshot-child exclusion is real. Current Aux lacks this original screenshot/scroll lifecycle, so substituting its existing `cloned_layer_tree_` would wrongly block unrelated close-animation layers and still fail to reproduce the original feature. The proper future port must carry the capture generation, child ownership, crossfade state, actual scroll initiation/settlement/cancel paths, and then the exact screenshot-active exclusion in Prepare. It must preserve the independent current NTP pre-detach/compositor path.

Actual155 supports the required surface copy (`RenderWidgetHostView::CopyFromSurface`, full-source rect, output size, bounded TimeDelta and expected bitmap result), real child View/layer ownership, native renderer layer opacity, and weak WebContents/document lifetimes. The missing piece is the original browser scroll owner and destination-selection lifecycle, not an unavailable graphics primitive. Current BrowserView's `GetGestureCommand(kGestureSwipe)` maps back/forward and is not that original ScrollEvent helper; it must not be repurposed by guessing. No target execution, owner screen capture, build or shared native edits occurred.
