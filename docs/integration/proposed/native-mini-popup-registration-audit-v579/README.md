# MiniPopup startup / real global registrar audit (actual579)

No missing browser-startup or registration integration was found. No source patch is justified by the reported synthetic Space event on the focused Settings switch.

- `BrowserView::Init`, under ENABLE_AUX_BROWSER, initializes the actual manager for normal non-profile-cache browsers. `PopupManager::Initialize` observes preferences, skips OTR/already registered/disabled cases, and really configures a persisted enabled setting. This is not gated by retired ENABLE_AUX_SHELL.
- Real LocalState registration sets `aux.popup.enabled=false` and `aux.popup.shortcut=Command+Shift+Space`. `getEnabled`/`getShortcut` are pure preference reads. `setEnabled` validates the argument/managed state, calls Configure first, and persists only after success. Off disables the actual registration and destroys retained windows.
- Configure parses the accelerator, rejects a missing/suspended registrar, and calls the real `GlobalAcceleratorListener::RegisterAccelerator`. The actual Mac non-media implementation calls Carbon RegisterEventHotKey, returning failure when that call fails. Only successful registration sets registered state, acquires the real keepalive and binds the actual profile. This is not a no-op/DOM shortcut handler.
- The real Carbon event reaches GlobalAcceleratorListenerMac::OnHotKeyEvent→NotifyKeyPressed→PopupManager::OnKeyPressed. It uses the actual active browser profile or retained weak profile, then ShowFor→Show opens the supplied local `chrome-extension://<actual Agent ID>/minipopup.html#/`. This native show path has no cloud or Vault-security preflight. The supplied page still owns its real account/model readiness; native window creation does not fabricate account availability.
- Existing profile retirement and browser shutdown unregister/destroy ownership. Browser main PostMainMessageLoopRun explicitly shuts down this Aux-browser manager.

The supplied original `asideMiniPopup` IDL and current branded schema expose hide, get/setEnabled, get/setShortcut, state/size/options, picker and profile-switch methods. Neither exposes show/toggle. There is therefore no supported local click-open native API to substitute for a real global event. Opening minipopup.html in an ordinary tab would not verify this native widget/activation lifecycle; this audit does not propose that or add an independent test endpoint.

Root observed that a CUA Space-containing synthetic event toggled the focused switch Off. That is consistent with delivery to the DOM switch rather than the Carbon hotkey channel; it is not proof that OS global dispatch ran. Actual global invocation remains unverified. Existing-scope human physical input, after enabling and moving focus off the switch, would distinguish it without changing native behavior; no such input/runtime/OS operation was performed in this lane.

`python3 verify.py` verifies all public source hashes, selected unique source anchors and exact original/current IDL method lists (including absence of show/toggle). Source receipts are current579 only, not runtime acceptance. No native/shared writes, build, launch, owner profile/credential/Keychain/OS access or UI/CSS changes.
