## Official system ownership evidence

Apple's [WWDC23 ScreenCaptureKit session](https://developer.apple.com/videos/play/wwdc2023/10136/) describes OS-level stream controls and content selection initiated directly from an existing window. It distinguishes that system experience from an application's own UI. Its [ScreenCaptureKit documentation](https://developer.apple.com/documentation/screencapturekit) identifies the system sharing picker as the framework's control surface.

Apple's [FaceTime remote-control guide](https://support.apple.com/guide/facetime/request-or-give-remote-control-fctmebd8481a/mac) separately identifies a Screen Sharing button and a Control Screen button. Its page links the official icon assets for those two labels, recorded in `evidence.json`; no pixel-identity comparison to the historical marks is claimed. This establishes that such system controls exist; it does **not** establish that FaceTime, a particular capturer or any specified session produced reference146. No remote image was downloaded or bundled as product artwork.

Together the native titlebar placement, lack of corresponding application AX buttons, surviving native window-control AX entries and documented system sharing/control surfaces support an **OS-indicator inference**. They do not provide a source-backed app component to port. Reproducing a purple pill or pointer as an Aux mode switch would invent behavior and potentially misrepresent a real capture/control state.
