# Exact candidate recovery — external migration tool only

This closes the previous caller's in-memory-candidate restart gap for the **software P256 existing-installation lane**. No delivered app, UI, dispatcher, active selection, Keychain, signing entitlement or owner state changes.

`InstallationCandidateArchive(candidate:)` encodes an exact allowlist: the already encrypted Aux-v2 wrapper, both public keys, explicit normal/canary channel, four original-row hashes, the existing transaction's candidate digest, and a canonical archive digest. It never encodes metadata bytes, signing/KEM private representations or plaintext DK. Fixed synthetic private fixture inputs travel through stdin, not a fixture file.

`store.archiveCandidate(archive)` writes only `candidate-archive.json` in the existing private transaction directory, before or after the first journal checkpoint. It uses the audited FD-relative owned 0700/0600, no-symlink/no-ACL/no-hardlink, nonblocking type checks, cooperating lock, O_EXCL create, file/directory fsync boundary. Existing exact bytes are re-synced; different/corrupt/partial existing bytes refuse without deletion or overwrite. A crash during its first write can leave a partial evidence file and block recovery; this is an explicit manual-review condition. Archive publication and journal HEAD are not a multi-file atomic operation. A pre-HEAD archive can be retained, but `loadCandidateArchive()` refuses until a valid journal binds its digest.

On restart: load current journal and `loadCandidateArchive()`, recapture the four original rows with separately reviewed selectors/custody, then call `recoverSoftwareP256Installation(rows, archive:, expectedCandidateSha256: current.journal.candidateSha256, verificationChallenge:)`. All four raw hashes must match; both existing public keys are checked during key import; a synthetic/explicit challenge checks signing continuity. The original legacy wrapper opens using its archived explicit channel and the exact archived Aux-v2 wrapper opens using Aux-v2 AAD; 32-byte roots are compared without early byte exit. Owned plaintext buffers are reset. The candidate is reconstructed through the **same-file fileprivate constructor**, and the original private candidate-digest algorithm must match the journal. No random wrapping runs on this recovery path. Pass that exact restored candidate to the existing `ExistingInstallationMigrationStepCaller`; uncertain intent handling remains observation-only under the corrected caller.

The archive checksum is not an authenticity MAC. Journal/capture hashes establish content continuity within this proposal, not trusted provenance. An adversary controlling all files and the asserted capture can forge these public checks. Caller admission, genuine writer custody, reviewed effective selectors/entitlements, original capture provenance and runtime approval remain external and unmet. Root copies/keys are never initialized, replaced or destroyed here. Memory wiping is best effort under Swift copy-on-write; no claim of guaranteed erasure.
