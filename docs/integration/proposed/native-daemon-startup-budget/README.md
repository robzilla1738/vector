# Bound actual daemon startup retries

The real local v135 launch repeatedly started and immediately lost its daemon child. No daemon/CDP listener appeared, and the browser remained in its startup gate. Both Start and DidLaunch previously restarted the 90-second readiness deadline on every child restart, so an immediately exiting child could hold startup forever. This followup retains the existing 90-second allowance across automatic retries, begins the initial allowance only after the first actual launch, preserves a fresh recovery allowance after a previously ready service fails health, and resets the budget after explicit shutdown or an explicit retry from failed state. Exit status is recorded as a number; externally reaped/missing-PID cases retain unknown -1. The original child-identity and shutdown checks remain intact. No readiness/authentication is synthesized.

Read-only signature verification of the local assembled daemon reported modified plist/signature; no signing or provisioning ran. The exact child-exit cause still needs direct process evidence. The source fix addresses the independently observed unbounded retry regardless of that cause. Source-only proposal, native compile and bounded runtime observation pending.
