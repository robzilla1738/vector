# Stable Browser/model identity boundary

Four pinned current-v32 source outputs port the original same-window identity write and transient empty-tab suppression into actual155 fields. Temporary replay passed every output SHA; shared checkout untouched, uncompiled and no runtime claim.

The only new Browser identity commit is private and accessible to the internal owner transaction. It requires the genuine normal regular Browser, actual distinct target, a prepared target ScopedProfileKeepAlive, an empty model, active in-progress/empty-suppression guards and no pending browser deletion. It changes only Browser's authoritative profile/active keepalive and the SAME emptied model's profile. Window, SessionID, TabStripModel object, delegate and all attached view/controller identity remain stable. TabStripModel's setter requires Browser's PassKey and rejects reentrant/nonempty/group-containing/selected state. There is no general-purpose external profile setter, const_cast, URL reopen or view replacement.

Original04559f80 changes old Browser+68 and model+58 while manager ownership is extracted, then adopts the same Browser in the target manager. It separately keeps the actual old/target profiles alive, and constructs the new active keepalive. Chromium155 has no original features+8 profile field; the stable profile-source hooks must be called on the actual individual controllers after this commit. `CommitAuxProfileSwitchIdentity` is intended ONLY inside the prepared `TransferForAuxProfileSwitch` closure; no external callbacks may run until identities agree.

The original source increments Browser+108 and sets byte+105 before extraction. Its Browser::TabStripEmpty implementation respects that temporary flag. The155 Browser currently closes the native window as soon as its final tab is detached; the port suppresses that close while the original transfer is in progress. PostClearAuxProfileSwitchEmptySuppression weakly posts the real zero-delay generation-bound clear; an older task cannot clear a newer switch's guard. The whole transaction's separate in-progress flag mirrors original+104 and must be scoped/restored by the owner. Cache-side temporary suppression uses the same guarded state, without granting a user-visible activation.

Browser's direct focused-group SessionService sink also skips migration callbacks. SessionServiceBrowserHelper and vertical/controller sinks have their separate generation-safe source-pinned guards: suppressing Browser::TabStripEmpty alone is not a persistence boundary.

Integration order is mandatory: prepare real target/profile/cache/keepalives and all fallible service bindings; begin Browser/helper/controller guards; detach real collections; transfer manager ownership with this private identity commit; rebind paused helpers and stable services/views; insert actual target collections; verify same-profile BrowserContexts; refresh coherent target UI; schedule original touched-profile rebuild and zero-delay suppression release. This patch deliberately does not install a UI trigger before the remaining view/service rebindings exist.

Source authority: authorized pinned supplied04559f80.c SHA and original constructor/zero-delay helper proofs in the workspace/transaction-map proposals. No original offsets are written into the changed155 classes.
