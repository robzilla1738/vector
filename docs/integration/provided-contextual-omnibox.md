The supplied UI and event consumers remain unchanged. This is a staged Chromium155 platform adaptation, not a replacement image-search interface. The new source files under proposed/contextual-omnibox have not been applied, compiled or loaded. They are a backend checkpoint; the existing Aux extension API is not yet wired to this handler. Do not advertise working Lens from this commit.

## Concrete adapter authored

OwnedContextualSession constructs the current upstream ContextualSearchboxHandler using the same service/config/source/invocation flow as NewTabPageUI and client callback pattern as RealboxHandler. It owns an OmniboxController/edit model even under Chromium155's model-less experiment, without flipping a global feature or touching the visible URL bar. The client binds autocomplete/Lens to the actual owner WebContents; a profile-only provider would silently lose the native Lens controller.

The handler's real PageHandler pipe exposes native autocomplete snapshots, selection/action/navigation modifiers, file/tab upload, status/error events, context deletion, clearing, modes, submission and session metrics. These are existing upstream implementations, not success stubs. A paired typed Page event receiver must be supplied by the extension adapter. Lens dispatch checks actual provider/tab/profile eligibility and contextual provider availability before calling the real edit model; success is dispatch acknowledgement, never a claim of overlay display or server completion.

A lazy actual per-profile ContextualSearchSessionHandle supplies contextual inputs and upload observers. SearchContentSharingSettings is checked on each acquisition. Invalid profile/document identity, committed main-frame navigation, owner destruction and command/event pipe disconnection close the handler before releasing its context handle. Releasing the last native handle removes the service session and cancels its native controller's work. No independent upload client, search endpoint, URL construction or substitute Lens feature is introduced.

The staged BUILD.gn contains a new target to append to the existing file. It does not replace existing targets or register the backend with the extension API. Parent owns source composition/GN/build scheduling. Current upstream source hashes and bounded anchors are pinned in provided-contextual-upstream.json.

## Extension binding follow-up (staged, not compiled)

The follow-up source now binds both pipes inside the actual private Aux extension API. It replaces the independent raw-byte/context-ready path and hand-actuated URL actions with the shared native handler. Original supplied UI/CSS are unchanged. This supersedes the checkpoint's “not yet wired” statement above; it remains an uncompiled proposal, not enabled acceptance.

- Native Page forwards all original core result fields, actual action metadata, selection, context token/status/error/file, native state, tab, Lens/policy/AIM/smart-sharing events. Chromium155-only Page updates are retained as newer native state, without invented original extension events. The source implements all25 actual current Page callbacks; the verifier checks exact generated method signatures.
- Queries, focus, native result snapshots, click/modifier actuation, non-URL actions, real file/tab upload and previews, context deletion/clearing, actual tool/model modes and submit/metrics lifecycle now use the upstream handlers. Keyword activation and edit-model selection observation port the existing current WebuiOmniboxHandler flow onto this session's owned controller. No visible browser omnibox is borrowed.
- A necessary instance-level UsesModelController hook replaces15 direct model-less-feature checks in SearchboxHandler. Its default retains current upstream behavior. Only this adapter opts into its own model, and base constructor initialization remains safe before derived dispatch. An owned controller alone would not fix later methods that still branch on the global model-less experiment.
- Actual callback object contracts were recovered from the pinned original framework, rather than guessed: getInputState returns available/state; preview returns hasPreview/previewDataUrl; native state uses maxInstances, toolConfigs.toolMode/modelConfigs.modelMode, imageGenUploadActive and aimUrlParams key/value. Newer native enum values unknown to1.26 remain “unknown” instead of pretending that its UI supports them. Original bounded converter ranges/ADRP+ADD string-key anchors are reproducibly audited.
- Tab IDs are explicitly distinct. Original TabInfo exports internalTabId plus optional actual extension tabId and lastActiveMs. The adapter resolves the native handle to the live exact-profile TabInterface before exporting tabId. Preview/add-tab input resolves actual extension tabId to a live handle within that same profile. There is no numeric-ID interchangeability, URL inference or cross-profile fallback.
- Every asynchronous reply retains the API call and rechecks actual owner WebContents, main frame, extension and live session before returning any data. Native file/tab acceptance callbacks are posted to avoid destruction reentrancy before upstream starts its real upload; deletion/session closure invokes real native cancellation. Default callback destruction resolves cancellation rather than leaving an unresolved Promise. A returned context token means accepted, while real server completion/failure arrives through status events.
