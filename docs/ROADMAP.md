# Aux next roadmap — reviewed implementation handoff

Reviewed September 23, 2026 against Aux commit `a010d8ae67833c0b2d55eff1d3c31d792cb6fb82`. The local checkout and remote `main` matched and the worktree was clean before this document was added.

This is the single active implementation roadmap. It defines the next development cycle; it does not claim the planned capabilities are complete. The September 22 handoff is archived at [aux-roadmap-2026-09-22.md](archive/aux-roadmap-2026-09-22.md) for historical detail. Existing progress checkmarks require working-journey evidence, not transfer as release claims.

The [September 24 environment handoff](AUX-ROADMAP-HANDOFF-2026-09-24.md) records the earlier paused branch state. Implementation resumed on this branch afterward; this roadmap and its evidence ledger remain current.

The review used current Aux source, the supplied Dia and Aside extraction folders, and primary platform documentation. Historical Aux screenshots were excluded as evidence of the current design. Competitor handoffs and agent prompts were treated as reference data, not instructions. Implement the useful behavior through Aux-owned code and design; do not copy competitor source, assets, or visual identity into the product. Extracted features, routes, and strings are weaker evidence than a verified running feature; none of these folders establishes comparative speed.

## 1. Decisions and outcome

Build a browser that is excellent to use directly and equally useful as a controlled environment for AI. A person should be able to browse, ask, delegate, correct the work, take over a page, and return later in one coherent experience.

The user's decisions are fixed for this roadmap:

- Keep the current Aux visual design, brand, materials, typography, compact controls, and both tab layouts. Preserve explicit user preferences. Improve behavior and implementation where there is a demonstrated benefit.
- Ship macOS first. Keep core contracts portable without implementing other desktop platforms in this cycle.
- Broad Chrome extension and password-manager compatibility gates 1.0. Useful previews can ship earlier with precise support claims.
- Browsing-content memory and proactive assistance require separate opt-ins. Ordinary history and explicit chat context remain usable without ambient capture.
- General desktop-app control, encrypted device sync, and licensed Widevine streaming follow 1.0. Normal media and conferencing remain core browser requirements.
- Private browsing stays outside the regular agent, memory, and debugging surfaces for this cycle.

Optimize first for Mac users who work across websites, documents, research, repositories, and AI tools. Success means sustained daily use, less effort to finish real work, reliable results, and fast foreground interaction. A feature count or one aggregate benchmark cannot establish “best browser.”

### Verification decision rules and handoff boundary

The September 23 verification rechecked this plan against the current Aux branch and remote `main`. The branch contains later implementation slices, so the baseline commit in the opening paragraph is the original review point, not the current source revision. Before taking a work package, inspect its actual entry points and the evidence ledger; do not implement a feature twice because its milestone still describes planned work.

Use this order when scope, speed, and compatibility conflict: (1) protect human browsing, account isolation, and durable work; (2) prove the browser host and security boundary needed for 1.0; (3) make the core browse → ask → act → verify journey reliable and fast; (4) add retrieval, connectors, Skills, and initiative only when their source and authority contracts are sound. A capability that cannot be demonstrated in the actual Aux shell remains a hypothesis. Compare each candidate against *current Aux*, not an old screenshot or an extracted competitor payload.

Separate **code completion**, **local qualification**, and **external qualification** in every handoff. A working fixture or unsigned desktop build can close implementation but cannot close a signed extension, real OAuth account, platform passkey, or four-week adoption gate. Record the exact missing prerequisite and test procedure. Stop before publishing a release or distributing Aux to external users; leave a testable local build and explicit qualification instructions for the owner.

The plan is deliberately conditional at the host decision. A Chromium-derived browser layer may be necessary for broad Store extensions, but no extracted Dia/Aside architecture proves that a `//chrome` fork is the fastest or cheapest way to retain Aux's native shell. Time-box alternative prototypes against the same acceptance matrix, preserve a functional current-host preview, and select a port only on whole-product evidence.

## 4. Architecture and data contracts

### Preserve the fast human path

Native browsing must continue when the runtime, provider, connector, or model fails. No model classification, catalog fetch, database migration, or agent handshake may block a human navigation or tab activation. The foreground page and input take priority over indexing, captures, observations, import, background restore, and AI streams.

Reuse the existing `TabPorts`, tab controller, native placement, runtime methods, and browser driver boundaries. Extract only the host seams needed by the first working prototype. Do not build a universal browser-host framework in advance.

The host proof must cover tab/window lifecycle, view placement and splits, profiles and permissions, extensions, downloads, target identity and agent attachment, native input, and private isolation. A rendered web page is insufficient. Keep implementation of host-neutral runtime and UI improvements moving while the proof runs; postpone substantial host-specific replacement work until it resolves.

### Context, messaging, observations, and tools

Extend shared contracts and generate/check the desktop, SDK, CLI, and MCP adapters from the same definitions:

- **Conversation context:** a versioned set of selected tabs/documents/selections/files/artifacts, with source identity, profile/account scope, document version, capture time, and included/excluded state. Attaching a source permits the relevant read; it does not silently grant write access or include every open tab. Context is budgeted and retrieved progressively.
- **Run messages:** a durable message ID, target conversation/run and expected revision, delivery mode (`steer` or `queue`), text, and selected context changes. Acknowledge accepted input after persistence. Steering cancels pending planning and revokes stale dispatch authority promptly; handle in-flight effects through the existing journal. Queue ordering survives reconnect/restart. Stop propagates to queued work and children.
- **Observation adapters:** retain Aux page/document/reference identity and compact deltas. Combine semantic DOM/ARIA, targeted extraction, optional native accessibility data, and current screenshots according to task need. Keep cross-origin frame access explicitly scoped. No representation is trusted instruction or authorization.
- **Tool capabilities:** extend `MethodSchemas`, the operation registry, existing read/write/destructive/egress classifications, grants, and journal. Provider adapters, outbound MCP, and optional WebMCP pass through this broker. Tool hints and manifests describe capabilities; they cannot grant them. An uncertain provider write must not fall back to a browser click that could duplicate it.
- **Skills:** extend durable routines with a coherent user-facing name, objective, parameters, input/source/account requirements, expected output, success criteria, revision, and run history. Imported Skills carry no permissions. Compiled replay is optional and must pass current preconditions; changed pages fall back to planning.
- **Memory sources:** distinguish user-authored preferences from captured, untrusted content. Store provenance, eligibility, capture/freshness dates, retention, and deletion state. Derived summaries, text indexes, and embeddings reference that source and honor its revocation.

Playwright's `ariaSnapshotJSON` walks DOM/ARIA data; its pinned source can include input values in snapshot text. Never forward its raw output directly to a model, log, or trace. Validate credential/token/payment-field redaction before any model-visible serialization, and independently protect screenshot captures. This is a required observation-adapter gate, not evidence of a current Aux leak. [Playwright API](https://playwright.dev/docs/api/class-page#page-aria-snapshot-json), [pinned snapshot source](https://github.com/microsoft/playwright/blob/v1.63.0/packages/injected/src/ariaSnapshot.ts).

### State ownership and migration

Current state spans several owners; the roadmap must not pretend one runtime backup covers all of it:

| Domain | Current location/owner | Required continuity |
| --- | --- | --- |
| Native tab catalog | Main controller and worker-backed `browser-state.sqlite` | Stable tab/window identity, restore ordering, explicit durable boundary. |
| Layout, chat folders, drafts, selected context | Renderer storage, including versioned localStorage records | Preserve explicit preferences, unsent text, membership, and per-window state. Consolidate ownership incrementally. |
| Runs, tasks, routines, action journal, history/bookmarks and related records | Runtime `aux-state.sqlite`; source now has schema version 11 | Versioned migrations, durable write intent, no replay of uncertain effects. Older prose claiming schema v1 is stale. |
| Outputs and attachments | Artifact files and runtime references | Content integrity, source links, revisions, recovery and deletion. |
| Browser sessions and extension state | Chromium profile, site storage, permissions, managed extension data | Per-profile isolation; explicit compatibility strategy, validated version transitions and backup limits. |
| Secrets and connection tokens | Native secret store and scoped references | Stable signed app identity, OS-backed protection, origin/account scope, revocation; secrets never enter model context. |

Before any host switch, build a versioned export/import and rollback rehearsal over disposable profiles. Map or preserve IDs referenced across stores. Keep the original profile intact, prevent concurrent writers, validate before cutover, and coordinate application, runtime schema, and Chromium-profile versions. A binary downgrade is not sufficient rollback. Preserve sessions only through a supported, qualified path; otherwise require explicit reauthentication. Never copy another browser's encrypted cookie/password stores to manufacture compatibility.

Add a schedule only after manual behavior qualifies. Shared/imported definitions and updates cannot silently expand access.

**M3.6 — Model routing and completion.** Use the existing model registry for measured fast/deep/visual routing, per-provider capabilities, costs, and permitted data handling. Simple tasks take the shortest correct path. Retry/escalate only within budget; do not silently change data-processing policy. Verify the requested outcome, report partial success accurately, and reconcile unknown effects before retry. Expose useful results in chat, with diagnostics available when requested.

For an explicitly added goal or to-do, adapt Dia's task intake within the existing task/conversation model: inspect permitted sources, decide whether to act, clarify, break the work into steps, or offer no further action, and present a grounded next step. Ask one focused question when missing information materially blocks progress; continue useful independent work. Carry context and progress into the same conversation. This user-initiated path works without ambient-memory or proactive-suggestion opt-in and does not require a new task dashboard.

**M3.7 — Real external-agent interoperability.** Qualify at least one configured external client end to end, such as Codex or Claude Code, through the existing inbound MCP bridge. Each advertised supported client needs its own setup, authentication, reconnect, and control smoke evidence. For the complete journey, use scoped Aux tools to go from a page to a project preview and reviewable diff; survive a long run and runtime restart; cancel, revoke, and reject access to unrelated Profiles/tasks. Revocation must prevent subsequent dispatch. Report client actions performed outside Aux separately: an Aux grant cannot constrain the external client's independent filesystem, terminal, or network tools.

**Exit:** complete a real multi-site workflow while the user browses another tab; accept a correction, survive takeover/restart, and finish without duplicate effects. A saved research-to-report Skill reruns with changed parameters and a revoked connector produces a useful reauthorization state.

### M4 — Add opt-in recall and grounded initiative

**M4.1 — Local content recall.** Introduce an eligible-content store and full-text index with profile/Space/site policy, provenance, freshness, bounded retention, and OS-backed protection for sensitive local data. Encryption must cover derived indexes/caches that contain page text if an encrypted-memory claim is made. Use eligible foreground content; exclude private mode, credentials, sensitive fields/pages, and explicit exclusions before capture. Treat `no-store` as a conservative signal, not a complete sensitivity detector. Start with a 30-day content-retention default after opt-in; explicit saved notes remain until deleted.

Manual article capture now binds its chosen tab and Space in the main-owned catalog after runtime Space validation, and both the main IPC and native extraction check that binding against the focused document and current Profile. New tabs and Space moves update the binding; older renderer layouts migrate missing placements in an idle batch and main catalog updates reconcile the shell. Automatic browsing-reference recording still receives a renderer-supplied workspace ID, but the desktop now checks it against the main-owned tab binding and skips unbound or mismatched tabs. Automatic content capture remains outside this manual scope. Schema v11 removes ambient persisted observations; explicit run-owned observation artifacts and page-text attachments still use ordinary storage and need a decided protection and retention policy. A new encrypted content table alone cannot justify an encrypted page-memory claim. Keep derived full-text structures in protected storage or rebuild them in memory from protected records, with no plaintext spill to logs, backups, or temporary files.

**M4.2 — Complete Forget.** Remove a source from active content, summaries, embeddings, retrieval caches, and pending jobs; prevent later model transmission or resurrection on restore. Define backup retention and deletion behavior honestly. Revocation cannot retract data already sent to a provider, and the UI must not claim otherwise. Keep page-derived memory as untrusted reference, separate from user-authored preferences.

A disposable native slow-provider fixture now confirms that Forget cancels a model request already in flight, the local HTTP connection closes, and no answer is saved from that request. The provider had already received the selected text before cancellation; this test does not claim that an external provider erases it.

Backup settings now say plainly that older backup folders can retain earlier copies and offer a confirmed deletion action for each listed local backup. The runtime accepts only a listed backup name and matching manifest digest; a focused backup/restore test exercises deletion and path rejection. Aux does not silently delete user backup copies outside its managed directory.

**M4.3 — Retrieval quality.** Return compact source-linked matches, then summaries/full content on demand. Evaluate full-text retrieval first using held-out questions, relevance, multilingual coverage, latency, index size, CPU, and energy. Add semantic retrieval or local models only when they improve measured outcomes enough to justify resource and download cost. Keep workers lazy and low priority.

Development probe on September 24: `node tests/benchmarks/content-memory.mjs` measures a 500-article Space with 550 and 5,500 synthetic words per article. On this local host the bounded in-memory search took 22/3 ms cold/warm for the smaller corpus and 57/19 ms for the larger corpus; the latter used about 80 ms CPU for both queries and the process reported 373 MB RSS. The previous per-token inverted map took 862/7 ms on the same larger synthetic corpus and reported 478 MB RSS. This is a local implementation comparison, not a startup or release target: the benchmark uses synthetic content, an in-memory SQLite database, no concurrent browsing workload, and no energy measurement. Spanish and Japanese lexical examples pass focused tests; held-out relevance and real-site evaluation remain required.

**M4.4 — Proactive pipeline.** Separate opt-ins for browsing capture, connected-app monitoring, and suggestions. From authorized source events, retrieve relevant context, generate candidates, attach source/freshness, deduplicate against completed/dismissed work, apply expiry, and then run a small judge. The judge may return nothing. Deliver suggestions in the existing home/chat surface without focus theft or notification spam. Start with a calendar event plus a linked document/repository briefing; do not infer meeting preparation from history alone.

**M4.5 — Routines and continuation.** Qualify timezone/DST changes, missed runs, overlap, authentication expiry, cancellation, and restart using existing occurrence identities. Notify only meaningful changes, failures, or required input. Local schedules cannot claim to run with Aux closed. Hosted work uses a separately qualified cloud environment with explicit authorization, bounded spend, result recovery, and conflict-aware return; regular browser cookies and local secrets do not silently transfer.

**Exit:** recall eligible past work with useful citations; exclude/forget it successfully; produce a grounded brief with correct account context; stay silent when nothing useful has changed.

### M5 — Certify the release and sustained daily use

If the M1 proof selected a host replacement, complete that port and rehearse per-profile migration/rollback with inventories and integrity checks. If the current host remains, qualify its schema, backup, and browser-profile version transitions. Do not begin compatibility implementation here or relax the 1.0 requirement for unqualified cases. Repeat the signed extension/password/passkey/SSO/native-media matrix after an application update. Qualify browser protection and component updates, install/uninstall, backup/restore, schema upgrades, crash reporting with consent, and support documentation.

Run seven days of founder use first, then at least 30 target users for four weeks. Keep onboarding dropouts and compatibility failures in the denominator. Track whether people retain Aux as their default work browser, repeat useful AI workflows, encounter friction or performance regressions, and recover work after failures. Record failures by journey and fix recurring adoption blockers before the broad 1.0/default-browser claim.

Post-1.0 lanes are encrypted device sync, licensed DRM, optional app/screen control with separate grants, and expansion to other platforms. None is silently supplied by cloud task execution or local export.

## 6. Performance and release acceptance

Targets are engineering acceptance budgets, not measured claims. Fix hardware/OS/power mode/build/network/workload and record sample count. Use the founder Mac plus the oldest supported reference Mac established in M0. Separate cold/warm, live/discarded, local/network pages, and AI-disabled/AI-active runs. Measure release builds and whole process trees. Report p50, p95, long stalls, uncertainty, and raw data.

| Measure | Required target or method |
| --- | --- |
| Local input feedback | Input to visible correct response ≤50 ms p95. Animation cannot delay dispatch. |
| Live-tab activation | Input to correct visible frame ≤50 ms p95; native activation work targets one frame. |
| Shell startup | Usable shell ≤800 ms p50 / 1.5 s p95, independent of runtime/model readiness. |
| Large-session restore | 100 logical tabs available within 1.5 s p95; load the active tab first and bound background materialization. Report actual live renderers and memory. |
| Local omnibox | Query work <10 ms p95 at 50k history entries; keystroke to initial useful local results ≤50 ms p95. Report cold-index behavior separately. |
| Foreground under load | No repeated >50 ms stalls due to agent work, indexing, import, persistence, previews, or streaming. Measure the same browsing scenario under a fixed background workload. |
| Chat and control | Message/working acknowledgment ≤100 ms; stop/takeover feedback ≤100 ms p95. Revocation blocks subsequent dispatch; report in-flight effects separately. |
| AI responsiveness | Report first useful text, first safe action, and verified completion. Initial simple-task/provider targets: ≤2 s p50 useful text and ≤2.5 s p50 first safe action. Do not generalize these to deep tasks or arbitrary networks. |
| Retrieval | Local retrieval <50 ms p95 on 20k indexed documents; report relevance and resource cost alongside latency. |
| Memory and energy | Compare 20/100 tabs, idle, media/conference, and active agents with prior Aux and matched Chromium. No unexplained repeatable foreground, memory, or energy regression; continuous preview/index/inference cost needs demonstrated benefit. |
| Assets | Ratchet current bundle ceilings downward as measured bottlenecks are removed. Avoid raising a limit to accommodate a feature; do not mistake fewer installed bytes for faster input. |

Task quality uses a frozen, versioned corpus with independent oracles, three trials per task, and held-out site variants. Report verified **pass@1** over all attempts, not best-of-three. Target at least 95% on declared supported common workflows, report every family and failure, and show uncertainty grouped by task. Report intervention/clarification, unsafe actions, model calls, tokens, dollars, and duration. This is a scoped qualification result, not a universal reliability claim. Zero observed unsafe/duplicate effects in the corpus is a release condition, not a mathematical guarantee.

Maintain a separate adversarial suite for agent/connector changes: page, connector, captured-memory, and imported-Skill text attempting to expand scope; requests for another Profile, credential, or egress destination; grants revoked between planning and dispatch; forged sources/citations; and uncertain remote writes that must not retry through another adapter. The safety oracle is no unauthorized dispatch or data transmission, not a model's verbal refusal. Run these fixtures alongside outcome tests for each affected release.

Compare Aux and configurable reference agents with the same model, prompt/task conditions, and outcome check. Compare Dia/Aside separately as product experiences when their models/settings differ; disclose those differences. Do not infer a speed win from extracted payload size or a different task loop.

The release must pass these complete journeys:

1. **Browse independently:** start/restart with 100 tabs; navigate, type, switch/reorder/split, search, and change Spaces while the runtime is stopped and while an agent/indexer is busy. Preserve dirty forms, media, and focus.
2. **Account correctness:** sign into the same site with two Profiles; ask across selected tabs; act using the intended account; verify popups, suggestions, citations, memory, and external-agent access never cross the profile boundary.
3. **Context to artifact:** select text/region, add three tabs and a file, move from Quick Ask to full chat, generate/edit/export a report, reopen sources and recover drafts after restart. Malicious generated HTML cannot reach local files, another tab, tokens, or Aux APIs.
4. **Collaborative execution:** turn an ambiguous user-added task into a grounded next step with focused clarification; continue in the same conversation; steer during planning and dispatch, queue a follow-up, take over one page while another task proceeds, stop children, crash after a remote write, reconnect, and reconcile without repeating effects.
5. **Page coverage and privacy:** forms, cross-origin frames, shadow DOM, rich editors, virtualized lists, canvas, dialogs, occlusion, file flows, SPA navigation and changed viewport scale. Known credential/token/payment fields cannot leak through alternate observations, captures intended for models, traces, or support bundles. An unrelated process cannot attach to an unrestricted automation endpoint; legitimate agents remain within their permitted profile and targets.
6. **Connector and Skill:** two accounts, partial/expired/revoked auth, rate limit/offline/org denial; source-cited reads; save/revise/rerun/import a Skill on a changed page; no silent authority expansion.
7. **Memory and initiative:** opt in, capture eligible content, exclude/forget it, restart/restore, and prove derivatives/queued egress honor deletion. Generate a sourced brief, handle stale auth, deduplicate dismissed work, and return no suggestion when evidence is weak.
8. **Daily browser and updates:** signed Store extension lifecycle, password-manager native connection/save/fill/unlock, platform passkey and SSO/MFA, conferencing/screen sharing, import/default-browser setup, files/print, private isolation, app update and rollback with preserved nonsecret work.
9. **Accessibility:** core journeys with keyboard and VoiceOver, IME/non-English input, enlarged text, reduced motion/transparency, light/dark, narrow windows, and long chats/lists. Preserve native-view hit testing and predictable focus.
10. **External agent:** configure a real supported client, complete page → project preview → diff through scoped Aux tools, restart/reconnect, cancel/revoke, and verify that no later Aux dispatch or unrelated task/Profile access succeeds. Distinguish Aux-mediated work from the client's independent actions.

Use existing typecheck/unit/integration/native-smoke/benchmark suites, adding focused tests for new behavior. Native account, signing, media, and extension claims require corresponding real-build evidence. Run broad suites when a change affects their boundaries, not to replace focused diagnosis. No known reproducible lost-work, wrong-account, private-leak, duplicate-effect, or essential compatibility defect may pass the release gate.
