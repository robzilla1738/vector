# Native Safari archive and fixture inventory slice 0099

This original implementation follows `docs/spec/native/adblock-import.md` I1/I2. It extends the native importer from 0088/0096. The artifact contains ten owned importer/preferences paths; it does not contain root startup recovery, profile isolation or shared registration changes.

Safari is offered as an explicit export ZIP source, with a single choice covering all profiles in the selected export. The native API accepts `safariArchive: {fileName, data}` where data is binary or an integer-byte array, bounded to 16 MiB. The native import WebUI provides a file chooser and explicit category consent. No arbitrary source pathname is accepted. Selected categories are bookmarks, history and passwords; unavailable categories remain disabled.

The archive reader never extracts files. It rejects unsafe paths, symlinks, encrypted entries, duplicate paths, excessive entries and declared/decompressed size limits. Only selected category contents are decompressed. Bookmarks HTML is parsed by Chromium's sandboxed bookmark utility, then written through the profile bookmark model with hierarchy and source dates. Safari history JSON requires its history metadata/schema and preserves actual latest visit times and source visit counts through HistoryService; it does not invent individual visit records. Password CSV uses Chromium's public parser and the existing native PasswordStore path, preserving notes. Decrypted entries stay native and are absent from RPC results and progress events. Cancellation drops parser bindings and pending native data. Successfully completed jobs retain only source/profile identities in a registered internal list preference.

Nonofficial builds support `AUX_IMPORT_FIXTURE_HOME` for disposable inventory tests. A supplied root must be a canonical private owner directory under the temporary directory; invalid roots fail closed, and source directory symlink escapes are rejected. It replaces source-home discovery only when explicitly supplied. Fixture inventory disables Chromium source encrypted categories so onboarding tests cannot query a real source Safe Storage item. Official builds ignore this override. No owner profile or source keychain was read during verification.

## Verification

Enabled `out/AuxAside` focused compilation passed the actual importer API service, import WebUI, preferences registration, Safari reader and native probe targets. The Safari probe passed valid bookmark/history/password ZIPs, timestamp/count preservation, malformed data, missing categories, unsafe archive paths and decompression bounds. The migrator probe passed disposable inventory for all ten declared source families, encrypted-category refusal in fixture mode, invalid fixture roots and symlink escapes, plus existing Chromium/Firefox snapshot checks. Existing encrypted and filtering engine probes also passed. These are standalone disposable-data probes; they do not prove a running browser destination import or OS permission prompt.

The consolidated patch reverse-apply check passed against the current shared checkout. Native sources were frozen after these checks for the integrator's final noncomponent browser build. No full app link was run in this lane.

Compiled filtering cache, refresh scheduling and full WebSocket/cosmetic runtime fixtures remain unfinished.
