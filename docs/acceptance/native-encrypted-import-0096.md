# Native migration and live filtering followup 0096

This independently authored slice follows `docs/spec/native/adblock-import.md` I1/I2 and F1/F4. It extends patch 0088; it does not supersede that slice's remaining acceptance gaps.

Chromium password and cookie categories now have a real macOS source authorization path for Chrome, Brave and Edge. The worker calls Security.framework for the selected source's Safe Storage item with an interactive LAContext. It never reads the destination OSCrypt provider, its mock-keychain switch or an installation credential. Missing/denied source key access produces a category failure. The public Chromium macOS v10 format is decoded with PBKDF2-HMAC-SHA1/AES-CBC; unsupported formats fail. Modern encrypted cookies validate the SHA256 host binding before accepting plaintext. Derived keys are cleansed on destruction. Snapshots remain read-only and bounded; decrypted batches stay in native worker/UI memory and never enter extension RPC responses or progress events.

Passwords are written through the profile PasswordStore, with source URL/realm/form fields, scheme, timestamps and usage metadata. The importer reads destination matches first and skips existing unique keys. Pending lookups are cancelled before further writes when an import is cancelled. Cookies are validated through CanonicalCookie and written through the profile's real CookieManager; progress advances only after its inclusion callback. Source expiry/security/HttpOnly/SameSite/priority/partition and source metadata are retained. Errors preserve an honest partial count. Firefox unpartitioned cookies use its SQLite schema and exact Unix-to-Windows timestamp conversion; container/partition attributes are rejected rather than merged into the wrong context.

Native source discovery now checks registered application bundle identity in addition to the known data directory. Source family identities and layouts still need full disposable installed-family fixtures. Unsupported source encryption families remain unavailable before starting.

Cosmetic rules now have a document-bound Mojo subscription. Browser activation and enabled-state changes notify existing documents. The isolated renderer replaces the previous observer/style, restores procedural display properties it still owns, and removes lifecycle listeners before applying new rules. Procedural restoration tracking is bounded to 20,000 nodes. WebSocket handshakes now pass through native rules using a browser-derived profile and initiator; unsupported redirect/rewrite actions fail closed. The normal extension request path is preserved for allowed sockets.

## Verification

Enabled `out/AuxAside` compilation passed the actual importer service, source decoder, reader, renderer observer, browser cosmetic host/service, WebSocket helper and shared browser WebSocket caller. The encrypted, Chromium/Firefox and engine probe binaries all pass. Root-requested current daemon supervisor and Chrome startup objects also pass independently; their changes remain outside this patch. The probe creates its own SQLite databases and encrypted values, checks a separately calculated fixture PBKDF2 vector, successful password/cookie decoding, host tamper rejection, unsupported encryption, exact metadata and key clearing. It never queries a real source Safe Storage item. Legacy v10 CBC is unauthenticated, so padding alone is not treated as proof of source-key identity; modern cookie host-binding validation is tested separately. The renderer update/cleanup script passes JavaScript syntax validation. Consolidation includes only this lane's owned files and the approved shared WebSocket hunk, with a scratch reverse-apply check.

## Remaining work

Real OS permission UI and writes into a disposable running browser have not yet been observed. Existing-key lookup is not an atomic insert-if-absent operation across concurrent destination writers. PasswordStore's public completion and actionable-error state do not expose every backend write error. No successful owner-profile/keychain import is claimed or authorized by the fixture results.

Safari ZIP migration, Arc pinned data, extension installation metadata, Firefox container/partition mapping and remaining encrypted-source families are unfinished. Compiled binary filter caching, automatic refresh scheduling and full native filtering runtime fixtures remain outstanding. No full app relink is included here. Root-owned startup recovery changes are compiled separately and belong to patch 0098, not 0096.
