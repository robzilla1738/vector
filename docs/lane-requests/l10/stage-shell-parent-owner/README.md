The standard aux-chromium stage-shell parent now validates an inherited compact original-owner receipt before any staging work. If no receipt is inherited, the existing native-slot guard captures its actual owned receipt once. The same original receipt remains in ENV for build/capture/install children; immediately before install the existing guard validates the retained receipt again, without recapturing a replacement. Existing fixed builder receipt is never replaced, normalized or logged. Parent and child use the same inherited HOME/default slot; builder separately pins HOME to the original helper value. Native-slot, host bindings and existing install/capture behavior remain unchanged.

No pnpm build, install, Stable or default slot operation runs. They prove fresh owned capture, inherited exact receipt, same-token changed inode refusal before work, owner drift during staging prevents install, and bounded malformed input refusal. All five fail on original parent and all five pass on result. Previous seven installer controls remain green. Strict focused test types, lint and exact forward/reverse/forward replay pass.
