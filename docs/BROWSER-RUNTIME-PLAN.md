# Aux: browser-as-agent-runtime build plan

## Context

Aux is a Chromium 154 fork. It has 135 patches in `chromium/patches/series`. The UI is a React 19 + zustand WebUI shell (`apps/shell`) served at `chrome://aux/` inside Chromium's Webium `WebUIBrowserWindow`. Each tab is a real `WebContents`, shown in the shell through SurfaceEmbed. A Node runtime (`apps/runtime`) runs once per loaded Chromium Profile, reached over an authenticated Unix socket. Native services live in `~/aux-chromium-stable/chromium/src/chrome/browser/ui/aux/**` (`methods/*.cc`, `AuxMethodRegistry`).

The owner wants Aux to be a browser that *has* an agent and IDE-grade tools, at reference-product polish. The 17-feature wishlist plus three differentiators has to land with unattended qualification journeys and be flipped to `on` in the feature registry. Today, much of that wishlist is only declared or partially built.

### Owner decisions (this session plus memory)

- **Cross-window:** Arc-style. Every window shows the same live Space sidebar. Clicking a tab held by another window **moves it here**; the old window shows a "moved" placeholder.

## Execution model

### Roles
- **Integrator (me):** owns the following, and is the only one who merges.
  - `packages/contracts/**`
  - all generated files
  - `apps/runtime/src/main.ts` wiring and global shell wiring (`App.tsx`, settings routes)
  - `chromium/patches/series` and patch numbering
  - `docs/qualification.json`, `HANDOFF`, `EVIDENCE`, `CONTINUATION` and the board
- **Builder agent:** one dedicated subagent. It is the **only** process that writes the stable Chromium tree, builds it, or runs journeys. It works through a FIFO queue in `~/aux-chromium-stable/build-queue/*.json`.
- **Lane agents:** `Agent` with `isolation:"worktree"`, branched from tag `contracts-v1`. Lanes read the stable tree but never write it. Native edits go into mirrored copies under `<worktree>/.native/<chromium path>`, and `scripts/native-diff.mjs` turns them into the lane's reserved patch file.
- **Design reviewer agent:** reviews contact sheets continuously against the `design-qa.md` rubric and files P0–P2 findings to the owning lane.

### Messaging (SendMessage, fixed prefixes)

| Prefix | Direction | Purpose |
|---|---|---|
| `CONTRACT-REQUEST` | lane → integrator | Zod diff saved as a patch, plus the reason |
| `CONTRACT-LANDED contracts-vN` | integrator → affected lanes | Ref and changed symbols; lanes merge the ref |
| `SHARED-FILE-REQUEST` | lane → integrator | Adapter diff for an integrator-owned file |
| `BUILD-REQUEST` / `BUILD-RESULT ok\|fail` | lane ↔ builder | Worktree, commit, patch files, journey ids. The result returns the log, manifests, and the failing step with an AX dump. |

| `MERGED` / `REBASE-NEEDED` | integrator → lanes | Lanes merge `integration`, never another lane's branch |
| `BLOCKED` | any → integrator | Lanes escalate when an outcome changes the plan or can't be resolved directly |

The integrator sends each lane the roster of agent IDs right after spawning it.

### Native slot
- One lock: a `mkdir` at `~/aux-chromium-stable/.aux-native-slot/` with `owner.json`. A dead PID means the lock is stale.
- `scripts/native-slot.mjs` provides it, and `aux-chromium build`, `qualify.mjs` and `run-journey.mjs` all acquire it.
- The lock covers build, staging and journeys, because the display, cursor and focus are shared.
- Integration builds take priority over lane builds.

**Builder cycle:**
1. Reverse the previous candidate patch.
2. Run `git apply --check`, then apply the candidate.
3. Build from the **candidate worktree**, with `AUX_SHELL_PIN_DIR` pointing at scratch.
4. Run `stage-runtime`.
5. Run the journeys.
6. Send `BUILD-RESULT`.

### F11: Smart download rename with Undo (`smartDownloadNames`, L9)

   - dangerous or insecure;
