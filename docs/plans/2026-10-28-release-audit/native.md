## New release blockers the audit doc does not mention

1. **High. Hardened runtime without resource-access entitlements.** The outer `Aux.app` is signed with hardened runtime and only `com.apple.security.cs.allow-jit`. The tree's own `chrome/app/app-entitlements.plist` declares `device.camera`, `device.audio-input`, `personal-information.location`, `photos-library`, `bluetooth`, `usb` and `print`. The repair plan pins allow-jit only. Under hardened runtime, camera, microphone, location and photos access is denied, so web video calls, `getUserMedia` and geolocation should fail. `NSAppleEventsUsageDescription` (Safari tab import) has no `com.apple.security.automation.apple-events`. `Aux Computer Use.app` is signed with hardened runtime and **no** entitlements, yet declares Contacts, Apple Events, Accessibility and Input Monitoring usage. Confirm in the live pass: open a camera test page.
2. **High. Candidate-dated state location compiled in.** User data lives in `~/Library/Application Support/Aux Browser Completion 20261026/User Data` and `~/Library/Caches/Aux Browser Completion 20261026`, hard-coded at `chrome/app/chrome_main_delegate.cc:697,709`, `chrome/browser/aux/AuxNativeParentColdLaunch.cc:275-322` and `native_peer_policy/AuxFreshBootstrapPolicy.swift:27-29`. Renaming it after any user has data is a migration. The shipping binary also accepts a `--user-data-dir` under `/private/tmp/aux-fresh-browser-*/home/Library/Application Support/Aux` (mode 8, `chrome_main_delegate.cc:617-618`).
3. **Medium-high (legal/attribution). About page miscredits Chromium.** `components/components_chromium_strings.grd:279` (`IDS_VERSION_UI_LICENSE`, pak id 35399) reads "Aux is made possible by the Aux open source project", with the link still pointing at chromium.org. The brand sweep replaced the Chromium credit that D7 says to keep.
4. **Medium. The release config is untested and differs in behavior** (see row 1): the official build drops the first-run and default-browser suppression and the dev-startup path, and needs PGO data. No official build has ever been produced.
5. **Medium. A daemon crash is unrecoverable without restarting the browser** on the shipping native route (row 9). There is also no UI (row 10), and the health check pins the exact daemon version `"1.26.1016.1852"` (`daemon_supervisor.cc:407`), so any daemon update needs a native rebuild.
6. **Medium. Vault is out of scope but still trusted for CDP** (`browser_platform.cc:288`) and sits in the WebAuthn path. The audit lists the broker as dead code, not the CDP trust.
7. **Medium (package, outside native scope). Candidate `Contents/Resources/aux/bundle.json` declares `"cloudPolicy": {"mode": "development", origins: dev-cloud.getaux.co}`**, and 47 daemon skill files hot-link `https://dev-cloud.getaux.co/builtin-skills/...` icons. STATUS says the build uses the production cloud. Hand this to the daemon/package audit.
8. **Low. Settings `isAux` is hard-coded `false`** (`chrome/browser/ui/webui/settings/settings_ui.cc:244`), so the Library's clear-data return path (`resources/settings/privacy_page/privacy_page.ts:136-141`) is dead and the user lands in Settings instead of History.
9. **Low. Reproducibility.** The `aux_native_pdf_bridge/node_headers` symlink in `added.tar.gz` points to a deleted absolute `/Users/rcourson/Documents/Vibe/web/...` path. `chromium-tree.py verify` writes objects into the checkout's `.git`, contrary to `chromium/tree/README.md`.
10. **Low. Exported UTIs `org.chromium.extension` / `org.chromium.shortcut`** (Info.plist `UTExportedTypeDeclarations`) collide with an installed Chromium or Chrome.
11. **Low. The Sparkle assert message still says "requires the Aux shell"** (`chrome/BUILD.gn:526-527`): a shell-era leftover that blocks the update path outright (row 28).
