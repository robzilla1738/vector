# Profile organization bridge

The renderer calls `organizationSnapshot()` and `organizationCommit({expectedRevision,layout})` on the trusted Aux host bridge. The host derives the Profile and browser window from the calling frame. Renderer arguments never contain either identity. A private window keeps its layout in memory and does not call these methods.

The exact payload schema is `OrganizationLayoutSchema` in `packages/contracts/src/organization.ts`. `layout.shared` contains Spaces, archived Spaces, favorites, and folders. `layout.window` contains the active Space, active tab per Space, split ratio, tab assignments and order, folder assignments, and split pairs. These tab-specific fields follow the calling window's catalog and cannot overwrite another window's tabs. The complete `layout` is capped at 256 KiB of UTF-8 JSON. IDs are at most 200 characters. Arrays are bounded in the schema. Validate the payload and frame ownership before storing it.

`organizationSnapshot()` returns `{revision,layout}`; `layout` is `null` only before first import. `organizationCommit` atomically replaces the current window's selection and the Profile's shared organization when `expectedRevision` matches. On a stale revision, reject with an error without writing. Revision numbers start at zero and increase by one per accepted commit. The renderer fetches a new snapshot and rebases its changed fields; unchanged fields retain concurrent edits. Retain at most 64 window selections per Profile, dropping the oldest inactive selection as new windows arrive. Both methods must use the same Profile-owned store, and snapshots from another Profile must never be returned. Quick Ask windows do not persist organization.

Publish `onOrganizationChanged(revision)` to the trusted shell after the Profile store accepts a commit, including commits from another window. The native Profile pref observer should be the publication point. The renderer fetches the new snapshot and updates its live layout when the revision advances.

On first load, the renderer reads the old `aux.layout.v1:<windowId>` key (or `aux.layout.v1` for the main window) only to import it when the host snapshot is empty. Later loads use the host snapshot. The Electron host writes `organization.v1.json` in its Profile directory; the Chromium implementation should use a Profile dictionary pref and preserve the same revision and conflict behavior.
