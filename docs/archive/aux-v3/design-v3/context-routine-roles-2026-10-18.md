## Shared modal lifecycle correction

Renderer keyboard traversal exposed a real existing lifecycle problem: Channel Options → Credentials changed its conditional initial-focus ref, causing `useNativeDialog` to close/reopen the same modal and replace its original return target with an internal control. The shared hook now stores latest focus configuration separately, reads it once when the actual open/dialog-ref lifetime starts, and keeps that opening's original target and initial focus. Later focus-prop changes do not re-acquire the modal or steal the selected control. A subsequent opening uses the latest configuration. The Channel caller keeps its conditional initial-focus ref; no caller compatibility shim or second modal stack was added.

A shared regression changes both initial/return focus refs while open, checks current control retention, Escape return to the original opener, latest initial focus on reopening and that opening's return target on unmount. A separate actual Channel tab regression traverses Options/Pairing/Credentials and restores its focused original Manage opener. Existing newer-focus and nested-modal protections remain.
