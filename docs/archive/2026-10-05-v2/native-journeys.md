# Native Aux.app journeys

The accepted S7 importer outcome uses three focused flags. `--browser-import-ui` asks an operator to select exact Chrome Profile/category pairs in Settings, then checks native destinations and restart. `--browser-import-formats` uses an isolated discovery root with Arc, Safari and Firefox fixtures; it checks each source/category, source hashes, idempotence and restart. `--browser-import-attached` launches a separate disposable headless Chrome CDP Profile, verifies borrowed tabs transfer into Aux without changing Chrome, then cancels a 5,000-visit History import, retries, isolates a corrupt second Profile, checks native History after normal Aux Quit and verifies History and sleeping imported tabs after restart. The last passing [attached import manifest](../release/test-artifacts/native-s7-browser-import-attached-2026-09-28-f/manifest.json) records the result. The fixture override changes only import discovery; Aux retains its real process `HOME` for native Profile/Keychain startup. No owner browser Profile is read.

`tests/host/native-app-journeys.mjs` runs the browser core and Aside layout journeys against an **Aux.app**, including the current `out/AuxDev/Aux.app` development build. It starts a fresh Profile in a short `/tmp` path, serves two loopback pages, and uses that Profile's owner-only runtime token. It never enables a public DevTools port or attaches to an existing Profile. The official static app and DMG are deferred.

```sh
node tests/host/native-app-journeys.mjs --list
node tests/host/native-app-journeys.mjs --app /Users/rcourson/aux-chromium-stable/chromium/src/out/AuxDev/Aux.app --rpc-only
node tests/host/native-profile-journeys.mjs --app /Users/rcourson/aux-chromium-stable/chromium/src/out/AuxDev/Aux.app
```

The full run needs macOS Accessibility permission for the terminal running it and Screen Recording permission for `screencapture`. It verifies the launched app's bundle ID and packaged runtime helper, distinct page IDs, readable page content, native click delivery, human takeover, tab closure, and the absence of `DevToolsActivePort`. It sends Control-Tab in both tab layouts and checks the active page ID, sends Command-L and checks that a labeled address field receives accessibility focus, and dismisses the floating Aside with Escape. It captures the real Aux window in vertical expanded, collapsed, edge peek, and horizontal states. Accessibility button checks and pixel change assertions catch broken sidebar toggles and edge reveal; use the captures to inspect clipping, contrast and compositing. **Do not infer native blur quality from screenshots alone**; compare the live material on the actual display. The manifest records the source SHA and each assertion. Captures and the manifest stay in ignored `release/test-artifacts/`.

For a machine without capture permissions, `--rpc-only` runs just the browser and runtime assertions. That mode does **not** qualify the Aside layout. `--output /absolute/new/directory` chooses a new evidence directory; existing evidence is never overwritten. The runner removes its disposable Profile on success or failure and never writes its bearer token to the report.

The Profile journey launches two disposable regular Profiles against the same local site, verifies separate HttpOnly cookies and denied cross-Profile page access, then restarts one Profile with `--restore-last-session` and checks that its active page ID and account survive. The native app journey also requires Find to count and advance visible matches and reset zoom. These core development journeys passed as recorded in the [native evidence log](evidence/native-aux-live-2026-09-25.md); rerun an affected suite when native/runtime changes touch its assertions. Full release qualification is deferred.
