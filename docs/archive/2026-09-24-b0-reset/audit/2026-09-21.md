# Aux audit — 2026-09-21

Commit `07cec7c7`. Local `main` matched `origin/main` with a clean tree. GitHub Actions `runtime` and `engine` both succeeded on that commit.

The pre-M1 writeups in this directory are not open bugs. On this tree the loopback API binds `127.0.0.1`, caps bodies at 2 MB, and takes `?token=` only on the `/ws` upgrade. Planner output cannot contain `evaluate` or expression waits (`PlanStepSchema`), page text is fenced, and `allowEval` defaults off. Shell and page views are sandboxed. Engine redirects are policy-checked again on the next hop, and the broker re-checks resolved addresses before the wire. MCP observe defaults to compact. Early dispatch runs validated steps while a single-page plan is still streaming. The stage lease is not process-global, and step rows are written in one transaction at the end of the program. Engine fallback does not replay a completed write or a remaining side effect. Cancel leaves a set run cancelled. `testharness.txt` is 114 lines. `wpt-partial-updates-latest.json` is 142 pass / 2 fail of 144. Those match the README.

Checked-in engine microbenchmarks are already microseconds on static fixtures (`docs/perf/m1-gate-latest.json`). They were not re-run. User-visible time is the model turn and Chromium, not layout.

## What changed

- The Aux window may call only runtime methods that appear in the renderer source (`apps/desktop/main/renderer-methods.ts`). `pages.execute`, `agentConnections.create`, and the other methods the window does not name are rejected in the main process. A test fails if the list and the renderer source diverge.
- `ui.openExternal`, `ui.openPath`, and `ui.revealPath` now require the shell document, matching the other window IPC handlers.
- Export save dialogs use the file's base name, so a suggested name of `..` or an absolute path cannot retarget the dialog.
- `runtime.describe` reports `checkpointResume: false`, which is what the comment above that flag and the API docs already said.
- Agent `navigate` to `javascript:` or `vbscript:` requires the evaluate capability. The engine checks `allowEvaluate`; the runtime checks `allowEval`.
- Page and document text carried as earlier-session context is inside the same prompt fence as observations.
- MCP `vector_page_execute` and `vector_set_map` accept only planner steps, so `evaluate` is not a tool argument.
- A run already marked `cancelled` stays cancelled when a saved program or the coordinator finishes afterward.
- A schema-upgrade database snapshot drops `setting:gatewayApiKey` after it is copied.

## Backlog

These are real and were left because the change is a product choice or a redesign.

- `openPath` and `revealPath` accept any path from the shell. Private windows already limit this to a completed download. The regular window uses the same IPC for downloads, project files, incident reports, and agent path chips. A single allow-list root would break the chips.
- The methods the window does call include `settings.set`, `chrome.importCookies`, `vault.unlock`, and `cloud.handoffAndStart`. A compromised shell can still call those, because the product UI does. The new gate does not invent a second permission system inside that list.
- `pages.execute` from a loopback bearer token still runs page script. That is the CLI and MCP path. The token file is owner-only.
